# ADR-046：评估失败的分诊与客户自助改进

- 状态：**已接受，四项缺口全部收口**（2026-11-01；分诊迁移 `460`、版式 `462`、提示词段 `463`、口径模块 `464`、评估运行器 `465` 均已落库）
- 日期：2026-10-31
- 决策者：用户（Larry）+ 开发 Agent
- 相关：ADR-045（评估用例的库化与权限维护）、ADR-044（回答质量的窄判官）、ADR-016（助手处境与任务闭环，缺口 #6）、ADR-030（助手参数框架）
- 目标（用户 2026-10-31 明确）：**运维跑完一轮评估后，改进由运维在系统内完成，不回开发**

## 1. 问题

评估报告今天只说"这条没过"。运维拿到它仍然不知道**该点什么**，于是每条失败都会变成一次"找开发"。
要把这条链路断掉，报告必须回答三个问题：**改哪里、怎么改、需要什么权限**。

## 2. 决策：每条用例自带"分诊"

`ASSISTANT_EVAL_CASE` 增加三列（迁移 460）：

| 列 | 语义 |
|---|---|
| `FIX_AT` | 失败时的修改落点（十类，见 §3） |
| `FIX_SUGGESTION` | 一句话建议动作（给人看，不做机读判定） |
| `FIX_PERMISSION` | 该落点需要的权限所属模块号（`code` 类留空——它改不了） |

**分诊是"如果这条失败，通常该去哪里改"，不是"已经失败"**；它随用例走，因此不需要等运行器就位。

## 3. 十类落点与现状（这是本 ADR 的核心表）

| `FIX_AT` | 典型失败 | 改哪里 | 现状 |
|---|---|---|---|
| `case` | 期望写错、问法不真实 | 3106 评估用例 | ✅ 已有 |
| `param` | 限额/采样/额度/熔断不合适 | 3105 助手设置 | ✅ 已有 |
| `prompt` | 规则缺失、措辞让模型误解 | 3105 基础提示词 + **8 段行为规则（未参数化）** | ⚠️ 部分 |
| `tool` | 工具描述与实际行为不一致 | 代码常量 | ❌ 未参数化 |
| `metric` | 口径名/维度/说明不对 | `REPORT_METRIC` | ❌ **只有 GET，无维护面** |
| `metadata` | 字段描述、必填、可见性、选择器 | 2302 元数据管理 | ✅ 已有 |
| `rule` | 校验规则/效果链动作文案与引擎不一致 | 230104 模块动作 | ✅ 已有 |
| `kb` | 缺制度/规范文档 | 3103 知识库 | ⚠️ **只有列表/删除，无入库卡片** |
| `data` | 前置数据缺失、业务数据本身错 | 业务操作（录入/结案/库存） | ✅ 业务侧 |
| `code` | 工具返回错、缺能力、权限误判 | 开发商 | ❌ 只能提缺陷单 |

**回填口径**：按 `LAYER` 给默认落点（`diagnosis→rule`、`functional/business/inference→prompt`、`action→metadata`、`authz→code` 等），
再对具体用例逐条覆盖。2026-10-31 的现状：`prompt 106 / rule 48 / code 31 / metadata 8`。

## 4. "自助改进"的边界（红线）

| 允许 | 禁止 |
|---|---|
| 客户侧有对应权限的人改用例、参数、元数据、规则、口径、知识库 | 自动改写行为（提示词/阈值）后**直接生效** |
| 系统按 `FIX_AT` 出"改进清单"与所需权限 | 用系统输出反过来改"期望"（循环论证） |
| `code` 类在系统内一键提缺陷单（带用例 ID、correlationId、证据） | 把 `code` 类混进"可自愈"清单，假装不用回开发 |

一句话：**不需要发布、不需要开发者，但不能没有责任人**——与"批核不可代签"同一条逻辑。

## 5. 为什么分诊先做

1. 零行为风险（只是给已有用例加三列事实）；
2. 立刻可用：评估报告/审阅表能按 `FIX_AT` 分组，运维知道点哪里；
3. 给后续投入排序提供依据：`FIX_AT` 分布告诉我们下一个该补哪个入口（当前 `prompt` 最大 → 提示词参数化收益最高）。

## 7. 复审条件

- 出现"自动改行为后直接生效"的实现 → 立即回退（红线）；
- `code` 类占比长期 > 40% → 说明"可自愈"面没建好，重排缺口优先级，而不是把 `code` 类改判；
- 客户侧无 `CanSetup` 责任人 → 自助评估不启用（否则没人担责）；
- 评估结果与真实用户反馈长期背离 → 先修用例，不要先调判官。
