# ADR-040：工作区标签的导航模型（模块窗口）

- 状态：**已实施批 0–5（2026-10-21）**——身份/跨模块入口/统一返回/`state` 透传/对照窗口与门禁均已落地
- 日期：2026-10-21
- 决策者：用户（Larry）+ 开发 Agent
- 相关：ADR-015（多标签工作区；本文**覆盖**其 §3.3 的 `from` 参与去重、§3.5.1 的去重键、§3.6.1 的历史匹配，其余条款继续有效）、ADR-006（统一表单）、ADR-024（报表入口）、`EOS.Web/src/components/layout/`、`EOS.Web/src/lib/navigation.ts`

> 本文只回答三件事：**标签代表什么**、**什么时候开新标签**、**返回去哪**。
> "改哪个文件、分几步上"属于实施计划，见 §6，不写进决策条款。

## 1. 为什么要重定

### 1.1 ADR-015 定死了八条，漏了一条

范围（全站）、真保持、上限 12、脏页切换不弹框、关闭语义、刷新懒挂载、POP 匹配、权限 403——这八条落地得是好的。

漏掉的是**"页面之间的跳转算什么"**。ADR-015 只写了两条特例：点菜单（§3.5.1）与列表→查看/编辑（标签内导航），
其余（待办→单据、报表中心→报表、表单→字段设置、流程图→模块）一个字没写。没有规则的地方，
就由每个页面自己写 `navigate()` 决定——全站 20 余处各写各的。

更麻烦的是 §3.5.1 那条实现取舍：**去重键 = 完整 URL**。而标签内导航会改写自己的 URL（`AppShell.tsx:626-636`）。
于是标签的"身份"是个会漂移的东西——这是下面所有怪现象的源头。

### 1.2 今天实际在跑的"隐式规则"

| 入口 | 实际行为 | 证据 |
|---|---|---|
| 侧栏菜单 / 菜单搜索 / 首页快捷 | 开新标签，**按完整 URL 去重** | `AppShell.tsx:423-441` |
| 列表双击行 / 新增 | 原地改写本标签 URL（模块配了 `NEWTAB` 时例外） | `DocumentWorkbenchPage.tsx:351-361` |
| 字段浏览链接（跨模块借看） | 开新标签，带 `from` + `back` | `FieldBrowseLink.tsx:40-46` |
| 待办 / 流程监控 / 审批历史 → 单据 | **原地顶掉来源页** | `MyTasksPage.tsx:179`、`FlowMonitorPage.tsx:171,249` |
| 报表中心 → 报表 | **原地顶掉报表中心** | `ReportCenterPage.tsx:152` |
| 列表/表单 → 字段设置、表单 → 报表 | 原地 | `FormEditorPage.tsx:2139,2187` |
| 业务流程图 → 模块 | **`window.open` 开浏览器窗口**，绕开标签 | `BusinessFlowPage.tsx:299-307` |
| 返回（统一表单） | `back` → `from` → 本模块列表，三档兜底 | `FormEditorPage.tsx:1236-1248` |
| 返回（BOM 各页） | 硬编码 `navigate('/bom/product')` | `BomProductEditorPage.tsx:357` 等 5 处 |
| 返回（版式设计器） | `navigate(-1)`（浏览器后退） | `LayoutDesignerPage.tsx:779,801` |

**同一个"返回"有 4 套口径，同一个"去别处"有 3 套口径。**

### 1.3 由此产生的七个症状（均有机制，不是观感问题）

| # | 症状 | 机制 |
|---|---|---|
| S1 | 点菜单冒出第二个同名标签 | 标签 URL 一旦进了单据（`/workbench/1405/view/X`）或带了筛选，就不再等于菜单地址 ⇒ `openTab` 判"未开" ⇒ 新建（`workspaceTabs.ts:274`） |
| S2 | 从待办/流程监控/报表中心打开后，来源页消失 | 那些入口用 `navigate()`（原地），而 `FieldBrowseLink` 用 `openTab`（新标签）——同类动作两种行为 |
| S3 | 返回的去向取决于"你是怎么进来的" | 四套口径并存（§1.2 后三行） |
| S4 | 浏览器后退"复活"已关闭的标签 | 切标签与关闭接管都走 `push`（`AppShell.tsx:451,467`），历史里混着各标签地址；`sync`（`workspaceTabs.ts:313-330`）按 URL 命中其它标签就切过去，否则改活动标签 |
| S5 | 上一条/下一条静默消失 | `WorkspacePanel.tsx:51-55` 把标签 location 的 `state` 固定成 `null`，而浏览顺序放在 `state.navKeys` 里传（`DocumentWorkbenchPage.tsx:360`）⇒ `FormEditorPage.tsx:1837` 判空后整段按钮不渲染 |
| S6 | 同模块两张单没法对照 | 双击即原地，没有"新标签打开"入口；`FORM_OPEN_MODE` 是**模块级**开关，不能按次决定 |
| S7 | 隐藏标签的跳转被静默丢弃 | `workspaceTabs.ts:331-338`：目标地址已被别的标签占用时直接 `return`，保存后回列表可能什么都不发生 |

## 2. 决策

### 2.1 模型：一个模块一个标签

标签 = **一个模块的工作现场**，不是一个会漂移的地址，也不是一个独立的页面实例。
列表、单据浏览/编辑/新增/复制、上一条/下一条都发生在**同一个**模块标签里；跨模块只切/开标签，绝不顶掉来源。

这正是旧系统用户"一个模块一个 IE 窗口"的心智：菜单点开的是"采购订单这个现场"，不是"采购订单列表这个页面"。

### 2.2 六条规则

1. **身份 ≠ 地址。** 标签身份由"它是哪个模块 / 哪个页面"决定；筛选、排序、页码、`from`、`back` 全不参与。
   地址只表示"这个现场现在停在哪一页"。
2. **跨模块跳转不改写来源标签。** 去 B 模块 = 切到 B 的模块标签（没有则新建），A 标签原样留着。
3. **返回只依赖"我在哪个模块"。** 表单工具栏的返回 = 本模块列表；不读 URL 参数，不做历史后退。
4. **一个标签一份状态与历史。** 切标签用 `replace`（不上历史），浏览器前进/后退归当前标签；
   标签必须能把导航 `state` 交给自己面板里的页面（否则依赖 state 的功能永远修不回来，见 S5）。
5. **点已开的模块菜单 = 只聚焦**，不改它停在那一页（拍板：2026-10-21）。
   要看列表，用表单的"返回"——菜单负责"去那个模块"，返回负责"回列表"，一个动作一个含义。
6. **要同时看两张单，显式开"对照窗口"**（§2.6）。

### 2.3 入口语义表（唯一口径）

| 入口 | 行为 |
|---|---|
| 侧栏菜单 / 菜单搜索 / 首页快捷 / 最近访问 | 切到该模块标签（无则新建），**只聚焦、不改位置** |
| 列表双击行 / 新增 / 复制 / 上一条 / 下一条 / 保存后转浏览 | 本模块标签内原地 |
| 列表 → 字段设置、表单 → 报表 / 字段设置 | 切到目标标签（无则新建），来源保留 |
| 待办 / 流程监控 / 审批历史 → 单据 | 切到目标模块标签并**定位到该单据**，来源标签保留 |
| 字段浏览链接（借看别处一条记录） | 切到目标模块标签并定位到该记录；**不再带 `back`** |
| 报表中心 → 报表 | 报表独立标签（身份 = `reportId`） |
| 流程图 → 模块 | 切到模块标签，**不再 `window.open`** |
| 打印 | 保持浏览器新窗口（A4 打印不属于工作区） |
| 助手全屏 / 半屏 | 沿用现有标签开关 |

### 2.4 身份与去重

| 标签类型 | 身份 | 说明 |
|---|---|---|
| 模块标签 | 模块号 | 工作台、报表承载页、打印、版式设计、模块兜底页都算该模块 |
| 页面标签 | 路径 | 首页、报表中心、查询/待办、系统管理子页、单报表（`/report/{reportId}`） |
| 对照窗口 | 模块号 + 主键 | 只由显式"在新标签打开"产生（§2.6） |

**查询串不参与身份**：同一个模块的列表，筛过的与没筛过的是**同一张标签**——
这正是 S1 的修法（点菜单聚焦已有标签，而不是因为筛选不同另开一个）。

**页面族**：同一工作现场下的一组父子页共用一个标签（父页↔子页原地切换）。目前只有六组：
BOM（`/bom/**`：列表、结构树、编辑、对比、反查）、数据表/字段维护（`/admin/tables*` + `/admin/tables/:id/fields` + `/admin/fields/:table/:field`）、
用户管理（`/admin/users/**`）、用户组（`/admin/groups/**`）、报表中心（含订阅收件箱）、系统设置（`/settings/**`）。
判据是"它们之间有返回关系、用户不会想同时开两个"；其余 `/admin/*` 各页各自成键——
按 URL 前缀粗暴归并会让点菜单落到另一个页面上，那比多开一个标签更糟。

`from` 降级为**纯展示提示**（面包屑/标题旁标注"← 来源模块"），不参与身份、不参与返回；`back` 参数**退役**。

### 2.5 历史与浏览器后退

- 切标签、关闭标签后的接管跳转一律 `replace`，不往历史里塞条目。
- 浏览器前进/后退 = 当前标签内的前后页（列表 ↔ 单据），命中本模块内的地址即改写本标签。
- 历史里若出现**别的模块**的地址（跨模块 `navigate` 的残余、外链进入），按"去那个模块"处理：
  有对应标签就聚焦，没有就新建一个承载它——**不把当前标签改成另一个模块**。

### 2.6 对照窗口（单据标签）

同模块两张单要并排看，走**模块级配置** `FORM_OPEN_MODE=NEWTAB`（列表双击即按该配置打开）：

- 它是一个**固定的**标签：身份 = 模块 + 主键，内容恒为那一张单；同一张单再打开只聚焦，不会开出第二个窗口；
- 不提供"上一条/下一条"与"新增/复制"（那是模块标签的事），即便模块配的是弹窗方式，也不在标签里再套窗体外壳；
- **新增/复制没有主键、没有单据身份**，仍留在模块标签里——否则每次新增都多一个标签；
- 它的**返回 = 关闭自己**（回到开它之前那个模块标签，`openedFrom` 精确回退，不取邻居）；
- 规模受同一上限约束（12 个），撞顶时与其他标签一样只提示。

## 4. 风险与回退

| 风险 | 缓解 |
|---|---|
| 身份改造动到标签主体（reducer + 外壳），回归面大 | 分批落地（§6），批 1–3 必须同批上（只改身份不改入口，问题会从"重复标签"变成"标签改模块"） |
| "点菜单只聚焦"导致用户找不到列表 | 表单返回固定回列表；标签标题带动作前缀（查看/编辑）让"停在哪"一眼可见 |
| 上限 12 在"对照窗口"下更易撞 | 对照窗口按需开，撞顶沿用既有提示；若实测频繁，按 ADR-015 §8 复审 |
| 回退 | 现有特性开关（`workspaceTabsEnabled`）保留：关掉即回单标签单任务，标签栏隐藏 |

## 5. 验收口径

1. 打开采购订单列表 → 进入某单 → 点左侧菜单"采购订单" ⇒ **不新增标签**，聚焦原标签且仍停在该单上。
2. 列表筛过再点菜单 ⇒ 仍是同一个标签（不因查询串不同另开）。
3. 从"我的待办"打开一张单 ⇒ 待办标签仍在，点它回到原来的位置。
4. 在 B 标签按浏览器后退 ⇒ 不跳到 A 标签；关闭 A 后再按后退 ⇒ **不复活** A 的内容。
5. 列表双击进入浏览态 ⇒ 上一条/下一条可用，且顺序与列表显示顺序一致。
6. 报表中心点开报表 ⇒ 报表中心标签仍在。
7. 同一模块开两个对照窗口 ⇒ 两张标签各自独立；在对照窗口里点"返回" ⇒ 关闭自己，回到开它之前的标签。
8. `npm run lint` + `npm run build` + 相关 `vitest` 全绿。

## 6. 实施批次（每批独立回归）

| 批 | 内容 | 通过口径 |
|---|---|---|
| 0 止血 | 标签 `state` 透传（恢复上一条/下一条、表单告警、弹窗首帧提示） | §5.5 |

| 2 入口归一 | 跨模块 `navigate` → "去那个模块"（切/开标签）；流程图不再 `window.open`；删硬编码返回与 `navigate(-1)` | §5.3/§5.6 |
| 3 返回 | 统一"返回 = 本模块列表"；`back` 退役、`from` 降级为展示 | §5.1/§5.7 |

## 7. 明确不做

- 不做标签内嵌浏览器式完整历史栈（前进/后退只到"本标签到过的页"）。
- 不做分屏对照（ADR-015 §4.7 不变）。
- 不做标签拖拽排序、不做除首页外的 `pin`。
- 不再为"返回"引入第二种参数（`back` 退役后不新增同类机制）。
