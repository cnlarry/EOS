# ADR-006：统一表单一次性重构（渲染分层 + 写入健壮性）

- 状态：已实施（2026-08-23 立项草案经三轮评审确认；2026-08-24 六步全部落地——
  契约先行 / 渲染器变体注册表 / 页面接入 / 对拍矩阵+E2E / 发布校验器扩展+存量批量 validate
  （264/265 通过，2306 豁免见 `logs/goal/form-rework/exemptions.json`）/ 回归全绿
  （regression-20260824-121627，4/4）；实施修订两处见正文决策 2.4/4）
- **部分被取代（2026-09-25，ADR-022）**：本文「不做可视化表单设计器」与
  「只消费既有 `FORM_*` 元数据、不引入设计器」两条**作废**，改由
  `ADR-022-模块级表单版式设计.md` 承接（模块级版式表 + 设计态）；分区表单（复用 `FORM_CELL_GROUP` 成节）
  由 ADR-022 的 `SECTION_ID` 取代。其余决策（渲染器变体注册表、幂等键、浏览态工具栏定序、
  双击进浏览、发布校验器界面质量闸）**继续有效**
- 日期：2026-08-23
- 决策者：项目团队
- 范围：`EOS.API` 与 `EOS.Web`

## 背景

统一表单是元数据驱动的 CRUD 运行时（M6），当前已承载 266 个白名单模块的建单/改单/查看，
是放量主线的基础设施。随着放量规模扩大与逐模块验收推进，现有实现暴露出两类结构性问题：

**界面效果类**（渲染器能力不足 + 元数据质量无闸）：

1. 渲染器只有「标签+控件」均质网格一种形态：所有字段同等权重、无分区分节、无视觉层次；
   标签列 `nowrap + ellipsis` 且无 `title` 兜底，中文长标签被截断（`app.css` 表单段）；
2. 浏览/查看态只是把字段置 readonly，仍渲染一堆禁用输入框，不是阅读视图；
3. 控件语义弱：数字用原生 `type=number`、日期用原生 `type=date`（datetime 的时间部分无法呈现）、
   `DISPLAY_FORMAT` 只在列表侧消费、编辑态无千分位/精度格式；
4. 错误呈现割裂：顶部 alert 摘要 + 字段红字，但不切换页签、不滚动聚焦，隐藏页签中的错误不可见；
5. 明细网格固定高度、硬编码补 5 行占位、行内文字删除按钮违反命令栏图标规范、键盘导航与复制被关闭；
6. 大量「难看」实际源于元数据质量（FORM_ORDER 缺失、F_DESC 过长、FORM_CELL_GROUP 未配），
   而 ADR-005 阶段 2 发布校验器未覆盖界面质量类规则。

**健壮性类**（真实数据风险）：

1. 幂等键基础设施已建成（ADR-005 阶段 3：`WORKBENCH_IDEMPOTENCY` + `IdempotencyKey` 契约），
   但前端保存请求从未携带——网络重试/双击仍可能重复建单，自动单号模块会白吃号；
2. datetime 往返丢时间：record 返回完整时间字符串被塞进 `type=date` 输入框，再次保存时间部分清零，
   属静默数据丢失；
3. 服务端 `FieldError(Field, Message, Code)` 不带行号，前端把全部明细错误挂到第一行
   （`FormEditorPage.tsx` 保存失败分支），多行时报错定位错误；
4. 两端校验漂移：regex 校验前端先 trim 服务端不 trim；数值格式只有服务端拦截且报错无指引
   （如输入千分位 `1,000`）；金额预览 JS 浮点与服务端 decimal 舍入可能不一致，「预览≠存后值」；
5. 并发保护不对称：edit 的 `original` 快照可选（不传即 last-write-wins），明细完全无并发检测；
6. `Regex.IsMatch` 无 match timeout；数值/日期解析依赖 invariant culture，容错策略未定义；
7. 明细保存 = 整删重插（旧系统语义），该边界从未显式拍板；
8. 自动批核失败仅记 warning 日志（`WorkbenchCommandHandler` 新增分支），用户以为单据已批核。

**时机判断**：项目处于开发阶段，无受影响用户，266 模块均经同一流水线放量、可批量重验。
这是唯一可以承受破坏性契约变更而不背兼容包袱的窗口期。因此本 ADR 选择**一次性重构到位**，
而不是长期渐进修补。

## 决策

### 1. 表单渲染分层（前端重写）

把 `FormFieldRenderer` 从单一组件升级为**控件变体注册表**：

| 变体 | 触发条件 | 行为 |
|---|---|---|
| `text` | 字符类型默认 | 单行文本 |
| `decimal` | decimal/numeric/money/float | 文本框 + `inputmode="decimal"`，失焦按 `DISPLAY_FORMAT` 格式化（千分位/精度），提交前规范化为不变文化字符串 |
| `date` / `datetime` | date vs datetime/smalldatetime | 分别用 `type=date` / `type=datetime-local`，编辑回显保留完整值，提交 ISO 规范串 |
| `select` | FORM_OPTIONS 非空 | 下拉（现状保留） |
| `chooser` | CHOOSE_ACTIVE 有效源 | 输入框 + 图标选择按钮（三件套复合单元格保留） |
| `checkbox` | bit | 复选框 |
| `readonly-text` | view 态或 serverFilled | **纯文本展示 + 状态徽标**，不渲染禁用输入框 |

约束：

- 新控件类型只加 renderer 变体，不改页面编排；`FormEditorPage` 只保留页面编排与状态管理；
- 表单设计 token 化：标签列宽、控件高、分区间距、必填标识、错误态统一定义于样式层；
  标签超宽换两行显示并带 `title` 全文，禁止静默截断；
- 主表布局升级为**分区表单**：页签内按业务分节（复用 FORM_CELL_GROUP 归组，无分组字段归入默认节），
  分节可带标题行；
- view 态是独立的只读渲染路径（向打印版式观感靠拢），不再是编辑态加 disabled。

### 2. 写路径健壮性（一次性收紧）

1. **幂等键强制**：新增/修改/批核/解批/结案/未结案/删除一律要求幂等键——前端在表单加载时生成
   uuid、每次成功保存后重置；服务端对上述写端点缺失幂等键返回 400（`IDEMPOTENCY_KEY_REQUIRED`）。
   开发期一步到位，不设宽松期。键生命周期＝「一次用户保存意图」（查漏 2026-08-23）：校验类失败
   （事务回滚即释放 claim）可沿用原键重试；保存成功、取消放弃或修改后再次提交均生成新键。
2. **FieldError 协议加行号**：`FieldError` 增加 `RowIndex`（主表恒为 null，明细分行为 0 起），
   前端按行精确映射错误；多行同时报错不再全部挂到第一行。
3. **datetime 往返契约**：record 返回值按字段 dataType 规范化格式化（datetime → `yyyy-MM-dd HH:mm:ss`），
   前端按变体渲染与提交；补一条「建单→读回→改存→读回」时间分量不丢的 E2E。
   契约细化（查漏 2026-08-23）：前端 `datetime-local` 控件值与提交载荷均为 `yyyy-MM-ddTHH:mm:ss`
   本地朴素串（不带时区后缀）；smalldatetime 按 SQL 类型分钟粒度语义取整；格式化只发生在渲染层，
   保存载荷始终是规范化串，防止两端各理解一套格式。
4. **校验单一来源对拍**：form-definition 已下发 maxLength/isRequired/regex/dataType/displayFormat，
   两端各自实现但必须结论一致——建立「同输入同结论」对拍测试矩阵（覆盖每个控件变体 ×
   空/超长/非法数值/非法日期/regex 不匹配），任一端修改规则先改矩阵。
   form-definition 同步下发数值字段 precision/scale（源 `sys.types`/`sys.columns`），
   作为 decimal 变体超精度校验的两端共同依据（现契约仅有 maxLength）。（查漏 2026-08-23）
   precision/scale 仅对 decimal/numeric 启用超精度校验，float/money 不适用（float 无精度语义、
   money 固定 scale=4）。（评审第二轮 2026-08-23）
   trim 归属拍板（评审第二轮 2026-08-23）：保存归一化统一 trim 前后空白，校验基于 trim 后值，
   两端按同一规则实现后再入矩阵，矩阵不测「未拍板的漂移」。
5. **数值解析容错明确化**：服务端接受千分位逗号与全角数字并规范化；无法解析时报错消息带示例
   （如「请输入数字，示例：1234.56」）；`Regex.IsMatch` 一律带 match timeout（1s）。
6. **乐观锁收紧**：edit 保存必须携带 `original` 快照，缺失返回 400；明细行级并发检测暂不做，
   登记技术债（整删重插语义下行身份无并发意义，见第 3 条）。
7. **保存响应带 warnings**：自动批核失败等「保存成功但有后续异常」场景通过响应 `warnings`
   数组回传，前端明确提示「已保存，但自动批核失败：<原因>」，不再只写日志。
   展示通道（评审第二轮 2026-08-23）：保存成功且带 warnings 时，随跳转携带路由 state，在浏览态
   顶部渲染 warning banner；禁止依赖 alert 跨页提示（页面卸载即丢失）。
8. **单号冲突友好化（查漏 2026-08-23）**：自动单号模块的新增默认值只是「预览号」，保存时非空即沿用
   ——两用户并发开单会取得同一号码，后保存者触发唯一键冲突（2601/2627），现状未被捕获、映射为 500。
   改为捕获后返回 400 `BILL_NO_CONFLICT`＋「单号已被占用，请刷新后重新保存」，前端保留用户已录内容
   并引导重试；纳入 E2E（两会话并发建单一成一败，胜者拿到缓存结果键）。
   范围限定（评审第二轮 2026-08-23）：仅自动单号模块且冲突唯一索引命中主键/单号列时才映射为
   `BILL_NO_CONFLICT`，其余唯一键冲突保持原样报错（2601/2627 是任意唯一键冲突，不能一律当作单号冲突）；
   重试语义：前端保留已录值、仅重新请求单号默认值后重提（服务端重试时重新生成单号），不做整页刷新；
   幂等键随新单号重新生成。

### 3. 明细更新语义显式拍板：保持整删重插

明细保存维持旧系统等价的整删重插语义，理由：

- SP 等价移植台账（108 行）已按此语义验收，改为差量更新等于重验全部带 SP 模块；
- SERIAL_NO 语义即序号而非行身份，库内无外部表引用明细行身份的证据；
- 差量更新的收益（减少日志量）在审计已切 AUDIT_EVENT 后有限。

配套护栏：发布校验器新增检测——若明细表被其它表外键引用（`sys.foreign_keys`），
该模块不得进入统一表单白名单（防整删重插断链）；此边界写入 `ERP_REFACTOR_HANDOFF.md`。

### 4. 元数据质量闸（发布校验器扩展）

`WorkbenchDefinitionValidator` 在现有 14 项校验码基础上新增界面质量类校验（警告级与阻断级分级）：

- F_DESC 超长阈值（建议 >20 字符警告，标签必然截断）；
- FORM_ORDER 缺失比例过高（回退 VERIFY_INDEX 导致顺序混乱）警告；
- FORM_OPTIONS 格式非法（非 `k=v;k=v` 或键重复）阻断；
- CHOOSE_RETURNVAL 映射目标不在本表字段集阻断；
  （实施修订 2026-08-24：向旧系统求证后确认目标可为跨模块死配置——子表选择器回填主表字段、
  或字段已删的历史残留，运行时未命中即跳过、无害且核心模块普遍存在，故降级为警告，
  随逐模块验收清理；判定范围同步改为「主表∪子表模块字段全集」）
- DFT_VALUE 按 dataType 不可转换阻断；
- datetime 字段缺 FORM 配置导致只能用 date 呈现的警告。

存量 266 模块在实施完成后批量重新 validate，输出机器可读报告；未过项进入豁免清单并登记技术债，
由逐模块验收消化。放量流水线共用同一道闸（沿用 ADR-005 阶段 2 模式）。

### 5. 录入效率（ERP 键盘体验）

- `Ctrl+S` 保存；主表 `Enter` 下一字段（textarea 除外）；
- 明细网格启用键盘导航与 Ctrl+C 复制（`ErpTable` 已有能力，去掉显式关闭）；
- 明细行删除按钮改图标按钮并对齐 `.erp-command-bar-icon` 规范；移除硬编码补空行
  （空态显示一条「+ 新增一行」虚线行）；
- 明细卡片高度弹性化（min/max 区间代替固定 300px）；
- 明细网格键盘规则（查漏 2026-08-23）：`Tab` 跨单元格移动，`Enter` 在下一行同列继续（末行则新增行）；
  选择器/日期弹层等原生控件获得焦点时不拦截按键。

### 6. 工具栏与交互契约（三态按钮集 + 双击进入浏览）

统一表单工具栏采用三态契约（由 `ErpCommandBar` 承载；页面按权限/状态声明 `visible`，组件内不写业务分支）：

| 状态 | 按钮集 | 显隐规则 |
|---|---|---|
| 新增/编辑 | 「保存」「取消」文字按钮（+ 附件，编辑态带主键且 FILE_VIEW 允许时） | 保存走写路径（幂等键）；取消即返回 |
| 浏览 | 「返回」+ 上一条/下一条/新增/复制/编辑/帮助 + FORM_BUTTONS 白名单动作（批核/解批/结案/未结案/打印/删除）+ 附件 | 按权限与单据状态显隐：新增/复制/编辑按 hasAdd/ifCopy/hasEdit；帮助仅 HELP_URL 非空；上下条按列表上下文可用；`hasWorkflow`/`CONFIRM_TAG` 决定批核解批互斥；`FINISHED_TAG`/`canEndCase`/`canUnEndCase` 决定结案未结案；`canDelete`/FILE_* 决定删除/附件 |
| 入口分工 | 工作台列表工具条仅保留「新增」+ 列表自身工具（搜索/导出/刷新/选择列/列宽）；复制/编辑/删除/批核/解批/结案/未结案/打印等单据级动作全部移入浏览态工具栏；进入浏览经主表行双击 | 列表工具条不再按行选中提供单据级动作（2026-08-24 已推翻通用列表规范「行级操作统一放列表页命令栏」，改为两工具栏分工）；浏览态按钮按权限/状态与 HELP_URL 显隐 |

- **保存后进入浏览态（已拍板 2026-08-23）**：新增/编辑/复制保存成功后，一律跳转至该单据的
  浏览态（`/document-workbench/{moduleId}/view?key=…`），不跳回列表、不停留编辑态；key 以
  保存响应返回的服务端权威键为准——自动单号场景下预览号可能与最终单号不同，禁止用表单内
  值拼 key；「取消」仍返回列表。与旧系统「保存后停留本页转编辑态」的行为差异就此关闭；
  warnings 经路由 state 传至浏览态顶部 banner 展示（见决策 2.7）。
- **浏览态入口补齐（已拍板 2026-08-23，依据旧系统）**：浏览态工具栏提供「新增」「复制」「编辑」「帮助」；
  帮助按钮仅 HELP_URL 非空时显示并打开新页（旧系统 `View_Master.aspx` 的 `lnk_HELP` 消费
  `MODULES.HELP_URL`，现代表单页未消费，属补全）；保存后进浏览态即可直接续建/复制/编辑，不强制返回列表；
  > **后记（2026-10-06，迁移 321）**：`MODULES.HELP_URL` 已**物理删除**——全库只有 2 个模块填过它，
  > 且值都是旧客户专属路径 `~/Client/<客户代号>/ProductIn.aspx`（`~/` 在现行契约里属非法形态，点开必坏链）。
  > 浏览态「帮助」按钮随之退场；同一批被删的还有 `NEW_URL` / `MODI_URL`（新增/修改路由）——
  > 能不能写改由统一表单名单与权限裁决，路由只留 `M_URL` 一个承载页字段。
- **上一条/下一条导航契约（已拍板 2026-08-24，依据旧系统）**：导航顺序＝进入浏览态时的工作台列表当前顺序
  （列表排序 SORT_FIELDS/用户当前排序 + 当前过滤条件），服务端按同一列表口径计算相邻记录主键，
  禁止按数据库物理顺序或主键数值相邻；旧系统实现：表单 Prior/Next 关闭模态后调用父列表
  `GoPrior/GoNext`，在 DxGridView 当前显示顺序的相邻行打开浏览（`DX/DxWebControls/DxButton.cs` +
  `View_Master.aspx`），且仅当前已加载列表页内导航（旧系统默认 20 行/页，跨页需回列表翻页）；
  现代实现是否跨页由实施时选择，但顺序口径必须与列表一致；
- **删除后去向（已拍板 2026-08-24，依据旧系统）**：浏览态删除成功后返回工作台列表并刷新
  （旧系统 `ModifyToolBar.btnDelete_Click` 删除成功后 `window.close()` 关闭表单模态回到主表列表）；
  删除仍受删除补偿守卫约束（已批核有副作用单据先解批）；
- **工作台列表工具条收敛（已拍板 2026-08-24）**：单据级动作从列表工具条移除（仅留「新增」），
  避免同一动作在列表与表单两处入口语义分叉；通用列表规范「行级操作统一放列表页命令栏」已推翻，
  改为两工具栏分工（工作台工具栏＝列表自身工具+新增；统一表单工具栏＝全部单据级动作）；
  理由：删除等破坏性操作必须先进入浏览态确认单据细节，禁止列表页「选复选框→直接删除」避免错删；
  AGENTS.md / EOS.Web README / 架构.md 已同步修订；
- **双击进入浏览（仅主表）**：工作台列表主表行双击进入该单据浏览态；**明细子表行双击不进入浏览**

## 备选方案（否决记录）

1. **渐进式 quick win 序列**：否决。渲染器变体注册表与 FieldError 协议变更存在耦合
   （错误定位依赖变体渲染的分节/页签结构），分批会造成新旧两套渲染与两套错误协议并存，
   维护成本高于一次重写；且当前是无用户的唯一窗口期。
2. **明细差量更新**：否决（见第 3 条）。作为技术债登记触发条件：
   若出现「外部表需引用明细行身份」的真实需求，再出 ADR 评审。
3. **第三方表单引擎/Grid 替代自研渲染**：否决。表格侧已有 ErpTable 既定栈；
   表单侧需求（元数据驱动 + 权限过滤 + 受控表达式）与通用引擎模型不匹配，且引包不解决元数据质量问题。

## 实施顺序

同一特性分支内按依赖分步合并（评审补充 2026-08-23：不留双轨 ≠ 单次大合并；约束是任意中间状态无新旧双轨并存，

1. **契约先行**：FieldError.RowIndex、保存响应 warnings、写端点幂等键强制 —— API 与前端类型同步变更；

   auto-enable 流水线、E2E、批量脚本——逐个确认幂等键生成/携带/保存后重置；同步对存量 266 模块跑一次
   只读预扫描，确认校验器新增阻断规则（明细表被外键引用禁入白名单）无已启用模块命中）

   幂等键生成时机＝点击时生成一次；导入等其它写端点列入消费面清单确认纳入或豁免）
2. **渲染器重写**：变体注册表 + 设计 token + 分区布局 + view 态只读渲染 + 错误 UX（切页签/focus/徽标）；
3. **页面接入（FormEditorPage / DocumentWorkbenchPage）**：幂等键生命周期、Ctrl+S/Enter、明细网格调整

4. **对拍测试矩阵** + datetime 往返 E2E + 多行错误定位 E2E + 幂等重复提交 E2E + 双击进入浏览 E2E
   （含：主表双击进浏览、明细双击不进、14999 类查询模块双击无动作）；
5. **校验器扩展** + 存量 266 模块批量 validate 报告 + 豁免清单登记（评审补充 2026-08-23：F_DESC 超长阈值
   按显示宽度/CJK 评估，渲染层「换两行 + title 兜底」为硬保障，校验器仅作质量提示）；
6. 回归全绿（单测 + 前端 lint/build/test + E2E 全链 + UI 冒烟）后合并。
