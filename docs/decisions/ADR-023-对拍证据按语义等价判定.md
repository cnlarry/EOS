## 摘要（先读我，写给人类）

**要解决的问题**：验收证据（"这条效果链批核/解批不会改坏数据"）今天挂在**快照版本号**上——
账本判"报告版本 ≥ 当前版本 ⇒ 证据有效"。而版本号的内容判据是**逐字符比较**
（`WorkbenchDefinitionSnapshotService.cs:240`），于是**只要定义里任何一个字节变了**（哪怕只是
把一堆从来没被执行过的空占位公式行删掉、把 `''` 统一成 `NULL`），整个模块的证据一起作废。

后果很具体：ADR-012 §13.6 记着一批**全空占位公式行**（当时 100 行，实测今 82 行 / 68 个模块），
注明"**暂不清理**"——因为清理会让该模块既有对拍报告降级为 C 类。**为了整洁而付证据代价，不划算**，
于是数据一直不敢清。

**本 ADR 的决定，用一句话说**：

> 把"什么算同一份配置"的判据从**字节**换成**语义**——凡有运行时代码行证明"运行时看不见"的差异，
> 一律先归一，再比较。**版本号从此就是语义标识**：版本没变 ⇒ 行为没变的证据仍然成立。

**边界（同样重要）**：只归一"**能指向一行运行时代码、证明它看不见**"的差异。
少归一的代价是"偶尔多升一版"；多归一的代价是"**真改了配置却复用旧版本、证据失效而无人发现**"——
后者比现状更糟，因此**宁可少归一不可多归一**。

**本 ADR 定与不做**：

- ✅ 已定：判据落点与同源要求（§5）、规范化规则清单 R1/R2（§4）、已知后果两条（§6）、回退方式（§8）。
- ❌ 不做：给快照加 `CONTENT_HASH` 列、改账本判据（§3.2）；候选三条归一（§7）；
  分面粒度（按事件/按段取哈希，§7）。

## 1. 背景：判据在哪，代价是什么

| 环节 | 落点 | 现状判据 |
|---|---|---|
| 发布：内容未变即复用版本（决策 #109） | `EOS.API/Data/WorkbenchDefinitionSnapshotService.cs:240` | `string.Equals(currentJson, definitionJson, StringComparison.Ordinal)` |
| 落后检测（`SERVICE` 与脚本共用） | 同文件 `:124` | `!string.Equals(row.StoredJson, rebuilt, StringComparison.Ordinal)` |
| 账本：证据新鲜度 | `scripts/adr012-acceptance-ledger.ps1:150-166` | 报告 `definitionVersion` 的 `v(\d+)$` ≥ 当前 `VERSION` ⇒ A/B，否则 C stale |
| 落后脚本 | `scripts/check-snapshot-staleness.ps1:47` | 调 `GET /api/v1/workbench-definitions/staleness`（即上面的检测器，脚本不另立标准） |

**为什么"裸内容哈希"不是答案**（阶段 A 独立复核过，结论成立）：决策 #109 已经做到
"字节未变即复用版本"，所以裸哈希判"哈希相等"与版本判"版本相等"是**同一件事的两种写法**；
字节变了裸哈希照样变，证据照样失效 ⇒ **零收益**。真正有价值的是**规范化后的内容**。

**实测代价（2026-09-25 连库）**：

- 全空占位公式行 **82 行 / 68 个模块**；**262 个当前快照里 68 个含占位行、合计 82 个** ⇒
  与库内一一对应，**清理必然改变这 68 个模块的定义字节**；
- 同一逻辑状态的两种写法**同时大量存在**（`SOURCE_CONSTANT` 空串 359 / NULL 43、`CONDITION_STRUCT`
  334/67、`REMARK` 360/5、`MATCH_STRUCT` 77/5、动作级 `CONDITION_STRUCT` 249/66、`PARAM_STRUCT` 153/33、
  `REVERSE_STRUCT` 2/16，合计约 1500 格）；
- 账本当前 **批核 A=0/B=0/C=95/D=15、解批 A=0/B=0/C=94/D=16**——双路证据整体处于失效态；
  95 个 C 模块里 **30 个根本没有占位行**（其失效不可能由整洁性解释）；模块 1404 快照已 **v22**
  而最新报告停在 **v9**（13 次版本前进）。

## 2. 决策

### 2.1 判据改为"规范化后内容等价"

**规范化 = 把运行时有代码行证明看不见的差异先归一，再比较**。
等价 ⇒ 复用当前版本（`published=false`、不写新快照行、仍清脏标记、仍刷新运行时缓存、审计如实说明）；
不等价 ⇒ 照旧 `MAX(VERSION)+1`。

### 2.2 不引入第二个身份（否决"加 `CONTENT_HASH` 列 + 改账本"）

版本号之所以不可信，正是因为**发布判据**用了字节比较；判据换成规范化比较之后，
**版本号本身就是语义标识**，下游一切按版本判定新鲜度的东西（账本、报告、脚本）**自动受益**。
另立一列哈希只会把同一个判断做两遍，而且**历史报告里没有哈希**，既有证据会被判"不可比对"——
严格更糟，因此不做（账本一行不改、无迁移、回退＝改回一行）。

## 3. 规范化规则清单（冻结）

> 判据一句话：**每一条归一都必须能指向一行运行时代码，证明"这个差异运行时看不见"；指不出的，一律不归一。**
> 每条规则必须带一个正例（断言等价）与一个反例（断言不等价），见 §7 与单测。

### R1 全空占位公式行：整元素剔除

| 项 | 内容 |
|---|---|
| 作用路径 | `businessActions[].ops[]` 中 `opCode` / `targetTable` / `targetField` 三者（去空白后）皆空的元素 |
| 运行时为什么看不见 | 加载期即跳过，既不执行、也不参与参数/结构校验；服务型效果的语义在 `params` 里 |
| 代码证据 | `EOS.API/Data/Effects/EffectPlanLoader.cs:128-131`（命中 `IsPlaceholderOp(...)` → `return null`）；判据本体 `EOS.API/Data/ModuleBusinessConfigValidator.IsPlaceholderOp`（加载期、保存期结构校验、保存期物理列校验三处共用同一判据） |
| 判别力用例 | 只差一条占位行的两份定义 ⇒ **等价**；在其上再加一条真公式行（`opCode='ACCUM'`）⇒ **不等价** |

### R2 空串 / 纯空白 ≡ 缺省（按字段白名单）

| # | 作用路径 | 运行时为什么看不见 | 代码证据 |
|---|---|---|---|
| 2.1 | `businessActions[].condition`、`.params`、`.reverse` | 三者都是"文本承载的结构列"，读取器把 `null`／缺省／空串／纯空白一律折叠为 `null` | `EffectPlanLoader.cs:331-358`（`:333-334` 拒 `null`/`undefined`；`:343-347` 空串 → `null`） |
| 2.2 | `businessActions[].ops[].condition`、`.match`、`.sourceTerms` | `condition` → `OptionalElement`；`match`/`sourceTerms` → `ParseEmbeddedArray`，空串同样折叠为 `null` | `EffectPlanLoader.cs:156`、`:231-255`（`:238-244` 空串 → `null`） |
| 2.3 | `businessActions[].ops[].sourceTable`、`.sourceField`、`.sourceAgg`、`.remark` | `OptionalString` 读法：**Trim 后为空即按"未设置"** | `EffectPlanLoader.cs:303-309`（`:307-308`：`text.Length == 0 ? null : text`）；调用点 `:172-173`、`:143`、`:157` |
| 2.4 | `businessActions[].ops[].sourceScope` | 空串与缺省都落到同一默认值 | `EffectPlanLoader.cs:162`（`OptionalString(...) ?? "MASTER"`） |
| 2.5 | `businessActions[].effectName`、`.failMode` | 空串与缺省折叠为 `null`；`failMode` 再落默认 | `EffectPlanLoader.cs:106`、`:75`（`?? "BLOCK"`） |
| 2.6 | `validationRules[].params`、`.message` | `OptionalElement` / `OptionalString` 同上 | `EffectPlanLoader.cs:270`、`:287` |

**R2 只归一"同一逻辑状态的两种写法"，不删除任何非空内容。**

## 4. 落点与同源要求（硬约束）

1. **一个比较器**：新增一个纯函数比较器（发布侧与检测侧**共用**，不再各写一次比较），
   输入是两份定义 JSON 文本，输出"语义是否等价"。两处**都不再直接用** `string.Equals(..., Ordinal)`。
2. **必须同源**：`PublishOneAsync`（发布）与 `DetectStalenessAsync`（落后检测）**同文件、同一判据**；
   `scripts/check-snapshot-staleness.ps1` 只调检测器端点，脚本侧不需要改。
   这条是历史教训的直接产物（2026-09-19 检测器曾因身份重建口径不一致而误报，最后靠"与发布同口径"收敛）。
3. **保守失败**：任一侧 JSON 无法解析时**回退到字节比较**（宁可判"不等价"，也不放行）。
4. **审计文案同步**：复用时的审计与日志要说明"**规范化后**内容未变"，不能再说"内容逐字未变"。

## 5. 已知后果（必须写明，接受）

**(a) 复用版本 ⇒ 不重写快照 JSON ⇒ 清理 DB 占位行后，快照里仍留着它们。**

这是"复用=不写"的必然结果：复用只清脏标记、刷新缓存，不 `INSERT` 新行。
一致性不受影响——**快照里留着的那条占位行，运行时本来就被跳过**（R1 的立论依据），
所以"快照内容 ≠ DB 内容"在这处差异上**恰好是等价的**；等下一次真变更发布时，快照自然被重写、占位行随之消失。
`DetectStalenessAsync` 用同一判据，因此**不会**把这种模块报成"落后"（否则就会出现"发布说复用、检测说落后"）。

**(b) R2 会把 `ops[].remark` 的空串归一成缺省，未来审计文本里是 `null` 而非 `""`。**

`ops[].remark` 会进审计明细（`EffectPipeline` 的动作快照）。归一后，一个原本存 `''` 的 remark
在新快照里以缺省形态存在，审计 JSON 里呈现 `null`。**业务行为不变，审计文本变了**：
排查历史时要意识到"`null` 与 `''` 在这里指同一件事（没写备注）"。这是 R2 的可见代价，接受。

## 6. 明确不纳入（候选已否决）

| 不归一 | 理由 |
|---|---|
| `ops[].sourceConstant`（当 `sourceScope = CONSTANT`） | 空串是**真实语义**（把该列清空，如 `FINISHED_PERSON=''`）：读取器在 CONSTANT 下刻意用不去空串的 `RawString`（`EffectPlanLoader.cs:165-169`），而 `null` 会让运行期直接抛"缺少 sourceConstant"（`EffectFormulaExecutor.cs:432-435`）⇒ 空串与 NULL **不等价**。**仅在 `sourceScope ≠ CONSTANT` 时归一。** |
| 显式默认值 ≡ 缺省（`failMode:"BLOCK"`、`sourceScope:"MASTER"` 等） | 语义上等价，但属于"删除显式配置"，收敛过宽会掩盖"配置里到底写没写"的意图（用户裁决：不纳入） |
| 大小写归一 | 加载器与公式执行器的闭集检查是大小写不敏感，但**闭集之外的消费者（事件映射、前端、发布校验）未穷尽证明**（用户裁决：不纳入） |
| 说明性字段（`remark`/`effectName` 非空文案）不参与身份 | 它们会进审计/报告文本，属"看得见的变化"（用户裁决：不纳入） |
| 数组/属性顺序 | 定义由同一序列化器按固定顺序产出（`ORDER BY EVENT_CODE,SEQ` / `OP_SEQ` / `SEQ`），配置层面产生不了顺序差异；归一顺序只会引入误判 |
| `{}` / `[]` vs `null`（`match`/`sourceTerms`） | 执行期同效，但**报错路径不同**（`EffectPlanLoader.cs:139-141` 对 `terms is null` 抛"缺少来源字段"） |
| **分面粒度**（按事件、或只对"效果相关段"取哈希） | 本批次不做，单独立项；**立项第一步做"逐版本 diff 归因"**（量化见方案文档 §9） |

## 7. 回退方式

- **零成本回退**：本 ADR **不新增库对象、不改数据**。回退 = 把发布与检测两处的比较换回
  `string.Equals(..., StringComparison.Ordinal)`（并删除比较器与其单测）⇒ 语义立即回到现状，无需修复数据。
- 试点若临时清理了某个模块的占位行：**清理脚本与回退脚本必须同时交付**（回退逐列按原值插回），
  且两者**幂等**；试点结束后按用户裁决复原脏标记与版本（读数见 `docs/status.md`）。

## 8. 验收口径

1. **判别力（注入自检）**：删掉一条归一化规则 ⇒ "断言等价"的正例必须**变红**；
   多加一条过宽的归一 ⇒ "断言不等价"的反例必须**变红**。
2. **端到端（真库）**：挑一个证据类别已是 C/D、且占位行最少的模块（**1406，1 行**），
   清掉该行后重发布：**版本号不变**（`published=false`）、**证据类别不降级**；
   前/后三项读数（版本 / 证据类别 / 脏标记）写进 `docs/status.md`。
   该试点同时是**决策 #90 的试点**，产物（清理 + 回退脚本）要能直接复用到全部 82 行。
3. **自洽**：发布判据与 `DetectStalenessAsync` / `check-snapshot-staleness.ps1` 口径一致，
   全量跑一次确认**不出现"复用却报落后"**。
4. `dotnet build` 0 错、相关门禁 PASS；账本判据**不变**（只换取数方式）。
