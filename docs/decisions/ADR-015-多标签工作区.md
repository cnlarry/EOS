## 1. 背景与事实

### 1.1 现状：单任务系统

右侧工作区同一时刻只承载一个页面，证据五处：

| 事实 | 证据 |
|---|---|
| `AppShell` 只有一个路由插槽 | `AppShell.tsx:603` 单个 `<Outlet />`（`React Router` 的路由插槽，即"当前路由的渲染坑位"），菜单 `navigate()` 即整区替换 |
| 切换模块即销毁重建 | `routeElements.tsx:20-23` 的 `WorkbenchRoute` 以 `key={moduleId}` 强制重挂载，注释明示"防上个模块状态串入下个模块"；副作用是分页/选中/滚动/子表展开全部丢失 |
| 数据缓存与视图状态分离 | `TanStack Query`（服务端数据缓存层）的请求缓存还在，但页面本地 `useState`（页码/排序/选中行/滚动位）随卸载消失；`DocumentWorkbenchPage` 用 `keepPreviousData`（保留上一页数据占位，防翻页闪空）也只覆盖单页内翻页，不覆盖跨模块切换 |
| 滚动容器全站共享 | `app.css:523` `.page-body { height: calc(100vh - 64px); overflow-y: auto }`——所有页面共用**同一个**滚动条，滚动位不是页面私有状态。⇒「每个标签各自保持滚动位置」在现有结构下不成立，必须先下放滚动权（§4.1） |
| 列表虚拟化与滚动加载绑定"最近的 overflow 祖先" | `ErpTable.tsx:289-304`（滚动容器发现）、`307-318`（可视窗口计算）：表格向上找最近的可滚动祖先。滚动容器下放后该逻辑自动跟随，但隐藏期 `clientHeight` 为 0、`scrollTop` 归零，需显式处理（§4.1） |

表单页有脏保护（`FormEditorPage.tsx:591-603`：`beforeunload` + `useBlocker(dirty)`），列表页切换是静默丢失上下文。

### 1.2 旧系统同样单模态，用户靠多窗口绕过

`ERP/Comm/View_Master` 系单模态表单（保存后停留本页，删除后关闭回列表，见 `ERP_REFACTOR_HANDOFF.md` §18），用户实际靠开多个 IE 窗口实现"订单对照送货、采购对照请购"。现代端连这个绕法都不顺：多浏览器标签共享同一 `Cookie` 会话、互不感知标签身份，不是产品级多任务。

### 1.3 需求侧证据

- 跨单对照是高频动作：请购 `1615/1616` 对采购 `1606`、订单 `1405` 对送货 `1406`、收付款 `170102/170202` 对银行；保存被数量超限校验（`qty-not-exceed`）拦下时要去上游单查余额。
- `AppShell` 已有"最近访问 8 个模块"（`RECENT_MODULES_MAX=8`，供首页快捷入口），说明用户本来就在模块间来回跳。
- 列表状态已 `URL` 化（`listStateUrl.ts`：排序/页码/关键词/筛选进 `?sortFields/page/keyword/q/cf`，刷新与分享可还原），每个标签本质就是一个 `URL`，这是多标签的地基。**注意其覆盖面有限**：选中行、滚动位、子表展开、表单草稿都不在 `URL` 内——这决定了 §3.2「真保持」不是可选优化，而是满足需求的必要条件。

## 2. 问题拆解

"要不要多标签"实际混了六个正交问题，分开决策：

| # | 问题 | 本文结论 |
|---|---|---|
| 1 | 范围是只做工作台还是全站？ | 全站（见 §3.1） |
| 2 | 切换是按 `URL` 重建还是真保持（后台常驻）？ | 真保持，一步到位（见 §3.2） |
| 3 | 标签上限与关联跳转（`from` 跨模块浏览）怎么算？ | 上限 8，`from` 算新标签（见 §3.3） |
| 4 | 脏页（未保存改动）关闭/切换时怎么办？ | 关闭拦截确认、切换不弹框（见 §3.4） |
| 5 | 点菜单时复用当前标签还是新开？重复打开同一 `URL` 怎么办？ | `URL` 去重 + 已开则聚焦（见 §3.5.1） |
| 6 | 刷新后恢复的标签何时挂载组件？ | 懒挂载，首次激活才挂载（见 §3.5.4） |

## 3. 决策条款（§3.1–§3.4 用户 2026-09-18 已拍板；§3.5 评审补充，待确认）

### 3.1 范围：全部（全站标签）

`AppShell` 下全部子路由进标签，不只 `/workbench/:moduleId`：

- 工作台列表 `/workbench/:moduleId`、统一表单 `/workbench/:moduleId/new|edit/*|view/*|copy`；
- 报表 `/reports/:moduleId`、报表中心 `/report-center`、查询中心 `/search-center`、明细查询 `/detail-query/:moduleId`；
- 管理页 `/admin/*`、流程 `/workflow/*`、`/my-tasks`、`/jobs`、`/import`、`/print/:moduleId`、`/bom-expand`、`/car-summary`、`/settings/*`、`/dashboard`、`/legacy/modules/:moduleId`。

理由：对照动作经常一端是单据、一端是报表或管理页（如查字段设置），只给工作台开标签会留下半截单任务。

### 3.2 一步到位：真保持（`KeepAlive`，后台常驻不卸载）

不接受"轻量历史标签（切换仍重挂载、只记住 `URL`）"作为终态，直接做真保持：

- 切后台的标签组件不卸载，以隐藏方式常驻（`display:none` 容器），其分页/筛选/选中/滚动/子表展开/表单草稿原样保留；
- 切回时不重请求：`TanStack Query` 缓存命中即直接呈现，后台期间数据过期则按现有失效策略静默重查（配合 `keepPreviousData`，不闪空）；
- 每个标签持有自己的完整 `URL`（路径 + 查询串，含 `P2 URL` 化的列表状态）；标签内导航（列表→查看→编辑）原地更新该标签的 `URL`；地址栏始终反映当前活动标签。

### 3.3 上限 8 个；`from` 跨模块浏览算新标签

- 上限 **12**（原定 8，评审复议后上调，理由见 §3.5.3）。第 13 个打开时拒绝新建并提示，先关一个再开；不做自动淘汰最久未用（`LRU` 自动淘汰会关掉用户可能有草稿的页，风险高于收益）。
- `FieldBrowseLink` 携带的 `from={来源模块}`（跨模块字段浏览，面包屑按来源呈现）打开目标时算新标签：来源标签保持不动，目标在新标签打开。面包屑/返回仍按现有"来源工作台呈现"语义，在新标签内生效。
- ⏳ 撞顶时的失败模式与上限数值本身在 §3.5.3 复议（现状是"拒绝新建、逼用户先关一个"，属最差的失败模式）。

### 3.4 脏页：拦截确认（含 2026-09-18 评审修订）

- 脏定义：页面自报"已改未保存"即为脏。**首批脏源为两处既有实现**：统一表单 `FormEditorPage` 的 `useBlocker(dirty)`、字段维护 `FieldEditorPage` 的 `useBlocker(() => dirtyRef.current)`（两处均已带 `beforeunload`）；注册表接口按这两个真实用例设计，后续菜单管理、报表版式设计器等有未保存草稿的页面按同一接口接入。接入方式见 §4.3（**脏页注册表**，不是各页各自守住自己的 `useBlocker`）。
- **关闭**脏标签、**关闭其他/关闭全部**涉及脏标签时，一律弹窗确认（保存 / 不保存关闭 / 取消）。
- 浏览器级刷新/关闭走 `beforeunload`（浏览器关闭前确认事件）兜底，有任一脏标签即提示。
- **修订（评审）**：**切换标签时不弹框**。原文"切换标签离开脏标签时一律弹窗确认"与 §3.2 自相矛盾——后台常驻已保留草稿，切换不丢任何东西，弹框是纯噪音（8 个脏页会变成弹框地狱）。切换时改为在标签上显示脏点标记；确认只解决"关闭/丢弃即丢"。
- **不做**"后台保留草稿免确认"之外的例外：关闭路径一律走确认，不静默丢弃。

### 3.5 交互规则（评审补充，2026-09-18 用户已确认）

> §3.3 定了上限，但没定"标签怎么来、怎么去"。以下四条是多标签工作区的第一交互规则，不定就会实现成"点菜单把当前标签顶掉"，对照场景立刻崩。

#### 3.5.1 菜单点击与去重：`URL` 为键，已开则聚焦

- 点菜单（侧栏、菜单搜索、首页快捷入口）打开目标 `URL` 时：**该 `URL` 已在标签列表 → 聚焦该标签（不新建）**；未开 → 新建标签并在其中打开。
- 去重键 = 完整 `URL`（路径 + 查询串）。**`from` 参与去重键**：`/workbench/1606?from=1615` 与 `/workbench/1606?from=1405` 视为两个标签（来源语义不同、面包屑不同），否则后开的会覆盖先开的面包屑语义。
- 标签标题不得只写模块名：带 `from` 的标签在标题后附来源（如 `采购订单 ← 请购单`，`title` 提示同步带完整来源），否则同一模块因来源不同开出两个标签时用户无法区分。
- 不再有"用新页面替换当前标签"的隐式行为；替换只允许通过显式的"关闭当前标签"发生。
- 列表→查看/编辑/新增属于**标签内导航**（原地更新该标签 `URL`），不新建标签；仅 `from` 跨模块浏览例外（§3.3）。

#### 3.5.2 "关闭其他/关闭全部"语义

- 关闭其他：保留当前标签 + 所有**脏**标签（脏标签不静默关闭，逐个提示或整批提示后由用户决定）；关闭全部：等同逐个关闭并走 §3.4 确认。
- **首页标签常驻（2026-09-18 用户拍板修订）**：`/dashboard` 标签固定占据首位、不提供关闭入口，且"关闭当前 / 关闭其它 / 关闭全部"三个动作都绕开它——**其余标签仍不设"锁定页"概念**，`pin` 只对首页这一例开放。首页标签的地址不被标签内导航改写（若首页内部发生导航，另开标签承载）。因此"关闭全部"的结果是**只留首页**，不再走"关空后落到首页"的兜底。
- 两个动作都不设"锁定页"概念（不特殊保留首页以外的任何标签）——除首页外本期不引入 `pin`（§4.7）。
- 关闭全部后只剩常驻的首页标签（首页不参与关闭，见 §3.5.2），不留空白工作区。

#### 3.5.3 上限定稿 12（原 8）

- 原条款（§3.3）为"第 9 个拒绝新建"。§3.1 把全站纳入、§3.4 又让 `from` 占新标签，日常对照（请购 `1615/1616` + 采购 `1606` + 送货 `1406` + 收付款 `170102/170202`，再加报表/管理页）很容易撞顶，而"先关一个再开"会打断用户当前动作。
- **定稿：上限 12**。理由是 §3.1 全站标签的实际并存面（单据 + 报表 + 管理页混用），不是"内存便宜"；`dirty` 白名单式 LRU 淘汰虽可消解"怕关掉有草稿的页"这一顾虑，但静默关页仍属打断，本期不做。
- 兜底：**接近上限（剩 1 个）时给出提示；撞顶仍拒绝新建并提示**，不做静默淘汰。
- **修订（2026-09-22 用户拍板）**：提示形式由「标签栏给出提示」改为**全局轻提示**（右上角、默认 4 秒自动消失、可手动关闭）。原因是标签栏是 34px 的**横向滚动单行**，标签开满时自身已经溢出，提示塞进标签栏只会与标签抢同一条窄带（贴左/贴右都一样）；同时把「接近上限」的触发对齐本条件——**只剩 1 个名额时提示**（原实现是开满 12 个之后才提示，那时用户已经撞过一次）。轻提示原语 `useToast()` 与「瞬时→轻提示 / 页内→alert / 需决策→Modal」三档口径见 `docs/架构.md`「设计系统最低约束」。

#### 3.5.4 刷新后的懒挂载

- §4.3 的持久化让刷新后恢复 8 个标签。若恢复即全部挂载，开页面瞬间会并发 8 组取数（列表 + 元数据 + 选择器），首屏延迟与库压力都不划算。
- 拟定：**刷新后标签列表恢复为 `URL` 占位，首次激活才挂载组件，此后常驻**。与 §3.2「真保持」不冲突——从未激活过的标签本来没有状态可保，懒挂载是无损的。

### 3.6 实施口径（2026-09-18 用户确认）

评审提出的五条实现级口径，与 §3.5 同日确认，属实现约束而非新的产品决策：

#### 3.6.1 历史（前进/后退）按 `URL` 先匹配标签

- 浏览器 **`POP` 事件（前进/后退）必须先按"`URL` 是否等于某个标签的当前 `URL`"匹配：命中即激活该标签，未命中才当作活动标签的标签内导航**（更新其 `URL`）。
- 理由：切换标签会 `push` 一条历史（浏览器标签页语义），历史栈里因此混有各标签的 `URL`；若一律按"标签内导航"处理，在 `B` 标签按后退会退到 `A` 的 `URL` 却仍显示在 `B` 里。
- 代价（接受）：单个标签没有独立后退栈，后退可能跨标签跳回——与浏览器标签页行为一致。

#### 3.6.2 权限回收：就地 403，不自动关闭

- 标签激活时重新校验权限；权限被回收 → **就地渲染 403**，标签保留、不自动关闭。
- 理由：自动关闭会静默丢弃该标签的脏草稿，与 §3.4"关闭路径一律走确认，不静默丢弃"冲突。

#### 3.6.3 多窗口 `localStorage`：last-write-wins

- 标签列表按用户持久化到 `localStorage`；两个浏览器窗口共享同一份存储时**按 last-write-wins 处理，不监听 `storage` 事件、不做跨窗口同步**，登记为已知限制。

#### 3.6.4 工作区路由表禁用数据 API

- 工作区子树用嵌套 `useRoutes` 渲染，**该路由表不得使用 `loader` / `action` / 数据 `lazy`**——`useRoutes` 不执行数据 API，加了会静默不生效（不报错）。
- 现状满足（工作区路由全部是 `element` + `React.lazy` + `Suspense`）；新增数据路由需求时须改造标签 host，不得直接往该表加 `loader`。

#### 3.6.5 标签栏视觉为过渡稿

- 标签栏样式先按现有设计 token（Tabler 变量 + `.erp-*` 命名）出一版可用样式；**视觉精调在本次落地收尾后单独进行**，不作为 §4.5 各段的通过口径。

## 4. 设计要点（实施约束，非拍板事项）

### 4.1 容器改造

- `AppShell` 的单 `<Outlet />` 改为标签容器：活动标签可见、其余隐藏常驻。路由仍是唯一真源，每个标签绑定一个 `URL`，不另立与路由平行的页面模型。
- `routeElements.tsx` 的 `key={moduleId}` 语义保留，但作用域收窄为"标签内跨模块复用时重置"，不跨标签串状态。
- **滚动容器必须下放到标签容器（实施前置，已落地）**：现状 `.page-body`（`app.css:523`）是全站唯一滚动条，标签无法各自保持滚动位。改造为：`page-body` 只负责撑满高度不滚动，每个标签容器 `.erp-tab-panel` `flex: 1 1 auto; min-height: 0; overflow-y: auto`。连带处理：
  - 标签栏占高（约 34～36px）后，`page-body` 的 `height: calc(100vh - 64px)` 需改为 `flex` 撑满并扣除标签栏高度；
  - `.page-body > .container-fluid > :first-child` 等直接子选择器规则需同步下沉/改写，容器链上新增的 `min-width: 0` 要补齐（防横向滚动条）；
  - `ErpTable` 的滚动容器发现与虚拟窗口计算（`ErpTable.tsx:289-304`、`307-318`）在容器下放后自动指向新容器，**无需改组件**，但需实测确认（吸顶表头、无限加载哨兵同源）。
  - 表格区按视口算的高度上限（`.erp-master-table-region` 的 `calc(100vh - 330px)`、`.erp-detail-card .table-responsive` 的 `calc(100vh - 430px)`）改为扣除新增的 `--erp-tabbar-height`（无标签栏时为 `0px`）；标签栏落地时只改变量，不再逐处改高度。
- **隐藏方式固定为 `display: none`**：不用 `visibility` / 位移隐藏（隐藏页会参与打印与可访问性树）。`@media print` 里显式排除隐藏标签（现规则只处理 `.page-body` 的 padding）。
- **隐藏期状态保真需显式处理**：`display:none` 下 `clientHeight` 为 0、`scrollTop` 归零、行高实测为 0。激活时需：恢复该标签记录的滚动位 → 触发一次虚拟窗口重算（复用 `applyScrollWindow` 的路径）。否则 §5.1 的"滚动保持"与虚拟化都会失真。

### 4.2 标签模型（最小字段）

`{ id, url（完整路径+查询串）, label（模块标题/页标题）, moduleId?, dirty, mounted }`。标签页不存业务数据，只存 `URL` + 脏位 + 是否已挂载（§3.5.4 懒挂载）；业务状态靠常驻组件实例持有。

### 4.3 与现有机制的衔接

- **脏页登记与拦截必须汇聚到 shell 层（实施前置，已实测冲突）**：`react-router` 7.18.2 的 `shouldBlockNavigation` 在注册了多个 blocker 时只打一条告警，并**只取最后注册的那个**（`entries[entries.length - 1]`）。今天单页挂载无所谓；一旦 8 个标签常驻、其中多个是脏表单，除最后挂载者外的所有离开保护会静默失效。
  - 落地：`AppShell` 持**唯一** `useBlocker`（判定 = 任一标签脏），并提供**脏页注册表** `registerTabDirty(tabId, { isDirty, save, discard })`；`FormEditorPage` 与 `FieldEditorPage` 都不再自己 `useBlocker`，改为向注册表登记（`dirty` 仍由页面本地 `useState`/`dirtyRef` 计算，只上报不复制）。
  - 注册表同时是 §3.4"保存 / 不保存关闭 / 取消"三选一的落点——"保存"必须能调到该标签自己的 save，而不是一个通用按钮。
- **写—读可见性规则（常驻标签特有）**：`providers.tsx:9-10` 为 `refetchOnWindowFocus: false` + `staleTime: 30_000`，常驻标签会把"隐藏页持有旧数据"变成用户可见的状态（切回来 30s 内不重查）。规则：任何写操作成功后 `invalidateQueries` 相关列表键（现有 `FormEditorPage.tsx:634` 已按 `['workbench', moduleId]` 做，保持），隐藏标签在**激活时**按 stale 策略静默重查，配合 `keepPreviousData` 不闪空。
- **"当前页"类上下文要下沉到标签容器**：`AppShell.tsx:601-605` 的 `FormBreadcrumbContext` / `PageBreadcrumbContext` 是 shell 单例，`PageContext`（上报当前模块给助手）同理；多标签常驻时隐藏页写入会覆盖活动页。改为 provider 下沉到每个标签容器（活动标签的值被 shell 读取用于面包屑/标题）。
- 权限：标签激活时仍走现有路由守卫（`RequireAuth`/`RequirePermission`，登录与模块读权限门）；权限被收回时对应标签关闭或转 403，不静默保留越权页。**常驻页需在激活时重新校验**（挂载后权限被回收的标签不能靠旧渲染继续展示），关闭脏标签同样走 §3.4 确认。
- 面包屑/标题：按活动标签的路由计算，现有 `findPath/crumbBasePath` 逻辑逐标签求值，不改单标签语义。
- 助手抽屉（`AssistantDock`，悬浮对话入口）保持全局单例，不随标签复制；页面上下文（`PageContext`，上报当前模块给模型）随活动标签切换。
- 持久化：标签列表（`id + url + label`，不含组件状态）按用户存 `localStorage`（参照现有 `storageKeys.ts` 模式），刷新后按 `URL` 重建（组件状态不跨刷新保持，脏位不持久化）；重建时按 §3.5.4 懒挂载。

### 4.4 标签渲染与 location 上下文隔离（实施前置）

- **渲染方式**：保持单 `createBrowserRouter`（数据路由）不变，每个标签子树按各自的 `URL` 求值渲染（`useRoutes(routes, tab.url)` 形态）；活动标签可见、其余常驻隐藏。`useParams` 取自路由匹配结果，天然逐标签正确。该路由表的数据 API 限制见 §3.6.4。
- **`useLocation` / `useSearchParams` / `useNavigate` 读的是浏览器真实地址**，不做隔离时隐藏标签会读到活动标签的 `URL` 并写回：列表页是"`URL` ↔ 本地 state"双向同步（`DocumentWorkbenchPage.tsx:40-41` 挂载读一次，`100-110` 每次变更 `setSearchParams(..., { replace: true })` 写回），跨标签会互相污染筛选/排序/分组参数。因此**每个标签子树必须包一层 location 上下文覆写**（`react-router` 7 导出 `UNSAFE_LocationContext`，与 `UNSAFE_RouteContext` 配合使用；`useRoutes` 只提供匹配结果，不覆写 location）。
- **不变式：隐藏标签不得导航**。隐藏态收不到用户事件，风险来自 effect 与异步回调（非法排序归一化、mutation 成功后 `navigate`、后台 refetch 回调）。标签 host 在非活动标签上把导航调用转为写入该标签自身 `URL`（或 no-op 并记录），一律不得改浏览器地址与历史。
- `useNavigate` 的现有调用点（18 个文件）**不需要改**：它们天然落在活动标签上，正是期望语义。
- **隔离实现只允许出现在一个模块**（标签 host / `TabKeepAlive`），全站不得散落 `UNSAFE_*` 依赖——该 API 名字带 `UNSAFE`，升 React Router 大版本时需单点替换（§8）。

每段可独立回滚，前一段不通过不进下一段：

| 段 | 内容 | 通过口径 |

| 3 多标签 | 多标签常驻、切换、去重与上限（§3.5.1/§3.5.3）、滚动位恢复（§4.1） | 开满上限切换状态保持；隐藏标签不污染活动标签 `URL`（§5.10） |

### 4.6 实施提示（按 §4.5 试做一轮后已验证的事实）

> 以下结论来自按 §4.5 段 1–段 3 试做一轮的实测（该轮代码已撤回，结论保留在此以省掉同类返工）。

1. **嵌套 `useRoutes` 要求父路由带通配**：在布局路由内部再调 `useRoutes(routes, url)` 时，父路由路径需为通配（`path="/*"`）或根 `path="/"`，否则 React Router 报 *parent route path has no trailing "*"*，子路由永不渲染。真实路由表里 AppShell 是 `path: '/'`（可行），而**测试夹具里无 path 的 `<Route element={<AppShell/>}>` 会踩这个坑**。
2. **改用工作区渲染后必须同步改测试夹具**：渲染 AppShell 的夹具，其"子路由"不再生效，需改为"注入路由表 + `path="/*"`"（`<Route path="/*" element={<AppShell routes={fixtureRoutes}/>} />`）。工作区的路由表应做成可注入、默认取 `app/` 下的工作区路由表；否则 `AppShell.test.tsx` 会整批失败（本次 19 例挂 9 例）。
3. **location 上下文的值形状**：`UNSAFE_LocationContext` 值为 `{ location, navigationType }`；`navigationType` 是 history 的 `Action` 枚举，且 `Action` **未从 `react-router-dom` 导出**——组件内用 `useNavigationType()` 取值即可（直接写字面量 `'POP'` 编译失败）。`useLocation()` 只取 `.location`。
4. **组件文件不要顺带导出 hook/常量**：oxlint 规则 `react(only-export-components)` 会告警（Fast Refresh 失效）。上下文与 `useWorkspace` 等放独立 `.ts` 文件，组件文件只导出组件。
5. **隐藏面板的行窗口化恢复**：`ErpTable` 行高测量已有 `measured > 0` 保护（隐藏期不会写坏行高），但隐藏期 `scrollHeight <= clientHeight + 4` 成立会把 `virtualActive` 置 false，且不再自恢复。面板恢复可见时 `window.dispatchEvent(new Event('resize'))` 即可触发重算——比改动这个被 33 处共用的组件安全。
6. **滚动位必须显式存还**：`display:none` 期间滚动容器的 `scrollTop` 归零，需在隐藏前存入 ref、恢复可见时写回（`useLayoutEffect` 中先写回再触发 resize）。
7. **地址变化必须区分来源**：外壳入口先登记"待打开地址"再导航，其余地址变化一律按"标签内导航"更新活动标签 `URL`；否则会把"菜单开标签"误判成"替换当前标签"，或把标签内跳转误判成开新标签（`openTab` 去重时还需 `from` 参与键，见 §3.5.1）。
8. **两条命令级坑**：`npx vitest run` 在本机被识别为 watch 命令，跑单测用 `npm test -- <路径>`；全量 `npm test` 在机器高负载时会出现大量超时假失败（本次 96 条失败、单跑全绿），跑基线前先确认机器空闲。
9. **入口落在站点根路径时不要开标签（收尾补记）**：工作区路由表里 `/` 只有一条重定向，没有自己的页面。为它开标签的后果是连锁的：该标签先渲染空白（重定向组件不产出内容），重定向后隐藏面板里的 `<Navigate>` 会在每次渲染重新触发，经 §4.4 的"隐藏标签导航收口"把它自己的地址改写成首页地址，于是与常驻首页标签**同址**，"去重键 = `URL`"（§3.5.1）失效、标签栏出现两个首页标签。落法：地址在进入标签状态机前统一归一（建初始态、恢复、解析持久化数据、`open`/`sync`/`tabUrl`/`reset` 各入口），外壳再把地址栏 `replace` 到首页地址。
10. **归一/重定向类导航必须放被动 `useEffect`（收尾补记）**：路由在**挂载期的 layout effect 阶段**才订阅 history，写在 `useLayoutEffect` 里的 `navigate` 会被**静默丢弃**（不报错、地址不变、`navigate` 返回值正常）。最小实验对照：layout 版地址停在 `/`，passive 版正常跳转。标签面板里用 `<Navigate>` 元素做重定向则不受影响（它本身就是被动 effect）。
11. **活动标签必须已挂载（收尾补记）**：接管活动位的标签可能是"刷新恢复但从未激活过"的那个——关闭活动标签由右邻接管、关闭其它、关闭全部落到首页都会走到这条路径。未挂载 ⇒ 没有面板 ⇒ 工作区空白。这条不变式放在 reducer 外层统一保证（而不是逐个动作各自记得标记），新加改变 `activeId` 的动作时不必重复考虑。

### 4.7 明确不做

- 分屏对比（左右并排两个标签）、标签拖拽排序、标签固定（`pin`，首页除外——首页常驻见 §3.5.2）：均不在本期，后续按需另立议题。
- 移动端（窄屏）标签溢出只做横向滚动，不做折行。

## 5. 验收口径

1. 开满上限（12）数量的不同模块标签，逐一切换，分页/筛选/选中/滚动均保持；超出上限的打开动作被拒绝并提示。
2. `A` 单列表页跳转其明细查看/编辑，标签内 `URL` 更新，地址栏同步；切到 `B` 标签再切回，`A` 的表单草稿仍在。
3. 脏表单下关闭标签必弹确认；确认关闭后草稿丢失，取消则停留原标签；**仅切换标签不弹框**，标签显示脏点。
4. 刷新浏览器，标签列表按 `URL` 恢复，业务数据正常加载，无 403/404；未激活的恢复标签不发起取数（懒挂载）。
5. 无权限账号的标签不渲染越权内容；权限回收后对应标签不可达。
6. 前端 `npm run lint` + `npm run build` + 相关 `vitest` 全绿；`ErpTable` 虚拟化（`virtualize`，大列表只渲染可视行）回归无异常。
7. **多脏标签下的离开保护**：同时开 2～3 个脏表单标签，浏览器返回/前进、点菜单跳转、刷新、退出登录，必须都被 `beforeunload`/唯一 blocker 拦下（对应 §4.3 已实测的多 blocker 失效）。
8. **资源指标**：8 标签全挂载后的页面堆占用可接受（浏览器任务管理器取样），刷新后首屏请求数不超过"活动标签 + 全局引导"的量级。
9. **标签栏可操作性**：`role="tablist"` + 键盘可操作（Tab 进入、左右方向键切换、Delete/中键关闭），关闭按钮有 `aria-label`；隐藏标签不进入打印输出。

10. **跨标签 `URL` 隔离**：在 `A` 标签改列表筛选/排序/翻页后切到 `B`，`B` 的地址栏与页面状态不受影响；隐藏标签不产生地址栏变化与历史记录项。

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| **滚动容器下放引发回归**（虚拟化窗口、吸顶表头、无限加载哨兵、打印布局、页面横向滚动条） | 先做容器层改造并单独一轮回归（不改任何页面逻辑），再上标签容器；§4.1 已列出需同步改写的 CSS 规则 |
| **多 blocker 失效**（`react-router` 7.18.2 只取最后一个注册者） | §4.3：shell 单一 blocker + 脏页注册表；§5.7 专项验收 |
| **location 上下文污染**（隐藏标签读到/写入活动标签 `URL`，表现为跨标签串筛选、地址栏被改） | §4.4：每标签子树覆写 location 上下文 + 隐藏标签不得导航的不变式；§5.10 专项验收 |
| **依赖 `UNSAFE_*` 内部 API**（升 React Router 大版本可能变更语义） | 只在标签 host 单一模块使用，不散落到页面；§8 登记替换评估条件 |
| **脏位双源漂移**（注册表 `dirty` 与页面 `useState` 不一致） | 注册表只做上报与聚合，不为页面提供真源；页面卸载时注销登记 |
| 常驻标签显示陈旧数据 | §4.3 写—读可见性规则（写后 `invalidateQueries` + 激活时按 stale 静默重查） |
| 内存与首屏压力 | 单表每页 15/18 行 + 明细窗口化，桌面端可接受；§3.5.4 懒挂载把刷新后的并发取数降到只剩活动标签。若实测仍敏感，降级为"表单标签常驻、列表标签按 `URL` 重建"，不改 §3 拍板的方向，只调实现策略 |
| 标签泛滥 / 撞顶打断操作 | §3.5.3（上限提至 12 或"淘汰最久未用且不脏"），待确认后定稿 |
| **回退** | 特性开关默认开；关闭即回单 `Outlet` 行为（单任务），标签栏隐藏，已开标签收敛为当前活动页。**收敛前若有脏页，复用 §4.3 同一确认链**（原文"不丢数据"仅对已保存数据成立） |

## 7. 考虑过的替代方案

| 方案 | 未选择原因 |
|---|---|
| 轻量历史标签（切换仍重挂载，只记住 `URL`） | 选中行/滚动/子表展开/表单草稿仍会丢，对照场景（一边改单一边看上游余额）不成立；`URL` 化只覆盖查询条件（§1.3） |
| 每个标签独立 `MemoryRouter`，只有活动标签同步浏览器地址 | 路由上下文天然隔离、`useLocation` 语义正确，但要重写全局 `navigate` 的落点（侧栏/面包屑/守卫全部改指向活动标签的内存路由），改造面比 `<Outlet>` 容器化大得多，且地址栏同步需手工 `history` 操作 |
| 依赖浏览器多标签页 + 每页独立窗口状态 | 共享同一 `Cookie` 会话，无标签身份、无跨标签对照交互，不是产品级多任务（§1.2） |
| 分屏（左右两栏同时可见） | 对照场景的价值是"保留上下文来回切"，不是"同屏看两页"；分屏对窄屏与明细页排版成本高，本期不做（§4.4） |

## 8. 复审条件

- 撞顶频繁（用户实测反馈标签上限不够）→ 按 §3.5.3 调上限或启用"淘汰最久未用且不脏"；
- 出现"必须同屏对照"的高频诉求（如两单明细逐行对账）→ 评估分屏（本期明确不做）；
- 常驻标签实测内存/首屏不可接受 → 按 §6 降级策略调整挂载范围（列表标签改按 `URL` 重建）；
- `/print/*`、`/layout-designer/*` 等重资源页（含 `iframe`）在常驻下出现明显占用 → 评估对这类路由设"独立窗口打开、不进标签"的例外清单；
- 后台标签出现轮询/定时器类行为（如 `/jobs` 状态刷新）→ 评估非活动标签暂停轮询的通用机制；
- `react-router` 大版本升级，或 `UNSAFE_LocationContext` / `UNSAFE_RouteContext` 语义变更 → 评估标签 host 的隔离实现替换（§4.4 单点依赖，替换面为一处）。
