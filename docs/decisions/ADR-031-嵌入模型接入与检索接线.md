# ADR-031 嵌入模型接入与检索接线（云端优先）

- 状态：**已接受**（2026-10-02）
- 日期：2026-10-02
- 相关：ADR-011（认知层与语义接口——知识通道与 embedding 决策标准）、ADR-016（知识通道接线缺口）、
  ADR-030（管理面：配置归属 §8、领域表 §6.1、密钥 §3）、ADR-002（网关与 RAG 边界，大部分已作废）

> **本 ADR 推翻一项既有拍板**：`docs/plans/RAG-选型.md` 的"本地优先、默认 bge-m3 sidecar"。
> 该文件与 `docs/plans/ADR-016-嵌入接线批-执行提示词.md` **未纳版本控制**（`git ls-files docs/plans` 为空），
> 所以定案必须记在这里——否则换一台机器就只剩"计划书里写着本地 sidecar"这一条线索。

---

## 1. 决定

| # | 决定 | 内涵 |
|---|---|---|
| 1 | **接入形态：云端 API 优先**，本地自建后置为"可选部署" | 不再要求在同一台机器上跑本地模型进程；架构上必须保留"换成自建端点"的切换点 |
| 2 | **接口口径：OpenAI 兼容 `POST /v1/embeddings`** | 与 chat 的 `/chat/completions` 同族；本地 sidecar（TEI 等）也走这个协议，于是"云端 ↔ 本地"只是换端点，不是换代码路径 |
| 3 | **配置归属仍走 3102**（供应商 → 模型 → 环境变量密钥） | 不新开配置节、不进 `appsettings`（ADR-030 §8）；模型表按**用途**区分对话 / 嵌入 |
| 4 | **同一时刻全库只有一个嵌入模型** | 换模型 = 相关集合重建；否则检索要按集合分别嵌入查询向量（1 次出网变 N 次） |
| 5 | **维度必须与集合登记一致** | 集合行记 `EMBEDDING_MODEL` / `DIMENSION`；两者与当前嵌入模型不符时**拒绝写入/激活**，不静默降级 |
| 6 | **fail-closed 不变** | 没配嵌入模型 ⇒ 维持 `PendingEmbeddingModel` 的可读失败（`KB_EMBEDDING_NOT_CONFIGURED` 家族），**不得**退化成空向量或"没有相关内容" |
| 7 | **预设目录扩容 + 型号清单由拉取得到** | 供应商预设只保证"入口可发出去"（端点 / 协议 / 密钥环境变量名）；型号由管理员填密钥后向厂商拉取候选再落库。**这条是模型面（3102）的通用能力，对话与嵌入同一机制**——定案记在 ADR-030 §12.3 |

## 2. 为什么推翻"本地优先"

原决策把成本放在**运维前置**上：一次性探针、权重获取、量化档位、与 SQL Server 抢内存、长驻进程启停。
换成云端后这些全部消失，代价换到两处：

1. **语料出网**：入库的是内部开发手册、ADR、业务规则、字段考古笔记。**这是部署方的合规判断，不是技术判断**——
   本系统的立场是"默认云端、本地随时可换"（§5 给了切换清单），在意语料外发的部署方自行切本地；
2. **检索路径每次出网**：`kb_search` 每次调用都要请求厂商，网络抖动与限流会直接体现在用户等待上。
   这一条**接受**，不做额外机制（不加重试风暴、不缓存查询向量去掩盖抖动）——真在意就切本地。

还有一层工程理由：本地优先把"能不能跑起来"押在**这台机器的 CPU/内存/依赖**上（无 CUDA、Windows Python 版本、
Docker 未装、WSL 才有 Linux 二进制），而云端把这条不确定性交给了厂商的可用性。**两者都是不确定性，
但后者不阻塞开发与验收**——接线批的价值在于让知识通道可用，而不是证明某台机器能跑模型。

## 3. 配置形状（落地细节）

### 3.1 复用"供应商 → 模型"两级，不新开第四档（ADR-030 §6.1）

```
ASSISTANT_PROVIDER  端点根 / 协议 / 密钥环境变量名 / 默认超时 / 启用
      └── ASSISTANT_MODEL  型号标识 / **用途** / **维度** / 超时 / 单价 / 启用 / **当前**
```

模型表新增两列：

| 列 | 用途 |
|---|---|
| `KIND` | `CHAT` / `EMBEDDING`（默认 `CHAT`，历史行不动） |
| `DIMENSION` | 仅嵌入用（如 1024）；对话模型为 `NULL` |

配套两处**必须一起改**的约束：

1. `UX_ASSISTANT_MODEL_ACTIVE` 是 `WHERE IS_ACTIVE = 1` 的筛选唯一索引 ⇒ **全表至多一条"当前模型"**，
   嵌入与对话无法各有一条。索引改为**按用途各一条**：`WHERE IS_ACTIVE = 1` 之上加 `KIND`。
2. `API_KEY_ENV_VAR` 在供应商表与模型表都是 `NOT NULL` + `LEN > 0` 检查 ⇒ **"无密钥端点"（本地自建）表达不出来**。
   放宽为可空（空 = 该端点不需要密钥，请求不带 `Authorization`）。
   这一条不是为了现在，而是为了让 §5 的"换回本地"**只改数据、不再改 schema**。

### 3.2 型号清单由拉取得到（**通用机制**；本 ADR 只补嵌入侧两条）

"型号不硬编码、由管理员填密钥后向厂商拉取候选再落库"是**模型面（3102）的通用能力，
对话与嵌入同一套机制**——定案记录在 ADR-030 §12.3，本 ADR 不重复。

嵌入侧只多两条：

- 拉回来的候选**由管理员指定用途**，嵌入还要**同时给出维度**（§3.1）——不靠型号名猜，
  猜错会得到一个永远打不通的行；
- **"这家有没有嵌入端点"也落在预设数据里**（与"能不能列出型号"同属能力差异）：界面据此明说
  "这家没有嵌入端点"，而不是让管理员配出一个必定 404 的行。

### 3.3 每个厂商都要有一条真值

预设里的每一行都必须是**能发出去的真值**（端点、协议、密钥环境变量名），且**逐家核实过是否提供
嵌入端点**。已知的两条实测（2026-10-02）：

- **DeepSeek**：官方文档的模型页列出了思考模式 / 工具调用 / Responses API / 视觉等能力，
  **没有**嵌入端点 ⇒ 不能默认它有嵌入（需要嵌入时得另配一家）；
- **小米 MiMo**：确有官方开放平台（mimo.mi.com）且声明兼容 OpenAI 与 Anthropic 两种格式；
  具体端点以官方文档为准（实现时核）。

其余（阿里百炼 / 智谱 / OpenAI / Moonshot 等）在实现时逐家核对，**核过才写进目录**。

## 4. 检索侧的配套约束

接线把知识通道从"空"变成"真的会注入"，因此下面两条与接线**同批**处理，不留到以后再补：

1. **相似度下限**：当前检索是 `VECTOR_DISTANCE('cosine')` + `TOP(@Top)`，**没有阈值**。
   知识库里满是参数键、错误码、模块号这类专有标识符——纯向量对它们最弱，且"凑得上的都注入"会污染回答。
   至少给一个"低于阈值不注入"的下限（宁可少报）；
2. **不可用的用户可见语义**：嵌入调用失败现在会被对话层统一兜成"工具执行出现内部错误，请换一种问法或稍后重试"——
   既没说清是向量服务不可用，还引导用户去重试一个重试不好的动作。要落成**可识别、可读**的失败原因。

## 5. 将来换回本地要动什么（一处清单）

1. 3102 里把嵌入模型的**供应商端点**改成自建地址（如 `http://127.0.0.1:8080/v1`），
   密钥环境变量名**留空**（约束已在 §3.1 放宽）；
2. 保证自建端点返回的**维度与集合登记一致**（不一致就重建集合）；
3. 自建进程的启停归运维（本系统不自启、不代管）；
4. 模型权重 / tokenizer / venv **不入库**，把"从哪里取、放哪里、怎么换"写进部署文档。

**不需要**：改代码、改 schema、改检索 SQL（协议与形状都没变）。

## 6. 未决与风险（如实登记）

| # | 事项 | 现状 |
|---|---|---|
| 1 | 各厂商嵌入端点的**逐家核实** | 只核了 DeepSeek（无）与小米（有平台）；其余待核 |
| 2 | **限流与批量入库** | 百余篇文档逐块嵌入会撞厂商 RPM；需要分批与退避，具体参数在实现时按厂商实测 |
| 3 | **网络抖动** | 接受（§2），不做额外机制 |
| 4 | 维度不一致时的**重建流程** | 拒绝写入是定的；"重建"是手工还是给一个动作，未定 |
| 5 | 嵌入用量是否进成本台账 | `ASSISTANT_USAGE_*` 现在按对话 token 记；嵌入是否入账未定 |
| 6 | 检索评估尺子（20–30 条中文问答的应命中文档） | 需要人工给正确答案，与黄金集同类工作 |
