- 决策者：项目团队

## 背景

`EOS.Gateway` 当前是 DeepSeek 最小试验：提供 `/api/chat`、`/api/chat/stream`、`/api/models`、`/api/usage/summary`，配置在启动时从配置文件、user-secrets 或环境变量读取。蓝图阶段 C 规划了只读智能助手、企业知识库检索与 RAG 组装，网关 README 将 RAG、限流配额、审计与成本报表等列为阶段 C 后建设。

在讨论中明确了三个需要固化的方向问题：

1. 网关是否、以及如何提供管理界面（模型设置、参数、用量与成本）；
2. 企业知识库（RAG）的文档与向量索引存储在哪里，谁负责入库、谁负责检索；
3. 知识库的“谁能用、能看到什么”如何判断，是否复用 ERP 权限系统。

## 决策

### 1. 统一 AI 运维控制台（EOS.Console）

- 网关配置与知识库入库共用一个管理界面：**`EOS.Console`（AI 运维控制台）**，不建设两套工具；
- 阶段 C 之前不建设控制台（`EOS.Console/` 规划目录仅保留职责文档），也不实现配置热更新；
- 控制台是**独立部署的小型运维 Web 应用**，使用运维身份登录，不寄生在网关进程中，也**不经过 `EOS.API` 中转**；
- 控制台分别调用：网关配置 API（模型、密钥、价格、用量）与入库服务 API（集合、文档、任务、可见性）；未来 Agent 管理扩展为同一控制台的新页签；
- 原因约束：`EOS.API` 不依赖 `EOS.Gateway`；网关不承担业务认证；控制台不得以明文展示模型密钥；
- 只读看板（用量、成本、模型列表）的数据源已存在，可作为阶段 C 的最小切入点，但同样不提前建设。

### 2. 知识库存储（RAG）

- 企业文档原始文件保存在业务存储（SQL Server、`UploadFile/` 等服务端位置），由 `EOS.API` 授权管理；
- 派生索引（chunk、向量、来源与权限元数据）存放在**独立于 SQL Server 的服务端向量库**，作为受控数据组件；
- 向量库逻辑上归 `EOS.API` 侧管理；网关、客户端、Agent 均不得直连；
- 具体向量库选型（Milvus / Qdrant / Weaviate 等）在阶段 C 启动前确定；
- 仓库根目录 `.rag/lancedb` 是本地开发用 RAG 工具（`mcp-local-rag-anything`）的缓存，不是企业知识库落点。
  （**现状注记（2026-09-15）**：该 MCP 与技能在本机未安装，`.rag/lancedb` 与 `ingest-driver.js` /
  `verify-driver.js` 仍在；决策本身不变，仅记录工具当前未接线，详见
  `docs/eos-development/09-元数据与RAG指南.md` §4。）

### 3. 入库与向量化

- 入库（上传、切分、向量化、写入索引）是**运维域动作**，由管理员/运维人员通过 `EOS.Console` 的知识库管理区执行，不以 CLI 为主；
- 入库工具独立于 `EOS.Web` / `EOS.Client` 的普通功能，使用运维身份或管理凭据，不受 ERP 日常权限系统左右；
- embedding 模型调用统一经 `EOS.Gateway` 出口；具体嵌入模型或供应商（本地开源模型或厂商 embedding API）在阶段 C 试验中确定；
- 索引是副本而非事实源：文档更新、删除或权限变化时必须同步更新或使索引失效，防止索引过期造成越权。

### 4. 检索职责

- 检索与权限过滤归 `EOS.API`（或其内部检索模块）；`EOS.API` 是最终权限边界；
- 编排归调用方：当前为 `EOS.Client`（先取上下文再调网关），未来为 `EOS.AgentRuntime`；
- `EOS.Gateway` 只接收已过滤上下文、组装系统提示词并调用模型；不检索、不反向调用 `EOS.API`；
- 检索契约：输入（用户身份 + 问题 + 可选知识库范围），输出（按可见性过滤后的片段列表 + 来源）。输出不得携带未复核的原文直接出网。

### 5. 身份与权限

- 身份认证唯一，复用 `EOS.API` 认证（SYSDL 账号 / Cookie 会话），不建立第二套身份系统；
- 功能门禁（能否使用知识库、能用哪些库）与文档可见性（全员 / 部门 / 角色 / 指定用户）使用知识库自有的轻量规则，由 `EOS.API` 强制执行；
- 业务数据可见性复用 ERP 权限系统（模块、字段、数据范围，含个人权限覆盖组规则），检索时逐条复核；
- 客户端、网关均不参与权限判断；前端隐藏仅改善体验。

### 6. 延期决策（阶段 C 前置）

- 向量库具体产品选型；
- ~~部署形态（独立网关服务 vs 与 AgentRuntime 合并部署）~~：**已定（2026-08-07）——合并部署，当日撤销**。Gateway 与 AgentRuntime 合并为一个 AI 平台服务进程的方案已回滚：网关保持独立进程（5288），详见 `ADR-003`；
- 知识库权限规则细节（部门映射、嵌套可见性等）；
- 入库服务的后端归属（独立管理服务 vs 挂靠 `EOS.API` 旁）。

## 选择理由

- 网关保持单一职责（统一模型推理出口），避免膨胀为半个 AgentRuntime；
- `EOS.API` 持有认证会话与权限模型，是唯一能可信判断“谁在问、能看到什么”的一方；网关收到的用户身份仅用于审计，不可用于授权；
- 入库作为运维域动作，避免用 ERP 日常权限系统污染知识库，同时通过管理界面满足非技术运维人员；
- 独立向量库与主交易 SQL Server 解耦，避免 ANN 检索影响事务库，并允许单独扩容与备份；
- “检索归 API、编排归调用方、网关只组装”延续了 `EOS.Client` 现有的“先取上下文再调网关”模式，未来迁移到 AgentRuntime 时网关无需改动。

## 考虑过的替代方案

### 方案 A：网关承担检索与权限过滤

优点：调用链短，客户端一次调用。

未选择原因：网关无法可信验证用户身份（身份委托复杂）；网关需要持有调用 `EOS.API` 的服务凭据；职责膨胀为半个 AgentRuntime，违反“网关只回答模型请求从哪里出网”的定位。

### 方案 B：网关管理界面经 `EOS.API` 中转

优点：复用现有前端与认证体验。

未选择原因：违反“`EOS.API` 不依赖 `EOS.Gateway`”的硬约束，也会让网关管理混入业务认证体系。

### 方案 C：入库作为 `EOS.Web` / `EOS.Client` 的普通功能

优点：实现成本低，复用现有界面。

未选择原因：入库是运维动作，不应受 ERP 日常权限系统左右，也不应占用业务界面；管理面与业务面需要分离。

### 方案 D：使用 SQL Server 向量能力

优点：不新增组件，复用现有数据库运维。

未选择原因：本次讨论确定向量库直接上独立组件；具体产品选型留阶段 C。主交易 SQL Server 不承担向量检索负载。

### 方案 E：CLI 入库工具

优点：脚本化、可批处理。

未选择原因：运维人员不一定具备技术能力，管理界面更友好；CLI 可作辅助能力，但不应是主要入口。

### 方案 F：网关进程内嵌管理界面（不独立部署）

优点：少一个部署组件。

未选择原因：控制台需要覆盖网关之外的入库管理，内嵌会让网关膨胀；独立薄应用可随 Agent 管理等新页签扩展，且不影响网关运行路径。

## 结果与影响

### 正面影响

- 边界清晰：身份与权限在 `EOS.API`，推理在网关，入库在独立运维工具；
- 知识库不会成为绕过 ERP 权限的数据旁路；
- 网关保持最小，未来 AgentRuntime 接管编排时无需改动网关；
- 企业文档与业务数据两类知识源采用不同权限策略，符合各自数据性质。

### 成本与风险

- 新增向量库组件带来部署、备份、监控与升级成本；
- 统一控制台独立部署带来一个额外的薄组件（部署与运维面）；
- 索引与原始文档的一致性需要同步或失效机制；
- 网关需要新增 embedding 能力（当前只有 chat 端点），嵌入模型路线未定；
- 阶段 C 前置（`EOS.API` 契约稳定、真实场景评估集、embedding 路线、部署形态）未满足前，不开始知识库与入库工具的实现；
- 管理界面需要独立的运维鉴权与密钥保护设计。

## 执行准则

- 阶段 C 前不新增 `EOS.Console`（规划边界，不建 `.csproj`）、向量库、入库服务的可执行实现；网关 embedding 端点作为最小试验需单独确认；
- 阶段 C 启动前置：`EOS.API` 业务契约稳定；真实场景评估集与成本预算；embedding 路线确定；部署形态确定；
- 现在可做的非代码工作：真实文档评估集收集、入库数据契约草案（见 `docs/plans/知识库入库契约.md`）、可见性规则草案；
- 实施时同步更新根 `README.md`、`blueprint.md`、`EOS.Console/README.md`、`EOS.Gateway/README.md`、`EOS.API/README.md`、`EOS.Skill/README.md`。

## 复审条件

出现以下情况时复审本决策：

- 出现第二个真实业务域或明确的 AgentRuntime 部署形态；
- 知识库数据规模或检索质量要求独立的检索服务；
- 向量库选型或供应商出现重大变化；
- 新模型厂商或 embedding 能力改变网关最小试验边界。
