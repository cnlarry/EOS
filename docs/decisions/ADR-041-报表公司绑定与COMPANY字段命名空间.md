# ADR-041：报表绑定开单公司，公司表成为打印的第三数据源

- 状态：已接受（2026-10-24 用户拍板）
- 日期：2026-10-24
- 决策者：用户（Larry）+ 开发 Agent
- 相关：ADR-009（报表系统重构）、ADR-010（可视化版式设计器）、ADR-024（报表资源模型）、ADR-036（共享原语单一真源）

## 1. 背景

打印一张单据时，页头的主体信息（公司中文名、英文名、地址、电话、传真）来自
`REPORT_LAYOUT` 里 `KIND='HEADER'` 的页头字典条目，而条目把公司名当成**自由文本**
存在 `CONTENT` JSON 里。这套做法有三个问题：

1. **重复且会漂移**：同一家公司在多个页头条目里各存一份名称/地址，改一处不等于改齐；
2. **大量报表没有页头**：实测 137 张默认报表中 88 张 `HEADER_ID` 为空、21 张指向已不存在的页头
   （旧系统迁移遗留），打印出来公司名是空白；
3. **公司资料本身没有被消费**：模块 `110101`（公司基本资料，主表 `COMPANY`）在系统里几乎没有
   读取方——它恰好就是打印页头需要的唯一真源。

用户同时明确：**多公司是有业务意义的**（大陆公司、香港公司、内地其它公司分别接单），
不是"单公司部署可以忽略"的遗留问题；因此"公司"需要一个明确的绑定位置，
而不是继续由页头文本隐式表达。

## 2. 决策

### 2.1 公司表是打印的第三张表

一张报表涉及三张表：**主表**（单据表头）、**明细表**、**公司表**（`COMPANY`）。
前两张随单据走，公司表是**开单主体**的配置。版式里新增第三个字段命名空间 `COMPANY.*`，
与 `MASTER.*` / `DETAILS.*` 并列。

- 字段白名单来自 `FIELDS`（`T_ID='COMPANY'`，要求物理列存在），保存校验与渲染共用同一份清单；
- 渲染时 `COMPANY.*` 从 `PrintData.Company` 取值；无公司记录时渲染为空（fail-closed，不猜）；
- `SYS.HEADER_COMPANY` / `SYS.HEADER_COMPANY_EN` 改为从公司记录取值，
  页头字典不再承担公司名。

### 2.2 绑定粒度：`REPORT.COMPANY_ID`

公司在**报表定义**上绑定（迁移 `449` 新增 `REPORT.COMPANY_ID nvarchar(20) NOT NULL`），不在页头字典上：

- 同一模块可以有"送货单归 A 公司、拣货单归 B 公司"；
- 页头字典保留其原本职责——LOGO、页头文本（如联系方式行）、表尾引用；它是**视觉资产**，
  不是法律主体；
- 取值**只认报表上的显式编号，不做任何"猜一个公司"的兜底**：存量报表在迁移 449 中
  **一律回填为系统默认公司编号 `DEFAULT`**（本库唯一公司记录的真实编号，见迁移 096），
  列同时收紧为 `NOT NULL + DEFAULT('DEFAULT') + CHECK 非空`；新建报表不写该列时也落显式值。
  编号为空或指向不存在的记录 → 公司字段全空（fail-closed），不回退页头旧文本。

### 2.3 设计器与报表维护的分工

| 入口 | 职责 |
|---|---|
| 报表定义维护（`report-admin`，2201） | 选报表绑定的**开单公司**（下拉来自 110101） |
| 版式设计器（`/layout-designer/{模块}`） | 摆字段：`{{COMPANY.NAME_CN}}`、`{{COMPANY.TEL}}`…；工具栏显示当前生效公司；样例预览也用真实公司 |
| 页头字典 | 只维护 LOGO 与页头文本；不再编辑公司名/英文名 |

### 2.4 旧页头公司文本的处理

页头字典 `CONTENT` 里的 `companyName` / `companyNameEn` **不再参与打印**。
库内仍存在的旧文本（客户公司的真实名称）不随仓库分发，也不做自动迁移；
需要保留的开单主体应录入 110101（公司基本资料）并在报表上绑定。
仓库内如出现真实公司名，按 `scripts/check-sensitive-terms.ps1` 的私有词表拦截。

## 3. 后果

- 迁移 `449`：`REPORT.COMPANY_ID`（NOT NULL + DEFAULT('DEFAULT') + CHECK 非空，存量 460 张报表一律回填 `DEFAULT`）。
- `ReportPdfMeta` / `PrintData` 携带公司记录；单据打印（`PrintService`）与报表清单打印
  （`ReportListPdfComposer`）走同一份公司数据，两条路径的公司名不会分叉。
- 报表定义接口新增 `GET /report-admin/companies`；保存时校验公司必须存在（不靠外键）。
- 版式保存校验接受 `COMPANY.*`，白名单现读 `FIELDS`；不传白名单的调用方一律判非法。
- 新增 `Data/Reports/CompanyPrintData.cs`（公司字段/记录/下拉的唯一读取点），
  不新增 `Data/` 根目录文件。

## 4. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 公司名继续存在页头字典，只在页头加"引用公司" | 同一家公司仍会在多个页头各存一份；且"哪家公司接单"与"用哪张页头样式"是两个维度，绑在一起后无法独立变化 |
| 所有页头统一用唯一公司记录，不做绑定 | 多公司是真实需求；没有绑定位置时，将来出现第二家公司只能靠改代码 |
| 让 `SYS.HEADER_COMPANY` 直接读 `COMPANY` 的固定列，不开放 `COMPANY.*` | 地址/电话/英文名/简称等字段无法进版式；页头仍然只能显示一个名字 |
| 在页头 CONTENT 里存 companyId | 页头是全局资产，报表才是"这张单据归哪家公司"的正确粒度 |
