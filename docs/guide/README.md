# EOS 开发手册

面向参与 EOS 开发的工程师：讲清系统有哪些能力、怎么用、怎么扩展、边界在哪。

与 `docs/eos-development/` 的分工：

| 目录 | 内容 | 读者 |
|---|---|---|
| `docs/eos-development/` | 生成型业务知识库（模块树、表清单、字段字典），由脚本从库导出 | 模型、检索、查数据时用 |
| `docs/guide/`（本目录） | 手写开发手册（机制、契约、扩展方式） | 开发工程师 |

## 一、怎么读

按角色选一条线，不必从头读：

| 角色 | 建议顺序 |
|---|---|
| 新加入 | 00 术语表 → 01 代码地图 → 02 环境与运行 → 03 工程规范 → 04 API 契约 → 05 迁移与建库 → 06 测试与门禁 |
| 后端 | 03 工程规范 → 05 迁移与建库 → 06 测试与门禁 → 10~12 元数据 → 20~22 权限 → 40~48 单据 |
| 前端 | 04 API 契约 → 40 统一工作台 → 42 统一表单 → 46 统一选择器 → 50 统一报表 |
| 做报表 | 44 受控查询 → 50 统一报表 → 51 报表设计器 → 52 打印版式 |
| 做助手 | 12 元数据消费 → 60 AI 工作助手 |
| 改配置 | 70 后台配置面总览 → 11 元数据运维 → 22 权限配置后台 |

完整篇目、写作状态与「文档 ↔ 源码」映射见 [`_map.md`](./_map.md)。

### 给 AI 助手的读法

本手册同时作为 AI 助手的上下文，按下面的顺序用命中率最高：

1. 先读 [`_map.md`](./_map.md)，定位「要改的能力」对应哪篇文档、哪些源码路径；
2. 读该篇及其标注的前置篇目，弄清约定与边界；
3. 再去读 `_map.md` 里登记的具体源码——**文档只讲约定，实现细节以代码为准**；
4. 动手前确认该篇里的「禁止 / 不要」条目，以及 [03-工程规范与硬约束](./03-工程规范与硬约束.md) 的硬约束；
5. 改完按第三节判断要不要同步文档，并跑一次陈旧检测。

写代码时可直接拿文档里出现的**表名、列名、文件路径、类名**当检索词——
本手册刻意保留这些精确标识符，就是为了让检索直接命中。

## 二、写作约定

- **每篇统一开头**，写清读者与前置：

  ```markdown
  > 读者：后端 ｜ 前置：03-工程规范与硬约束
  ```

- **只写"怎么用 / 怎么扩展 / 边界在哪"**，不做逐行代码解读、不抄实现细节。代码能直接回答的不要写进文档——那部分一定先过时。
- **能生成的不手写**：接口清单、元数据清单、效果清单、报表清单一律由脚本导出，文档只引用导出结果，不手工维护副本。
- **一事实一处**：同一结论只在一个地方写全，其他篇目链接过去，不复制粘贴。
- 文档里不写日期与版本号，新鲜度由检测脚本判断（手写的日期一定会假）。

## 三、功能变更时怎么保证文档不烂

靠两件事配合，不靠自觉：

1. **映射表 [`_map.md`](./_map.md)**：每篇文档登记它对应的源码路径。写文档时同步登记；漏登记会被脚本报出来。
2. **陈旧检测 `_tools/check-freshness.ps1`**：对每篇文档比较「该文档最后一次提交」与「其对应源码最后一次提交」。源码更新而文档没跟上，就报 STALE。

```powershell
pwsh docs/guide/_tools/check-freshness.ps1            # 只报告
pwsh docs/guide/_tools/check-freshness.ps1 -Strict    # 有 STALE 即退出码 1
```

哪些变更必须同步文档：

| 变更类型 | 要求 |
|---|---|
| 接口、路由、错误码、配置项、权限键、公共组件 props、数据库对象结构 | **必须**同步对应文档 |
| 已有能力的内部重构、性能优化 | 建议同步（对外行为没变可不动） |
| 缺陷修复、样式调整、测试补充 | 不必同步 |

脚本无法判断"这次改动属于哪一类"，所以它只负责提醒「源码动了、文档没动」，由改代码的人判断要不要动文档。这样不会因为无关改动而被迫改文档。

## 四、目录边界

- 本目录是 `docs/` 下**唯一纳入版本控制**的子树（`.git/info/exclude` 中 `docs/*` 排除全部，仅 `!docs/guide/` 放行）。
  新文档必须放在本目录内，放在 `docs/` 其他位置不会进仓库。
- 本目录面向开发工程师。面向使用者的说明仍在根目录 `README.md`、`ARCHITECTURE.md`、`QUICKSTART.md`、`CONTRIBUTING.md`。
- 本地忽略规则的恢复副本在 `publish/report/local-exclude.txt`，改动 `.git/info/exclude` 时需同步该文件，否则换机恢复后规则丢失。
