# 72 导入与导出

实现：`EOS.API/Controllers/ImportController.cs`、`EOS.API/Data/ImportService.cs`、
`EOS.API/Data/RecordPayloadValidator.cs`（校验）。该文件同时是**统一表单写路径**的校验与默认值入口
（类型转换、必填 / 正则 / 长度 / 精度、新增态默认值展开的判据 `IsTodayDefault`），两条路共用同一份口径。

## 一、导入：四步，预览与落库分离

路由前缀 `api/v1/import`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/tables` | 列出**可导入**的表 |
| `GET` | `/{table}/definition` | 取导入定义（列映射与规则） |
| `POST` | `/preview` | **预览**：校验并给出将写入的内容，**不落库** |
| `POST` | `/execute` | 执行导入 |

**预览与执行分离**是核心设计：导入是批量写，出错代价高。
先预览、确认无误再执行，而不是"导进去看结果"。

### 可导入的表

由 `TABLES.CAN_IMPORT` 控制（见 [10-元数据模型](./10-元数据模型.md)）。
**未开启该标志的表不会出现在 `/tables` 里**，即使表已登记。

### 导入定义

`/{table}/definition` 给出该表的列映射与规则。实施侧据此准备数据文件——
列顺序、必填、类型都由定义决定，不靠约定俗成。

## 二、导入是写路径

和手工新增一样，导入要过完整通道：

1. **权限门**：按目标模块判定新增权限；
2. **字段级限制**：被"禁新增"的字段不得写入；
3. **校验**：必填、正则、长度、引用存在等（`RecordPayloadValidator`）；
4. **审计**：导入写入 `AUDIT_EVENT`；
5. **事务**：批量写入的事务边界由服务端控制。

因此：**导入不绕过任何校验**。如果数据在界面上填不进去，导入同样会被拒——
这是设计意图，不是导入功能的问题。

## 三、导出

导出是工作台的能力（见 [40-统一工作台](./40-统一工作台.md)）：

| 端点 | 说明 |
|---|---|
| `POST /api/v1/document-workbench/{moduleId}/export` | 按当前查询条件导出全部命中行 |
| `POST .../export-selected` | 导出所选行，**1~500 行**，主键数量须与定义一致 |

两条约束：

- **导出字段按模块定义的可见列解析**——被"禁看"的字段**不会出现在导出文件里**；
- 行数超限或主键数量不符时返回 `INVALID_EXPORT_KEYS`（400），不静默截断。

导出是**读路径**：审计用 best-effort 写入（动作 `EXPORT`，资源类型 `EXPORT`），
审计写失败不影响导出结果。

## 四、前端

`EOS.Web/src/features/import/` 是导入界面。
导出按钮在工作台工具栏（主按钮 + 分割下拉，见工具栏约定）。

## 五、排障

| 现象 | 原因 |
|---|---|
| `/tables` 里没有目标表 | `TABLES.CAN_IMPORT` 未开启 |
| 预览报字段错误 | 数据不符合导入定义；按定义调整列顺序与内容 |
| 预览通过、执行报错 | 执行期校验（如唯一约束、引用存在）与预览期口径不同；看返回的字段级错误 |
| 导出文件少列 | 该列不可见（字段级权限）或不在定义里 |
| 导出报 400 | 行数超 1~500，或主键数量与定义不一致 |
| 导入成功但界面看不到 | 该数据的行级范围把当前用户排除了（`DATA_FILTER`） |

## 六、注意事项

- **先预览再执行**，不要拿生产库试导入；
- **不要为导入开"跳过校验"的口子**——那是绕过整个写入通道；
- **导出受字段级权限约束**，这是有意的：能看才能导；
- 大结果集导出会撑内存，导出前先用条件收窄。
