# 72 导入与导出

实现：`EOS.API/Features/Import/`（`ImportService.cs`、`ImportMappingStore.cs`、`TabularFileReader.cs`、
`ImportContracts.cs`、`ImportLimits.cs`）、`EOS.API/Controllers/ImportController.cs`、
`EOS.Web/src/features/import/`。导入的每一行最终交给 `EOS.API/Data/WorkbenchCommandHandler.cs`
的新增写路径，它与 [42-统一表单](./42-统一表单.md) 是同一段代码——校验、默认值、效果链、审计都只有一份。

## 一、导入按**模块**进行，不按表

导入的目标是 `MODULES` 的模块（主表只是模块的落地形态）。原因是权限、字段级限制、默认值、
效果链、审计全都挂在模块上：按表导入只能裸写库，按模块导入就等于"替用户手工录一行"。

| 端点 | 作用 |
|---|---|
| `GET /api/v1/import/targets` | 可导入模块清单 |
| `GET /api/v1/import/targets/{moduleId}/definition` | 导入定义（可填列、必填、必须映射的键） |
| `GET /api/v1/import/targets/{moduleId}/readiness` | **前置资料就绪度**（必填字段引用的主档还是空表） |
| `GET /api/v1/import/targets/{moduleId}/mapping` | 该（用户 + 模块）**记住的列映射** |
| `PUT /api/v1/import/targets/{moduleId}/mapping` | 记住这份列映射 |
| `GET /api/v1/import/targets/{moduleId}/template` | 下载空模板 CSV（列名 = 字段标签） |
| `POST /api/v1/import/parse` | 上传文件（multipart）→ 解析成表格 |
| `POST /api/v1/import/targets/{moduleId}/preview` | **预演**（真实事务内执行后回滚） |
| `POST /api/v1/import/targets/{moduleId}/execute` | 执行导入 |

### 可导入的范围

**候选 = 统一表单写名单（`UnifiedFormEditorSettings.EnabledModuleIds`）∩ 统一工作台模块**
（`V_MODULE_NODE.NODE_KIND='WORKBENCH'`）。不设第三处"允许导入"标记：能写就能导，
多一处开关只会多一处能配错、且必须与权限保持对齐的东西。

> `TABLES.CAN_IMPORT` 是旧系统的遗留列，**不再是导入的判据**（全库为 0 且无写入路径）。
> 不要为它补维护界面。

### 权限

两道门，都在服务端：

1. **功能入口**：模块 `230902`（基本资料导入）的浏览 + **设置权**——与"产品可用库存重计"
   这类工具页同一口径（见 `ImportController.CanUseAsync`）；
2. **每个目标模块**：`WorkbenchAccessPolicy.AuthorizeFormAsync(userId, moduleId, "new")`，
   与统一表单新增同一入口（写名单 + `ADDNEW` 动作位 + `HasAdd`）。

被拒时**明说原因**（缺哪个动作位、模块不在写名单），不按 404 掩饰——用户问的是
"我自己为什么做不了这件事"，而不是探测别人数据是否存在。

## 二、导入是写路径：一行 = 一次新增

每行提交给 `WorkbenchCommandHandler.CreateRecordAsync`，于是自动获得：

1. **字段级限制**：被"禁新增"（`DENY_NEW_FIELD_MASTER`）的字段不在表单定义里，提交即被拒；
2. **校验**：必填、正则、长度、精度、类型转换（`RecordPayloadValidator`）；
3. **默认值**：`DFT_VALUE`（含 `'D'` 日期哨兵）与 `FormDefaultRules`；
4. **领域规则**：自动单号、默认单别、服务端填充列、只读联动列补齐；
5. **效果链**：`SAVE` 阶段动作链（`EffectEngineInvoker`）；
6. **审计**：逐行写 `AUDIT_EVENT`（`ACTION='INSERT'`，`RESOURCE_TYPE='WORKBENCH_RECORD'`），
   整批另写一条（`ACTION='IMPORT'`，`RESOURCE_TYPE='IMPORT'`，摘要含成功/失败行数与来源文件名）；
7. **模块过滤判定**：跑完效果链之后判"记录是否仍在模块范围内"。

**空白单元格 = 不提供该值**，不是"写成空串"：把空串当值提交会顶掉库里的默认值
（`ApplyDefaults` 只补缺失的键）。

**主键不可由服务端生成的列必须映射**（`definition.requiredKeys`）：自增列与自动单号列不算，
让用户填一个自己也不知道的值只会制造失败行。

### 预演 = `dryRun`

预演跑的是同一条路径、同一个事务，只是把提交换成**无条件回滚**（`FinishAsync`），
因此"预演通过"与"执行通过"是同一条判据，不是两份实现。预演不写任何数据、不留审计痕迹。

### 逐行独立提交

每行自带事务：**失败的行不影响已经成功的行**。因此结果必须逐行回报，界面也要逐行展示
"哪几行进去了、哪几行没有及原因"，失败明细可导出为 CSV 供改好后重导。

不要为此改成"整批一个大数据事务"：单事务会把锁持有时间拉长到与行数成正比，
与"导入只是个调用方"的设计冲突。

### 规模上限

`ImportLimits` 是**唯一**声明处（文件 10 MB、`MaxRows` 行、`MaxColumns` 列）：

- 文件超过行数上限即截断，并把"实际总行数 / 已载入行数"如实回报，由界面提示拆分；
- 单次请求的行数超过 `MaxRows` 直接 400（`IMPORT_TOO_MANY_ROWS`）。

上限之所以存在：每行都要走完整写通道（各自事务 + 审计 + 效果链），代价与手工录一行同阶，
不是批量直写的吞吐。**不要**为了"导得快"给它开裸写旁路。

## 三、文件解析

`TabularFileReader` 只负责"读成格子"，不做任何业务判定：

- `.csv` / `.txt` / `.tsv`：自解析，支持引号包裹、引号内换行与转义双引号；
  编码按 BOM 判定，无 BOM 时先按严格 UTF-8 试解，失败回落 GB18030（旧系统导出的常见编码）；
  分隔符按首个物理行在引号外的出现次数判定（`.tsv` 直接定为制表符）；
- `.xlsx` / `.xlsm`：交 MiniExcel 读取（样式化日期、公式缓存值、内联字符串由它处理）；
- `.xls`（旧版二进制格式）**不支持**，返回可照做的提示（另存为 .xlsx 或 .csv）。

表头即第一行；空表头回落 `列N`；参差行按最大列数补齐；全空行丢弃。

## 四、前端：安装向导（一次一步）

`EOS.Web/src/features/import/` 是一页**分步向导**：一次只显示一步，点「下一步」上一步的界面就消失。

| 步 | 界面 | 进入这一步做什么 |
|---|---|---|
| 1 选择模块 | **清单上方**的搜索框（含匹配计数）+ 可导入模块清单（`ErpTable`，首列**单选**列，点行或点 radio 选中）+ 已选模块摘要 + 前置资料就绪度警告 | — |
| 2 选择文档 | 拖放/点击选择区（整块可点，打开系统文件框）+ 下载空白模板链接 | 解析文件 |
| 3 字段映射 | 映射表（数据文件列 → 导入到字段）+ 导出/导入映射链接 | — |
| 4 数据预览 | 逐行状态网格（限高内滚动、表头吸顶）+ 计数与显示范围 | **进入即跑预演**（dryRun） |
| 5 开始导入 | 导入日志（控制台式，逐行输出到完成） | **进入即开始写库**，完成后给结果与审计说明 |

**版面四条硬规矩**：

- **页面内只允许出现「上一步 / 下一步」两个按钮**，放在**「第 N 步」标题的同一行、靠右对齐**
  （`align-items: center`，两者中线对齐）；辅助动作（下载模板、导出/导入映射、导出失败明细）
  一律走**文字链接**。进度条上的节点是唯一例外——可点回看已过的步骤。
  **不写步骤说明文字**：每一步的界面自己应当说明白它要什么（标题 + 内容 + 必要的行内提示），
  标题下面再压一段泛泛的说明只是把版面撑长（曾经 5 步各一段，已全部去掉，`StepMeta` 也随之
  只留 `label` / `Icon` / `title`）。因此这一页**不用 `ErpListCard` 的命令栏**——不给 `search`
  与 `actions`，它就不渲染，卡片顶部直接是进度条。
- **高度是固定窗口**：整页铺满可用高度，**只有步骤内容区内部滚动**（进度条与步骤头固定）。
  这一页不能是"内容自适应"：卡片高度随内容涨落（选模块后多出来的一行摘要、一次定义请求的加载态）
  会连带把页面撑开再缩回，看上去就是"选中时抖一下"；更糟的是页面级滚动条随之出现/消失，
  它会吃掉约 15px 宽度、整页横向重排。**顺带的口径**：加载态不许用整块 `LoadingState` 占位——
  它比它替换掉的那条摘要高出近 300px；同理不要给表格写 `max-height: 44vh`，vh 按视口算、
  与真正可用的高度无关，行少时还会拉出一片空白。
- **进度条占满整宽且节点等距**：每段 `flex:1`，段内 `1fr auto 1fr` 让左右连线各占一半；
  首尾两段连线隐藏但保留占位（否则首末节点会被推到边上）。节点用与语义相符的图标。
- **每个界面自成一块**（有边界与标题栏，块间就是 10px 区块间距）；映射表只放映射，
  示例值由数据网格承担——挤成一片会让人以为是一张表。

**几条必须守住的**：

- **结论随数据作废**：改映射或换文件即清空预演结论与导入结果（`importWorkbench.workSignature`
  决定第 4 步要不要重跑），不能拿过期判定去写库。
- **第 4 步的按钮不叫「下一步」**：它推进的是**写库**，文案就是四个字「开始导入」，**任何情况下
  都不回落成「下一步」**——一屏写库操作被读成"翻到下一页"，就是这么漏的。
  **文案里不带行数**：`开始导入 2 行` 会被读成"只导 2 行"（实际是这一批里通过的全导），
  而"这一批多少行、能导多少行"由这一屏的计数条独立承担（`共 N 行：可导入 M ｜ 失败 K`）
  ——两处都写只会互相干扰，按钮只管一件事：点下去就开始导。不能推进时按钮禁用，
  原因由 `title` 给出（正在校验… / 还没有校验结论 / 预演里没有可导入的行）。
  因为文案自带确认语义，不再另设确认弹窗——确认责任落在第 4 步的数据预览上
  （点它之前那一屏的结论必须不是过期判定，见上一条）。
- **表格收缩到可用高度后再内部滚动** + 表头吸顶：预览几千行时页面本身不该被撑长，行少时也不留空白。
- **第 1 步首列是单选列**（`radioSelectColumn`，与统一选择器单选模式同款）：目标模块只能选一个，
  给复选框是错的语义；行选中态由页面自己维护（`activeRowId`），不借用表格的多选行状态。
- **模块搜索是本地过滤**（候选约 260 条已全量在前端）：不发请求、输入即出结果、Ctrl+K 聚焦；
  关键词放在**页面级** state，因此从第 2 步退回第 1 步时关键词与筛出的结果都还在
  （放步骤组件里会随步骤卸载而丢）。搜索框只出现在第 1 步，且**贴着它要过滤的清单上方**
  （`ErpSearchBox` 自带 `max-width: 360px`，与表格左边界对齐），右侧同一行给「匹配 N / 共 M」
  ——别挂到卡片顶部的命令栏（那里离内容远，按钮还会被读成"上一步/下一步"那套的东西）。
- **导入日志**是第 5 步的全部内容：目标模块 / 来源文件 / 字段映射 / 逐行结果 / 汇总 / 审计；
  逐行列出的上限 1000 行，超出时明确写出还剩多少行（不静默截断）。
- **模块不做成选择器**：候选直接列在这一步里（点行即选）。这是对「统一选择器」约定的一处
  **有意例外**——它不是"从既有业务数据里选一条记录作为输入"，而是这一页自己的第一步内容。
  对应地，曾为它注册的 `import.targets` 选择器数据源**已删除，别再加回来**。
- **映射是资产**：按（用户 + 模块）记住，存的是**列名**而不是列下标——补导的文件由 Excel 另存后
  列序常变而列名不变。匹配顺序 = 记住的映射 → 字段标签 → 字段代号；记住的"不导入"会被尊重。
- **前置资料就绪度**：必填字段引用的主表还是空表时，在第 1 步就警告。判据取 `FIELD_DATASOURCE`
  （字段 → 来源表）而不是外键——本库刻意不用外键表达引用（全库仅 16 个），引用记在字段数据来源里。
- **失败明细导出带原列**：原文件全部列 + 行号 + 失败原因 + 错误码 + 字段级说明，改完直接原样再传。
- 路由 `/import` 由模块 `230902` 的读权限守卫；列表一律用 `ErpTable`。

**本期不做**（各自有明确的前置条件，别顺手加）：

- **草稿持久化**（刷新/换页后文件与结论还在）：要落 localStorage 或服务端暂存，大文件有撑爆配额
  的风险，得先定"多大就不缓存"的口径；
- **模板带引用下拉**（币别/员工等列在 Excel 里就是可选项）：要换一个能写数据验证的 Excel 写出库；
- **一份文件同时导主表 + 子表**（客户 + 联系人）：第 3、4 步要从"一张表"变成"主从两张"；
- **存在则更新（upsert）**：前置定义是"Excel 里的空单元格是清空还是不动"，未定之前不做。

## 五、导出

导出是工作台的能力（见 [40-统一工作台](./40-统一工作台.md)）：

| 端点 | 说明 |
|---|---|
| `POST /api/v1/document-workbench/{moduleId}/export` | 按当前查询条件导出全部命中行 |
| `POST .../export-selected` | 导出所选行，**1~500 行**，主键数量须与定义一致 |

两条约束：

- **导出字段按模块定义的可见列解析**——被"禁看"的字段**不会出现在导出文件里**；
- 行数超限或主键数量不符时返回 `INVALID_EXPORT_KEYS`（400），不静默截断。

导出是**读路径**：审计用 best-effort 写入（动作 `EXPORT`，资源类型 `EXPORT`），
审计写失败不影响导出结果。

## 六、排障

| 现象 | 原因 |
|---|---|
| 打不开导入页 | 模块 230902 的读权限不足（前端守卫），或缺少该模块的**设置权**（接口 403） |
| 目标模块清单里没有它 | `TABLES` 登记无关紧要：该模块不在统一表单写名单，或不是统一工作台模块（无主表） |
| 选得到模块但定义 403 | 你对这个模块没有 `ADDNEW` 动作位；文案会点名缺哪个动作位 |
| 某列选不到字段 | 该字段被"禁新增"（`DENY_NEW_FIELD_MASTER`）、是虚拟列、服务端填充列或自增列 |
| 预演报字段错误 | 数据不符合该模块的校验；逐行明细里给了字段名与错误码 |
| 预演通过、执行报错 | 预演与该行执行之间数据变了（并发写），或唯一约束在同行批次内被另一行占用 |
| 执行结果里部分行失败 | 预期行为：逐行独立提交，失败行不进库；按失败明细改好后重导 |
| 重复导同一批 | 主键冲突被拒（`DUPLICATE_RECORD_KEY`），不会写重 |
| 导入成功但界面看不到 | 该数据的行级范围把当前用户排除了（`DATA_FILTER`） |
| 导出文件少列 | 该列不可见（字段级权限）或不在定义里 |

## 七、注意事项

- **先预演再执行**，不要拿生产库试导入；
- **不要为导入开"跳过校验"的口子**——那是绕过整个写入通道；
- **导出受字段级权限约束**，这是有意的：能看才能导；
- 大结果集导出会撑内存，导出前先用条件收窄。

## 收口（迁移 334/335）：导入不再回填行归属列

导入原先由服务端为每行写 `CI` / `OWNER` / `OWNER_G`（行公司、建单账号、建单账号主组），
这三列已随迁移 334 全库下线，导入侧不再写入；"谁导进来的"仍由 `CREATE_PERSON` 留档。
导出侧不受影响（列清单来自 `FIELDS`）。
