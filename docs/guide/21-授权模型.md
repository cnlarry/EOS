# 21 授权模型

授权分三层，改动功能时先想清楚落在哪一层：

| 层 | 决定 | 粒度和来源 |
|---|---|---|
| 模块级 | 能不能进这个模块、能不能做某个动作 | 模块 ID + 动作位，来自个人/组权限 |
| 字段级 | 某个字段能不能看 / 新增时填 / 修改时改 | 分号分隔的字段名清单 |
| 行级 | 能看到哪些**行** | 数据范围过滤表达式 |

服务端实现：

| 文件 | 职责 |
|---|---|
| `EOS.API/Security/IPermissionService.cs` | **唯一模块权限判断入口** |
| `EOS.API/Security/PermissionService.cs` | 实现（含缓存） |
| `EOS.API/Security/ModulePermission.cs` | 权限结果包装与命名动作判定 |
| `EOS.API/Security/PermissionAction.cs` | 动作枚举 |
| `EOS.API/Data/ModuleRightsRepository.cs` | 权限读取与**聚合规则** |
| `EOS.API/Models/ModuleRightsModels.cs` | `ModuleRights` / `ReportRights` 定义 |

控制器与仓储**不再直接调 `ModuleRightsRepository` 做权限决策**，一律经 `IPermissionService`。

## 一、数据来源

| 表 | 内容 |
|---|---|
| `SYSDD` | 个人模块权限（按 `USER_ID` + `M_IDX`） |
| `SYSDH` | 组模块权限（按 `G_IDX` + `M_IDX`） |
| `SYSDG` | 用户组 |
| `SYSDG_USER` | 用户与组的归属关系 |

`SYSDD_REPORT` 只承载报表中心的**用户状态**（收藏/排序/最近使用），**不是权限表**。

## 二、聚合规则（最容易写错的地方）

`ModuleRightsRepository.GetAsync` 的流程：

```
查个人权限 SYSDD（USER_ID + M_IDX）
├─ 有记录 → 【完全采用个人权限】，直接返回，不再看组
└─ 无记录 → 查该用户所属组的权限 SYSDH
            ├─ 有记录 → 按组间规则聚合
            └─ 无记录 → 全部拒绝（fail-closed）
```

### 个人覆盖组

**某模块只要有个人权限记录，就完全采用个人权限，不与组权限合并。**

推论：给某人在某模块配了个人权限后，**再调整他的组权限对该模块毫无影响**。
排查"为什么改了组权限他不生效"时，先看有没有个人权限记录。

### 组间聚合

| 项 | 规则 |
|---|---|
| 布尔授权位（新增/修改/删除/批核/解批/结案/未结案/附件各动作/成本/机密/Setup/模块配置） | **取 OR**（任一组给了就算有） |
| `EXEC_TAG` | 取**字符串最大值**（按序数比较，从 `A` 起，越靠后权限越高） |
| 禁止字段（禁看/禁新增/禁改，主表与明细各一组） | 取**交集**——即"所有组都禁止，才真的禁止" |
| `DATA_FILTER` | 各组非空表达式**用 `AND` 连接**（每个加括号） |

禁止字段取交集是最反直觉的一条：**组是叠加权限的，不是限制权限的**。
要给某人限字段，用个人权限或专门的限制组。

### `EXEC_TAG` 与"能否浏览"

浏览权限不是独立的布尔位，而是由 `EXEC_TAG` 推导：

```csharp
CanBrowse = !string.Equals(ExecuteTag, "A", StringComparison.OrdinalIgnoreCase)
```

即 **`EXEC_TAG = 'A'` 表示不能浏览**，大于 `A` 才能浏览。字段读不到值时按 `'A'` 处理，
所以**缺数据 = 没权限**，方向是安全的。

> **执行范围已退役（2026-10-07，迁移 334/335）**：`EXEC_TAG` 当年还有一层"按执行范围看数据"
> 的语义——`B` 仅本人、`C` 本人及下级、`D` 本人所属组、`E` 本人及下级所属组，靠单据主表上的
> `OWNER` / `OWNER_G` 两列过滤。这两列已全库下线，四档范围随之退役：
> **只有 `Z` / `A` / 空 表示"无附加范围"，`B`/`C`/`D`/`E` 与未知取值一律拒绝**
> （`WorkbenchScopeFilter`，fail-closed、不降级为全量查询）。要按条件限制行可见性，用
> `DATA_FILTER`。细见 ADR-013 §8。

## 三、`ModuleRights` 字段总表

| 字段 | 含义 |
|---|---|
| `CanBrowse` | 能否浏览（由 `EXEC_TAG` 推导） |
| `CanAddNew` / `CanEdit` / `CanDelete` | 新增 / 修改 / 删除 |
| `CanApprove` / `CanDeapprove` | 批核 / 解批 |
| `CanEndCase` / `CanUnEndCase` | 结案 / 取消结案 |
| `CanViewCost` | 能否看成本字段 |
| `CanViewSecrecy` | 能否看机密字段 |
| `CanSetup` | 字段/列设置权（模块 `2302`） |
| `CanModuleConfig` | 模块配置权（行为动作/校验规则/自定义按钮），**默认关闭** |
| `CanFileView` / `CanFileUpda` / `CanFileEdit` / `CanFileDele` | 附件四项 |
| `DeniedMasterFields` / `DeniedDetailFields` | **禁看**字段（主表 / 明细） |
| `DenyNewMasterFields` / `DenyNewDetailFields` | **禁新增**字段 |
| `DenyModiMasterFields` / `DenyModiDetailFields` | **禁改**字段 |
| `DataFilter` | 行级过滤表达式 |
| `ExecuteTag` | 执行许可等级 |

`ModulePermission` 提供命名动作判定：`permission.Can(PermissionAction.Edit)`，
比散落的 `permission.Rights.CanEdit` 更好读，也方便将来加动作。

**`CanModuleConfig` 是 fail-closed 的**：默认关闭，需要显式授权。

## 四、字段级权限怎么用

三组禁止清单的值是**分号分隔的字段名**（`;`），比较时**大小写不敏感**：

```
DENY_VIEW_FIELD_MASTER  →  DeniedMasterFields     禁看
DENY_NEW_FIELD_MASTER   →  DenyNewMasterFields    禁新增
DENY_MODI_FIELD_MASTER  →  DenyModiMasterFields   禁改
```

语义：

- **禁看**：该字段不下发给前端，列表与表单都不出现；
- **禁新增**：新增单据时不可填（编辑时可）；
- **禁改**：编辑时不可改（新增时可）。

字段级权限在组装**表单定义与列表定义**时生效——服务端从字段清单里剔除，
而不是下发后再由前端隐藏（后者等于没做）。

## 五、行级：数据范围

`DATA_FILTER` 是行级过滤表达式。几条要点：

1. **它是配置数据，属于受控解析范围**——不能未经解析直接拼进 SQL，
   见 [45-受限表达式与虚拟字段](./45-受限表达式与虚拟字段.md)；
2. 多个组时，各组的过滤器**用 `AND` 串起来**——即"必须同时满足所有组的范围"，
   这会让可见范围**收窄**（与布尔位取 OR 的方向相反，注意别搞反）；
3. 服务端在查询组装时把它与前端提交的条件合并，前端**无从绕过**；
4. **表达式只允许引用主表自身的列**——这是安全边界，不是实现细节：谓词被拼进一句单表查询，
   允许引用旁表就等于要自动 JOIN。要按旁表的列过滤只有两条路：主表恰好有该列（直接写），
   或用**视图**把该列暴露成主表列（`MODULES.MASTER_TABLE` 指向视图）。
   **虚拟派生列不可用**（过滤白名单只收真实列，`FIELDS` 里有、`sys.columns` 里没有的列都不行）。
   写法越界时一律 **fail-closed 整页拒绝**（`403`），不会降级成"看全量"；
   解析口径见 `EOS.API/Data/DataFilterParser.cs` 与 `WorkbenchScopeFilter.cs`。

## 六、报表权

**唯一真源是归属模块的 `REPORT_TAG`**（个人 `SYSDD` 优先，否则组 `SYSDH` 取 OR）。

```
能进这个模块 → 就能看、能打、能导出它名下的报表
```

- **没有报表级 override**：任何"逐报表再配一次权限"的做法都是在造第二处真源；
- 通过时的 `ReportRights` 是三者全开（`CanPreview` / `CanPrint` / `CanExport`），
  其 `DataFilter` 为空——**行级范围统一由模块的 `DataFilter` 决定**，
  报表链路对它做 `AND` 合并。所以"报表权限里再过滤一次"也是多余的。

## 七、缓存

`EOS.API/Security/PermissionCache.cs`：

- 键为 `用户 + 模块`，TTL 默认 **60 秒**（配置项 `Security:PermissionCache:TtlSeconds`）；
- **权限写路径（用户/组权限保存）后全量失效**（`InvalidateAll`）——写操作低频，全清最稳。

推论：改完权限立即生效，不需要等 TTL；但如果你绕过接口直接改库，最多要等 60 秒。

## 八、服务端怎么用

```csharp
var permission = await permissions.GetAsync(userId, moduleId, token);   // 不校验动作
if (!permission.CanEdit) return Forbid();                               // 403

// 或者：不满足即抛 PermissionDeniedException（403）
var required = await permissions.RequireAsync(userId, moduleId, PermissionAction.Approve, token);
```

**两种取法的区别很重要**：

| 场景 | 用法 | 返回 |
|---|---|---|
| 需要区分"无权限"与"对象不存在" | `GetAsync` 再自行判断 | 无权限 → 403；不存在 → 404 |
| 动作前置条件，不需要区分 | `RequireAsync` | 不满足即 403 |

**不要用 404 掩盖 403**（或反之）：403 表示"你没权限"，404 表示"这东西不存在"，
前端据此给出不同提示。

### 身份上下文（`EOS.API/Security/CurrentUserContext.cs`）

权限主体恒为**使用者本人**（不是服务端、也不是任何代理）。登录时随会话签发的身份声明由
`CurrentUserContext` 读取，除 `UserId` / `EmployeeName` 外还有：

| 属性 | 声明 | 用途示例 |
|---|---|---|
| `EmployeeId` | `employee_id` | 工号展示、单据经办人比对 |
| `DepartmentId` / `DepartmentName` | `department_id` / `department_name` | 部门范围判断、界面与提示文案 |
| `CompanyId` | `company_id` | 归属公司回填 |
| `DefaultGroupId` | `default_group_id` | 默认用户组 |

声明缺失时返回空串而**不抛错**（缺一个声明不该让整个端点 500）。注意这些声明是**身份事实，
不是授权**：能不能办事只由 `IPermissionService` 判定，`CurrentUserContext` 不参与授权决策。

## 九、前端权限键

前端另有一套字符串权限键，格式：

```
fallback-module.{moduleId}.read
```

由 `EOS.Web/src/features/auth/modulePermissions.ts` 的 `moduleReadPermission()` 生成，
用于**路由守卫与按钮渲染**（`RouteGuards.tsx`、`hasPermission()`）。
权限清单随 `/api/v1/app/bootstrap` 一起下发。

**这套键只影响体验**：

- 服务端不认这个字符串，它认的是模块 ID + 动作；
- 前端隐藏了按钮，服务端仍会鉴权——绕过界面直接调接口，该 403 还是 403。

所以：**加新页面时，前端要加路由守卫，服务端更要加权限门，两者缺一不可。**

## 十、排障速查

| 现象 | 大概率原因 |
|---|---|
| 改了组权限，某人不生效 | 该模块有**个人权限记录**，个人覆盖组 |
| 某人能看到别的组才能看的数据 | `DATA_FILTER` 是 `AND` 合并，检查是否有多组叠加 |
| 用户看不到某模块 | 无个人也无组记录（fail-closed）；或 `EXEC_TAG='A'` |
| 刚改完权限没生效 | 权限缓存最多 60 秒；改的是库不是接口？ |
| 字段该隐藏却还在 | 检查是字段级权限配错，还是前端自行判断没走服务端定义 |
| 报表看不见 | 看**归属模块**的 `REPORT_TAG`；系统里没有报表级 override 可查 |
