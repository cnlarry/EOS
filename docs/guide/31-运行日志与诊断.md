# 31 运行日志与诊断

## 一、三套手段的分工

排障前先判断该用哪个，能省很多时间：

| 手段 | 回答的问题 | 保留 | 入口 |
|---|---|---|---|
| **审计** | 谁改了什么、结果如何 | 长期 | `AUDIT_EVENT`（见 [30-审计日志](./30-审计日志.md)） |
| **运行日志** | 这次请求为什么慢/为什么 500 | **只留 Warning+** | 界面「日志管理」页，或磁盘 `logs/api-json.log` |
| **指标与健康检查** | 服务是否正常、整体水位 | 实时 | `/health/*`、`/metrics` |

**界面入口（2026-09-29 新增）**：`/admin/logs`「日志管理」页（模块 `2313`，系统管理 23 → 数据表维护 2311）——
看系统诊断信息（版本/构建时间/是否跑着旧程序/健康检查/迁移台账）、按级别与关键字读运行日志、
以及**一键下载诊断包**。配套接口 `GET /api/v1/logs`（读）、`/files`、`/diagnostics`、`/bundle`（打包）。
权限：**页面、菜单与接口同锚模块 `2313`**——读日志 = `CanBrowse`（拥有该权限的系统用户即可）；
**打包下载另需** `CanSetup`。

**诊断包内容**（白名单，不含业务数据）：日志文件 + `diagnostics.json` + `manifest.txt`；
**不含**配置文件原文、审计明细原文、附件与任何业务数据。日志在写入时已脱敏（见 §五），
所以打包外发前不需要再处理一次。

## 二、日志落盘与级别策略

实现：`EOS.API/Middleware/RequestLoggingMiddleware.cs`。

一条请求结束后按下面的顺序判定级别（**先命中先算**）：

| 条件 | 级别 | 是否落盘 |
|---|---|---|
| 状态码 ≥ 500 **或** 有 `error.code` | `Error` | 是 |
| 耗时 ≥ **1000ms** 的成功请求 | `Warning` | 是 |
| `/api` 下的其他请求 | `Information` | **否**（仅控制台） |
| 非 `/api` 请求 | `Debug` | 否 |

这就是"**正常请求在文件里查不到是预期行为**"的原因——文件日志专门留给有诊断价值的请求。

前端错误会记成 `client_error` 事件；慢请求阈值是 `SlowRequestThresholdMs = 1000`。

**日志放哪、留多久**（`appsettings.json` 的 `Logging:File`，2026-09-29 起显式可配）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `Path` | `logs/api-json.log` | **相对程序自身目录**（不是"启动时的工作目录"）；可写绝对路径或含 `${VAR}` 环境变量引用（引用机制见 [`02-本地环境与运行.md`](02-本地环境与运行.md) 第八节） |
| `MaxBytes` | 52428800（50MB） | 单文件上限，达到即轮转为 `.1`/`.2`/`.3` |
| `MaxFiles` | 3 | 轮转份数 |
| `RetentionDays` | 14 | **时间门**：超期副本在启动与每次轮转后被删除，即使没到大小上限 |

目录不可创建或不可写时**不会让服务起不来**：进程降级为"只向控制台输出"并记一条 Error，
`/health/ready` 的 `log_file` 项报 `Degraded`（刻意不用 `Unhealthy`——日志写不了不该把服务摘出负载）。

日志文件：`EOS.API/logs/api-json.log`，JSON 行格式。

## 三、一条请求日志里有什么

```
HTTP 请求结束 http_request {Method} {Path} -> {Status} 耗时 {ElapsedMs}ms db={DbElapsedMs}ms
  user={User} client={ClientId} module={ModuleId} action={Action}
  definitionVersion={DefinitionVersion} correlation={CorrelationId}
  trace={TraceId} span={SpanId} error={ErrorCode}
```

各字段的来源：

| 字段 | 来源 | 用途 |
|---|---|---|
| `Event` | 固定 `http_request` | 便于按事件名过滤 |
| `Method` / `Path` | 请求 | |
| `Status` | 响应状态码 | |
| `ElapsedMs` | 端到端耗时 | |
| `DbElapsedMs` | `DbTimingCollector` 累计的 DB 耗时 | **区分"应用慢"还是"库慢"** |
| `User` | 当前用户；未登录为 `anonymous` | |
| `ClientId` | `X-Client-Id` 头归一后的值 | 区分 Web / Agent / 集成 |
| `ModuleId` | 路由里的 `moduleId` | 按模块定位 |
| `Action` | `controller.action`（小写） | 精确到方法 |
| `DefinitionVersion` | 当时使用的定义版本 | **行为不一致时的关键证据** |
| `CorrelationId` | 见下节 | 跨前后端串联 |
| `TraceId` / `SpanId` | W3C 追踪标识 | |
| `ErrorCode` | 业务错误码 | 对照 [04-API契约与前后端协作](./04-API契约与前后端协作.md) |

## 四、关联键体系

实现：`EOS.API/Telemetry/RequestContext.cs`。

| 键 | 传入方式 | 缺省行为 |
|---|---|---|
| `correlationId` | 请求头 `X-Correlation-Id`（≤128 字符） | 回退 `HttpContext.TraceIdentifier` |
| `clientId` | 请求头 `X-Client-Id` | 归一为 `ClientIds.Unknown` |
| `traceId` / `spanId` | W3C `Activity` | 回退 `TraceIdentifier` 的 `trace:span` |
| `moduleId` | 路由参数 | |
| `action` | 控制器与动作名 | |

两个要点：

- **`correlationId` 会回写到响应头 `X-Correlation-Id`**——前端或脚本可以从响应里拿到它，
  报障时直接给出这个值即可定位整条链路；
- **调用方应主动传 `X-Correlation-Id`**：前端一次用户操作可能触发多个请求，
  用同一个值串起来才看得出"这一次点击发生了什么"。

> **✅ 口径已统一（2026-09-29）**：异常出口（`GlobalExceptionHandler`）、业务拒绝映射
> （`ApiExceptionFilter`）与助手会话落库的关联键，**全部改读 `RequestContext.GetCorrelationId`**，
> 与本节其余出口同值——响应体里的 `correlationId`、响应头 `X-Correlation-Id`、文件日志的
> `correlation=`、审计的 `CORRELATION_ID` 现在是同一个键，按它一次检索即可命中。
> 细节见 [`docs/decisions/ADR-025`](../decisions/ADR-025-关联键单一真源与日志脱敏接入.md)。
>
> 前端关联键：默认每次请求生成一个；**同一次用户操作触发多个请求时，调用方应显式传入同一个值**
> （`apiClient.post(..., { headers: { 'X-Correlation-Id': id } })`，传输层以调用方传入的为准）。
> 界面上"复制报障编号"的入口见 §八。

## 五、脱敏

实现：`EOS.API/Logging/LogRedactor.cs`。输出前对所有字符串字段与消息应用，模式包括：

| 模式 | 覆盖 |
|---|---|
| `password` / `pwd` / `passwd` / `secret` / `api_key` / `token` 赋值 | 凭据键值 |
| `Authorization: Bearer …` | 令牌 |
| `Cookie: …` | Cookie 内容 |
| `eyJ…` 三段式 | JWT |
| 连接串要素：`Server=`、`Password=`、`User ID=`、`Pwd=` | 连接串 |

命中后统一替换为 `***`。

> **✅ 已接入（2026-09-29）**：`JsonFileLoggerProvider` 在**序列化前**对「消息 + 字段的字符串值 +
> 异常文本」统一过 `LogRedactor`，所以落盘文件里不会有凭据原文。两点边界要知道：
> ① 凭据值的字符集是**白名单**（字母数字与常见符号），不是"除空白外全吃"——
> 这是刻意的：旧写法会把凭据后面的整段中文说明一起替换成 `***`，把排障信息误伤掉；
> ② **脱敏不是许可**：日志里本来就不该写整行业务数据、附件正文与模型全文，
> 命中不到模式的敏感业务值不会被掩码。见
> [`docs/decisions/ADR-025`](../decisions/ADR-025-关联键单一真源与日志脱敏接入.md)。

**日志与审计里不出现附件正文、不出现模型全文**——不是靠脱敏兜底，而是调用方本就不记录。

## 六、指标与健康检查

### 健康检查

| 端点 | 检查项 | 用途 |
|---|---|---|
| `/health/live` | 无 | **存活**：进程还在就 OK |
| `/health/ready` | `erp_database`、`erp_migrations`、`attachment_storage`、`configuration` | **就绪**：能不能正常干活 |
| `/health/startup` | `erp_migrations` | 启动期迁移是否成功 |
| `/health/version` | | 程序集版本 |
| `/metrics` | HTTP 计数与耗时分布 | 见 `EOS.API/Telemetry/ApiMetrics.cs` |

四个检查各自对应一类故障：

- `erp_database` 数据库不可达；
- `erp_migrations` 迁移没跑成功（**注意：`/health/ready` 为 Healthy 不等于迁移已落库**，
  判定以 `sys.columns` / `ERP_SCHEMA_JOURNAL` 为准）；
- `attachment_storage` 附件目录不可写；
- `log_file` 日志目录不可写（**Degraded 而非 Unhealthy**：日志写不了不影响业务请求，
  但会让事故无据可查，所以单列一项而不是把整个服务判红）；
- `configuration` 关键配置缺失或非法。

### 指标

`ApiMetrics` 记录 HTTP 请求计数与耗时（`CountHttpRequest` / `ObserveHttpDuration`），
经 `/metrics` 导出。`DbTimingCollector` 按请求累计 DB 耗时，落到日志的 `db=` 字段。

## 七、异常出口

实现：`EOS.API/Middleware/GlobalExceptionHandler.cs`（`IExceptionHandler`）。

未处理异常时：

- 记一条 `Error` 级日志，含**异常类型、路径、用户、client、module、definitionVersion、correlation**
  （关联键取 `RequestContext`，与响应体/审计同值）；
- 返回统一的 500 `ProblemDetails`（错误码 `INTERNAL_ERROR`），带上 `traceId` / `correlationId` 等；
- 若请求能定位到模块，附带 `definitionVersion`；
- **仅开发环境**在响应里附完整异常信息（`detail`），生产环境不泄漏堆栈。

响应已经开始写出时不再接管（避免半截响应）。

前端侧（`EOS.Web`）：

- 根级 **React 错误边界**（`app/AppErrorBoundary.tsx`）接管渲染期崩溃：给错误页 + 「重试 / 返回首页 /
  复制诊断信息」，并**强制上报**到 `client-errors`（只显示不上报等于把崩溃静默掉）；
- 变更类请求失败时，全局弹一条带「**复制报障编号**」的提示（`app/providers.tsx` 的 MutationCache）；
- 页内错误仍用 `ErrorState` / `alert`，需要给用户编号时加 `ErrorDiagnostics` 组件。

## 八、排障流程

### 场景 1：用户说"这个操作报错了"

1. **先要报障编号**——用户现在**自己就能给**：
   - 失败提示条上点「复制报障编号」；
   - 或进「日志管理」页（`/admin/logs`）点「复制诊断信息」（含版本 + 页面 + 时间 + 编号）；
   - 也可让用户复现一次，从浏览器网络面板取响应头 `X-Correlation-Id` 或响应体的 `correlationId`；
2. **查审计**：`SELECT * FROM AUDIT_EVENT WHERE CORRELATION_ID = '<值>'`，
   拿到 `ACTION`、`RESULT`、`ERROR_CODE`、`RESOURCE_KEY`；
3. **查运行日志**：在「日志管理」页按同一个编号过滤，或在 `logs/api-json.log` 里 grep，
   看异常堆栈与 `db=` 耗时；
4. **对照错误码**：`ERROR_CODE` 去 [04-API契约与前后端协作](./04-API契约与前后端协作.md) 查语义。

> 让用户**直接发一个诊断包**更省事：`/admin/logs` →「下载诊断包」，包里含日志 + 版本/构建/健康检查
> 摘要 + 打包清单；不含配置文件原文与业务数据。

### 场景 2：用户说"这个页面很慢"

1. 日志里按 `Path` 或 `module` 过滤，找 `Warning` 级的慢请求（≥1s）；
2. 看 `db=xxxms` 与总耗时的比例：
   - `db` 接近总耗时 → 慢在库（缺索引、查询条件太宽、子表关联缺失）；
   - `db` 很小 → 慢在应用或前端（序列化、大结果集、前端渲染）；
3. 结合 `module` 与 `action` 定位到具体接口。

### 场景 3：用户说"数据和昨天不一样"

1. 查 `AUDIT_EVENT` 按 `M_IDX` + `RESOURCE_KEY` 看该记录的全部动作；
2. **特别关注 `ACTION LIKE 'EFFECT:%'` 的行**——效果链会改数据，且带明确前缀；
3. 比较两次操作的 `DEFINITION_VERSION`：如果不同，说明中间发布过定义，
   行为差异可能来自配置变更而非代码。

### 场景 4：服务起不来

1. 看启动日志（迁移失败会直接抛异常，不进入正常服务状态）；
2. 查 `/health/startup` 与 `/health/ready` 的报告体（`WriteHealthReportAsync` 输出逐项结果）；
3. 迁移相关问题对照 [05-数据库迁移与建库](./05-数据库迁移与建库.md) 的诊断表。

## 九、注意事项

- **文件日志只留 Warning+**：别因为"文件里没有"就判断"没发生过"，先看控制台或审计；
- **不要为排障临时调低全局日志级别**：需要更多细节时应加结构化字段（`clientId`、`moduleId`、
  业务键）而不是把 Debug 全打开——后者会让文件日志失去"只留有用信息"的价值；
- **凭据类内容不要手写进日志**：脱敏是兜底，不是许可；
- **"日志里没有"要先分清是哪一类请求**：只有 5xx、带 `error.code` 的 4xx、慢请求（≥1s）与
  `client_error` 会落盘。普通 401/403（未带错误码）**按设计不落盘**，排查这类问题要靠访问日志之外
  的手段（界面提示、审计、网关日志）——这是实测确认过的预期行为，不是漏写。

## 十、诊断包（一键取现场）

实现：`EOS.API/Features/Diagnostics/`（`LogFileReader` + `LogsController`），界面入口
`/admin/logs`「日志管理」页。

| 端点 | 权限 | 用途 |
|---|---|---|
| `GET /api/v1/logs/files` | 模块 `2313` `CanBrowse` | 日志文件清单、总占用、可用级别 |
| `GET /api/v1/logs` | 模块 `2313` `CanBrowse` | 按 `level`/`keyword`/`correlationId`/`event`/`from` 过滤读数（`take` 上限 2000） |
| `GET /api/v1/logs/diagnostics` | 模块 `2313` `CanBrowse` | 版本/构建时间/进程启动/是否跑着旧程序/健康检查/迁移台账摘要/配置项清单 |
| `GET /api/v1/logs/bundle` | 模块 `2313` **`CanSetup`** | 流式 zip 诊断包 |

**包里有什么**：日志文件（写入时已脱敏）+ `diagnostics.json` + `manifest.txt`（生成时间、
脱敏声明、范围声明、文件清单与诊断摘要）。**包里没有什么**：配置文件原文、审计明细原文
（`AUDIT_FIELD_CHANGE` 存的是字段改动的原始值）、附件、任何业务数据。

三条设计约束，改动时别破坏：

- **配置摘要只报键名与是否已设置，不报值**，且用**白名单**枚举应用自身的配置节——
  早先按"排除敏感节"遍历 `IConfiguration`，而它还包含环境变量提供程序，实测把整台机器的
  环境变量名（`DEEPSEEK_API_KEY`、`MSSQL_ERP_CONN` 等）列进了包；数组型配置折叠成一项报项数。
- **打包动作落 `AUDIT_EVENT`**（`ACTION=DIAGNOSTICS_BUNDLE`，best-effort）：文件日志会被保留策略
  清掉，而"谁在何时取走了诊断包"属运维审计面。
- **体积上限 100MB**，超限返回 **413** 并给可读文案，不返回坏包；体检单里 `logs.path` 与
  `migrations.appliedCount/embeddedCount` 用来一眼判断"日志在哪、库是不是落后于磁盘脚本"。
