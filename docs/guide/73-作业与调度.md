# 73 作业与调度

作业是**批量/长耗时**的服务端任务。它不由用户逐条触发，但同样走受控通道与审计。

实现：`EOS.API/Controllers/JobsController.cs`、`EOS.API/Data/HumanResourceJobsService.cs`、
`EOS.API/Data/MrpRecalcService.cs`、`EOS.API/Services/ReportInboxScheduler.cs`。

## 一、作业端点

路由前缀 `api/v1/jobs`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/mrp-recalc` | MRP 重算 |
| `POST` | `/card-batch` | 卡片批处理 |
| `POST` | `/attendance-generate` | 考勤生成 |
| `POST` | `/attendance-calc` | 考勤计算 |
| `POST` | `/attendance-adjust-wage` | 考勤调整工资 |

特点：

- **作业是同步长请求**（不是后台队列），因此调用方要给它足够的超时；
- 考勤三件套有先后关系：**生成 → 计算 → 调整工资**，顺序错了结果无意义；
- 作业的权限门与对应业务模块一致，不是"有 jobs 端点就能跑"。

> 历史教训值得记：曾出现"服务下沉重构漏注册 `HumanResourceJobsService`，
> `/api/v1/jobs/*` 全量 500"——**编译 0 错、单测全绿都没发现**。
> 改了依赖注册后，记得实际调一次端点。

## 二、报表定时生成与订阅收件箱

`ReportInboxScheduler`（`EOS.API/Services/`）负责报表的定时生成与投递。

相关表：

| 表 | 行数（实测） | 说明 |
|---|---|---|
| `REPORT_INBOX` | **0** | 报表收件箱 |
| `REPORT_SUBSCRIPTION` | **0** | 报表订阅 |

**这两个表都是 0 行**——收件箱与订阅子系统已建好，但**当前没有实际使用**。
读到相关代码时不要当成主路径；如果需要该能力，先确认设计意图再启用。

端点挂在报表中心：`api/v1/report-center`（`ReportInboxController`）。
详见 [50-统一报表](./50-统一报表.md)。

## 三、审计与留痕

- 作业执行会写审计（动作按业务语义，如库存类作业的 `RESERVE` / `FREEZE` 等）；
- 审计里还能看到**作业类的痕迹**，如 `month-close-snapshot`、以及各类 `EFFECT:` 记录
  （效果链由作业触发时同样留痕）；
- 排查"谁在什么时候跑了批量"就查审计的 `ACTOR_*` 与 `ACTION`。

## 四、排障

| 现象 | 原因 |
|---|---|
| 作业端点全量 500 | **依赖注册缺失**——检查 `Program.cs` 里对应 Service 是否注册；这类问题编译与单测都发现不了 |
| 作业超时 | 作业是同步长请求，数据量大时需放宽调用方超时 |
| 考勤结果不对 | 检查是否按"生成 → 计算 → 调整工资"的顺序执行 |
| 报表收件箱一直为空 | 该功能当前无数据/未启用（见第二节） |
| 跑完看不到效果 | 查审计确认作业是否真的执行了；作业不等于"立刻可见"（可能需重新发布定义或刷新页面） |

## 五、注意事项

- **作业是写路径**：同样受权限、校验与审计约束，不是"管理员专用后门"；
- **不要在前端同步等待过久**：长作业要考虑超时与重复触发；
- **重复触发要防**：同一作业重复跑可能产生重复数据，调用前确认幂等性；
- **作业入口有权限门**：不要因为方便就把它挂到无鉴权的路径上。
