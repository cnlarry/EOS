# 02 本地环境与运行

目标：从空环境把 EOS 跑起来，看到完整的模块菜单与空的业务数据。

## 一、环境要求

| 项 | 要求 |
|---|---|
| 运行时 | .NET 10 SDK |
| 前端 | Node.js 20+ 与 npm |
| 数据库 | SQL Server 2025+（结构含原生 `vector` 列，兼容级别 170） |
| 命令行工具 | `sqlcmd`（随 SQL Server 客户端工具安装） |

数据库需具备建库权限（dbcreator / sysadmin），或由 DBA 代为执行建库脚本。

> **菜单图标**配在 `EOS.API/appsettings.json` 的 `NavigationIcons` 里，键是**一级模块号**、值是关键字
> （如 `"23": "settings"`、`"31": "robot"`）。关键字与图标的对应表在前端
> `EOS.Web/src/components/layout/navigationIcons.ts`；没登记的关键字会回落默认图标，不会报错。

## 二、初始化数据库

仓库**不附带业务数据库备份**。建库脚本在 `db/bootstrap/`，必须按编号顺序执行：

| 步骤 | 脚本 | 作用 |
|---|---|---|
| 1 | `00_create_database.sql` | 创建 `EOS.ERP` 数据库 |
| 2 | `10_schema.sql` | 表、函数、视图与运行时依赖的存储过程（纯结构，无数据） |
| 3 | `20_metadata.sql` | 元数据种子：模块菜单、字段登记、通用查询、报表与表单版式 |
| 4 | `30_admin.sql` | 初始管理员账号 |
| 5 | `40_journal_baseline.sql` | 登记已固化的迁移编号，使应用启动时不重复执行 |

```powershell
# 脚本为 UTF-8，sqlcmd 必须带 -f 65001（否则中文脚本在部分区域设置下解析失败）
sqlcmd -S . -E -i db/bootstrap/00_create_database.sql -f 65001
sqlcmd -S . -E -d "EOS.ERP" -i db/bootstrap/10_schema.sql -f 65001
sqlcmd -S . -E -d "EOS.ERP" -i db/bootstrap/20_metadata.sql -f 65001
sqlcmd -S . -E -d "EOS.ERP" -i db/bootstrap/30_admin.sql -f 65001
sqlcmd -S . -E -d "EOS.ERP" -i db/bootstrap/40_journal_baseline.sql -f 65001
```

以上以当前 Windows 账户连接本机默认实例（`-E`）。用 SQL 账号登录时换成 `-U <用户> -P <口令>`。

**建库后的口径**：

- 元数据（模块、字段、查询列、报表版式、表单布局、流程定义）随仓库走，
  新库会用与开发环境一致的界面元数据启动；
- 业务数据（单据、主档、员工等）全部为空，需在界面中自行建立；
- 除 `admin` 外不预置任何账号。

## 三、配置并启动后端

配置里只写**环境变量引用**：`appsettings.json` 中是 `${MSSQL_ERP_CONN}` 这类占位，真值放环境变量
（配置因此可入库，连接串与密钥不落文件）。设两个变量：

```powershell
# 业务库连接串（必填）
[Environment]::SetEnvironmentVariable('MSSQL_ERP_CONN',
  'Server=localhost;Database=EOS.ERP;Trusted_Connection=True;TrustServerCertificate=True', 'User')

# 工作助手的模型密钥（可选；不配则助手降级，其余功能不受影响）
[Environment]::SetEnvironmentVariable('EOS_ASSISTANT_API_KEY', '<你的密钥>', 'User')
```

设完**重开终端**再启动（环境变量在启动进程时继承）。

```powershell
dotnet run
```

- 服务监听 `http://localhost:5261`；
- 健康检查：`/health/live`（存活）、`/health/ready`（就绪）。

**首次启动会做什么**：应用经 DbUp 检查迁移台账 `dbo.ERP_SCHEMA_JOURNAL`，只执行台账中没有记录的
迁移脚本。由于 `40_journal_baseline.sql` 已预登记基线内的编号，首次启动通常只跑基线之后的新迁移，
属正常现象。

**日常开发不需要手工跑迁移**，也不需要手工改 `ERP_SCHEMA_JOURNAL`——新增脚本放到
`EOS.API/Data/Migrations/` 后，启动即自动应用。

## 四、启动前端

```powershell
cd EOS.Web
npm install
npm run dev
```

开发服务器读 `vite.config.ts`：

- 端口 **80**（如需改端口或与其他服务冲突，改 `server.port` 即可）；
- 把 `/api` 代理到 `http://localhost:5261`，所以前端**不需要**配置 API 基址；
- 只允许 `localhost` / `127.0.0.1` / `www.erp.com` 作为 Host 访问（`server.allowedHosts`；
  本地 hosts 把 `www.erp.com` 指向本机时即以该域名打开，见 `AGENTS.local.md`）；
- 构建时把仓库根 `version.json` 的产品版本注入产物（`__APP_VERSION__`，供「日志管理」页展示）；
  版本真源与发布流程见 [`docs/decisions/ADR-026`](../decisions/ADR-026-版本管理与发布流程.md)。

打开 `http://localhost/` 即可。

## 七、常见问题

| 现象 | 排查方向 |
|---|---|
| 登录提示用户不存在 | 确认已执行 `30_admin.sql`，且连接串指向正确的数据库 |
| 菜单不完整 / 字段缺失 | 确认已执行 `20_metadata.sql` |
| 启动时迁移报错 | 确认 bootstrap 五个脚本已按顺序执行完；`10_schema.sql` 与 `40_journal_baseline.sql` 必须来自同一版本 |
| 日志提示表名/列名不存在 | `10_schema.sql` 是结构快照；用旧快照建库后再升级代码，要么重新初始化，要么等新迁移补齐结构 |
| 前端起来但接口 404 | 确认后端在 `5261` 上运行（Vite 把 `/api` 代理到该端口） |
| 80 端口起不来 | 该端口可能被系统服务占用；改 `server.port` |
| 助手回复"尚未配置模型接入" | `Assistant:ApiKey` 为空——见第八节的配置来源 |

## 八、配置来源与凭据（`${VAR}` 环境变量引用）

项目只有**一份**配置文件 `appsettings.json`（入库），它承载两样东西：

- **非敏感默认值**：日志、导航图标、统一表单白名单、`Security:AllowedOrigins` 等；
- **敏感项的引用占位**：形如 `${MSSQL_ERP_CONN}` / `${EOS_ASSISTANT_API_KEY}`。

真值**只存在于环境变量**，配置文件里永远没有连接串与密钥——这就是"配置可入库、凭据不入库"的落法，
`AGENTS.md` 的"不提交凭据到代码库"因此不再依赖"记得把文件加进 `.gitignore`"这类人工纪律。

### 解析语义（启动时一次性完成）

`EOS.API/Configuration/EnvironmentReferenceResolver.cs` 在配置装载完成后扫描配置树，把值里的
`${VAR}` 替换为环境变量的值（同一个值内可写多个引用）。下游（强类型绑定、`SqlConnection`、
健康检查）看到的都是**替换后**的值，因此不需要各消费点自己解析。

- 变量**未定义** ⇒ 解析为**空串**，并在启动日志里 `Warning` 点名（写明"哪个键引用了哪个变量"）：
  语义上等于"未配置"，**不会**把 `${VAR}` 字面量当值使用（否则连接串/密钥会以字面量身份静默失败）；
- 空值随后由既有检查点接住：`ConnectionStrings:ErpDatabase` 为空 ⇒ `/health/ready` 报 **Unhealthy**；
  `Assistant:ApiKey` 为空 ⇒ 助手降级并提示"尚未配置模型接入"。

### 需要设的环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `MSSQL_ERP_CONN` | 是 | 业务库连接串。**本地脚本与真库测试也用它**（`scripts/dev/eos-sql.ps1` 优先取 User 级该变量），一处配置全仓可用 |
| `EOS_ASSISTANT_API_KEY` | 否 | 工作助手模型密钥；不配则助手降级（回复"尚未配置模型接入"），其余功能不受影响 |

```powershell
[Environment]::SetEnvironmentVariable('MSSQL_ERP_CONN', '<连接串>', 'User')
[Environment]::SetEnvironmentVariable('EOS_ASSISTANT_API_KEY', '<密钥>', 'User')
# 设完重开终端，再启动服务（环境变量在启动进程时继承）
```

IIS / Windows 服务下同样要把这两个变量给到承载进程（应用池环境、`web.config` 的
`<environmentVariables>`——那份通常入库，**不要**把值写进去，或用系统/服务账户级变量）。

### 环境变量做不到的事（决定了哪些配置必须留在文件里）

1. **数组与大块结构不适合**：`Security:AllowedOrigins`、`NavigationIcons`、
   `UnifiedFormEditor:EnabledModuleIds`（261 项，且 `scripts/auto-enable-batch.ps1` 的放量流水线要写它）
   都留在 `appsettings.json`；
2. **环境变量无法缩减 JSON 数组**（只能覆盖已有索引或追加新索引），所以"生产要比基础少几项来源"
   这类需求只能靠文件；
3. 环境变量对本机同账户的其它进程可读：比"明文写进入库文件"安全，但低于
   DPAPI / 凭据管理器 / 密钥库。

### 轮换与限权

- 轮换：改环境变量 → **重启服务**（环境变量在进程启动时读取）；
- 确需在磁盘上落一份配置时（例如多机分发），用 ACL 只给运行账户可读；
- 诊断包与日志**不会**带走密钥：`configDigest` 按白名单只报"某个配置节是否已设置"（不列值），
  日志经 `LogRedactor` 脱敏（见 [`31-运行日志与诊断.md`](31-运行日志与诊断.md)）。
