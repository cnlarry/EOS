# 75 部署与环境配置

本篇讲**把系统装到客户机器上并长期跑起来**：产物怎么组、配置从哪来、升级与备份怎么做、哪些边界
决定了"只能单实例"。本地开发环境（Vite、`dotnet run`、调试）看 [02](./02-本地环境与运行.md)；
迁移机制本身看 [05](./05-数据库迁移与建库.md)，健康检查与日志字段的细节看
[31](./31-运行日志与诊断.md)——本篇只写部署侧的取舍，不重复它们。

## 一、受支持的部署形态：单实例 + 同源 + HTTPS

| 维度 | 受支持的形态 | 为什么 |
|---|---|---|
| 进程数 | **一个** `EOS.API` 实例 | 会话、登录限流、权限缓存、报表订阅调度都在进程内（见第九节） |
| 前端托管 | `EOS.API` 同时提供 API 与前端静态文件（同一端口） | 同源 ⇒ 会话 Cookie 与写操作的 CSRF 校验天然成立，无需配跨域白名单 |
| 传输层 | **HTTPS**（`ASPNETCORE_ENVIRONMENT=Production` 时强制） | 生产环境认证 Cookie 带 `Secure`；纯 HTTP 下浏览器不保存它，表现为"登录成功但仍是未登录" |

**前端外壳对未登录请求放行是设计，不是漏洞。** 登录页是前端路由 `/login`，权限边界在 `/api`：
未登录访问任何页面路径都会拿到同一个 SPA 外壳，由前端路由守卫把用户送到登录页；
未登录访问 `/api` 一律 401。反过来（外壳要求授权）会让未登录用户打不开登录页本身——
登录跳转又落回受保护路径，形成 `ERR_TOO_MANY_REDIRECTS`。

> **用反向代理终止 TLS 时有一个必配项**：写操作（POST/PUT/PATCH/DELETE）由
> `SameOriginGuardMiddleware` 按 `Origin` 与请求 `Host` 比对同源。代理转发到后端若是 HTTP、
> 且转发时 `Host` 不带端口，后端会按 `:80` 推断端口，与 `https://…:443` 的 `Origin` 不等 ⇒
> **所有写操作 403**。处置是把对外访问地址加进 `Security:AllowedOrigins`（白名单命中即放行，
> 不参与端口推断），而不是放宽校验；同源直连（API 自己终止 TLS）不需要这一项。

## 二、构建产物与目录布局

```powershell
# 1) 后端
dotnet publish EOS.API\EOS.API.csproj -c Release -o <部署目录>

# 2) 前端（产物就是 API 的静态文件根）
pwsh scripts/build-web.ps1          # 构建 EOS.Web 并放入 EOS.API\wwwroot，带产物断言
pwsh scripts/build-web.ps1 -Destination <部署目录>\wwwroot   # 直接落到部署目录
```

`build-web.ps1` 做三件事并各自断言：构建前要求产物里有 `index.html` 与 `assets/`、复制前清空
目标目录（默认目录保留 `.gitkeep`，避免上一版哈希命名的 chunk 残留）、复制后回读并核对
**`index.html` 引用到的每个 `assets/*` 都真的在目标目录里**——"漏一个 chunk、页面白屏、
服务端一切正常"就是这么来的。`-Install` 先跑 `npm ci`，`-SkipBuild` 只搬现有产物。
仓库里的 `EOS.API/wwwroot` 已按 `.gitignore` 排除，构建产物不会被误提交。

产物里**必须同时带上的资产**（漏了不会报错，只会在用到时报）：

| 资产 | 来源 | 缺失后果 |
|---|---|---|
| 迁移脚本 | 编译进程序集（嵌入资源） | 不需要单独拷贝 `.sql`；但**必须用本仓库构建的二进制**，换别处编的包就没有迁移 |
| 内置报表版式 | `EOS.API/ReportFormats/**/layout.json`（csproj 已 `CopyToOutputDirectory`） | 内置报表打印报"版式不存在"（客户定制版式在库里，不受影响） |
| PDF 中文字体 | `EOS.API/Fonts/NotoSansCJKsc-Regular.otf`（同上已复制） | 打印件中文缺字 |
| 前端 `wwwroot` | `EOS.Web` 的 `dist` | 打开首页 404 |

> 静态文件的 200 与 404 差别只在"有没有拷 `wwwroot`"——上线前用第六节的验收项确认一次，
> 不要靠浏览器缓存试出来。

## 三、配置项清单

真值**只从环境变量来**：`appsettings.json` 里写的是 `${VAR}` 引用，启动时一次性解析成实际值；
未定义的引用解析为空串并在启动日志里 Warning 点名（不会把 `${VAR}` 字面量当值使用）。
机制细节与"哪些配置必须留在文件里"见 [02](./02-本地环境与运行.md) 第八节。

| 配置项 | 必填 | 生产怎么给 | 说明 |
|---|---|---|---|
| `ConnectionStrings:ErpDatabase` | **是** | 环境变量 `MSSQL_ERP_CONN` | 唯一业务库 `EOS.ERP`；为空时 `/health/ready` 报 Unhealthy |
| `ASPNETCORE_URLS` | 是 | 环境变量 | 监听地址没有写在配置文件里（开发用的 `5261` 来自 `launchSettings.json`） |
| `ASPNETCORE_ENVIRONMENT` | 是 | 环境变量 | 不设即 `Production`：强制 HTTPS、HSTS、OpenAPI 需授权 |
| `Security:AllowedOrigins` | 视形态 | 配置文件 | 同源直连无需改；反向代理终止 TLS 时必须把对外地址列进来（见第一节） |
| `DataProtection:KeysDirectory` | **是（要持久）** | 配置文件或环境变量 | 默认 `%LOCALAPPDATA%\EOS\DataProtection-Keys`；认证 Cookie 的加解密密钥在这里，丢了全员掉线 |
| `DataProtection:ApplicationName` | 是 | 默认 `EOS.API` | 与密钥目录一起决定"谁是同一套密钥"；`/health/ready` 会校验非空 |
| `Attachment:StorageRoot` | 是（要持久） | 配置文件 | 附件正文落磁盘，库里只有元数据；空 = 程序目录下的 `attachments` |
| `Logging:File:Path` | 否 | 默认 `logs` | 相对内容根目录；不可写时只降级为控制台输出（详见第八节） |
| `ReportFormats:StorageRoot` | 否 | 默认内容根下 `ReportFormats` | 内置版式根目录（只读资产），客户定制版式在库 |
| `ReportInbox:ScanIntervalSeconds` | 否 | 默认 300 | 报表订阅调度扫描间隔（下限 10 秒） |
| `Audit:FieldChangesEnabled` | 否 | 默认 `true` | 关闭即停写字段级审计明细（写放大止血开关，见 [30](./30-审计日志.md)） |
| `AssistantTranscript:Enabled` | 否 | 默认 `false` | 助手回合录制开关（**部署期诊断**）：打开后把每次模型调用的输入/输出录成 JSON，供引擎 parity 使用，见 [06](./06-测试与质量门禁.md) 的「引擎 parity」。会写盘，且内容含业务问答，**排查完请关掉并清理目录** |
| `EffectEngine:Enabled` | 否 | 默认 `true` | 效果引擎**断路器**，改配置即生效（无需重启）；管的是引擎自身系统性缺陷，不管单模块配置错误 |
| `Workflow:OverdueDays` | 否 | 默认 3 | 待办逾期判定天数 |

模型密钥不在配置里：助手模型与供应商在「工作助手管理 → 模型与用量」界面维护，密钥由界面写进
环境变量，库里只存变量名。见 [62-嵌入模型与知识库接线](./62-嵌入模型与知识库接线.md)。

## 四、首次部署（空环境）

1. **建库**：按 `db/bootstrap/` 的编号顺序执行（`00 → 10 → 20 → 25 → 30 → 40`）。这一步不是
   "先让应用自己跑迁移"——迁移是增量演进，只有建库脚本能从空库建成可用库。
2. **设环境变量**：至少 `MSSQL_ERP_CONN`、`ASPNETCORE_URLS`、`ASPNETCORE_ENVIRONMENT=Production`。
   设完重开终端再启动（环境变量在启动进程时继承）。
3. **放产物**：后端发布目录 + `wwwroot` 前端产物（第二节）。
4. **首次启动**：迁移随启动执行，日志里应有"EOS.ERP 数据库迁移完成（N 个脚本）"。
5. **验收**：按第七节逐项过一遍。
6. **改口令**：初始账号 `admin`（口令 `admin`）拥有全部权限，**首次登录后立即修改**。

## 五、升级已部署库

升级是**换二进制 + 重启**：迁移脚本编译在程序集里，启动时 DbUp 只执行台账里没有的脚本
（机制与命名规则见 [05](./05-数据库迁移与建库.md)）。顺序不能颠倒——先备份，再停服，最后换包：

1. **备份**：业务库、附件目录、密钥目录（第六节）。
2. **停服务**：单实例部署下没有热切换余量；迁移在启动早期执行，并发请求会看到半升级的库。
3. **换产物**：后端发布目录与 `wwwroot` 一起替换（前端与后端版本必须同批，接口契约没有向前兼容）。
4. **启动并观察**：迁移失败**即启动失败**（每个脚本一个事务，失败的那个整体回滚，前面的已提交）。
   看到"迁移失败"不要重试启动，先按报错定位——重复启动不会修复它。
5. **核对台账**：`pwsh scripts/check-migration-journal.ps1`（脚本数与台账行数一一对应）。
6. **清标脏模块**：迁移可能把受影响模块标脏。`pwsh scripts/check-snapshot-staleness.ps1` 看有没有
   `stale/silent`，再用 `pwsh scripts/publish-workbench-snapshots.ps1` 重发布；定义快照与发布语义见
   [41](./41-定义快照与发布.md)。
7. **冒烟**：第七节 + `EOS.API.Tests/E2eSpaShellAuth.ps1`（未登录访问边界，秒级、不写库）。

**回滚口径**：迁移是**前向**的，没有自动降级脚本。回滚 = 停服 → 还原升级前的库备份与附件 →
换回旧二进制 → 启动。**不要手工删 `ERP_SCHEMA_JOURNAL` 里的行**：那等于骗 DbUp 重跑历史脚本，
而多数脚本的守卫是按"有事可做"写的，重跑会直接抛错。

## 六、备份与恢复

三样东西各备一份，少一样都恢复不出"原样"：

| 对象 | 内容 | 丢了会怎样 |
|---|---|---|
| SQL Server `EOS.ERP` | 全部业务数据、元数据、报表定义与定制版式、审计 | 数据没了 |
| 附件目录 | `Attachment:StorageRoot` 下的文件正文 | 库里附件记录还在，点开是空 |
| DataProtection 密钥目录 | 认证 Cookie 的加解密密钥 | **不丢数据**，但所有已签发会话立即失效（全员重新登录）；密钥不稳定还会表现为"多台机器互不认登录" |

恢复顺序：还库 → 还附件 → 还密钥 → 启动 → 第七节验收。附件与库**必须成对**恢复到同一时刻，
否则会出现"记录指向不存在的文件"。内置报表版式与字体是产物资产，随包发布，不在备份范围内。

## 七、健康检查与上线验收

| 端点 | 用途 | 未登录 |
|---|---|---|
| `/health/live` | 进程活着（只答"要不要重启"） | 可访问 |
| `/health/ready` | 就绪：数据库、迁移、附件目录、日志目录、必要配置 | 可访问 |
| `/health/startup` | 启动期：迁移是否成功 | 可访问 |
| `/health/version` | `commit` / `buildTimeUtc` / `processStartTimeUtc` / `stale` | 生产需授权 |
| `/metrics` | Prometheus 指标 | 生产需授权 |

`/health/version` 的 `stale=true` 表示**运行中的进程比二进制旧**（换了包没重启）——升级后最容易被
忽略的一项。逐项含义与报告体格式见 [31](./31-运行日志与诊断.md)。

上线验收清单（前六项机器可判，后三项人工）：

1. `/health/live` = 200；`/health/ready` 报告体里每一项都 Healthy（`log_file` 允许 Degraded，见第八节）。
2. `/health/version` 的 `commit` 与本次发布的提交一致，`stale=false`。
3. 未登录打开站点任意深链落在登录页（不是 `ERR_TOO_MANY_REDIRECTS`）；未登录访问 `/api` 得 401。
4. 登录成功且**刷新后仍在登录态**（否则就是 Cookie 没落地——多数是 HTTP 而非 HTTPS）。
5. 打开一个统一表单模块，能查到列表、能打开单据。
6. 打印一张内置报表，中文与页头公司信息正常（验证字体与 `COMPANY.*` 数据源）。
7. 录入一张业务单据并批核，状态位变化正确。
8. 附件上传与下载各一次（验证附件根目录可写、权限位生效）。

## 八、日志与磁盘

- **文件日志只落 Warning+**：正常请求只有控制台与审计（库里），排障时"日志里查不到这条请求"是预期。
- 按天切分 `api-yyyyMMdd.log`，单日超 50 MB 再切序号，默认保留 14 天、最多 30 个文件
  （`Logging:File` 可调）。审计 `AUDIT_EVENT` 在库里，不随日志滚动清理，磁盘压力在数据库侧。
- 日志目录不可写时**不摘流量**：`/health/ready` 的 `log_file` 项为 Degraded（业务仍正常），
  但排障证据没了——要按报告体判定，别只看总状态。
- 打印用中文字体随产物发布，不需要在服务器上装字体。

## 九、单实例边界：为什么不做多实例

`EOS.API` 的认证是**无状态票据**（Cookie 里就是票据本身，库里没有会话表），所以多实例之间
只要共用**同一套 DataProtection 密钥**就能互认登录。真正卡住多实例的是下面四处进程内状态：

| 进程内状态 | 多实例后果 | 要多实例时的前提 |
|---|---|---|
| 登录限流与临时锁定（`ConcurrentDictionary`） | 每实例各算一份，暴力破解的尝试次数被摊薄 ⇒ 限流形同虚设 | 换共享存储（见 [20](./20-认证与会话.md)） |
| 权限缓存（TTL 60 秒） | 各实例独立，改权限后最迟 60 秒一致 | 可接受，不必改 |
| 报表订阅调度（`ReportInboxScheduler`） | **每个实例都会扫一遍到期订阅**，同一份订阅被重复生成 | 只让一个实例跑调度，或给它加分布式锁 |
| 效果引擎断路器（`IOptionsMonitor`） | 配置文件逐实例读 | 各实例配置须一致 |

当前按**单机交付**；要扩成多实例必须先把上表第一、三行做实，而不是把进程复制几份。

## 十一、故障入口

先按现象选入口，别一上来翻代码：

| 现象 | 先看 |
|---|---|
| 服务起不来 / 起一半 | 启动日志的迁移报错、`/health/startup`；02 篇"常见问题" |
| 某个操作报错、页面报 500 | [31](./31-运行日志与诊断.md)：按 `correlationId` / `error.code` 取日志与审计 |
| 登录后立刻又是未登录 | 是否 HTTPS、Cookie 是否落地、`DataProtection` 密钥目录是否可写 |
| 打开任意页面重定向次数过多 | 前端产物是否在 `wwwroot`、`ASPNETCORE_ENVIRONMENT` 是否符合预期 |
| 列表/表单读不出数据 | 模块权限与字段级权限（[21](./21-授权模型.md)）、数据范围过滤 |
| 数据库整库报 I/O 错误 | 先查磁盘、存储与安全软件的实时扫描排除项；此类故障**不要按"脚本坏了"排查** |
