# 74 搜索中心

搜索中心是**全局检索入口**：不先打开某个模块，直接从"我想找 XX"出发。

实现：`EOS.API/Controllers/SearchCenterController.cs`、`EOS.API/Data/SearchCenterRepository.cs`、
`EOS.Web/src/features/search-center/`。

## 一、端点

路由前缀 `api/v1/search-center`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/modules` | 列出**当前用户可检索**的模块 |
| `GET` | `/{moduleId}/definition` | 取该模块的检索定义（可搜哪些字段） |
| `POST` | `/{moduleId}/query` | 执行检索 |

流程是**两步式**：先选模块（或由模块决定检索面），再在模块内检索。
这样检索条件能走统一的字段白名单与结构化条件，而不是拼一个跨表模糊查询。

## 二、检索面

搜索中心直接读元数据来确定能力：

| 来源 | 用途 |
|---|---|
| `MODULES` | 能搜哪些模块 |
| `FIELDS` | 每个模块能搜哪些字段 |

因此：

- **可搜模块 = 有浏览权限的模块**——`/modules` 返回的是过滤后的结果；
- **可搜字段来自字段登记**，受字段级权限约束（"禁看"的字段不出现在检索面里）；
- 检索值走**结构化条件 + 参数化**，与工作台列表同一套（见 [44-受控查询与条件模板](./44-受控查询与条件模板.md)）。

## 三、权限

搜索中心**不放大任何权限**：

- 只能搜有权浏览的模块；
- 结果受**行级数据范围**（`DATA_FILTER`）约束——和工作台看到的一样多；
- 禁看字段既不返回也不可搜。

一句话：**搜索中心看到的就是用户本来能看到的**，只是换了个入口。

## 四、与其他入口的分工

| 入口 | 找什么 |
|---|---|
| **搜索中心** | 模块与业务记录（"这个物料在哪个模块""这张单子在哪"） |
| 报表中心 | 报表（见 [50-统一报表](./50-统一报表.md)） |
| 帮助 / 知识库 | 说明文档（助手侧见 [60-AI工作助手](./60-AI工作助手.md)） |

三者都不进菜单导航，都是**发现式入口**。

## 五、排障

| 现象 | 原因 |
|---|---|
| `/modules` 里没有目标模块 | 当前用户无该模块浏览权限 |
| 搜不到某些字段 | 字段不可见，或被字段级权限挡住 |
| 搜得到模块但搜不到记录 | 行级数据范围把它排除了——**这是正确的** |
| 搜索结果与工作台列表不一致 | 检查检索条件是否更宽/更窄；两者数据范围应一致 |
| 检索很慢 | 条件过宽；收窄关键字或用模块内的高级查询（见 44 篇） |

## 六、注意事项

- **检索面不靠模块条目承载**：`/search-center` 自己不需要"查询中心"模块——可搜模块由各业务模块的
  `MODULES.SEARCH_1`（主表）/ `SEARCH_2`（副表）决定；清掉某模块的这两个位，就等于把它移出检索面。
  旧系统"每个业务域一个查询页"留下的八个「××查询中心」壳模块（2501-2508）已于迁移 314 下线，
  **不要再新增这类壳模块**；
- **不要为搜索中心单独开一套权限逻辑**：它必须复用模块权限与数据范围，
  否则会变成绕过权限的旁路入口；
- **不要跨模块拼一个大 SQL**：检索按模块走，各自用自己的字段白名单；
- **不要返回禁看字段**——即使只是"用于匹配"，也不该把值带出来。
