# 74 搜索中心

搜索中心是**全局检索入口**：不先打开某个模块，直接从"我想找 XX"出发。

**入口是菜单里的「查询中心」（模块 `34`，承载页 `/search-center`，一级节点）**：它自己没有主表，
只是一个入口模块——`SEARCH_1/SEARCH_2` 必须为 0，检索面由各业务模块的检索位决定（见第六节）。
**URL 不带模块号**：`/search-center` 是页面本身（`M_URL` 是精确路径，不追加 `/{moduleId}`），
当前检索哪个模块写在查询串 `?module={模块号}` 里——模块号是页面内的检索目标，不是页面身份，
写进路径会让每个模块都变成一个不同的地址（标签、标题解析都要跟着特判）。
菜单可见性与页面可达性是同一条读权限（`moduleReadPermission(34)`）；进入后能看到哪些模块、
哪些行，仍由各自的模块权限与数据范围过滤。

实现：`EOS.API/Controllers/SearchCenterController.cs`、`EOS.API/Data/SearchCenterRepository.cs`、
`EOS.Web/src/features/search-center/`。

## 一、端点

路由前缀 `api/v1/search-center`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/modules` | 列出**当前用户可检索**的模块 |
| `GET` | `/{moduleId}/definition` | 取该模块的检索定义（可搜哪些字段） |
| `POST` | `/{moduleId}/query` | 执行检索 |

流程是**两步式**：先选模块（或由模块决定检索面），再在模块内检索。
这样检索条件能走统一的字段白名单与结构化条件，而不是拼一个跨表模糊查询。

## 二、检索面

搜索中心直接读元数据来确定能力：

| 来源 | 用途 |
|---|---|
| `MODULES` | 能搜哪些模块 |
| `FIELDS` | 每个模块能搜哪些字段 |

因此：

- **可搜模块 = 有浏览权限的模块**——`/modules` 返回的是"检索位 ∩ 当前用户可浏览模块"，
  权限判定复用导航（`NavigationRepository`），不另写一套 SQL；
- **可搜字段来自字段登记**，受字段级权限约束（"禁看"的字段不出现在检索面里）；
- 检索值走**结构化条件 + 参数化**，与工作台列表同一套（见 [44-受控查询与条件模板](./44-受控查询与条件模板.md)）。

## 三、权限

搜索中心**不放大任何权限**，因为它与统一工作台共用同一套判定：

- 只能搜有权浏览的模块（`/modules` 已按权限过滤；直接调 `/{moduleId}/query` 由
  `WorkbenchAccessPolicy.AuthorizeDefinitionAsync` 拒绝，口径是 **404 防探测**，不区分"不存在"与"无权限"）；
- 结果受**行级数据范围**约束——`SearchCenterRepository` 在拼 WHERE 时先经
  `WorkbenchScopeFilter` 落地**模块主表过滤条件（`MODULES.FILTER`）+ 用户 `DATA_FILTER` + `EXEC_TAG`**；
  查明细表时通过主表关联键推导成 `EXISTS (...)`，与工作台子表同一条路径；
- 禁看字段既不返回也不可搜。

一句话：**搜索中心看到的就是用户本来能看到的**，只是换了个入口。
这条从"文档承诺"变成了"实现保证"——`WorkbenchScopeFilter` 是唯一真源，两处不会漂移。

## 四、与其他入口的分工

| 入口 | 找什么 |
|---|---|
| **查询中心**（菜单 34） | 跨模块、跨单据明细的即席倒查（"这个物料出现在哪些制令单的明细里"） |
| 统一工作台列表 | 单模块内**已有语境**的查找（左上角关键字 + 高级查询） |
| 报表中心 | 预定义好的报表（见 [50-统一报表](./50-统一报表.md)） |

三者的区别是**是否需要预先定义／是否需要先进模块**：查询中心不需要预先定义、也不需要先进模块；
工作台需要先进模块，且明细区要先选主表行；报表需要有人先把报表定义出来。

## 五、排障

| 现象 | 原因 |
|---|---|
| `/modules` 里没有目标模块 | 当前用户无该模块浏览权限 |
| 搜不到某些字段 | 字段不可见，或被字段级权限挡住 |
| 搜得到模块但搜不到记录 | 行级数据范围把它排除了——**这是正确的** |
| 搜索结果与工作台列表不一致 | 检查检索条件是否更宽/更窄；两者数据范围应一致 |
| 检索很慢 | 条件过宽；收窄关键字或用模块内的高级查询（见 44 篇） |

## 六、注意事项

- **检索面不靠模块条目承载**：可搜模块由各业务模块的
  `MODULES.SEARCH_1`（主表）/ `SEARCH_2`（副表）决定；清掉某模块的这两个位，就等于把它移出检索面。
  **没有主表的节点两个位必须都清掉**（迁移 340 起由菜单保存在服务端强制、`scripts/check-module-node-kind.ps1` 守）：
  模块清单直接读 `MASTER_TABLE`，为 NULL 会把整页打成 500（读取侧现已兜住 NULL，但"启用了却搜不了"
  仍是无意义配置）。检索面**与承载页无关**：自定义承载页只要有主表就能被检索，所以这对标志位不随节点形态隐藏。
  旧系统"每个业务域一个查询页"留下的八个「××查询中心」壳模块（2501-2508）已于迁移 314 下线，
  **不要再新增这类壳模块**；全库只有模块 34「查询中心」这一个入口（迁移 444），
  它没有主表、检索位必须为 0，也不承载任何检索面；
- **不要为搜索中心单独开一套权限逻辑**：它必须复用模块权限与数据范围，
  否则会变成绕过权限的旁路入口；
- **不要跨模块拼一个大 SQL**：检索按模块走，各自用自己的字段白名单；
- **不要返回禁看字段**——即使只是"用于匹配"，也不该把值带出来。

## 收口（界面重塑：与统一工作台同一套交互）

原页面把「字段 + 值」单行输入和关键字框并排摆着，必须先点「查询」才发请求，且查到结果后不能排序、
不能打开单据——一个跨单据倒查工具断在"找到了在哪"这一步。重塑后与统一工作台完全同构：

| 位置 | 内容 |
|---|---|
| 命令栏左 | 模块下拉、数据表下拉（模块两个检索位都开时才出现）、关键字（`ErpSearchBox`，防抖 400ms） |
| 命令栏右 | 高级查询（`ErpQueryBuilder`，多条件/运算符/and-or，生效条件数作角标）、结果列、导出、最近查询、刷新 |
| 表格上方 | 查询摘要（模块 · 表 · 条件数 · 关键字）与"双击一行打开单据"提示 |
| 表格 | 服务端排序、列宽拖拽、Ctrl+C 复制；**行双击按主键打开单据** |

四个语义决定：

- **选中模块即查**，不再有"必须先点查询"这道仪式；切模块/切表/改条件/改关键字都自动重查。
- **默认查哪张表由检索位决定**：模块只登记了明细位（`SEARCH_1=0 / SEARCH_2=1`，如 1505 入库单）时
  默认查明细表——固定按主表查会拿到 404（"这个模块不能用主表检索"）。用户手动切表仍然优先。
- **条件与关键字进同一份字段白名单**：切模块后沿用条件，当前表里不存在的字段静默剔除（不把查询打成 400）。
- **排序走服务端**（字段白名单由 `WorkbenchQueryComposer.ResolveOrder` 校验，与工作台同一份），
  否则"翻页后再排"只会排当前页。
- **明细行也能打开主单**：`SearchDefinition.MasterPkOrder` 下发主表主键，仓库在明细查询时把主表主键列
  并入投影（仅当明细表物理存在该列），前端据此拼 `/workbench/{moduleId}/view/{主键}`。

后端契约随之调整：`SearchQueryRequest` 改为 `(Table, Conditions[], Keyword, SortField, SortDirection)`，
条件解析**复用 `WorkbenchQueryComposer`**（字段白名单 / 虚拟字段 / 可查询性 / 算子渲染），不另写一套；
条件非法返回 400 `SEARCH_QUERY_INVALID`。

**显示口径与列序沿用统一工作台**（同一张表不该有两种排法与两种对齐）：

| 项 | 来源 | 说明 |
|---|---|---|
| 字段顺序 / 显隐 | 后端 `SearchDefinition.Columns`（= 工作台装配好的字段：个人列配置顺序 + 系统默认） | 前端不再自己排；「结果列」的**当前列**是本屏显示的那些、**默认列**取工作台 `SYS_DEFAULT_COLUMN`，选择只在本屏生效 |
| 列宽 | 个人宽度 `SYS_USER_COLUMN.F_WIDTH`，回落 `FIELDS.DISPLAY_LENGTH` | **与工作台同一端点写回**（`PUT /document-workbench/{moduleId}/column-widths`），两者共用 `useColumnWidthSaver` 队列；查询中心关掉本地列宽持久化，避免同一列两份 |
| 排序 | `sortFields` / `sortDirections`（逗号分隔，与工作台同形态） | 表头 Shift+点击可叠多列；白名单与去重都走 `WorkbenchQueryComposer.ResolveOrder`，无效字段回退主键 |
| 格式化 | `formatFieldValue(value, dataType, DISPLAY_FORMAT, numericRole)` | 与工作台同一函数；金额按语义族两位小数、零显示空白 |
| 对齐 | `alignClass(ALIGN / HEADER_ALIGN, dataType)` | 表头与单元格分开取，不再按"是不是数字"猜 |
| bit 列 | 只读复选框 | 与工作台一致，不显示 `1/0` 文本 |

`SearchField` 因此补齐 `Width / Align / HeaderAlign`（`FIELDS` 的同一批列），前端列定义与工作台的
`meta`（`className` / `cellClassName` / `minWidth` / `truncate` / `title` / `copyText`）逐项对齐。

**导出只对主表开放**（复用工作台的 `/export`，同一套条件白名单、模块过滤、数据范围与审计）；
明细结果的导出让位于"打开单据"，不另复制一套 CSV/Excel 构建器。

**工作台接回日常操作**：单元格右键新增「在查询中心查找此值」，跳到 `/search-center?module={模块号}&find=字段:值`
并自动按"包含"查询——从"我看到一个料号"到"它在哪些单据里"只差一次右键。
该项只在模块登记了 `SEARCH_1/2` 时出现。

**最近查询 / 结果列**是个人本地状态（`localStorage`，按模块+表分开存），不进库：
只有统一工作台的列宽才写回服务端（见 AGENTS 的列宽口径）。

## 收口（恢复为菜单入口，范围与统一工作台同源）

- **入口**：由"统一工作台工具栏上的一个按钮"改为一级菜单 **34「查询中心」**（承载页 `/search-center`，
  迁移 444）。工作台上的按钮已移除——它是列表工具，不该承载跨模块入口；而查询中心需要"先进去再选模块"，
  两者形态本就不同。菜单可见性与页面可达性同一条读权限（`moduleReadPermission(34)`），
  授权镜像同期跨模块聚合页 2102「我的任务」，逐人/逐组授予。
- **权限与行范围**：`/modules` 由"检索位"改为"检索位 ∩ 用户可浏览模块"（复用 `NavigationRepository`）；
  `/{moduleId}/query` 在拼 WHERE 前先经 `WorkbenchScopeFilter`（模块 `FILTER` + `DATA_FILTER` + `EXEC_TAG`），
  明细表经主表关联键推导。此前这两侧只有字段级权限与 `CanBrowse`，行范围是缺的——
  这等于绕过模块主表过滤条件与数据范围，现已收口。
- **判定口径**：不可浏览一律 404（与工作台一致），不改口为 403。
- **为什么推翻"检索面不进菜单"**：那条口径解决的是"每个业务域一个查询页"造成的菜单壳（2501–2508），
  不是"查询中心不该有入口"。壳模块已下线，能力仍在，缺的正是入口。理由与取舍见决策记录第 139 条。



- 前端 `EOS.Web/src/features/search-center` 只随表格库 `@tanstack/react-table` 8 → 9 换了 import 来源（v8 式
  API 由 [`lib/tanstackTable.ts`](../../EOS.Web/src/lib/tanstackTable.ts) 保留），检索面、模块权限与行级范围
  的判定未变。

## 收口（显示与列表行为）

- **金额显示按语义族分派**：`NUMERIC_ROLE = AMOUNT` 固定两位小数、整型列一律不分组（编号不再显示成
  `1,024`）、其余数值去尾零。语义族经 `numeric-context` 的 `fieldRoles` 下发，**不进定义快照**
  （否则存量快照会全部判落后）；搜索中心与工作台列表、统一表单、报表一并消费。
- **列表翻页与筛选保留旧行并变灰**（`keepPreviousData` + `isFetching`），不再闪一瞬空表；
  虚拟表格滚到底不再残留底部空白。
- **行键要能标识一行**：撞键时 `ErpTable` 会按出现顺序补 `#2`/`#3` 并告警（拦的是"整表画成空白"），
  但选择态只认第一行——快照型列表按快照下标取键。
- **分页入参收敛到 `PageWindow`**：页号越界（`(page-1)*pageSize` 溢出成负 `OFFSET`）、同一列进两次
  `ORDER BY`、排序参数只剩分隔符这三类构造入参不再整页 500，解析为空即回落默认排序。
- 检索面（按模块各自字段白名单）、模块权限与行级范围的判定均未变。
