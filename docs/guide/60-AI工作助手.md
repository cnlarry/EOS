# 60 AI 工作助手

工作助手是内嵌在工作台里的 AI 助手。这篇讲它的**边界**与子系统——边界比功能更重要，
因为它是一条新增的数据通路。

**处境感知、对象级诊断、配置面、闭环与操作卡、双重门禁**另见
[61-工作助手的处境与诊断](./61-工作助手的处境与诊断.md)（处境感知已交付，其余待交付）。

实现：`EOS.API/Features/Assistant/`（7 个子系统 + `ChatService.cs` + `Situation/`）、
`EOS.API/Controllers/AssistantController.cs`、`KbController.cs`。

## 一、四条不可逾越的边界

| 边界 | 含义 |
|---|---|
| **模型推理内聚在 `EOS.API`** | 前端不持有厂商密钥、不直连模型厂商；模型调用经受控抽象 `IChatModel` |
| **模型输出永不进入 SQL 或表达式解析器** | 助手不能成为绕过白名单与参数化的后门 |
| **业务数据读取只能由 `EOS.API` 授权提供** | 助手读数据走语义接口，权限与普通请求同一套 |
| **助手不得绕过 API 直接访问数据库** | 与所有调用者同等约束 |

配套的设计约束（写在 `IChatModel` 的契约里）：

> 实现只负责**出网调用与协议解析**，不做权限判断、不落库、不组装提示词、不执行工具。

也就是说：模型接入层是最薄的一层，所有决策都在 `ChatService` 与工具层。

## 二、子系统一览

| 目录 | 内容 | 职责 |
|---|---|---|
| `ModelAccess/` | `IChatModel`、`IEmbeddingModel`、`DeepSeekChatModel`、`AssistantSettings` | 模型接入 |
| `Tools/` | 19 个工具 + 注册表 + 网关 | **语义接口**：助手能调用的受控能力 |
| `Situation/` | `AssistantSituationService`、`AssistantSituationBudget`、`SituationContextSanitizer`、`SituationDigestService`、`SituationFactsReader` | **处境**：上报校验、处境认知、打开即见（见 [61](./61-工作助手的处境与诊断.md)） |
| `Memory/` | `AssistantMemoryStore`、`MemoryDistiller` | 长期记忆与提炼 |
| `Kb/` | `KbChunker`、`KbIngestScanner`、`KbReferenceVerifier` | 知识库摄入与引用校验 |
| `Metrics/` | 指标定义、编译、执行、字段关系 | 指标语义接口 |
| `Governance/` | `AssistantGovernance` | 成本上限与熔断 |
| `Admin/` | `ChangeSetService`、`FieldMetaWriter` | 变更集与字段元数据写入 |
| — | `ChatService.cs` | 对话编排（提示词、工具轮次、落库） |

## 三、会话与流式对话

路由前缀 `api/v1/assistant`，**全部端点登录可用**；**数据按 `USER_ID` 服务端强制隔离**。

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `POST` | `/sessions` | 列会话 / 建会话 |
| `DELETE` | `/sessions/{sessionId}` | 删会话 |
| `GET` | `/sessions/{sessionId}/messages` | 取历史消息 |
| `POST` | `/sessions/{sessionId}/chat` | **流式对话（SSE）** |
| `GET` | `/situation` | 打开即见的处境快照（**零模型调用**，见 [61](./61-工作助手的处境与诊断.md)） |

### SSE 事件

| 事件 | 含义 |
|---|---|
| `delta` | 文本增量 |
| `done` | 回复已落库，**含用量** |
| `error` | 流中失败 |

两个行为要记住：

- **客户端断开即中止模型调用**——不会继续烧 token；
- **半截回复不落库**，历史经 `GET /messages` 恢复。

## 四、语义接口：19 个工具

`Tools/` 是助手与业务之间的**唯一通道**。工具名即能力清单（**以 `EOS.API/Program.cs` 的注册为准**，
下表与之对应）：

| 类别 | 工具 |
|---|---|
| 元数据探查 | `ListModulesTool`、`ListTablesTool`、`ListViewsTool`、`ListProceduresTool`、`DescribeModuleTool`、`DescribeTableTool`、`GetFormSchemaTool`、`GetFieldRelationsTool` |
| 数据读取 | `SearchRecordsTool`、`GetRecordDetailTool`、`GetMyDigestTool` |
| 处境与能力 | `ListMyCapabilitiesTool`（本人有哪些操作权；**只作按需查询，不常驻提示词**，见 [61](./61-工作助手的处境与诊断.md)） |
| 诊断 | `DiagnoseModuleTool`、`GetModuleFlowTool` |
| 指标 | `EnumMetricsTool`、`ResolveMetricTool` |
| 知识库 | `KbSearchTool` |
| 草稿与写入 | `DraftRecordTool`、`ApplyChangeSetTool` |

网关（`AssistantSchemaGateway`、`WorkbenchSearchGateway`、`ModuleFlowGateway`）负责把工具调用
转换成**受权限约束**的内部查询。

**两条硬约束**：

1. **工具声明的 JSON Schema 由服务端硬编码，绝不接受客户端传入**（`ToolDefinition` 的契约）；
2. 工具执行的每次数据读取都走正常的授权路径——**助手不是特权调用者**。

## 五、模型接入

`IChatModel` 是最小流式接口：

| 成员 | 说明 |
|---|---|
| `ModelName` | 实际模型名，写入 `ASSISTANT_MESSAGE.MODEL_NAME` 与审计 |
| `IsConfigured` | 配置是否齐备；**不可用时以 `AI_MODEL_NOT_CONFIGURED` 快速失败，不影响 API 其余功能** |
| `StreamAsync` | 按序产出文本/工具调用增量与 usage 收尾帧 |

消息角色（`ChatRole`）：`System` / `User` / `Assistant` / `Tool`。

> `Tool` 角色**只存在于单轮内存上下文，不落库**。

## 六、治理：成本与熔断

`Governance/AssistantGovernance.cs`。默认值（可按真实数据校准，校准走评估集回归）：

| 项 | 默认 |
|---|---|
| 全局日上限 | **50 元** |
| 用户日上限 | **5 元** |
| 每百万 token 输入 / 输出单价 | 1 元 / 2 元（按公示价，可校准） |
| 每轮预留额 | 0.05 元 |
| 连续失败阈值 / 冷却 | 3 次 / 60 秒 |

两个实现细节值得注意：

**单请求预留是"轮数感知"的**：实际预留 = 每轮预留额 ×（`MaxToolRounds` + 1），
覆盖工具多轮调用的最坏调用次数。这样并发请求不会把额度算穿。

**失败熔断只统计技术性失败**：

| 计入 | 不计入 |
|---|---|
| 模型错误、超时、空回复 | **权限拒绝**、**用户取消**、**限额触发** |

这条区分很重要：用户"没权限"或"自己取消"不该把账号熔断掉。
熔断状态是**按用户、进程内**的，服务重启即重置。

## 七、记忆

| 端点 | 作用 |
|---|---|
| `GET` / `POST` `/memory` | 读写记忆 |
| `DELETE` `/memory/{memoryId}` | 删一条 |
| `GET` `/memory/pending` | 待确认的记忆 |
| `POST` `/memory/pending/{memoryId}/resolve` | 处置待确认项 |
| `DELETE` `/memory/all` | 清空 |
| `PUT` `/memory/preferences` | 偏好设置 |

**记忆有"待确认"环节**（`pending`）：助手提炼出的记忆不直接生效，需用户处置。
`MemoryDistiller` 负责从对话中提炼。

## 八、知识库

表：`KB_COLLECTION`（集合）、`KB_DOCUMENT`（文档）、`KB_CHUNK`（切块）。

| 组件 | 职责 |
|---|---|
| `KbIngestScanner` | **敏感数据拦截 + 业务引用抽取**（注意：它**不扫文件系统**，尽管名字像扫描器） |
| `KbChunker` | 切块 |
| `KbReferenceVerifier` | **引用校验** |

`KbController` 提供摄取与检索入口。**摄取是推入式**：正文由请求体传入，服务端没有"扫描某个目录并入库"的通路
（`docs/` 下的文档不会自动进知识库）。

> 实测现状：`KB_DOCUMENT` 89 条、`KB_COLLECTION` 2 个，但 **`KB_CHUNK` 为 0**——
> 文档已录入、切块尚未生成，检索面还不完整。

## 九、指标与字段关系

`Metrics/` 子系统：

| 组件 | 职责 |
|---|---|
| `MetricRepository` / `FieldRelationRepository` | 指标定义与**字段关系**（`FIELD_RELATION` 292 行） |
| `MetricExpressionParser` / `MetricPlanCompiler` | 表达式解析与计划编译 |
| `MetricExecutor` | 执行 |
| `MetricDefinitionValidator` | 定义校验 |
| `SysMetricSchemaProbe` | 结构探测 |

指标由助手经 `EnumMetricsTool` / `ResolveMetricTool` 使用，
对应端点 `api/v1/report-metrics`。

**注意**：指标表达式的解析同样受控——模型不能直接生成表达式去执行。

## 十、变更集与写入

这是助手唯一能"改东西"的通路：

| 组件 | 作用 |
|---|---|
| `DraftRecordTool` | 生成**草稿**（不落库） |
| `ApplyChangeSetTool` + `ChangeSetService` | 应用变更集 |
| `FieldMetaWriter` | 字段元数据写入 |
| 端点 `POST /apply-changeset` | 应用入口 |

约束：

- 草稿与应用**分离**——生成草稿不等于改数据；
- 应用时走正常鉴权与校验，**不是"助手特权写入"**；
- 与普通写入一样进审计。

## 十二、边界与禁止事项

- **不要在前端持有厂商密钥或直连模型**——所有推理走 `EOS.API`；
- **不要把模型输出拼进 SQL、表达式或动态标识符**——这是红线；
- **不要让工具绕过权限**：工具读的每条数据都要走正常授权；
- **不要接受客户端传入的工具 Schema**——由服务端硬编码；
- **不要跳过草稿直接写**：写入走变更集，走鉴权，进审计；
- **不要用"用户取消"去触发熔断**：失败熔断只认技术性失败。

## 十三、排障

| 现象 | 原因 |
|---|---|
| 提示 `AI_MODEL_NOT_CONFIGURED` | 模型配置缺失（`AssistantSettings`）；**其余 API 功能不受影响** |
| 对话报额度不足 | 触发了用户日上限或全局日上限（见第六节） |
| 连续几次失败后被挡住 | 技术性失败达阈值，进入冷却（默认 60 秒） |
| 断线后没有回复 | 设计如此：客户端断开即中止，半截回复不落库 |
| 助手说"没有权限" | 工具走的正常授权——**当前用户的模块权限不足，不是助手故障** |
| 记忆没生效 | 可能在 `pending` 待确认状态 |
| 知识库搜不到内容 | `KB_CHUNK` 为空，切块未生成 |
| 用量与账单不一致 | 单价是可校准配置（默认按公示价），费用为估算 |
