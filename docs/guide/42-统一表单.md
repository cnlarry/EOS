# 42 统一表单

统一表单是单据的**浏览态与编辑态**页面。列表态在 [40-统一工作台](./40-统一工作台.md)，
版式资产与设计器在 [43-表单版式设计](./43-表单版式设计.md)。

实现：`EOS.API/Data/Forms/`、`EOS.API/Controllers/FormLayoutController.cs`、
`EOS.API/Controllers/DocumentWorkbenchController.cs` 的 `/form-definition` 与 `/record`。

## 一、模块准入：模块声明两位能力

**能力是模块的声明**（`dbo.MODULES` 两列，与批核入口 `APPROVE_ENABLED` 同口径：**现读、不进定义快照**，
保存即生效、不需要标脏/重发布），在 2301 菜单管理的「统一表单（浏览、新增、编辑）」与
「允许写入（新增、修改、删除）」两个开关上配：

| 声明 | 能力 | 典型模块 |
|---|---|---|
| `UNIFIED_FORM_ENABLED = 1` 且 `UNIFIED_FORM_EDIT_ENABLED = 1` | 可浏览 + 新增/修改/删除 | 绝大多数单据模块（259 个） |
| `UNIFIED_FORM_ENABLED = 1` 且 `UNIFIED_FORM_EDIT_ENABLED = 0` | **只能浏览**：可打开、可看，可点自定义按钮；新增/修改/删除一律不发路由、端点也一律 404 | 审计 2316、库存余额 1303、批次账 1302、应收未收明细 14997 |
| 两位都为 0 | 该模块**只有列表**（汇总/查询类模块双击不进表单） | 库存日志、安全预警、今日需入库、考勤日报等查询面 |

库约束 `CK_MODULES_UNIFIED_FORM_EDIT` 钉住非法组合（未启用表单 ⇒ 不可写）。
读取点只有一处：`EOS.API/Data/Workbench/UnifiedFormCapability.cs`（`IUnifiedFormCapabilitySource`），
写路径判定、浏览目标、发布管理与发布门、导入候选集、助手能力目录都从它派生——
`StaticArchitectureGuardTests.统一表单能力只有一处真源` 扫列名出现位置守着这条。

**"只能浏览"为什么必须存在**：像库存余额、批次账这类表，主表由库存移动引擎维护。
如果允许通用表单写入，写路径会**绕过移动引擎直接改账**。所以这类模块只能停在浏览态——
写路径必须封死，且封在**结构**上（模块声明），不靠授权位——权限是配置，能改；
"审计记录不可改、账本不许通用表单写"是事实。

> 判断一个模块能不能允许写入，问一句："通用表单直接改这张表，会不会绕过某个引擎？"
> 答案是"会"，就把「允许写入」关掉。

## 二、取表单定义

```
GET /api/v1/document-workbench/{moduleId}/form-definition?mode=new|edit|view
```

`mode` 只支持 `new` / `edit` / `view`，其他值返回 400 `INVALID_FORM_MODE`。

判定顺序：

| 检查 | 不通过 |
|---|---|
| 模块定义存在、字段可解析 | 404 |
| 模块在某个名单内（不在则读只读也不行） | 404 |
| `new` 需 `CanAddNew`；`edit` 需 `CanEdit`；`view` 需 `CanBrowse` | **403** |
| 定义声明了该能力（`new` 需 `HasAdd`，`edit` 需 `HasEdit`） | 404 |

**只读模块只放行 `view`**：`new` / `edit` 一律 404（不发路由、不渲染）。

另外，**只读模块下发的表单定义会剥掉写动作**（`WithoutWriteActions`）——
浏览态工具栏据此不渲染编辑/复制/删除/批核/结案。这些端点对该模块一律 404，
按钮留着只会开出一次失败。

## 三、打开方式与栅格列数

两件事，两个来处：**打开方式**是模块级（`MODULES` 的三列：`FORM_OPEN_MODE` +
`FORM_DIALOG_WIDTH`/`FORM_DIALOG_HEIGHT`），**栅格列数是页签级**（`MODULE_FORM_TAB.LAYOUT_COLUMNS`，
NOT NULL DEFAULT 4）。两者都随 `/form-definition` 一并下发
（`openMode` / `dialogWidth` / `dialogHeight` / `tabs[].columns`）——**定义里没有模块级的 `columns` 兜底段**
（迁移 319 的终态里就没有这一层），历史快照缺页签列数时两端统一按 4 列兜底。

**配置入口都在表单设计器**（单据表单页的字段设置菜单 ›【表单设计】，需 `FORM_DESIGN_TAG`；
2026-10-06 起 2301 那个「统一表单」页签已删——呈现配置只有这一处入口）：

- **打开方式与窗体尺寸**：页签行最右端的【表单呈现】按钮（那里本来就是空白）→ 弹窗里改；
- **一行几列**：页签上右键 →「布局列数」（改的就是该页签，见下）。

**它们与版式同一笔保存、同一次重发布 ⇒ 保存即生效**——不走模块管理那条"存草稿 → 人工点发布"的链
（那条链是元数据编辑面，呈现面不必绕它）。也正因同源，**设计器画板按配的弹窗尺寸摆**：
配 900×600 的弹窗，画板就按 900 宽（高度为下限）来排，行内折行位置与运行态一致（见 [43-表单版式设计](./43-表单版式设计.md)）。

> 曾经的 `FORM_BUTTONS`（内置动作「受控注册码」）**已随迁移 320 退役并物理删列**：
> 工具栏动作只由「能力 + 权限 + 单据状态」决定，自定义按钮走 `MODULE_BUSINESS_ACTION`。
> 该列在库内全为空，删前删后运行态逐字节等价。

| 打开方式 | 值 | 行为 |
|---|---|---|
| 本页签（默认） | `TAB` | 在当前工作区标签内打开，表单占满可用区域 |
| 新页签 | `NEWTAB` | 在工作区标签栏新开一个标签打开 |
| 弹窗 | `DIALOG` | 按模块配的宽高把表单装进**统一弹窗组件**（`components/ui/Modal`，dialog 类 `erp-form-dialog`）；**地址与路由不变**——弹窗只是同一个表单页的另一种容器 |

要点：

- **弹窗不引入第二套渲染路径**：保存、校验、脏位登记、权限判定全走同一条；壳体沿用统一弹窗
  （标题取模块名，右上角 X 与工具栏「返回 / 取消」同路），未保存的改动照样由工作区脏位登记兜住。
  窗体尺寸超过屏幕时按视口收缩，内容只在窗体内部滚动。
- **弹窗里的落点与整页只有一处不同：工具栏移到窗体内第一行**（依据旧系统：
  `ERP/UserControl/ModifyToolBar.ascx` 在编辑窗体第一行、字段区之上）且**只常显主干动作**——
  返回 + 新增/编辑/删除/批核\|解批，其余动作按同一顺序收进「更多」菜单（菜单项与整页工具栏逐项相同：
  菜单项带文字，工具条本体是 28×28 纯图标、同样禁用态），避免十几个按钮挤在一行。**页签照摆**（2026-10-06 推翻此前"弹窗内不摆页签、
  所有页签的字段挤在同一栅格"的做法：那一版让"页签"这个结构在弹窗里彻底消失，与整页两副样子）——
  页签与栅格的关系、工具栏与页签的那 10px 间隙都与整页一致，只有列宽受窗体宽度约束。
  背后渲染该模块的工作台列表当底图（只读观感层，`inert` 冻结交互、不写地址、不上报助手处境），
  于是弹窗是"浮在工作台上"而不是"先开一张空白页再弹窗"。
- **开窗不抖**：打开方式与窗体尺寸随定义下发，列表页导航时还会把窗体提示（标题+尺寸）放进导航 state；
  定义重取（上一条/下一条、保存后刷新）与记录加载期间沿用上一次已知的窗体，加载态/错误态渲染在
  窗体内部；「列表 → 新增/编辑」「浏览 → 编辑」会重新挂载表单页，故这份记忆按模块存在组件外的
  进程内缓存里，首帧就定容器，定义一到即以定义为准覆盖。
- **打开方式只作用于"从列表或别处打开表单"**：表单页内部的动作（新增/复制/编辑/上一条下一条）
  都在已打开的窗体或标签里继续导航，不会每点一次就多冒一个标签。
- **新增入口只有统一表单一处**（`NEW_URL` / `MODI_URL` 已随迁移 321 物理删除）：承载页是 `/workbench`
  （或留空但有主表 = 默认落统一工作台）时按打开方式走统一表单；自定义承载页由页面自己负责入口，
  与打开方式无关。
- 未配置或配了无法识别的值时一律回落本页签：呈现开关不该让表单打不开。

| 栅格列数 | 值 | 说明 |
|---|---|---|
| 一行一列 ~ 一行四列 | `MODULE_FORM_TAB.LAYOUT_COLUMNS` = 1..4（NOT NULL DEFAULT 4） | **页签级、只此一处真源**：同一表单的页签 1 一行两列、页签 2 一行一列都合法；页签没声明过（历史快照）时两端统一按 4 列兜底 |

列数决定**该页签**一行排几个字段，字段的列跨度（`SPAN`）由版式给出、按**该行所属页签**的列数夹取
（见 [43-表单版式设计](./43-表单版式设计.md)）。把页签从 4 列改成 2 列时，设计器**顺手把该页签内
`SPAN > 2` 的行夹到 2**（用户 2026-10-06 拍板"调整布局即合规"），其它页签不受影响；服务端写入侧
同样按页签列数夹取，两侧一致。

## 四、表单定义里有什么

`WorkbenchModels.FormFieldDefinition` 描述了每个字段在表单上的一切：

| 项 | 来源（`FIELDS`） |
|---|---|
| `Key` / `Label` | `F_ID` / `F_DESC`（空则回落 `F_ID`） |
| `DataType` / `DisplayLength` / `DisplayFormat` | `F_TYPE` / `DISPLAY_LENGTH` / `DISPLAY_FORMAT` |
| `IsRequired` / `VerifyIndex` / `Regex` | `IS_VERIFY` / `VERIFY_INDEX` / `REGEX` |
| `DefaultValue` | `DFT_VALUE` |
| `IsReadonly` / `IsVisible` | `IS_READONLY` / `IS_VISIBLE` |
| `OnlyChoose` / `ChooseMultiple` / `ChoosePage` / `Choosers` | `ONLY_CHOOSE` / `CHOOSE_MULTI` / `CHOOSE_PAGE` / 选单配置 |
| `IsPrimaryKey` / `IsAutoIncrement` / `IsVirtual` | `IS_PK` / `IS_AUTOINC` / `IS_VIRTUAL` |
| `IsCost` / `IsSecrecy` | `IS_COST` / `IS_SECRECY`（受权限位控制） |
| `ServerFilled` | 服务端可自行填充（不算"用户可填"） |
| `MaxLength` | 物理列长度 |
| `TabNo` / `FormOrder` / `Span` / `NewLine` / `CellGroup` / `CellRole` | **版式**（见 43 篇） |
| `Options` | `FORM_OPTIONS`（固定枚举下拉） |
| `DisplayOnly` / `CanCopy` | 只显示 / 复制时携带 |

### 生命周期字段不参与版式

建立/修改/批核/结案的人·日期·状态位（10 列）是**记录元信息**，不是录入字段：

- 服务端在 `new` / `edit` 态把它们从字段集里剔除；`view` 态分流到
  `FormDefinition.LifecycleFields`，**不进 `MasterFields`**（因此也不占版式格）。
- 浏览态的呈现是固定的：状态位 → 工具栏右侧徽标；经办/日期 → 主表单卡底部固定区。
  无结案能力（主表没有 `FINISHED`）时只显示批核状态，底部三组等分。
- `FormDefinition.HasFinishCapability` 是**模块能力**（主表物理列），不是用户的
  `ENDCASE_TAG` 权限位；权限只控制结案按钮，能力控制状态/分组。
- 设计器字段池与画布都不再出现这 10 列；画布下方只有一块固定区预览（不参与拖拽）。
  存量版式里的生命周期行读取时忽略，下一次保存时丢弃；不需要迁移数据。
- 空页签不渲染：一个页签在当前用户可见业务字段里一个都没有时，运行态不显示该标签。

### 默认值的两处消费方，判据必须同源

`DFT_VALUE` 有两条生效路径：

- **保存态**：字段缺省时由服务端补齐（`RecordPayloadValidator.ApplyDefaults`）；
- **新增态**：下发给客户端前，服务端已把**日期哨兵**展开成实际日期（`WorkbenchDefinitionBuilder.BuildNewDefaultsAsync`）。

`DFT_VALUE='D'` 表示"今天"，只对日期类型生效。客户端只会把默认值**原样套用**，它不认识哨兵——
哨兵若原样下发，客户端会拿它当普通日期值提交，保存时因转换失败而整单被拒
（症状是"这个字段什么也没改，一点保存就报数值格式不正确"）。
因此新增态必须先把哨兵展开再下发，不能只在保存态认识它。

## 五、字段渲染规则

### 数据仅可选入（`ONLY_CHOOSE`）

`ONLY_CHOOSE=1` 的字段**不接受键入**：文本框、数值框、多行文本渲染成 disabled 控件，
值只能由选择器（`FIELD_DATASOURCE` 的启用来源）回填；选择按钮照常可用，必填星号照常显示
（锁的是键入，不是填写）。参考系统的同义形态是输入框 `ReadOnly=True` + chooser 按钮
（如 `ERP/CAR/Mission.aspx` 的单别）。三条边界：

- **只在真有选择入口时生效**：没有启用来源的自由文本字段不锁——锁了就是永远填不上的字段。
  存量里存在 `ONLY_CHOOSE=1` 但未配数据来源的字段（多为单别、部门），那是元数据缺口，
  补上数据来源后约束自然生效，界面不替它兜成死结。
- **下拉（`FORM_OPTIONS`）、复选与日期不额外加锁**：原生控件本身就是选择，不存在自由键入面
  （日期控件允许键入格式化日期串，与参考系统的日期编辑框一致）。
- **明细里的单别不靠这条**：明细单别是身份列（`isReadonly + serverFilled`），
  值由「新增一行」从主表同名值带出、渲染成只读文本，本来就不可键入
  （参考系统 `setTRKeyValue` 同口径）。`ONLY_CHOOSE` 管的是用户可自由键入的那一类控件。
- **约束的是录入面，不是值的存在性**：服务端无法判断一个值是否来自选择器；
  "值必须在来源里存在"由 `reference-exists` 校验规则承担，两者不互相替代。

单别走的就是这道判据。`FIELD_DATASOURCE` 里 `SOURCE_T_ID=BILLKIND` 的来源，
过滤条件是 `B_M_IDX={module}` 加 `APPROVED=1`——**未批核的单据性质不进候选**
（草稿配置不能拿来开单）。维护单别时两件事一起做：给本模块建 `BILLKIND` 行、把
`APPROVED` 置 1。`BILLKIND.BILL_CODE` 是**全库唯一主键**，同一业务的新旧两代表
（如 `HR_*` 与 `HRM_*`）不能共用编码，新表那代要另立一个（见迁移 `423`）。

### 虚拟列默认不出现在表单上

未定制版式时，虚拟列会被**摘掉**：

> 虚拟列是"选择器回写的伴生显示列"，只有版式**显式排入**时才作为只读字段出现在表单上，
> 否则每个模块都会凭空多出一批没有输入控件语义的列。

### 字段级权限在表单上的体现

- **禁看**：字段不下发，表单上不出现；
- **禁新增**：新增态不可填（编辑态可）；
- **禁改**：编辑态不可改（新增态可）。

这些是**服务端剔除**的，不是前端隐藏——前端隐藏等于没做。

`IsCost` / `IsSecrecy` 字段同样按权限位决定是否下发。

### 主档编号（主表主键）在编辑态只读

`FormFieldSelector.LockPrimaryKeysOnEdit` 在 **edit** 模式把主表主键字段标成只读：编号是记录对外的身份，
单据、库存余额（`INV_PRO_DEPOT`）、库存流水（`INV_DEPOT_LOG`）、批次账、报表条件都按它的**值**引用，
改写它等于把那些引用改断（余额与流水会挂在一个不存在的编号上）。

- **new / copy 态不受影响**：手填编号的主档靠新增态建档（自动编号的键本来由服务端持有）；view 态本就全只读；
- **判定不落在 `FIELDS.IS_READONLY`**：那个位与模式无关，置 1 会把新增态一起禁掉（编号就填不了了）；
- **只作用于主表字段**：明细行的身份是「主表键 + 项次」（服务端按既有项次保留），明细主键里的属性列
  （如库位编号）随整行重写，改它不会打到别的行上；
- **只读是体验，边界在服务端**：写路径独立拦"提交值不等于记录键"的主键列
  （`RecordPayloadValidator.CheckImmutableKeys` → 400 `PRIMARY_KEY_IMMUTABLE`）。不设这道闸，构造请求
  仍可改编号；而写入侧"跳过主键列"的写法又会让改动**静默丢弃**，调用方以为改成功了。

### 明细录入的批量粘贴（与 Excel 互操作）

从 Excel 复制一块数据粘到明细某一格：按列落位写入**可键入**的字段，超出末行自动补行；
`Delete` 清空选区、`Ctrl+D` 以选区首行向下填充。三条口径：

- **只落可键入列**（`writableDetailKeys`）：只读、`serverFilled`、`displayOnly`、虚拟字段与带启用来源的
  `ONLY_CHOOSE` 字段都不接收粘贴值。注意 `writableFields` 是"随保存提交"的口径（含只读但必填的联动列），
  拿它当粘贴白名单会让"只能选入"的字段被绕过。
- **金额联动照常复算**：批量写入与逐格输入走同一条 `applyDetailPatches`（金额预览、行内错误清除），
  不因为是粘贴就跳过。
- **服务端仍是权威**：粘贴只改界面草稿，保存时与逐格输入走同一套校验与效果链；小数/日期的格式规范化
  仍在保存前完成。

### 中文标签缺失时

`F_DESC` 为空、`'NULL'`、`'&nbsp;'` 或 NULL 时回落显示 `F_ID`（见 [12-元数据消费](./12-元数据消费.md)）。

## 六、提交

新增/修改/删除走 `POST` / `PUT` / `DELETE /record`，与工作台**同一条受控通道**：

1. 权限门（按动作）
2. 字段级限制（禁新增/禁改的字段不得写入）
3. 校验（必填、正则、长度、引用存在……）
4. 效果引擎（保存前后的效果链）
5. 事务：主表 + 明细 + 效果 + 审计同一事务

失败时返回 `fieldErrors`（字段名 → 错误信息数组），前端据此做字段级回填。

其中一条是**身份键的边界**：主键（主档编号）不可改——提交值与记录键同值算"原样回传"（忽略），
不同值直接拒（400 `PRIMARY_KEY_IMMUTABLE`，字段级错误）。身份键不是"可改的字段"，是"定位条件"。

## 七、附件

附件挂在字段上，**元数据在库、文件在磁盘**，权限按字段位强制
（`CanFileView` / `CanFileUpda` / `CanFileEdit` / `CanFileDele`）。
详见 [71-附件](./71-附件.md)。

## 八、选值

表单上的选值走统一选择器：`formField`（复用 `CHOOSE_*` 元数据）
或 `sourceKey`。表单字段的选择器数据源由 `GET /form-chooser/{fieldKey}` 提供。
详见 [46-统一选择器](./46-统一选择器.md)。

## 九、前端

`EOS.Web/src/features/document-workbench/`。要点：

- 路由 `/workbench/:moduleId/new|edit/:key|view/:key|copy`；
- 工具栏按钮**顺序固定**、动作集由**能力 + 权限 + 单据状态**决定（见 [03-工程规范与硬约束](./03-工程规范与硬约束.md)、[ADR-018](../decisions/ADR-018-单据动作按钮.md)）；
- 破坏性操作（删除）必须**先在浏览态确认单据细节**再执行，禁止列表页直接删；
- 字段渲染、必填标记、只读、下拉选项全部以服务端下发的表单定义为准；
- 编辑/浏览态的写请求键取 **URL 路径主键**（`keyParam`，权威且同步），不取界面上的字段值：界面值在
  记录尚未回填时是空的，而主档编号本身又是只读字段——用界面值拼键会把请求打到别的记录上。

## 十、排障

| 现象 | 原因 |
|---|---|
| 表单打不开（404） | 模块没声明启用统一表单（`UNIFIED_FORM_ENABLED = 0`）；或"只能浏览"的模块访问了 `new`/`edit` |
| 按钮点了报错找不到端点 | "只能浏览"的模块：写动作端点一律 404，前端也不该渲染这些按钮 |
| 某字段在表单上不出现 | `IS_VISIBLE=0`；字段级"禁看"；或该字段是虚拟列且版式未显式排入 |
| 表单设计器里找不到建立/批核/结案等列 | 设计如此：它们不参与版式，浏览态固定显示在状态徽标与主卡底部信息区 |
| 必填字段没有红色标记 | `IS_VERIFY` 未置位；或该字段 `ServerFilled`（服务端填充，不算用户必填） |
| 保存报 400 且带 `fieldErrors` | 字段级校验未过，按返回的字段名定位 |
| 新增态能改、编辑态不能 | 该字段被配成"禁改"（`DENY_MODI_*`）；或它是主表主键（编号在编辑态一律只读） |
| 编辑态编号改不了 | 设计如此：主档编号是记录身份，编辑态只读；要换编号请**新建**记录 |
| 改编号保存报 400 `PRIMARY_KEY_IMMUTABLE` | 构造请求绕过了界面只读——编号建立后不可修改 |
| 保存/删除报 404 且提示"记录不存在或已被删除" | 记录已不在（或请求的键不是这条记录的键）：回列表重新进入 |
| 改了版式但表单没变 | 版式未保存成功，或模块定义快照未重发布（见 [41-定义快照与发布](./41-定义快照与发布.md)） |
| 改了打开方式/列数但表单没变 | 同上一行：这几项也随快照冻结，模块保存后要**发布** |
| 配了新页签却仍在当前页签打开 | 模块配的是本页签；或工作区标签功能未启用（此时"新页签"退化为当前页导航） |
| 弹窗比配的尺寸小 | 窗体超过视口时按屏幕收缩（`max-width/height: calc(100vw - 32px)`），内容改为内部滚动 |
| 把模块改成 2 列后版式保存报"列跨度越界" | 原有版式行里有 `SPAN > 2` 的格，按设计态提示改掉再保存 |

## 收口（迁移 334/335）：归属三列不再是系统列

`CI` / `OWNER` / `OWNER_G` 已随迁移 334 全库下线，不再有"新增/编辑态隐藏、浏览态只读"的系统列处理，
也不再占用版式行的字段位（`MODULE_FORM_LAYOUT` 里引用它们的行已清）。
`DEPT.CI` / `SYS_EMPLOYEE.CI` 是部门与员工的公司归属（保留列），按**普通字段**的规则呈现——不想让人在表单里
改，把这两行元数据设成只读即可。
