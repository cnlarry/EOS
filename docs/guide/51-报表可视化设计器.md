# 51 报表可视化设计器

**先分清两个"设计器"**，这是最容易混的地方：

| | 本篇（报表设计器） | [52-报表打印版式](./52-报表打印版式.md) |
|---|---|---|
| 设计什么 | 报表的**数据定义**：取哪些字段、怎么筛、怎么排、挂哪个模块 | 输出的**版式资产**：页面、区段、字段位置、样式 |
| 产物 | `REPORT` / `REPORT_SORT` 等库内配置 | `ReportFormats/{模块号}/layout.json` 等文件 |
| 端点 | `api/v1/report-admin` | `api/v1/print`、版式资源端点 |
| 使用者 | 实施、业务配置人员 | 版式设计人员 |

下面只讲第一篇。

## 一、端点一览

路由前缀 `api/v1/report-admin`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/reports` | 列报表 |
| `POST` | `/reports` | 新建报表定义 |
| `PUT` | `/reports/{id}` | 修改报表定义 |
| `DELETE` | `/reports/{id}` | 删除报表定义 |
| `GET` | `/sorts` | 列排序定义 |
| `POST` | `/sorts` | 新增排序定义 |
| `PUT` | `/sorts/{reportId}/{serialNo}` | 修改排序定义 |
| `DELETE` | `/sorts/{reportId}/{serialNo}` | 删除排序定义 |
| `GET` | `/modules` | 可选归属模块 |
| `GET` | `/field-options` | 可选字段 |
| `GET` | `/formats` | 可用版式清单 |
| `GET` | `/headers` / `/tails` | 页头 / 页脚字典 |

## 二、报表定义的内容

一条 `REPORT` 记录描述一张报表：

| 项 | 说明 |
|---|---|
| `REPORT_ID` | **身份**：全库唯一、不可变，规范 `^[A-Za-z0-9_-]{3,40}$` |
| `REPORT_NAME` | 显示名 |
| `M_IDX` | **归属业务模块**——权限、条件、入口锚点全在它身上 |
| `FORMAT_ID` | 绑定的版式（对应版式资产） |
| `REPORT_FILTER` | 报表级筛选 |
| 页头 / 页脚 / `TAIL_ID` | 打印时的页眉页脚 |
| `IS_DEFAULT` | 是否模块默认报表 |
| 审计列 | 建立/修改信息 |

### 三条设计约束（与 50 篇一致）

1. **归属只能是业务模块**，不能是承载页；
2. **不要加"表来源/字段来源"列**——取数走归属模块的数据集与 `ReportAggregateRegistry`；
3. **不要加报表级权限**——可见性只看归属模块的 `REPORT_TAG`。

## 三、排序定义

`REPORT_SORT` 是报表的排序来源（实测 558 行）。

- 排序字段**必须来自该报表的可见列**，不接受任意列名；
- 一条排序定义按 `reportId` + `serialNo` 定位；
- 前端改动排序即改定义，不在前端本地排序（否则导出/打印与屏幕不一致）。

## 四、字段选项从哪来

`GET /field-options` 返回可选字段。它**不是**前端写死的清单：

- 字段来自归属模块的表登记与字段登记（`FIELDS`），经权限过滤；
- 被"禁看"的字段不会出现在选项里——**报表设计器也受字段级权限约束**；
- 成本/机密字段按权限位决定是否可选。

## 五、可用版式

`GET /formats` 列出可绑定的版式。版式资产是文件，不是库内配置，
所以这里返回的是**服务端扫描到的版式清单**，见 [52-报表打印版式](./52-报表打印版式.md)。
资产根目录由 `ReportFormats:StorageRoot` 指定（可写绝对路径或 `${VAR}` 环境变量引用；
留空则用程序目录下的 `ReportFormats`）。

## 六、前端

`EOS.Web/src/features/reports/`。

- 报表中心与报表查看在这里；
- 设计器相关的界面走 `report-admin` 端点；
- 列表统一 `ErpTable`（见 [03-工程规范与硬约束](./03-工程规范与硬约束.md)）。

## 七、配置一张新报表的步骤

1. 确定**归属业务模块**（不是承载页）；
2. 起一个符合规范的 `reportId`（单数=单资源实例，复数/带后缀=集合或工具页），
   **定了就不能改**；
3. 在 `/reports` 新建定义，绑定归属模块与版式；
4. 配排序（`/sorts`）与筛选；
5. 需要时配页头页脚；
6. 确认该模块的 `REPORT_TAG` 已授权给目标用户——**没授权就谁也看不见**；
7. 从报表中心或模块单据的「报表」动作进入验证。

## 八、明确不要做的事

| 想法 | 为什么不行 |
|---|---|
| 给报表加一条"表来源"列 | `REPORT` 不得关联 `TABLES`；跨表聚合走 `ReportAggregateRegistry` |
| 给某张报表单独配权限 | 这是造第二处真源；用归属模块的 `REPORT_TAG` 表达 |
| 把报表挂进菜单 | 报表不进菜单；入口是报表中心、搜索、深链、情境入口 |
| 在报表里写 SQL | 取数走受控数据集与结构化条件 |
| 在前端做排序 | 导出与打印会与屏幕不一致 |

## 九、排障

| 现象 | 原因 |
|---|---|
| 报表列表为空 | 归属模块选错；或该模块下没有报表定义 |
| 建好了但用户看不到 | 归属模块的 `REPORT_TAG` 未授权（**没有报表级权限可查**） |
| 字段选项里找不到某个字段 | 该字段不可见，或当前用户无字段权限 |
| 排序下拉为空 | 该报表没有可见列，或没有配 `REPORT_SORT` |
| 改完排序没生效 | 排序是服务端定义，确认保存成功；再看是否被报表自身筛选覆盖 |

## 收口（删除一张报表的级联面；`SYSDD_REPORT` 已改名 `REPORT_USER_STATE`）

- `DELETE /reports/{id}` **不是只删 `REPORT` 一行**：与本体同一事务里还要清五张引用表 ——
  `REPORT_SORT` / `REPORT_INBOX` / `REPORT_SUBSCRIPTION` / `REPORT_USER_STATE` / `SYSQR`
  （`REPORT_ID` 是它们共同的引用列；清单取自 `ReportAdminRepository.DeleteReportAsync` 的常量数组）。
  **只删本体就会留下孤儿行**，并撞上真库棘轮断言 `ReportIdStandardLiveTests`——它逐个比对这五张表的
  孤儿行数上限（所以退役是"只减不增"的安全动作，但漏清一张就会把它顶红）。
- 五张里的 `REPORT_USER_STATE` 是在**迁移 336** 由 `SYSDD_REPORT` **改名**而来：该表自 ADR-024 的 R7 起
  只承载**用户状态**（收藏 / 排序 / 最近使用），权限四列早在迁移 278/279 就退役了，旧名"用户报表权限"
  早已名不副实。改名连同表名、主键约束、默认约束一并处理，并订正了两处旧语义元数据
  （`TABLES.T_REMARK` 里那句早已退役的 `report.r_m_idx` 关联、`FIELDS.M_IDX` 的字段说明）。
  **看到旧名的地方（老文档、外部脚本、手写 SQL）需要跟着改。**
- 改名过程中踩到的两条 SQL Server 细节（约束改名要按对象类型传 `@objtype`；元数据表之间的外键会让
  改 `FIELDS.T_ID` 被 `Msg 547` 拦下）记在
  [`05-数据库迁移与建库.md`](05-数据库迁移与建库.md) 的「改名迁移的三条教训」一节，此处不重复。
