# 22 权限配置后台

规则在 [21-授权模型](./21-授权模型.md) 讲，本篇讲**怎么把权限配进去**。

## 一、入口与权限门

| 控制器 | 路由前缀 | 权限门 |
|---|---|---|
| `RightsAdminController` | `api/v1/admin` | **`CanSetup(2306)`**（权限管理员） |
| `UserAdminController` | `api/v1/admin/users` | 用户管理权限 |

权限管理端点服务于两个模块：**2306 用户权限设定**与 **2305 用户组管理**。

权限管理员本身也是一项权限（模块 `2306` 的 `CanSetup`）——**不能自己给自己授权**：
无此权限者调用一律 403，不是 401（已登录但无权限）。

写入侧遵守固定列白名单 + 受控校验 + 审计，不是"想改哪列改哪列"。

## 二、端点清单

`api/v1/admin` 下：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/users/{userId}/rights` | 取某人的模块权限矩阵 |
| `PUT` | `/users/{userId}/rights` | 保存某人的模块权限矩阵 |
| `GET` | `/users/{userId}/button-rights` | 取某人的按钮级权限 |
| `PUT` | `/users/{userId}/button-rights` | 保存某人的按钮级权限 |
| `GET` | `/users/{userId}/groups` | 取某人所属组 |
| `PUT` | `/users/{userId}/groups` | 设置某人所属组 |
| `GET` | `/users/{userId}/effective-rights` | **取某人的生效权限**（诊断用） |
| `GET` | `/groups` / `POST` `/groups` | 列组 / 建组 |
| `PUT` / `DELETE` | `/groups/{groupId}` | 改组 / 删组 |
| `GET` / `PUT` | `/groups/{groupId}/rights` | 组的模块权限矩阵 |
| `GET` / `PUT` | `/groups/{groupId}/button-rights` | 组的按钮级权限 |
| `GET` / `PUT` | `/groups/{groupId}/members` | 组成员 |
| `GET` | `/rights/fields` | 字段级拒绝的可选字段元数据 |

`api/v1/admin/users` 下是用户主档（新增/修改/停用启用/设置密码/所属组等）。

## 三、两种配法

### 按组配（推荐）

```
建组（POST /groups）
  → 配组的模块权限（PUT /groups/{gid}/rights）
  → 加成员（PUT /groups/{gid}/members）
```

适合"岗位相同的一批人"。改一次组权限，全组生效。

### 按人配

```
PUT /users/{userId}/rights
```

用于个例：临时授权、特殊情况收紧。

### 关键交互：个人覆盖组

**某模块只要有个人权限记录，该模块就完全采用个人权限，组权限被忽略。**

所以：

- 给某人配了模块 A 的个人权限后，**再改他的组权限对 A 无效**；
- 想让他回归组权限，得**删掉**那条个人记录，而不是把组权限调大；
- 混用两种配法时，最容易出现"明明给了组权限，他却没有"——先查个人记录。

## 四、按钮级权限

自定义单据动作按钮有独立的授权名单（用户级、组级各一套端点）。

规则是 **fail-closed**：

- 名单里没有 = **不渲染按钮**；
- 未获授权的用户看不到按钮，服务端对动作本身**另行鉴权**，没有"配了就能用"的豁免；
- 组级与用户级都配时，按 [21-授权模型](./21-授权模型.md) 的聚合规则处理（用户级优先）。

## 五、字段级拒绝的可选字段

`GET /rights/fields` 返回可配置的字段清单——**不能凭字段名随便填**，
写入时按受控校验处理。三组清单分别对应禁看 / 禁新增 / 禁改，主表与明细分开配。

## 六、生效权限预览

`GET /users/{userId}/effective-rights` 是排查权限问题的**首选工具**：
它直接给出聚合后的结果，不用手工推演"个人覆盖组、组间取 OR、EXEC_TAG 取最大"这一串规则。

排查顺序建议：

1. 调 `effective-rights` 看结果是否符合预期；
2. 不符合 → 查该模块有没有个人权限记录（覆盖了组）；
3. 仍不符 → 查用户所属组是否正确、组权限是否保存成功；
4. 刚改完立刻看没变 → 权限缓存最多 60 秒，或确认是走接口改的还是直接改库。

## 七、前端页面

| 位置 | 用途 |
|---|---|
| `EOS.Web/src/features/rights-admin/` | 权限配置 |
| `EOS.Web/src/features/user-admin/` | 用户与用户组管理 |
| `EOS.Web/src/features/menu-admin/` | 菜单/模块维护 |

> **页面间距只有一档：10px**（2026-10-01 定，权限矩阵页就是按它对齐的）。页边距（上下左右）
> 由 `.erp-tab-panel` 与 `.erp-tab-panel > .container-fluid` 各出 10px；**区块与区块之间**由页面级
> 容器的 `gap: var(--erp-block-gap)` 出 10px（token 定义在 `EOS.Web/src/styles/app.css`，
> 与 `--erp-workspace-gap` 并列，是"一处定义"）。
> **页面根容器不要再挂 Bootstrap 的间距工具类**（`gap-*` / `mb-*`）：它们带 `!important`，
> 会把 10px **静默**压成 8px 或 16px —— 权限矩阵页曾挂 `gap-2`（实测 8px），已改回。

## 八、配置时的注意事项

- **删组前确认没有成员**：有成员关联的组会被拒绝删除，不会级联清理成员；
- **改权限走接口**：直接改库不会触发权限缓存失效，最多 60 秒后才生效；
- **权限写操作有审计**：谁在什么时候改了谁的权限，可在审计里查到；
- **不要把权限配置当数据修复手段**：需要临时收紧时先建限制组，别逐人改；
- **新增模块记得配权限**：`MODULES` 加了模块只是有了菜单入口，没授权谁都不进去
  （无记录 = 全部拒绝）。
