# 22 权限配置后台

规则在 [21-授权模型](./21-授权模型.md) 讲，本篇讲**怎么把权限配进去**。

## 一、入口与权限门

| 控制器 | 路由前缀 | 权限门 |
|---|---|---|
| `RightsAdminController` | `api/v1/admin` | **`CanSetup(2306)`**（权限管理员） |
| `UserAdminController` | `api/v1/admin/users` | 用户管理权限 |

权限管理端点服务于两个模块：**2306 用户权限设定**与 **2305 用户组管理**。

权限管理员本身也是一项权限（模块 `2306` 的 `CanSetup`）——**不能自己给自己授权**：
无此权限者调用一律 403，不是 401（已登录但无权限）。响应体的 `message` 会写明缺的
是哪一个权限位（如「需要『用户权限设定』(2306) 的设置权(CanSetup)」），界面可直接展示——
这是统一拒绝出口的行为，见 [04-API契约与前后端协作](./04-API契约与前后端协作.md) 第三节。

> 由此可解释一类常见困惑：某账号能进 `/admin/users` 列表（需要 `CanBrowse`）却打不开
> `/admin/groups`（需要 `CanSetup`）——**浏览权与设置权是两个独立的权限位**，
> 前者不等于后者。

写入侧遵守固定列白名单 + 受控校验 + 审计，不是"想改哪列改哪列"。

## 二、端点清单

`api/v1/admin` 下：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/users/{userId}/rights` | 取某人的模块权限矩阵 |
| `PUT` | `/users/{userId}/rights` | 保存某人的模块权限矩阵 |
| `GET` | `/users/{userId}/button-rights` | 取某人的按钮级权限 |
| `PUT` | `/users/{userId}/button-rights` | 保存某人的按钮级权限 |
| `GET` | `/users/{userId}/groups` | 取某人所属组 |
| `PUT` | `/users/{userId}/groups` | 设置某人所属组 |
| `GET` | `/users/{userId}/effective-rights` | **取某人的生效权限**（诊断用） |
| `GET` | `/groups` / `POST` `/groups` | 列组 / 建组 |
| `PUT` / `DELETE` | `/groups/{groupId}` | 改组 / 删组 |
| `GET` / `PUT` | `/groups/{groupId}/rights` | 组的模块权限矩阵 |
| `GET` / `PUT` | `/groups/{groupId}/button-rights` | 组的按钮级权限 |
| `GET` / `PUT` | `/groups/{groupId}/members` | 组成员 |
| `GET` | `/rights/fields` | 字段级拒绝的可选字段元数据 |

`api/v1/admin/users` 下是用户主档（新增/修改/停用启用/设置密码/所属组等）。

## 三、两种配法

### 按组配（推荐）

```
建组（POST /groups）
  → 配组的模块权限（PUT /groups/{gid}/rights）
  → 加成员（PUT /groups/{gid}/members）
```

适合"岗位相同的一批人"。改一次组权限，全组生效。

### 按人配

```
PUT /users/{userId}/rights
```

用于个例：临时授权、特殊情况收紧。

### 关键交互：个人覆盖组

**某模块只要有个人权限记录，该模块就完全采用个人权限，组权限被忽略。**

所以：

- 给某人配了模块 A 的个人权限后，**再改他的组权限对 A 无效**；
- 想让他回归组权限，得**删掉**那条个人记录，而不是把组权限调大；
- 混用两种配法时，最容易出现"明明给了组权限，他却没有"——先查个人记录。

### 批量回归组权限

"删掉那条个人记录"在个别模块上是手工活，但在**上百个模块**上就不成立了——历史遗留的
全量授权常常一次铺满三百多个模块，逐个删实际上做不到。权限矩阵工具条的
「**批量清空全部（N）**」把所有 `hasPersonal` 的模块一次性标记为清空，保存后这些模块的
个人记录被删除、权限回退到组权限。它走的仍是 `PUT /users/{userId}/rights` 同一个端点
（一次提交 N 行 items），没有新增写路径；按钮上的 N 就是影响范围，执行前需要确认。

对应地，单个模块的清空仍是工具条上的「清空个人权限」，两者互不替代：前者处理"这个人整体
不该有特殊权限"，后者处理"某个模块收回"。

## 四、按钮级权限

自定义单据动作按钮有独立的授权名单（用户级、组级各一套端点）。

规则是 **fail-closed**：

- 名单里没有 = **不渲染按钮**；
- 未获授权的用户看不到按钮，服务端对动作本身**另行鉴权**，没有"配了就能用"的豁免；
- 组级与用户级都配时，按 [21-授权模型](./21-授权模型.md) 的聚合规则处理（用户级优先）。

## 五、字段级拒绝的可选字段

`GET /rights/fields` 返回可配置的字段清单——**不能凭字段名随便填**，
写入时按受控校验处理。三组清单分别对应禁看 / 禁新增 / 禁改，主表与明细分开配。

## 六、生效权限预览

`GET /users/{userId}/effective-rights` 是排查权限问题的**首选工具**：
它直接给出聚合后的结果，不用手工推演"个人覆盖组、组间取 OR、EXEC_TAG 取最大"这一串规则。

排查顺序建议：

1. 调 `effective-rights` 看结果是否符合预期；
2. 不符合 → 查该模块有没有个人权限记录（覆盖了组）；
3. 仍不符 → 查用户所属组是否正确、组权限是否保存成功；
4. 刚改完立刻看没变 → 权限缓存最多 60 秒，或确认是走接口改的还是直接改库。

## 七、前端页面

| 位置 | 用途 |
|---|---|
| `EOS.Web/src/features/rights-admin/` | 权限配置 |
| `EOS.Web/src/features/user-admin/` | 用户与用户组管理 |
| `EOS.Web/src/features/menu-admin/` | 菜单/模块维护 |

> **页面间距只有一档：10px**（2026-10-01 定，权限矩阵页就是按它对齐的）。页边距（上下左右）
> 由 `.erp-tab-panel` 与 `.erp-tab-panel > .container-fluid` 各出 10px；**区块与区块之间**由页面级
> 容器的 `gap: var(--erp-block-gap)` 出 10px（token 定义在 `EOS.Web/src/styles/app.css`，
> 与 `--erp-workspace-gap` 并列，是"一处定义"）。
> **页面根容器不要再挂 Bootstrap 的间距工具类**（`gap-*` / `mb-*`）：它们带 `!important`，
> 会把 10px **静默**压成 8px 或 16px —— 权限矩阵页曾挂 `gap-2`（实测 8px），已改回。
>
> **页面外壳也只有一套**：白卡与顶部命令栏由 `ErpListCard` 提供，页面根只挂语义类
> （`erp-full-list-page` / `erp-menu-admin` / `erp-config-workbench` …），高度链与滚动归语义类管；
> 页面里不再手写 `.card` / `card-header` —— 手写会被 `scripts/check-page-shell.ps1` 拦下
> （见 [03-工程规范与硬约束](./03-工程规范与硬约束.md) 的「列表卡外壳」）。
>
> **操作列（组权限 / 按钮权限 / 成员 / 编辑 / 删除 那一列）与普通列一样可拖列宽**，初始宽度按该列表
> 实际渲染的按钮组自适应（`meta: { frozenRight: true, autoWidth: true }`）。两页的按钮都是一整排文字按钮，
> 原先靠手工试一个够放的固定值（2305 给 332px、2306 给 356px），换文案或多一个按钮就得重试；
> 改成按内容自适应后宽窄跟着按钮组走，用户仍可自己拖。口径见 [03-工程规范与硬约束](./03-工程规范与硬约束.md) 同节。

## 八、配置时的注意事项

- **删组前确认没有成员**：有成员关联的组会被拒绝删除，不会级联清理成员；
- **改权限走接口**：直接改库不会触发权限缓存失效，最多 60 秒后才生效；
- **权限写操作有审计**：谁在什么时候改了谁的权限，可在审计里查到；
- **不要把权限配置当数据修复手段**：需要临时收紧时先建限制组，别逐人改；
- **新增模块记得配权限**：`MODULES` 加了模块只是有了菜单入口，没授权谁都不进去
  （无记录 = 全部拒绝）。

## 收口（依赖升级批次）

- 权限与用户组页面（`EOS.Web/src/features/rights-admin`、`user-admin`）只随表格库
  `@tanstack/react-table` 8 → 9 换了 import 来源（v8 式 API 由
  [`lib/tanstackTable.ts`](../../EOS.Web/src/lib/tanstackTable.ts) 保留），授权判定与页面行为未变。

## 收口（报表权限的逐报表矩阵已退场：本后台不再有第二处可配）

- **报表可见性的唯一真源是归属模块的 `REPORT_TAG`**（ADR-024 的 D16）。原先挂在用户组页上的
  「报表权限」逐报表例外矩阵**已退场**——管理面不再有第二个可配的地方。用户组页现在的子页面是
  **组权限 / 成员**两个；删除用户组的确认文案也相应改成"同时删除该组的**模块权限**"
  （不再提报表权限）。
- 所以排查"某人看不到某张报表"时**不要在本后台找开关**：先看那张报表的**归属模块**是否给了他权限
  （模块权限 + 该模块的 `REPORT_TAG`），详见 [`50-统一报表.md`](50-统一报表.md)。
- 本后台里与报表相邻的只剩一处：**自定义按钮授权矩阵**（`ButtonRightsMatrix`）——它是 fail-closed 名单
  （配好并发布的按钮**默认全场无人可点**，显式授权给谁谁才能点），与模块权限同一处维护，
  但**缺省方向与报表相反**：本页默认"只显示已授权"，而不是像报表那样"只显示例外"。

## 收口（ADR-033）：配置面的权限**从 2301 一个总开关变成每面一个**

- 模块行为配置的四张面各自持授权行、各按**自己的模块号**判权：**230101** 模块定义（读写属性、发布、版本历史）、
  **230102** 分组、**230103** 自定义按钮、**230104** 行为动作。要"只能配按钮、不能改动作"，
  把 `SYS_USER_MODULE_PERMISSION`/`SYS_GROUP_MODULE_PERMISSION` 里 230103 的 `SETUP_TAG` 给他、230104 不给即可。
- `MODULE_CONFIG_TAG` 的粒度随之细化：配置面各读**自己那一行**上的这一位（此前只看 2301 那一行）。
  分发权限时若只给了 `SETUP_TAG` 而没给该面的 `MODULE_CONFIG_TAG`，该面仍然进不去——
  两个位一起给，别只给一个。
- **按钮的运行期授权（`SYS_USER_BUTTON_PERMISSION` / `SYS_GROUP_BUTTON_PERMISSION`）没有变**：那张矩阵仍是 fail-closed，
  与上面的**配置面权限**是两回事，不要混用。

## 收口（悬空类名清理）

- 权限矩阵的模块树去掉了深度类名（`erp-nav-child-depth-*` / `erp-nav-children-depth-*`）：深度几何早已改由 `--menu-line` / `--menu-cpad` 变量驱动，类名是改造前的遗留。缩进、圆点与虚线位置实测未变。
