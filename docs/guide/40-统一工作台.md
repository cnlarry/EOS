# 40 统一工作台

一个工作台承接**所有**单据模块：模块之间不是不同的页面，而是同一套代码 + 不同的定义。
所以给某个模块加字段、改列、加按钮，改的是**配置**，不是这里。

| 层 | 位置 |
|---|---|
| 后端控制器 | `EOS.API/Controllers/DocumentWorkbenchController.cs` |
| 后端仓库 | `EOS.API/Data/DocumentWorkbenchRepository.cs` |
| 工作台子服务 | `EOS.API/Data/Workbench/`（明细引用回填、主表派生列回填） |
| 定义组装 | `EOS.API/Data/WorkbenchDefinitionBuilder.cs` |
| 前端 | `EOS.Web/src/features/document-workbench/` |

## 一、路由与端点

前缀 `api/v1/document-workbench/{moduleId}`——**模块号在路由上**，它是权限判定与日志归档的输入。

### 定义与列表

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/definition` | 取模块定义（表、字段、按钮、能力） |
| `GET` | `/records` | 列表查询（简单条件走查询串） |
| `POST` | `/query` | 列表查询（结构化条件走请求体） |
| `GET` | `/details` | 取明细行（**必须带主表关联键**） |
| `GET` | `/actions` | 取该模块可用的动作与自定义按钮 |

### 单据

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/record` | 读一条单据 |
| `POST` | `/record` | 新增 |
| `PUT` | `/record` | 修改 |
| `DELETE` | `/record` | 删除 |
| `GET` | `/form-definition` | 取表单定义（浏览/编辑/新增） |

`/record` 的 `key` 参数是**主键值数组的 JSON 编码**，如 `["A","B"]`。

### 状态动作

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/approve`、`/deapprove` | 批核 / 解批 |
| `POST` | `/endcase`、`/unendcase` | 结案 / 取消结案 |
| `POST` | `/action/{actionKey}` | **自定义动作**统一入口 |

> **自定义动作的两次请求共用一个关联键（2026-09-29）**：`CONFIRM_TAG` 的动作先探路
> （`confirm=false`，不写库、不占幂等键）再真执行（`confirm=true`），前端在**点击处**生成一个
> `X-Correlation-Id` 并贯穿这两次；幂等键则各自独立。这样用户报障给的报障编号能对上
> 「先算了什么、再执行了什么」的完整链路。口径见
> [`docs/decisions/ADR-028`](../decisions/ADR-028-全局异常捕获与错误追踪.md)。

### 列与字段设置

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` / `PUT` / `DELETE` | `/columns` | 列配置读取 / 保存 / 重置 |
| `GET` | `/column-editor` | 列编辑器数据（当前列 + 默认列） |
| `PUT` | `/column-widths` | 批量保存列宽 |
| `GET` / `PUT` | `/field-settings[/{fieldKey}]` | 字段设置 |
| `GET` | `/field-settings/lookups/{kind}` | 字段设置的下拉数据 |

### 导出与选值

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/export` | 按当前条件导出 |
| `POST` | `/export-selected` | 导出所选行（**1~500 行**，主键数量须与定义一致） |
| `GET` | `/form-chooser/{fieldKey}` | 表单字段的选择器数据源 |

## 二、策略层单入口（授权判定）

模块可见性、统一表单名单、动作权限位、行级数据范围与写路径幂等键的判定**全部收敛在**
`EOS.API/Data/Workbench/WorkbenchAccessPolicy.cs`：它是唯一判定点，控制器只消费判定结果
（`AuthorizeDefinitionAsync` / `AuthorizeFormAsync` / `AuthorizeActionAsync` / `AuthorizeDeleteAsync` /
`AuthorizeWorkflowAsync` / `AuthorizeUserActionsAsync` / `AuthorizeSetupAsync` / `CheckIdempotencyKey`）。
`EOS.API.Tests/WorkbenchPolicyEquivalenceTests.cs` 与 `scripts/check-workbench-policy-single-entry.ps1`
把"控制器里不得再出现判定谓词"固定成**可测、可 grep** 的事实，而不是约定。

**为什么要收敛**：同一句"能不能以某模式访问该模块"原先在控制器里写了两遍（表单访问与
`form-definition` 的内联判定），连失败响应都不一致。判定分散时，任何新的消费方（例如助手侧
"哪些单可做"的预判）都会再抄一份，两份口径必然漂移。因此判定结果是**结构化的**：允许时携带
载荷（定义 / 表单 / 权限），拒绝时带稳定原因码（`WorkbenchDenialCodes`），供日志与后续消费方
解释"为什么不可做"。

权限真源仍是 `IPermissionService`（个人覆盖组、组布尔 OR、`EXEC_TAG` 取最大值），
本层不新增第二套权限读取或缓存。

**失败响应口径（逐端点）**：

| 端点 | 判定 | 拒绝响应 |
|---|---|---|
| `GET /definition`、`/records`、`/query`、`/details`、`/export`、`/export-selected`、`/columns`、`/column-editor` | 定义装配（浏览位） | 404 |
| `PUT` / `DELETE /columns` | 定义装配（浏览位） | 404 |
| `GET /record` | 表单访问（view，失败回退 edit） | 404 |
| `POST /record` | 表单访问（new） | 404；幂等键不合法 400 `IDEMPOTENCY_KEY_REQUIRED` |
| `PUT /record` | 表单访问（edit） | 404；幂等键不合法 400 |
| `DELETE /record` | 表单访问（edit）+ 删除位 | 404；删除位不足 403；幂等键不合法 400 |
| `GET /form-definition` | 表单定义（模式 + 动作位 + 能力位） | 模式非法 400 `INVALID_FORM_MODE`；**动作位不足 403**；名单外 / 能力位不符 404 |
| `POST /action/{actionKey}` | 动作入口（不要求统一表单名单） | 404；幂等键不合法 400 |
| `GET /actions` | 定义装配 + 有可写页面 | 404 |
| `POST /approve`、`/deapprove`、`/endcase`、`/unendcase` | 定义装配 + 可写页面 + 动作位 | 名单外 404；动作位不足 403 |
| `GET` / `PUT /field-settings*`、`PUT /column-widths` | 字段维护面（浏览位 + 维护位） | 403 |

> `form-definition` 的 **403** 与其余路径的 **404** 是两条不同的既有口径，**不要统一**：
> 前者是动作级权限位不足，后者是"模块/记录不在你的可访问范围"的防探测设计。

## 三、读取路径

```
/records 或 /query
   ↓
取定义（快照优先，见 41 篇）
   ↓
叠加当前用户的部分：字段级权限、列偏好、数据范围
   ↓
字段白名单校验（不可见字段不得查询/排序）
   ↓
QueryConditionRenderer 渲染结构化条件（见 44 篇）
   ↓
合并数据范围（AND）
   ↓
参数化执行
```

三条硬约束：

- **子表查询必须带有效的主表关联键**（`/details` 的参数），缺少关联条件时禁止无条件读取——
  否则一次失误就把整表带出来；
- **排序字段必须来自服务端定义的可见列**；
- **数据范围是 `AND` 合并进来的**，不是可选项。

## 四、写入路径

新增/修改/删除都走同一条受控通道：

1. **权限门**：按动作判定（新增需 `CanAddNew`，修改需 `CanEdit`，删除需 `CanDelete`）；
2. **字段级限制**：被"禁新增/禁改"的字段不得写入；
3. **校验**：字段校验规则（必填、正则、长度、引用存在等）；
4. **效果引擎**：保存前后的效果链（见 [47-单据行为效果引擎](./47-单据行为效果引擎.md)）；
5. **事务**：业务写入与审计**同一事务**；
6. **审计**：`AUDIT_EVENT` + 字段级变更明细。

### 删除路径：先守卫，再从属行处置，最后落库

删除比保存多两道拦：**状态与流程守卫**（结案、已批核有副作用、在途流程、已有库存流水，
见 `WorkbenchApprovalService.EnsureDeletionAllowedAsync`）与 **DELETE 阶段的校验目录**
（`MODULE_VALIDATION_RULE` 的 `custom-validation`，见 [47-单据行为效果引擎](./47-单据行为效果引擎.md)）。

之后是**从属行处置**（`Data/Workbench/WorkbenchDeleteCascades`，按主表登记的闭集）：
主档的某些从属行是**服务端自动生成**的，用户看不到、也没有逐个删除的入口——新建仓库时写入的
库位哨兵行（`LOCATION_NO='-'`）即属此类。不处置，这类主档就"建出来便删不掉"：外键冲突冒泡成 500。

口径是**未被库存使用时随宿主清理，已被使用时以可读码拒绝**（`DEPOT_IN_USE`）。不能一律级联——
库位被库存余额 / 流水 / 批次明细与货位分配引用，级联等于物理销毁库存台账；也不能一律拒绝——
那样登记错一个仓库就没有退路。库位是自引用树，且 `FK_DEPOT_LOCATION_PARENT` 是
**SAME TABLE REFERENCE**（行级即时校验，同语句先删父再删子当场冲突），因此按"没有下级引用的行优先"
反复删——判据是**"没有下级"而不是"没有上级"**：根节点同样可能有子树。

**仍被外键拦下的删除**（例如主档被业务单据引用）由 `WriteFailureTranslator` 翻成
`REFERENCE_CONFLICT` 的 400，与新增 / 修改同口径：删除路径同样不允许把库层错误原文冒泡成 500。

### 幂等与并发

- **幂等**：重复提交（连点、重试）不应产生重复数据，工作台命令路径有幂等保护；
- **并发**：并发修改同一条单据不得静默覆盖，服务端检测到已被他人改动时返回冲突。

### 预演（`dryRun`）

`CreateRecordAsync` / `UpdateRecordAsync` / `DeleteRecordAsync` 各有一个 `dryRun` 开关：
为真时跑**完整条路径**（校验、单号、效果链、状态翻转）后把提交换成**无条件回滚**，
并跳过提交之后才发生的自动批核。预演与执行共用同一段代码，因此不会出现"预演说没问题、执行却失败"的漂移；
单号、效果与状态翻转随回滚一起释放，幂等键也不占位（预演不 claim）。

调用方是助手动作层（`EOS.API/Features/Assistant/Actions`）：预演走这条路径取"能不能做、为什么不能"，
执行前再独立重新授权一次。**助手不是特权调用者**——它用的是与界面完全相同的那条写管线。

### 助手代表的写入（审计身份）

写管线与审计写入器之间有请求作用域内的一个标记（`Data/Workbench/AgentWriteContext`）：
助手发起的新增 / 修改 / 删除会把审计记为 `ACTOR_TYPE=3` / `CLIENT_TYPE=3`，
而 **`ACTOR_USER_ID` 仍是真实用户**（权限主体恒为使用者）。标记**只影响审计身份，不参与授权判定**，
详见 [30-审计日志](./30-审计日志.md)。

### 事务边界

一次保存是**一个事务**：主表 + 明细 + 效果链 + 审计要么全成、要么全回滚。
不要在控制器里手工拆事务。

### 状态位拒绝编辑时说的那句话只有一份

已结案 / 已批核 / 流程在途三类拒绝（错误码 `FINISHED_EDIT_FORBIDDEN` /
`CONFIRMED_EDIT_FORBIDDEN` / `FLOW_IN_PROGRESS_EDIT_FORBIDDEN` 与对应文案）登记在
`EOS.API/Data/Workbench/LifecycleEditGuards.cs`，**保存路径与只读诊断路径共用同一份**。
新增同类拒绝（例如又一种"当前状态不允许改"）时加进这里，不要就地写字符串——
两份文案必然漂移，而用户会在诊断里同时看到它们。

## 五、列配置

| 操作 | 端点 | 说明 |
|---|---|---|
| 读当前列 | `GET /columns` | 用户自定义列（有则用，见 12 篇的优先级规则） |
| 读编辑器数据 | `GET /column-editor` | 当前列 + 系统默认列，供编辑器展示 |
| 保存 | `PUT /columns` | 上限 200 列，字段须在可见白名单内，先删后插、单事务 |
| 重置 | `DELETE /columns` | 删除该用户在该表上的配置 |
| 批量列宽 | `PUT /column-widths` | 钳制 `[40, 300]`，单事务，写后标脏 |

**列宽持久化只在这里做**（写回 `FIELDS.DISPLAY_LENGTH`，需 `CanSetup`）。
其他列表的列宽一律本地持久化，不得新增写回服务端的逻辑。

## 六、字段设置

`/field-settings` 提供字段元数据的读写，需要**字段维护模块（2302）的 `CanSetup`**。
保存后：写回 `FIELDS` → 标脏该模块 → 记审计（资源类型 `WORKBENCH_METADATA`）。

详细规则见 [11-元数据运维](./11-元数据运维.md) 与 [12-元数据消费](./12-元数据消费.md)。

## 七、动作与按钮

- `GET /actions` 返回该模块**当前用户可见**的动作与自定义按钮；
- 按钮级授权是 **fail-closed** 的：未获授权的用户**不渲染按钮**，服务端另行鉴权；
- 动作执行统一走 `POST /action/{actionKey}`（批核/结案等有专用端点，语义更明确）。

按钮的**位置**由前端固定顺序决定，`MODULES.FORM_BUTTONS` 只决定动作**有无**，
不决定位置（见 [03-工程规范与硬约束](./03-工程规范与硬约束.md) 的工具栏约定）。

## 八、导出

- `/export`：按当前查询条件导出全部命中行；
- `/export-selected`：导出所选行，**1~500 行**，主键数量必须与模块定义一致，
  否则返回 `INVALID_EXPORT_KEYS`；
- 导出是**读路径**，审计用 best-effort 写入（不阻塞导出）；
- 导出字段按定义的可见列解析，**不导出被禁看的字段**。

## 九、前端

`EOS.Web/src/features/document-workbench/`：

| 文件/职责 | 说明 |
|---|---|
| `DocumentWorkbenchPage.tsx` | 列表态页面 |
| `FormEditorPage.tsx` | 统一表单编辑页：主表复合格 + 明细网格 |
| `FormFieldRenderer.tsx` | 单字段渲染（控件 + 选择器按钮）；浏览态走只读文本 |
| `ChooserSourceMenu.tsx` | 多数据源字段的「来源菜单」（贴在选择器按钮上，见下） |
| 表格 | 统一使用 `ErpTable`，行内单选、列宽拖拽等默认能力 |
| 工具栏 | 只放列表自身工具与「新增」入口；单据级动作不在这里 |
| 字段渲染 | 选值走 `UnifiedChooser` |

前端**不定义列、不定义字段、不判断权限的真实性**——它渲染服务端给的（定义 + 权限），
服务端仍会对每个请求重新授权。

**明细录入格的 `cell` 必须是稳定组件**：`ErpTable` 把列的 `cell` 当作 React 元素类型，
写成行内箭头函数时每次渲染都是新身份，React 据此**把整格卸载重挂**，正在输入的控件随之失焦
（表现为每敲一个字符都要重新点一下）。故编辑态明细列固定用模块级的 `DetailEditCell`：
行值取 `row.original`，错误、来源菜单与回调经 `DetailEditContext` 下发。

**复合格（`cellGroup` / `cellRole` 驱动，前端不按字段代号特判）**：

- 同格各字段**等宽均分**（`flex: 1 1 0`）：两组合、三组合、四组合一律均等，不出现"一长一短"；
- **带选择器的字段与它的选择按钮算一个整体**（按钮在字段控件的行内），
  故"厂商编号 + 选择按钮"与"厂商名称"两个整体等宽；
- 三件套里**三处距离相等**：字段↔按钮、按钮↔下一个字段、字段↔字段都取
  `--erp-form-control-gap`（设计态与编辑/新增态同一 token，画板与运行态观感一致）。

**多数据源字段的来源入口**：

- 只有一个启用来源时直接打开 `UnifiedChooser`；有多个时先在选择器按钮下方弹来源菜单；
- 菜单**与按钮连成一体**（左缘对齐）：弹出时按钮让出朝向菜单的那侧边框与圆角
  （向下弹 → 按钮下边框为 0、左下/右下为直角，菜单左上角为直角；向上弹则上下相反），
  菜单朝按钮那侧再**挪 1px**（向下弹取 `margin-top:-1px`，向上弹取 `margin-top:1px`——
  菜单按 `top` 定位，`margin-bottom` 对 fixed 元素无效），
  按钮同时**不透明 + 抬高到菜单之上**（`z-index:1083` > 菜单 1082），
  于是被盖住的是菜单那条边框，接缝上只剩按钮自己那条边；hover 态也强制同底色，
  否则鼠标正停在按钮上时按钮变灰、菜单不变，接缝会露出色差；
- 字段贴近屏幕下缘（下方放不下）时**改从按钮上方弹出**（方向在打开那一刻按按钮位置判定）；
- 选过的来源随保存下发（`chooserSources`），服务端据此记住"这张单当初从哪个来源选入"。

**选择器取数的 FROM 由两路 JOIN 拼成，必须按别名去重**（`form-chooser/{fieldKey}` 服务端）：
过滤条件的跨表 JOIN（`ChooserFilterCompiler` + `ChooserJoinCatalog`）与回填映射里虚拟列的
JOIN（`VirtualColumnResolver`）拼的是**同一段 FROM**，两路各自拼一次同名别名时 SQL Server 直接报
"在 FROM 子句中多次指定了相关名称"（整单选择器 500）。
典型触发：来源表的过滤条件引用 `PRODUCT.BUSINESS_TAG`，回填映射又要 `PRODUCT.PRO_NAME` 这类虚拟列。
故 `BuildJoinClause` 回传**本段实际出现的别名**（含依赖闭包），虚拟列解析把重复的别名让出去——
两侧别名同源同一张 `QUERY_RELATION`，让出的那一段必然已存在，SELECT 片段照常引用得到。

**正则校验（`FIELDS.REGEX`）**：

- **正则文本不显示在控件下方**，改由控件自身的 `pattern` 属性承载（只在原生文本输入上设；
  数值类控件里存的是带千分位的展示串，套原始正则会误判，故不设该属性）；
- **失焦即校验**（`FormFieldRenderer.onFieldBlur` → `formValidation.validateField`，与服务端同一份判定）：
  空值先按必填判（必填报"该字段不能为空。"），**可空字段空值直接放过**，有值才比对正则；
- 键入即清掉旧错误（`changeMasterValue`），下一次失焦再给新结论。

**矩形尺寸由版式说话**：长文本（`text`/`ntext`、`*REMARK`）**只在版式没排过时**才按"整行独占 + 多行"
兜底；版式排过（`rowSpan` 有值）就以版式为准——`rowSpan = 1` 用单行输入控件，
`≥ 2` 的文本框高度按每行 26px 给（2 行 = 52px，与默认一致）。

**自建浮层的视口定位**：所有自定义右键/浮层菜单统一走
`EOS.Web/src/components/common/useMenuPlacement.ts`（按菜单真实尺寸量测）——
默认向右下展开、右/下越界向内收，**下方放不下则整体翻到落点上方**，不再被窗口裁掉。

## 十、排障

| 现象 | 原因 |
|---|---|
| 列表少列 | 该用户有 `SYSQL_FIELDS` 配置 → 完全采用用户配置（见 12 篇） |
| 查询某字段无结果 | 该字段不在定义的可见列里，被白名单拦掉 |
| 明细查不出来 | `/details` 缺主表关联键，被拒绝 |
| 改了配置界面没变 | 快照未重发布（见 [41-定义快照与发布](./41-定义快照与发布.md)） |
| 新增按钮不见了 | `MODULES.NEW_URL` 为空；或无 `CanAddNew` |
| 导出行数报错 | 超出 1~500 区间，或主键数量与定义不一致 |
| 保存成功但明细没写 | 明细关联键无效；查审计里的字段级变更确认到底写了什么 |
| 明细录入每敲一个字符就失焦 | 列的 `cell` 写成了行内箭头函数（每次渲染都是新元素类型）→ 整格被卸载重挂；编辑态明细列必须用模块级组件（见 §九） |

## 十一、扩展时怎么做

| 要做的事 | 改哪里 |
|---|---|
| 给某模块加字段/列 | **配置**：`FIELDS` + 列配置 + 版式（走迁移） |
| 给某模块加按钮 | `MODULES.FORM_BUTTONS` + 按钮授权名单 |
| 给某模块加业务规则 | 校验规则目录 或 效果配置（见 47 篇） |
| 改工作台对**所有**模块的行为 | 改控制器与 `Data/Workbench/`，并同步本手册 |
| 只服务某一个领域 | **不要**往工作台里加业务开关，放 `EOS.API/Features/<域>/` |
