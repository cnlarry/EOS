# 10 元数据模型

EOS 的界面形态由库内元数据决定：**加一个模块 = 往元数据里加数据，不是写一个新页面**。
三张核心表是这套机制的根：

| 表 | 主键 | 作用 | 当前规模 |
|---|---|---|---|
| `MODULES` | `M_IDX` | 模块：菜单节点、权限锚点、主/明细表绑定 | 364 行 |
| `TABLES` | `T_ID` | 表登记：哪些物理表可供界面使用 | 488 行 |
| `FIELDS` | `T_ID` + `F_ID` | 字段登记：每个列怎么显示、怎么校验、怎么选值 | 12104 行 |

> 行数是本文写作时的实测值，会随开发变化，不必当常量记。

## 一、`MODULES`：模块

模块是业务单元。它同时承担四件事：菜单节点、权限锚点、单据结构声明、界面配置入口。

### 树结构

| 列 | 含义 |
|---|---|
| `M_IDX` | 模块编号（主键） |
| `M_P_IDX` | 父模块编号 |
| `M_ROOT_IDX` | 根模块编号（便于整树取用） |
| `SORT_IDX` | 同级排序 |
| `M_DESC` / `M_ALIAS` | 显示名 / 别名 |

### 路由与图标

| 列 | 含义 |
|---|---|
| `M_URL` | 浏览（列表）路由 |
| `NEW_URL` | 新增路由；为空表示不能新增 |
| `MODI_URL` | 修改路由；为空表示不能修改 |
| `HELP_URL` | 帮助入口 |
| `M_ICON` | 菜单图标 |

**只读模块的做法是让 `NEW_URL` / `MODI_URL` 留空**，而不是在前端隐藏按钮——服务端据此判定该模块不开放写入。
路由本身还要登记进服务端路由白名单，否则按未映射处理。

### 单据结构

| 列 | 含义 |
|---|---|
| `MASTER_TABLE` | 主表（`TABLES.T_ID`）。为空 = 该模块不是单据模块 |
| `DETAIL_TABLE` | 明细表。为空 = 只有主表 |
| `DETAIL_NO_FIELDS` / `DETAIL_NO_SAVE` | 明细相关控制 |
| `NOT_BACK_FIELDS` / `NOT_BACK_FIELDS_M` | 不允许回填的字段（明细 / 主表） |
| `IF_COPY` | 是否允许复制单据 |
| `AUTO_APPROVE` | 保存即自动批核 |
| `ERROR_NO_SAVE` | 出错时不保存 |

当前 364 个模块中，306 个绑定了主表、181 个绑定了明细表（有明细的一定有主表）。

### 能力与状态列

| 列 | 含义 |
|---|---|
| `CONFIRM_TAG` | 是否具备批核能力。**声明了批核能力的模块，主表必须有对应的状态位列** |
| `EFFECT_ENGINE_TAG` | 是否走效果引擎 |
| `FORM_BUTTONS` | 表单按钮配置（只决定动作**有无**，不决定位置——顺序由前端固定） |

### 其它

- `M_TAG`：模块标记；
- `SEARCH_1` / `SEARCH_2` / `FILTER` / `SORT_FIELDS`：列表检索与排序配置；
- `GROUP1`~`GROUP5` + `GROUP_EXP1~5` + `GROUP_DESC1~5`：列表分组配置（表达式 + 显示名）；
- `CI` / `OWNER` / `OWNER_G`：公司别与归属（权限与数据范围的输入）；
- `CREATE_PERSON` / `CREATE_DATE` / `LAST_UPDATE_BY` / `LAST_UPDATE_DATE`：审计列。

## 二、`TABLES`：表登记

| 列 | 含义 |
|---|---|
| `T_ID` | 表名（主键），必须与物理库对象名一致 |
| `T_DESC` | 显示名 |
| `T_TYPE` | 对象类型 |
| `T_KIND` | `P` = 主表，`S` = 明细表 |
| `T_REMARK` | 备注 |
| `FK_T_ID_1`~`FK_T_ID_5` | 关联表 |
| `DF_CONDITION` / `DF_VERIFY` | 默认条件 / 默认校验 |
| `QUERY_RELATION` | 查询联表定义 |
| `CAN_IMPORT` | 是否允许导入 |

未被 `TABLES` 登记的表，界面层用不到它。

## 三、`FIELDS`：字段登记

字段元数据分几组，逐组说明。

### 身份与显示

| 列 | 运行时含义 |
|---|---|
| `T_ID` | 所属表（复合主键之一） |
| `F_ID` | 列名（复合主键之一），必须与物理列名一致 |
| `F_DESC` | **显示名（标签）**。不是列名 |
| `F_TYPE` | 数据类型 |
| `DISPLAY_LENGTH` | 列宽 |
| `DISPLAY_FORMAT` | 显示格式 |
| `ITEM_ALIGN` / `HEADER_ALIGN` | 内容对齐 / 表头对齐 |
| `F_REMARK` | 备注 |
| `LAST_UPDATE_BY` / `LAST_UPDATE_DATE` | 审计列 |

### 行为开关

| 列 | 含义 |
|---|---|
| `IS_VISIBLE` | 是否可见。**幽灵字段（元数据还在、物理列已被改名或删除）应置 0**；虚拟字段没有物理列，不算幽灵字段 |
| `IS_DEFAULT_FIELDS` | 是否进入系统默认列（用户没自定义时用哪些列，见 [12-元数据消费](./12-元数据消费.md)） |
| `IS_QUERY` | 是否可作查询条件 |
| `IS_READONLY` | 是否只读 |
| `IS_VERIFY` / `VERIFY_INDEX` | 是否必填 / 校验与排序序号 |
| `IS_PK` | 是否主键列 |
| `IS_AUTOINC` | 是否自增 |
| `IS_COST` | 是否成本字段（按权限位控制可见） |
| `IS_SECRECY` | 是否机密字段（按权限位控制可见） |
| `CAN_COPY` | 复制单据时是否带过去 |
| `DFT_VALUE` | 默认值 |
| `REGEX` | 校验正则 |

### 虚拟字段

| 列 | 含义 |
|---|---|
| `IS_VIRTUAL` | 是否虚拟字段（值由表达式算出，库里没有对应物理列） |
| `VIRTUAL_EXP` | 虚拟列的表达式 |
| `CONVERT_FUNCTION` | 转换表达式 |

库内约束（实测）：`IS_VIRTUAL=1` 的 1549 行**全部**有非空 `VIRTUAL_EXP`，没有例外。
表达式随字段保存即生效，详见 [45-受限表达式与虚拟字段](./45-受限表达式与虚拟字段.md)。

### 选值配置

| 列 | 含义 |
|---|---|
| `BROWSE_URL` / `BROWSE_M_IDX` | 选单入口 / 目标模块 |
| `ONLY_CHOOSE` | 只能选、不能手输 |
| `CHOOSE_PAGE` / `CHOOSE_MULTI` | 选单页 / 是否多选 |
| `FORM_OPTIONS` | 下拉选项定义（固定枚举用） |

选值能力的现代形态是统一选择器，详见 [46-统一选择器](./46-统一选择器.md)。

## 四、表单版式：`MODULE_FORM_LAYOUT` 与 `MODULE_FORM_TAB`

字段级版式已不再是 `FIELDS` 上的列，而是独立的版式表。

### `MODULE_FORM_LAYOUT`（11583 行）

主键 `M_IDX` + `T_ID` + `F_ID`。

| 列 | 含义 |
|---|---|
| `TAB_NO` | 所属页签 |
| `ORDER_NO` | 页签内顺序 |
| `SPAN` / `ROW_SPAN` | 横向跨列数 / 纵向跨行数 |
| `NEW_LINE` | 是否另起一行 |
| `SECTION_ID` | 区段 |
| `CELL_GROUP` / `CELL_ROLE` | 复合格：**同组字段共用一个标签**，主字段带标签、从字段不重复出标签 |
| `IS_HIDDEN` | 是否隐藏（**必填列不允许隐藏**） |
| `UPDATED_BY` / `UPDATED_AT` | 审计列 |

### `MODULE_FORM_TAB`

`M_IDX` + `TAB_NO` + `TAB_TITLE`：页签编号与标题。

> 版式是**模块级**的：同一个表在不同模块下可以有不同的排布。

## 五、列配置：`SYSQL_FIELDS` 与 `SYSQL_DEFAULT`

| 表 | 键 | 含义 |
|---|---|---|
| `SYSQL_DEFAULT` | `T_ID` + `T_ID_R` + `F_ID`（+ `F_IDX`） | **系统默认列**：用户没自定义时显示哪些列、什么顺序 |
| `SYSQL_FIELDS` | `USER_ID` + `T_ID` + `T_ID_R` + `F_ID`（+ `F_IDX`） | **用户自定义列** |

- `T_ID` 是主表，`T_ID_R` 是目标表——主子表场景下用同一张配置表区分主表列与明细列；
- `F_IDX` 是顺序号；
- 优先级规则见 [12-元数据消费](./12-元数据消费.md)：**用户有配置就完全采用用户配置**。

`SYSQL_CONDITION` 是另一类：用户保存的查询条件（见 [44-受控查询与条件模板](./44-受控查询与条件模板.md)）。

## 六、你该知道的两处现存数据问题

改动元数据时留意，别把它们扩散。

**1. `FIELDS.F_TYPE` 混有非类型名的值**

实测分布（部分）：`nvarchar` 5895、`float` 2252、`datetime` 1281、`nchar` 1147、`bit` 821……
但另有 **`String` 14 行、`Integer` 1 行、NULL 13 行**。

`F_TYPE` 的约定是 SQL 类型名。新增/修改时用正确类型名；遇到这几行按需订正，不要照抄。

**2. `F_DESC` 曾出现占位文本**

历史上把"无说明"写成了非空占位文本 `'NULL'` 与 `'&nbsp;'`，读取侧"空则回落字段代号"的兜底拦不住，
于是标签上直接显示字面量 `NULL`。现读取侧已显式剔除这两个值，
`F_DESC` 的合法值就是**真描述或 NULL/空串**，不要再写占位文本。

## 七、已退役的列（看到别纳闷）

以下列在库里**已不存在**，历史迁移或旧文档里仍可能见到：

| 已删除 | 曾经的用途 |
|---|---|
| `FIELDS.DATASOURCE_SQL` | 字段数据源 SQL，由虚拟列表达式体系取代 |
| `MODULES.FORM_TABS` / `FORM_COLUMNS` | 字段级页签与分栏，由 `MODULE_FORM_LAYOUT` / `MODULE_FORM_TAB` 取代 |
| `MODULES.UPDATE_SP` / `AFTERSAVE_SP` | 保存前后过程钩子，由校验与效果体系取代 |
| `SYSDH_REPORT` | 组报表权限，报表可见性改为取归属模块的 `REPORT_TAG` |

代码与脚本里不得再引用这些名字。
