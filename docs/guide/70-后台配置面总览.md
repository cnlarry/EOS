# 70 后台配置面总览

"这个配置在哪改"是最高频的问题。这篇是一张**入口地图**——每个后台管什么、端点在哪。

配置面是**白箱化**的：每个后台都有明确的接口与权限门，不存在"改某个隐藏文件"的路子。

## 一、入口总表

| 配置面 | 路由前缀 | 管什么 | 详见 |
|---|---|---|---|
| 菜单与模块 | `api/v1/admin/menus` | 模块树、菜单显示、模块属性（**230101**） | 第二节 |
| 模块分组 | `api/v1/admin/module-groups` | 为其它模块维护列表分组（分组名称 / 表达式 / 顺序）·**230102** | 第二节 |
| 自定义按钮 | `api/v1/admin/module-buttons` | 为其它模块维护自定义按钮（处理器键 / 文案 / 启用 / 授权镜子）·**230103** | 第二节 |
| 行为动作 | `api/v1/admin/module-business-config` | 为其它模块维护效果链动作与校验规则（页内两个页签、一次提交）·**230104** | 第二节 |
| 分组读取 | `api/v1/navigation` | 读模块的分组定义与分组值（工作台列表的筛选入口） | 第二节 |
| 用户 | `api/v1/admin/users` | 用户主档、启停用、密码、所属组 | 第三节 |
| 权限 | `api/v1/admin` | 个人/组权限矩阵、按钮级权限、字段级拒绝 | [22-权限配置后台](./22-权限配置后台.md) |
| 字段与表 | `api/v1/admin`、`api/v1/table-data` | 表登记、字段登记、列配置、字段设置 | [11-元数据运维](./11-元数据运维.md) |
| 模块业务配置 | `api/v1/admin/module-business-config` | 模块级的业务开关与规则绑定（**230104** 面；`?scope=` 决定替换哪一片） | 第四节 |
| 系统参数 | `api/v1/settings` | 可配置的运行时参数 | 第五节 |
| 报表维护 | `api/v1/report-admin` | 报表定义与数据集、条件模板、版式绑定、**开单公司**（`COMPANY_ID`，`GET /report-admin/companies`） | [51](./51-报表可视化设计器.md)、[52](./52-报表打印版式.md) |
| 工作助手管理面 | `api/v1/admin/assistant` | 供应商与模型（对话 / 嵌入）、知识库集合与文档、助手参数与作用域覆盖 | [60-AI工作助手](./60-AI工作助手.md) |
| 应用信息 | `api/v1/app` | 用户、权限、菜单树引导数据（`bootstrap`） | — |

> `api/v1/admin` 由多个控制器共用（权限、字段维护、菜单），靠子路径区分。

## 二、菜单与模块

`MenuAdminController`（`api/v1/admin/menus`）+ `NavigationGroupsController`（`api/v1/navigation`）。

这里维护的就是 `MODULES` 表（见 [10-元数据模型](./10-元数据模型.md)）：

- 模块树的层级与排序；
- 菜单显示名、图标、承载页（`M_URL`，**唯一路由字段**：空 = 目录节点、`/workbench` = 统一工作台、精确路径 = 自定义页）；
- 主表/明细表绑定；
- 表单呈现（打开方式 / 弹窗宽高）与页签列数：**不在本模块里配**——只能进表单设计器改（单据表单页的字段设置菜单 ›【表单设计】；页签行右端【表单呈现】+ 页签右键「布局列数」），**保存即生效**；
- 检索与排序配置。

> **左侧菜单的悬停提示是 `{M_IDX}-{M_DESC}`**（如 `2301-模块管理`）：模块编号是模块在库里的身份，
> 配置面、报表、流程图都按它指认模块；只给名字时，用户没法把界面上的这一项与手上的模块号对上。
> 为此 `/app/bootstrap` 对**分组节点也下发 `moduleId`**（纯目录分组同样有），前端据此拼提示，
> 挂在树里的每一项与折叠态浮层的每一行的 `title` 上。菜单搜索另有 `route` 那道门，不受影响：
> 纯目录分组虽然也带编号，仍不参与搜索（它没有可打开的页面）。

**列表分组不在这里配（迁移 341/342）**：工作台列表右上角的分组下拉由独立模块 **230102「模块分组」**维护
（原 2315，迁移 347 重编号）——它是一个**定制承载页**（`/admin/module-groups`），要办的事是
"选一个模块 → 维护**它的**分组"（分组名称 / 分组表达式 / 顺序），这些**其它模块**的配置不是通用表单能表达的，
所以不走统一表单，也不走发布流程（分组表达式在组装工作台定义时实时读取、不进快照——保存即生效）。
2301 原来的「分组」页签与那 15 个字段随之删除。

**三个行为配置面各自独立成页（ADR-033，迁移 347/348/349）**：2301 原来的三个行为页签全部迁出，
230101 只定义"模块是什么"（基础 / 主表 / 子表），配置面按"配什么"分开：

| 面 | 模块 | 定制页 | 端点前缀 | 权限门 |
|---|---|---|---|---|
| 自定义按钮 | **230103** | `/admin/module-buttons` | `api/v1/admin/module-buttons` | 230103（读 `CanBrowse` / 写 `CanSetup`） |
| 行为动作 | **230104** | `/admin/module-actions` | `api/v1/admin/module-business-config?scope=actions` | 230104（读 `CanBrowse` + `CanModuleConfig` / 写 `CanSetup` + `CanModuleConfig`） |
| 显式发布（模块级） | 230101 | —（菜单页内按钮） | `api/v1/admin/module-business-config/{id}/publish` | 230101 |

- **230104 用两栏外壳：左栏是模块清单，右栏是选中模块的配置**（`EOS.Web/src/features/admin/ConfigWorkbench.tsx`）：
  没有"选择模块"弹窗、也没有"双击总览行才进编辑"这类隐藏手势。左栏用一个**下拉**按"配了什么"筛选
  （**有配置 / 有动作 / 有规则 / 全部**，默认「全部」，选项里带各档模块数），每行**分列两个计数**（动作数、规则数）——一个总数看不出
  "这个模块是配了动作还是只配了规则"；排序恒按模块号，不按已配条数，否则刚保存的模块会跳到列表顶部、
  鼠标下的行换人。深链接 `?moduleId=`、未保存有一个点、切换有脏确认（`Modal`，不是原生 `confirm`）、
  只读账号出"只读 + 原因"，且**新建 / 编辑 / 删除 / 保存一律不可点**（不是点完才被服务端 403）。
  未选中模块时右栏给**按模块聚合的全库总览**（模块号 / 模块名 / 主表 / 动作数 / 规则数 / 停用数 / 事件分布），
  需要逐行事实时切「**动作明细 / 规则明细**」——一上来铺 328 行既读不完也搜不动
  （实测库内确有 328 条效果链动作 + 188 条校验规则）。
  总览只读，**编辑仍按模块进行**（不新增编辑机制）；
  三个面各有一个 `overview` 读端点（`GET …/module-groups/overview`、`…/module-buttons/overview`、
  `…/module-business-config/overview`），它同时供左栏与总览；谓词与保存路径的删除谓词同源
  （`= MANUAL` / `<> MANUAL`），两者分叉会让界面显示一批保存时不归它管的行——真库契约见
  `EOS.API.Tests/ConfigOverviewLiveTests.cs`。（前端原有的 `ConfigOverview` 组件已退役删除，不留双份实现。）
  外观与菜单管理（230101）一致，也与全站列表页同一套外壳：整页是标准列表卡（`ErpListCard`——
  白色圆角卡片 + 顶部命令栏，搜索框与各面按钮分别走它的 `search` / `actions` 槽），
  页面根另挂语义类 `.erp-config-workbench`，模块清单与配置区两栏走 `card-body`。
  两栏按字段设置页那套骨架（卡片体作 grid、左右各自内部滚动），页面级不出滚动条，**不写死 `vh` 高度**。
  右栏页头只有一条：模块名 + 编号 + 可改/只读 + 主表与明细 + 当前条数 + 保存状态
  （`未保存` / `已保存 · 已发布 vN` / `已保存但未生效`）。「保存」只在**有未保存改动且可写**时可用——
  没改动也能点会白白走一次保存 + 发布。命令栏的「刷新」语义只有一个：**丢弃草稿并重取**（有脏改动先确认），
  不存在第二个叫"重新加载"、行为却不同的按钮。
- **230102 与 230103 走扁平列表 + 弹窗**：两者配的同样是"别的"模块，但模块在界面上只是**行上的一列**
  （可排序、可搜索）——一整张跨模块的 `ErpListGrid` 列出全库行（模块号 / 模块名 / 各自的内容列 / 操作），
  右上角「新增」与操作列「编辑」共用一具 `Modal`，删除另走一具确认弹窗。新增时都先选模块，
  候选走已注册的统一选择器数据源（`module-groups.targets` / `module-buttons.targets`，与各自写路径的目标模块同源）。
  - **230104 之外的差异在写路径**：230103 的按钮行是**按模块整面替换**，故弹窗提交前先取该模块的
    **完整**按钮行再改（总览下发的是投影，拿它回传会把界面不显示的条件 / 参数 / 反向 / 公式行抹掉）；
    230102 的分组行是**逐行增删改**（`POST` / `PUT` / `DELETE` / `move`），弹窗保存只动这一行。
  - 230103 的「谁能用」随 `overview` 一起下发（按模块成组：授权粒度是「模块 + 按钮键」），
    故 0/0 的"配了没人能用"能直接摆在行上；230102 的**样例值**要真跑一次查询，故只在弹窗里显示
    （`GET …/{moduleId}` 才有），列表只给「表达式校验」的可用性——逐模块真跑查询不压在首屏上。
- **两个面的行都按模块分块、都不合并单元格**：模块分组天生是"一个模块挂两三条"，自定义按钮也可能一个
  模块配好几个，所以模块号与模块名会在多行上重复——但跨行合并**不做**：`ErpTable` 每行每列必产出一个
  `<td>`（合并要改公共组件），而合并会打坏复制（它按列索引取单元格）与排序（同模块的行一被重排，
  合并块就碎）。改为按「模块号 + 顺序」聚拢，并在每块第一行画一条分隔线（`.erp-module-block-start`）；
  一按列排序，同模块的行散开，线随之隐藏。
- **模块内排序各走自己现成的写路径**：230102 有 `move` 端点（逐行 top/up/down/bottom），点一次一次请求；
  230103 没有这个端点，用它本来就有的"按模块整面替换"——取该模块完整按钮行、互换相邻两行的 `SEQ`、
  再整面提交。两者都按"块内第一行不能上移、最后一行不能下移"禁用按钮，所以**只配了一个的模块两个方向
  都点不动**。
- **230104 编辑面复用 230101 的那一份面板，不另造一套**：进入模块后默认选中第一条动作，
  下方直接是它的"加工单"逐句表格（点句选中该步骤，sheet / grid 两种视图）——不必先猜要点哪一行。
  工具条分三级、权重不同：页签内容顶部只放**视图切换**（配方 / 专家）与**只读诊断 / 批量动作**
  （预演、行为说明书、停用全部动作，均为 ghost 次级按钮）；列表级的「新增 / 从其它模块复制」在表格标题行；
  **编辑 / 复制 / 上移 / 下移 / 删除只在选中一行后出现在上下文条里**（双击行也可直接编辑）。
  「停用全部动作」走 `Modal` 确认，写完由服务端**自动发布一次**（与保存同语义），结果复用同一条
  发布提示——不再出现"停了但本页没有发布入口"的死角。
  弹窗只用于编辑**单条**动作 / 步骤：按"何时触发 / 做什么 / 条件与追溯"分区，低频项默认折叠并标
  "已设 / 未设"；结构化 JSON（源加减项）边输边校验；底部给一句人话"保存后会发生什么"。
  两个面配的是同一条链、同一套语义，复制一份编辑器才是债——所以页面上看到的面板与 230101 行为页签里的是同一个。

两条由此产生的机制，拆页面之前必须先有（ADR-033 §6）：

- **写路径显式作用域**：按钮与效果链动作**同表**（`MODULE_BUSINESS_ACTION`，按钮是 `EVENT_CODE='MANUAL'`），
  而写路径是"整模块全删全插"。两个面各自保存时若都发全量请求，保存按钮就会删光动作（反之亦然）——
  **静默数据损失**。故保存必须声明 `scope`：`manual` 只替换按钮行、`actions` 只替换非按钮动作 + 全部校验规则、
  `all` 保留全量语义（合成保存用）。未知 `scope` 一律 400，**不静默回退**；作用域与请求体不一致（按钮面里塞动作行）
  也直接拒。真库防线见 `EOS.API.Tests/ModuleBusinessConfigScopeLiveTests.cs`。
- **保存即发布（用户看不见发布这一步）**：按钮动作与校验规则都进快照、都要过发布门，
  故两个配置面的按钮就叫「保存」，**服务端保存成功后自动发布一次**；校验不通过时语义是
  "**已保存，但未生效**" + 逐条原因（响应带 `checks[]`）。**模块定义面的保存不自动发布**——
  它改的是主/副表这类结构性字段，常常要改多项后统一从 230101 发布。

配置面端点（`ModuleGroupAdminController`，门挂在 230102：读 `CanBrowse`、写 `CanSetup`）：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/admin/module-groups/{moduleId}` | 目标模块 + 它的分组清单（含每行表达式是否可用与原因、**样例值**） |
| `GET` | `/admin/module-groups/{moduleId}/fields` | 该模块可参与分组表达式的字段（与写入校验同一份白名单） |
| `POST` | `/admin/module-groups/{moduleId}` | 新增一个分组（顺序自动追加到末尾） |
| `PUT` | `/admin/module-groups/{moduleId}/{groupId}` | 修改名称与表达式 |
| `DELETE` | `/admin/module-groups/{moduleId}/{groupId}` | 删除分组 |
| `POST` | `/admin/module-groups/{moduleId}/{groupId}/move` | 同模块内排序（top / up / down / bottom） |

**只有统一工作台模块能配分组**：形态判据取视图 `dbo.V_MODULE_NODE`（迁移 340），选择器候选集
（`module-groups.targets`）与服务端拒存规则同源；表达式必须来自目标模块主表的物理字段
（虚拟字段与未登记字段都会被拒，且报错指名到列）。

**样例值**：每行还会带上 `samples`——把该表达式在目标主表**真跑一次**取前 3 个值（去重），
好回答"这个分组长什么样"（只给表达式答不出来；空 = 主表当前没有行）。它与 `available` **分开**：
`available` 只由受控编译器决定，样例执行失败走单独的 `sampleError`——把样例结果并进可用性判定，
会让一次瞬时失败（表被锁 / 正忙）被读成"表达式不可用"，把判定变成看运气。

读侧是 `NavigationGroupsController`（`api/v1/navigation`）：`GET {moduleId}/groups` 列该模块的分组、
`GET {moduleId}/groups/{groupId}/values` 取某组的分组值；工作台列表用 `groupId` + `groupValue`
做分组筛选（见 [40-统一工作台](./40-统一工作台.md) 末节）。

**注意**：能不能新增/修改由本页「统一表单」那两个开关（`UNIFIED_FORM_ENABLED` /
`UNIFIED_FORM_EDIT_ENABLED`）与权限共同决定，
路由字段不再参与（`NEW_URL` / `MODI_URL` / `HELP_URL` 已随迁移 321 物理删除）。
承载页 `M_URL` 留空 = 目录节点（只展开不跳转）；单据模块填 `/workbench` 走统一工作台；
自定义页填真实路径（需同时登记服务端路由白名单与前端路由表）。

**配置面按节点形态收敛（迁移 340）**：`MODULES` 一行是菜单节点，形态（统一工作台模块 / 自定义承载页 /
目录节点，判据见 [10-元数据模型](./10-元数据模型.md) 第一节）决定这一页露出什么——

- **统一工作台模块**：主表/子表、数据范围、排序字段、不可解批、**批核入口声明**（「启用批核」，
紧接「自动批核」；勾选要求主表具备批核状态 / 批核人 / 批核日期三列）、单据行为，
以及行为动作 / 校验规则 / 自定义按钮；行为页提供「**停用全部动作**」一键批量停用
（行级 `ENABLED`、只停效果链动作；模块级效果引擎开关自 ADR-035 起已退役）。「单据行为」一组现在是
**启用批核 / 自动批核 / 可以复制 / 异常记录不可保存**——旧的「效果引擎（灰度开关）」复选框已随
迁移 346 与 ADR-035 下线；
- **自定义承载页**：只留基础信息与"数据源"——主表/副表**只读**（它们是报表数据集、搜索中心与选择器的
  锚点，改这里会打断那些消费方），数据范围（`FILTER`）与通用查询仍可改；
  行为三类配置不出现：这些节点不装配工作台定义，配了也不会有消费方；
- **目录节点**：只剩基础 / 主表 / 子表（它靠承载页与主表定义自己是什么），其余一律不出现。

右侧默认是**浏览态**（表单只读），点「编辑」才可输入、才出现保存/取消；改名、启停、排序、移动、删除
始终在左侧菜单上做，不必进右侧表单。**不摆"形态说明"横幅**：这个节点是什么，由右侧留下的页签与可写的字段
自证，解释性横幅是噪声（同一口径见 [62-嵌入模型与知识库接线](./62-嵌入模型与知识库接线.md)）。承载页字段下
也不复述填法与形态判定：三种合法填法写在**占位符**里，填错由**保存期校验**当场拒掉并说清规则
（`MenuAdminRepository.Validate`）。
**「发布」与「版本历史」只对统一工作台模块出现**——发布快照只属于它们
（非工作台节点过不了发布的 `runtime_whitelist` 门，标脏也只会在"待发布"清单里挂上永远发布不出来的条目）。
服务端另有一道兜底：非工作台节点上形态外的配置在保存时被归一成默认值，主表/副表被改动则直接拒收。

配置页还会向工作助手**上报"正在配置哪个对象"**（字段面 / 数据源 / 按钮 / 效果键），
好让助手在你打开它时知道你正在配什么。上报只是**数据**：标识符由服务端按库内元数据校验、
**不作为权限依据**，各配置端点各自独立鉴权。见 [61-工作助手的处境与诊断](./61-工作助手的处境与诊断.md)。

## 三、用户与权限

| 面 | 路由 | 说明 |
|---|---|---|
| 用户主档 | `api/v1/admin/users` | 新增/修改/停用启用/设置密码/所属组 |
| 权限矩阵 | `api/v1/admin` | 个人与组的模块权限、按钮级权限、字段级拒绝 |

权限门是**权限管理员**（模块 `2306` 的 `CanSetup`）。配置流程与陷阱见
[22-权限配置后台](./22-权限配置后台.md)。

## 四、模块业务配置

`ModuleBusinessConfigController`（`api/v1/admin/module-business-config`）。

按模块绑定业务行为与规则。改动会影响该模块的保存/批核行为，**改完要重新发布定义**
（见 [41-定义快照与发布](./41-定义快照与发布.md)）。

相关的服务端登记在 `EOS.API/Data/ModuleBusinessMap.cs`（模块 → 领域规则、
需批核模块 → 主表映射、保存后行为已迁目录的模块清单），见 [11-元数据运维](./11-元数据运维.md) 第五节。

## 五、系统参数

`SettingsController`（`api/v1/settings`）+ `EOS.API/Data/SystemParameterService.cs`。

系统参数是**纵向化**的：每个参数有

| 项 | 说明 |
|---|---|
| 类型 | 参数值类型（`bit` / `int` / `decimal` / `string`） |
| 分组 | 界面上的归类（分组名与组间顺序也是数据） |
| 说明 | **必须非空**的人话说明 |
| 生效范围 | `immediate` / `restart`（**助手的参数全部是 `immediate`**，见 [60](./60-AI工作助手.md)） |
| 默认值 | 缺省值；**字符串型参数的默认值留在代码里**（列留 `NULL`），标量型写在列里 |
| **归属模块** | 参数挂在哪——**它同时决定"谁能改"** |

纪律：

- **说明不能为空**——空说明在界面上就是露出一个英文键，配置者看不懂；
- 引用键必须真实存在（校验规则、效果动作、已发布快照、源码里点名的参数键，
  都要能在对应归属模块里找到）；
- 同一分组内序号唯一。

**权限按参数行的 `OWNER_MODULE` 判，不按页面判**：写要该模块的 `CanSetup`。已登记的归属模块：
`110111` 系统参数设置、`180213` / `180662` 考勤、`3105` 助手设置。新增一个归属模块要同改三处：
`SystemParameterService.ScopeModules`（页面 scope 令牌）、`scripts/check-system-params.ps1` 的白名单、
以及该模块自己的读写入口。

> **例外：3105 助手设置不走通用端点。** 通用端点的写门是 `CanEdit`，而 3105 声明的是 `CanSetup`
> （那一页改的是系统提示词与全局限额，比模型管理更要紧）。所以助手参数**读写仍经
> `SystemParameterService`，入口却挂在 3105 自己的控制器下**；`ModuleForScope` 里没有 `assistant`
> 令牌，通用端点在它上面继续返回 404。见 [ADR-030 §4.3](../decisions/ADR-030-工作助手管理面.md)。

## 六、改配置的纪律

| 改动 | 怎么落 |
|---|---|
| 别人拉代码后**也需要的**（新模块、新字段、新列配置、新默认列、版式） | **写迁移**（见 [05-数据库迁移与建库](./05-数据库迁移与建库.md)） |
| 只影响本机数据/某个用户习惯 | 后台页面直接改 |
| 改了模块业务配置、字段元数据、版式 | 后台改完 → **重新发布定义**（见 41 篇） |

判断标准一句话：**这个改动别人拉下代码后需不需要？** 需要就写迁移。

> 它们来自人事主档（`SYS_EMPLOYEE`）与用户组（`SYS_USER_GROUP`），允许自改就等于在权威数据之外造第二处真源；
> 改密码也不在这一页（凭据操作走侧栏用户菜单的弹窗，见 [20-认证与会话](./20-认证与会话.md)）。
> 页根类 `erp-profile-page` 已在 `app.css` 的「页面骨架」那一组里，区块间距因此与其它页同为 10px

> 多标签工作区与侧栏折叠是外壳启动时读一次的配置，页面写入后提示"重新打开页面生效"。

> **新增定制页要同改三处**（否则菜单点进去是空壳页）：库内 `MODULES.M_URL`、
> 后端 `ModuleRouteValidator.ExactRoutes`、前端 `workspaceRoutes.tsx`。
> 日志管理就是按这个套路加的：模块 `2313`（系统管理 23 **本级**，迁移 353 从 2311 数据表维护移出）、
> 路由 `/admin/logs`、权限读位最初镜像 `110111`、**改锚本页模块 `2313`**（迁移 `284` 把初版的 `110112`
> 编号退役，按 23 段重编号）。
>
> **反向的减项也要三处同减**：操作审计当初也按这个套路做成了 `/admin/audit` 定制页，
> 迁移 354 判定它"就是一张表 + 一个只读列表"、改判为统一工作台承载（`M_URL=/workbench`）后，
> 库内 `M_URL`、后端 `ExactRoutes`、前端 `workspaceRoutes.tsx`（含 `lazyRoutes.tsx`）
> 与 `ModuleRouteValidatorTests` / `workspaceRoutes.test.ts` 里钉它的用例一并减掉，页面与专属控制器删除；
> **模块号保留**（权限锚点不变，授权行不用重配）。
>
> **一页一个模块号**：日志管理是 `2313`（`/admin/logs` 定制页）、操作审计是 `2316`
> （`/workbench/2316` 工作台承载页），两个都挂在 23 系统管理**本级**（迁移 353 把 2313 从 2311
> 数据表维护移出）。它们看似相近，其实读的是两种东西——运行日志是磁盘文件（只留 Warning+），
> 操作审计是库表 `AUDIT_EVENT`；共号会把"能看日志 = 能看审计"焊死。
> **换号要改的仍是那三处**：`MODULES.M_URL`、后端白名单、前端路由；
> 工作台承载的模块还多两位模块声明（统一表单可用 / 允许写入，见 [42-统一表单](./42-统一表单.md)），
> 外加权限行要按新号镜像一次（否则新模块无人有权限，页面进去是 403）。

> **两张诊断页的形制**：2313 日志管理是定制页，按统一工作台列表那一套做——`ErpListGrid` +
> `ErpCommandBar`（首列复选框、列宽可拖、行点击单选、吸顶表头），时间列走
> `EOS.Web/src/features/admin/timestamp.ts` 的 `formatTimestamp`：它只把服务端时间串截到秒，
> **不做时区换算**（这个时间是要拿去和日志文件、和同事对表的）。2316 操作审计直接由统一工作台承载，
> 时间列的"到秒"是字段元数据的事（`FIELDS.DISPLAY_FORMAT = yyyy-MM-dd HH:mm:ss`），
> 不再需要页面侧格式化；两者的读模型也不同，分页形式因此不同：
> 2313 是一次读进来的**单个快照**（前端排序，条数固定）；2316 是**服务端分页**（服务端排序 + 滚动加载）。

> **页面间距只有一档：10px**（2026-10-01 定，菜单管理页就是按它对齐的）。页边距（上下左右）
> 由 `.erp-tab-panel` 与 `.erp-tab-panel > .container-fluid` 各出 10px；**区块与区块之间**由页面级
> 容器的 `gap: var(--erp-block-gap)` 出 10px（token 定义在 `EOS.Web/src/styles/app.css`，
> 与 `--erp-workspace-gap` 并列，是"一处定义"）。
> **页面根容器不要再挂 Bootstrap 的间距工具类**（`gap-*` / `mb-*`）：它们带 `!important`，
> 会把 10px **静默**压成 8px 或 16px —— 菜单管理页曾挂 `gap-2`（实测 8px），已改回。

> **配置面各页的自建浮层（右键菜单 / 下拉菜单）统一走
> `EOS.Web/src/components/common/useMenuPlacement.ts`**：按菜单真实尺寸量测后定位，
> 右/下越界向内收，**下方放不下时整体翻到落点上方**。菜单管理页的模块树、表单设计器的右键精修
> 与图层面板都已接上；新写浮层不要再各自拿 `clientX/clientY` 直接 `position: fixed` 贴上，
> 否则贴近屏幕下缘会被窗口裁掉、选项点不到。

## 八、排障

| 现象 | 原因 |
|---|---|
| 改了菜单但用户看不到 | 该用户无该模块权限——**菜单可见性由权限决定**，不是菜单表 |
| 新增按钮不出现 | 模块没声明「允许写入」（`MODULES.UNIFIED_FORM_EDIT_ENABLED = 0`；迁移 355 起这是"能写"的唯一真源，现读、免重启），或用户无 `CanAddNew` |
| 字段改了但界面没变 | 定义快照未重发布（见 [41-定义快照与发布](./41-定义快照与发布.md)） |
| 系统参数填了不生效 | 检查生效范围与归属模块；参数键必须真实存在于归属模块 |
| 权限改了立即无效 | 权限缓存最多 60 秒；走接口改会立即失效（见 [21-授权模型](./21-授权模型.md)） |
