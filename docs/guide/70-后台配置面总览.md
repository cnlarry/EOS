# 70 后台配置面总览

"这个配置在哪改"是最高频的问题。这篇是一张**入口地图**——每个后台管什么、端点在哪。

配置面是**白箱化**的：每个后台都有明确的接口与权限门，不存在"改某个隐藏文件"的路子。

## 一、入口总表

| 配置面 | 路由前缀 | 管什么 | 详见 |
|---|---|---|---|
| 菜单与模块 | `api/v1/admin/menus` | 模块树、菜单显示、模块属性 | 第二节 |
| 导航分组 | `api/v1/navigation` | 导航分组 | 第二节 |
| 用户 | `api/v1/admin/users` | 用户主档、启停用、密码、所属组 | 第三节 |
| 权限 | `api/v1/admin` | 个人/组权限矩阵、按钮级权限、字段级拒绝 | [22-权限配置后台](./22-权限配置后台.md) |
| 字段与表 | `api/v1/admin`、`api/v1/table-data` | 表登记、字段登记、列配置、字段设置 | [11-元数据运维](./11-元数据运维.md) |
| 模块业务配置 | `api/v1/admin/module-business-config` | 模块级的业务开关与规则绑定 | 第四节 |
| 系统参数 | `api/v1/settings` | 可配置的运行时参数 | 第五节 |
| 工作助手管理面 | `api/v1/admin/assistant` | 供应商与模型（对话 / 嵌入）、知识库集合与文档、助手参数与作用域覆盖 | [60-AI工作助手](./60-AI工作助手.md) |
| 应用信息 | `api/v1/app` | 用户、权限、菜单树引导数据（`bootstrap`） | — |

> `api/v1/admin` 由多个控制器共用（权限、字段维护、菜单），靠子路径区分。

## 二、菜单与模块

`MenuAdminController`（`api/v1/admin/menus`）+ `NavigationGroupsController`（`api/v1/navigation`）。

这里维护的就是 `MODULES` 表（见 [10-元数据模型](./10-元数据模型.md)）：

- 模块树的层级与排序；
- 菜单显示名、图标、承载页（`M_URL`，**唯一路由字段**：空 = 目录节点、`/workbench` = 统一工作台、精确路径 = 自定义页）；
- 主表/明细表绑定；
- 表单呈现（打开方式 / 弹窗宽高）与页签列数：**不在本模块里配**——只能进表单设计器改（单据表单页的字段设置菜单 ›【表单设计】；页签行右端【表单呈现】+ 页签右键「布局列数」），**保存即生效**；
- 检索与排序配置。

**注意**：能不能新增/修改**不在这里配**——它由统一表单名单（`UnifiedFormEditor` 的写/只读名单）与权限决定，
路由字段不再参与（`NEW_URL` / `MODI_URL` / `HELP_URL` 已随迁移 321 物理删除）。
承载页 `M_URL` 留空 = 目录节点（只展开不跳转）；单据模块填 `/workbench` 走统一工作台；
自定义页填真实路径（需同时登记服务端路由白名单与前端路由表）。

**配置面按节点形态收敛（迁移 340）**：`MODULES` 一行是菜单节点，形态（统一工作台模块 / 自定义承载页 /
目录节点，判据见 [10-元数据模型](./10-元数据模型.md) 第一节）决定这一页露出什么——

- **统一工作台模块**：全部配置面（主表/子表、数据范围、排序字段、不可解批、单据行为、分组、
  行为动作 / 校验规则 / 自定义按钮）；
- **自定义承载页**：只留基础信息与"数据源"——主表/副表**只读**（它们是报表数据集、搜索中心与选择器的
  锚点，改这里会打断那些消费方），数据范围（`FILTER`）与通用查询仍可改；
  分组与行为三类配置不出现：这些节点不装配工作台定义，配了也不会有消费方；
- **目录节点**：只剩基础 / 主表 / 子表（它靠承载页与主表定义自己是什么），其余一律不出现。

右侧默认是**浏览态**（表单只读），点「编辑」才可输入、才出现保存/取消；改名、启停、排序、移动、删除
始终在左侧菜单上做，不必进右侧表单。**「发布」与「版本历史」只对统一工作台模块出现**——发布快照只属于它们
（非工作台节点过不了发布的 `runtime_whitelist` 门，标脏也只会在"待发布"清单里挂上永远发布不出来的条目）。
服务端另有一道兜底：非工作台节点上形态外的配置在保存时被归一成默认值，主表/副表被改动则直接拒收。

配置页还会向工作助手**上报"正在配置哪个对象"**（字段面 / 数据源 / 按钮 / 效果键），
好让助手在你打开它时知道你正在配什么。上报只是**数据**：标识符由服务端按库内元数据校验、
**不作为权限依据**，各配置端点各自独立鉴权。见 [61-工作助手的处境与诊断](./61-工作助手的处境与诊断.md)。

## 三、用户与权限

| 面 | 路由 | 说明 |
|---|---|---|
| 用户主档 | `api/v1/admin/users` | 新增/修改/停用启用/设置密码/所属组 |
| 权限矩阵 | `api/v1/admin` | 个人与组的模块权限、按钮级权限、字段级拒绝 |

权限门是**权限管理员**（模块 `2306` 的 `CanSetup`）。配置流程与陷阱见
[22-权限配置后台](./22-权限配置后台.md)。

## 四、模块业务配置

`ModuleBusinessConfigController`（`api/v1/admin/module-business-config`）。

按模块绑定业务行为与规则。改动会影响该模块的保存/批核行为，**改完要重新发布定义**
（见 [41-定义快照与发布](./41-定义快照与发布.md)）。

相关的服务端登记在 `EOS.API/Data/ModuleBusinessMap.cs`（模块 → 领域规则、
需批核模块 → 主表映射、保存后行为已迁目录的模块清单），见 [11-元数据运维](./11-元数据运维.md) 第五节。

## 五、系统参数

`SettingsController`（`api/v1/settings`）+ `EOS.API/Data/SystemParameterService.cs`。

系统参数是**纵向化**的：每个参数有

| 项 | 说明 |
|---|---|
| 类型 | 参数值类型（`bit` / `int` / `decimal` / `string`） |
| 分组 | 界面上的归类（分组名与组间顺序也是数据） |
| 说明 | **必须非空**的人话说明 |
| 生效范围 | `immediate` / `restart`（**助手的参数全部是 `immediate`**，见 [60](./60-AI工作助手.md)） |
| 默认值 | 缺省值；**字符串型参数的默认值留在代码里**（列留 `NULL`），标量型写在列里 |
| **归属模块** | 参数挂在哪——**它同时决定"谁能改"** |

纪律：

- **说明不能为空**——空说明在界面上就是露出一个英文键，配置者看不懂；
- 引用键必须真实存在（校验规则、效果动作、已发布快照、源码里点名的参数键，
  都要能在对应归属模块里找到）；
- 同一分组内序号唯一。

**权限按参数行的 `OWNER_MODULE` 判，不按页面判**：写要该模块的 `CanSetup`。已登记的归属模块：
`110111` 系统参数设置、`180213` / `180662` 考勤、`3105` 助手设置。新增一个归属模块要同改三处：
`SystemParameterService.ScopeModules`（页面 scope 令牌）、`scripts/check-system-params.ps1` 的白名单、
以及该模块自己的读写入口。

> **例外：3105 助手设置不走通用端点。** 通用端点的写门是 `CanEdit`，而 3105 声明的是 `CanSetup`
> （那一页改的是系统提示词与全局限额，比模型管理更要紧）。所以助手参数**读写仍经
> `SystemParameterService`，入口却挂在 3105 自己的控制器下**；`ModuleForScope` 里没有 `assistant`
> 令牌，通用端点在它上面继续返回 404。见 [ADR-030 §4.3](../decisions/ADR-030-工作助手管理面.md)。

## 六、改配置的纪律

| 改动 | 怎么落 |
|---|---|
| 别人拉代码后**也需要的**（新模块、新字段、新列配置、新默认列、版式） | **写迁移**（见 [05-数据库迁移与建库](./05-数据库迁移与建库.md)） |
| 只影响本机数据/某个用户习惯 | 后台页面直接改 |
| 改了模块业务配置、字段元数据、版式 | 后台改完 → **重新发布定义**（见 41 篇） |

判断标准一句话：**这个改动别人拉下代码后需不需要？** 需要就写迁移。

## 七、前端入口

| 位置 | 对应后台 |
|---|---|
| `EOS.Web/src/features/menu-admin/` | 菜单与模块 |
| `EOS.Web/src/features/user-admin/` | 用户与用户组 |
| `EOS.Web/src/features/rights-admin/` | 权限 |
| `EOS.Web/src/features/field-admin/` | 表与字段（2302：字段元数据、未管理字段批量生成、幽灵字段清理、按物理对象登记新表） |
| `EOS.Web/src/features/settings/` | 个人资料与系统参数 |
| `EOS.Web/src/features/admin/` | 系统管理入口（字段审计、库存策略、**日志管理 `/admin/logs`**） |
| `EOS.Web/src/features/assistant-admin/` | 工作助手管理面（3101 会话 / 3102 模型与用量 / 3103 知识库 / 3104 机制总览 / 3105 设置） |
| `EOS.Web/src/features/form-designer/`、`layout-designer/` | 表单版式设计 |

> **新增定制页要同改三处**（否则菜单点进去是空壳页）：库内 `MODULES.M_URL`、
> 后端 `ModuleRouteValidator.ExactRoutes`、前端 `workspaceRoutes.tsx`。
> 日志管理就是按这个套路加的：模块 `2313`（系统管理 23 → 数据表维护 2311）、路由 `/admin/logs`、
> 权限读位最初镜像 `110111`、**改锚本页模块 `2313`**（迁移 `284` 把初版的 `110112` 编号退役，
> 按 23 段重编号）。

> **页面间距只有一档：10px**（2026-10-01 定，菜单管理页就是按它对齐的）。页边距（上下左右）
> 由 `.erp-tab-panel` 与 `.erp-tab-panel > .container-fluid` 各出 10px；**区块与区块之间**由页面级
> 容器的 `gap: var(--erp-block-gap)` 出 10px（token 定义在 `EOS.Web/src/styles/app.css`，
> 与 `--erp-workspace-gap` 并列，是"一处定义"）。
> **页面根容器不要再挂 Bootstrap 的间距工具类**（`gap-*` / `mb-*`）：它们带 `!important`，
> 会把 10px **静默**压成 8px 或 16px —— 菜单管理页曾挂 `gap-2`（实测 8px），已改回。

> **配置面各页的自建浮层（右键菜单 / 下拉菜单）统一走
> `EOS.Web/src/components/common/useMenuPlacement.ts`**：按菜单真实尺寸量测后定位，
> 右/下越界向内收，**下方放不下时整体翻到落点上方**。菜单管理页的模块树、表单设计器的右键精修
> 与图层面板都已接上；新写浮层不要再各自拿 `clientX/clientY` 直接 `position: fixed` 贴上，
> 否则贴近屏幕下缘会被窗口裁掉、选项点不到。

## 八、排障

| 现象 | 原因 |
|---|---|
| 改了菜单但用户看不到 | 该用户无该模块权限——**菜单可见性由权限决定**，不是菜单表 |
| 新增按钮不出现 | 模块不在统一表单**写名单**（`UnifiedFormEditor.EnabledModuleIds`；迁移 321 之后这是"能写"的唯一真源），或用户无 `CanAddNew` |
| 字段改了但界面没变 | 定义快照未重发布（见 [41-定义快照与发布](./41-定义快照与发布.md)） |
| 系统参数填了不生效 | 检查生效范围与归属模块；参数键必须真实存在于归属模块 |
| 权限改了立即无效 | 权限缓存最多 60 秒；走接口改会立即失效（见 [21-授权模型](./21-授权模型.md)） |
