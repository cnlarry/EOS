# 50 统一报表

报表是**业务模块的资源**，不是承载某个页面的附属品。这句话决定了下面五条硬约束，
改报表相关代码前先读它们。

实现：`EOS.API/Data/ReportRepository.cs`、`ReportAdminRepository.cs`、
`ReportAggregateRegistry.cs`、`ReportListGrouping.cs`；
控制器见第四节。

## 一、五条硬约束

### 1. 报表身份 = `reportId`

- 主键、**全库唯一、不可变**；
- 编号规范 `^[A-Za-z0-9_-]{3,40}$`（与列宽同口径）；
- 规范 URL 为 `/report/{reportId}`；
- 命名约定：**单数 = 单资源实例，复数或带后缀 = 集合或工具页**。

### 2. 归属 = `REPORT.M_IDX`（业务模块）

`M_IDX` 是**四件事的唯一锚点**：

1. 数据集与筛选条件
2. 字段级权限
3. 行级权限
4. 模块功能权限

两条禁令：

- **`REPORT` 不得关联 `TABLES`**——不要再引入任何"表/字段来源"列；
- **跨表聚合的唯一出口是 `ReportAggregateRegistry`**。

### 3. 报表不进菜单

发现途径是：报表中心目录、搜索、深链，以及**情境入口**（统一表单工具条的「报表」动作）。

从目录点开一张报表会在**它自己的标签**里打开（身份 = `reportId`），报表中心留在原标签里；
工作台工具条的「报表」动作同理——都不顶掉来源页（见 [ADR-040](../decisions/ADR-040-工作区标签的导航模型.md)）。

`/reports/{M_IDX}` 只是"按归属模块列报表"的跳转端点，**不是入口解析器**。

### 4. 可见性唯一真源 = 归属模块的 `REPORT_TAG`

- 个人 `SYS_USER_MODULE_PERMISSION` 优先，否则组 `SYS_GROUP_MODULE_PERMISSION` **取 OR**；
- **这段判据只有一处实现**：`EOS.API/Data/Reports/ModuleReportVisibility.cs`（集合查询拼 `ForUser`、
  单模块查询走 `IsVisibleAsync`，后者就是把同一段谓词套进 `CASE WHEN`）。报表权、打印面板的报表清单、
  报表中心目录三处都引它——三处各写一遍时，"目录里看得见、打印面板里没有"只能靠人眼发现，
  离线用例 `StaticArchitectureGuardTests.报表可见性判定只有一处实现` 守着这条；
- **没有报表级 override**：`REPORT_USER_STATE`（2026-10-08 由旧名 `SYSDD_REPORT` 改来，迁移 336）只承载报表中心的**用户状态**（收藏/排序/最近使用），
  **不是权限表**；
- 任何"逐报表再配一次权限"的设计都是在造**第二处真源**，不要加。

通过时权限是三者全开（预览 / 打印 / 导出），且**行级范围统一由模块的 `DATA_FILTER` 决定**——
报表链路对它做 `AND` 合并，所以"报表级再过滤一次"同样是多余的。

### 5. 条件随模块

`SYS_REPORT_PARAMETER` / `SYS_USER_REPORT_PARAMETER` 的 `M_IDX` 指向**归属模块**（不是承载页）。

## 三、运行时的取数链路

```
按 reportId + 归属模块 M_IDX 取报表定义
   ↓
可见性：归属模块的 REPORT_TAG（个人优先，否则组 OR）
   ↓
字段级权限：模块的禁止字段清单
   ↓
行级权限：模块的 DATA_FILTER（AND 合并）
   ↓
结构化条件（SYSQR_*，见 44 篇）
   ↓
排序与分组（REPORT_SORT / 分组定义）
   ↓
参数化执行
```

要点：

- **报表不进菜单**，所以"这个报表在哪"的答案永远是：报表中心目录、搜索、深链，
  或从它归属模块的单据上点「报表」；
- **跨表取数走 `ReportAggregateRegistry`**，不在报表定义里写 SQL；
- 分组由 `ReportListGrouping` 处理，列表型报表的分组在服务端完成。

## 四、端点

| 控制器 | 路由前缀 | 作用 |
|---|---|---|
| `ReportController` | `api/v1/reports/{moduleId:int}` | 按归属模块列报表、取数 |
| `ReportCenterController` | `api/v1/report-center` | 报表中心（目录、搜索、收藏） |
| `ReportInboxController` | `api/v1/report-center` | 报表收件箱 |
| `ReportAdminController` | `api/v1/report-admin` | 报表定义维护 |
| `ReportResourceController` | `api/v1/report` | 报表资源 |
| `ReportMetricController` | `api/v1/report-metrics` | 报表指标 |

`REPORT_METRIC` 的**维护**（新增 / 修改 / 确认 / 删除）不在这张表里：它在
`api/v1/report-admin/metrics`，权限门是独立模块 **2317 指标口径**（读 `CanBrowse`、写 `CanSetup`）。
同一条指标被报表与助手共同消费，挂在报表权限上会让"谁能改口径"取决于"谁能改报表"。
确认状态只有候选与已确认，**删除只对候选开放**——已确认的可能被报表与结论引用，先改回候选那一步
本身就是一次决策。

**报表定义维护页 = 模块 2201 的定制页**，不是统一表单模块。承载页 `/admin/report-setup`
（`EOS.Web/src/features/admin/ReportAdminPage.tsx`），端点只有上面那一个前缀，**读 `CanBrowse(2201)` /
写 `CanSetup(2201)`**，服务端逐端点复核。库内 `MODULES.UNIFIED_FORM_ENABLED = 0`，且**不要把它改成统一表单**：

- 删一张报表要**级联清 5 张引用表**（`REPORT_SORT` / `REPORT_INBOX` / `REPORT_SUBSCRIPTION` /
  `REPORT_USER_STATE` / `SYS_USER_REPORT_PRINT`）并在同一个事务里做完；通用管线的删除只删主表一行，
  孤儿行既不报错也不生效——是"删了但没删干净"里最难发现的一种；
- `FORMAT_ID` 必须是**存在且同模块**的版式包、`COMPANY_ID` 必须是存在公司、`REPORT_ID` 受
  `^[A-Za-z0-9_-]{3,40}$` 约束、排序/分组字段必须命中归属模块的字段白名单——这四条都在
  `ReportAdminController` 里，换成通用管线会全部丢失；
- 它是**配置面**不是单据：没有批核/结案语义，也不需要列表列配置。

这条约束有两个执行点：`scripts/check-module-node-kind.ps1` 断言 2201 必须保持 `CUSTOMPAGE` 且
`UNIFIED_FORM_ENABLED = 0`；`EOS.API.Tests/ModuleRouteValidatorTests.cs` 钉住 `/admin/report-setup → 2201`。

**页面的写入口由服务端下发的能力位决定**（`GET /report-admin/capabilities` → `{ canBrowse, canSetup }`）。
只有浏览权的账号看到的是「只读」徽标 + 禁用的新增/编辑/删除，并写明"要改请让管理员放开 2201 的 SETUP"，
而不是点下去才吃 403。三条边界：

- **能力位只是体验层，不是权限依据**：每个写端点仍各自复核 `CanSetup`（离线用例
  `ReportAdminCapabilitiesTests` 两头都钉：能力位如实下发 + 浏览权账号直打写端点必被拒）；
- **能力位取不到时按只读处理**（fail-closed），并提示"未能确认写权限"——反向的"取不到就放开"
  会把这道补强变回原样；
- 新增端点意味着**前后端同批部署**：旧后端没有 `/capabilities`，新前端会一律按只读展示。

2201 **名下不再挂报表定义**：它继承自旧系统的 3 张（`REPORT` / `REPORT_229801` / `SYS_Report_List`）
已随迁移 467 退役——一个"用来列报表"的页面再挂 3 张报表清单，只会在报表中心多出一个与页面职责
重复的业务域。同理，`REPORT` 表上 4 条指向已删列（`DEFAULT_PAPER` / `DEFAULT_PRINTER` / `IMAGE_ID` /
`REPORT_PATH`）的字段登记也在那条迁移里清掉。

报表**查询条件**（`SYS_REPORT_PARAMETER`）没有运行时写侧：原 2205「报表过滤条件设置」页已随 ADR-009 P4
下线（迁移 025），条件模板只随迁移改。

> 2202 页头设置 / 2203 页尾设置 / 2204 表尾设置**已整模块退役**（2026-10-07，迁移 329）：它们的承载表
> `REPORT_HEADER` / `REPORT_FOOTER` / `REPORT_TAIL` 早随 ADR-009 §11 删除，页头/页尾/表尾现由版式资产
> 承载（见 [52-报表打印版式](./52-报表打印版式.md)）。"报表设置四页"的说法只剩 2201 一页。

## 五、前端

`EOS.Web/src/features/reports/`：报表中心、报表查看、收件箱、车辆汇总分析等**报表相关页面**。

- 该目录只放报表相关页面，**模块的承载页不放这里**——原先放在此处的"详情查询页"已随
  `/detail-query` 承载面下线（跨表明细改由统一工作台承载，见 [12-元数据消费](./12-元数据消费.md)）；
- 报表中心目录的「全部报表」按业务域折叠；展开后用**磁贴网格**展示域内报表（名称 + 模块 + 编号 +
  默认标记），不再用"一整行只有报表名"的长条列表——空间用来承载归属模块与编号，扫读更快。
  收藏与最近使用同为磁贴网格（最近使用磁贴带模块名与最近使用时间），三区视觉一致；
- 列表统一用组合件 `ErpListGrid`（内部即电子表格 `ErpTable`，见 [03-工程规范与硬约束](./03-工程规范与硬约束.md)）；
- **报表查看页与表格是一个整体**：左上只留「模块名 + 模块号」（单行加粗），报表切换、查询条件、查询、
  打印、返回等动作都在结果卡的命令栏里（图标按钮，与统一工作台同形），不再有独立的页头条块；报表名
  只在右侧 select 与页签上，不再重复一行大标题。「查询条件」和「打印设置」都以弹窗承载，打印设置不再
  在结果上方插一块。页根按 `erp-base-page + erp-page-fill` 占满，页面级不滚，滚动只发生在结果表格内。
- **页内切换报表不整页重载**：报表定义查询用 `placeholderData` 保留上一张定义，切换期间只有表格区
  显示 fetching；新定义到位后按新报表默认值重置条件并自动重查一次。页签标题由页面经
  `usePageBreadcrumb` 上抛当前报表名（`/report/:reportId` 路径里没有名字），切换时即时更新。
  外壳只在**离开定制子页**时清理页面级面包屑；不要按「当前路径不是定制页」无条件清理——报表页的
  标题是页面自己上抛的，切走再切回会被误清成默认「报表」。
- **查询条件的交互与统一工作台高级查询同形态**：条件收进「查询条件」弹窗（工具栏入口 + 生效条件数角标 +
  重置/取消/查询），确认后一次性应用并查询；不再把全部条件平铺在结果上方。弹窗里标签列取最长标签宽度，
  所有控件左缘对齐；输入框与下拉同高同内边距。报表参数语义不变——范围/固定单选/数据源单选/多选、默认值、
  深链 `f{serialNo}`/`t{serialNo}` 与用户记忆都照旧。
  **任意字段 + 运算符的高级筛选不能直接替代报表参数**：聚合报表的参数绑定 SQL 参数、受控选项与
  数据源选择器都不是"字段比较"能表达的；需要时只能作为附加条件与报表参数 AND 合并，另立一层实现；
- 打印走版式资产 + 解释层，见 [52-报表打印版式](./52-报表打印版式.md)。

## 六、改报表时的检查清单

1. **不要给 `REPORT` 加"表/字段来源"列**——归属模块就是来源锚点；
2. **不要加报表级权限配置**——可见性只看归属模块的 `REPORT_TAG`；
3. **不要把报表塞进菜单**——入口是报表中心、搜索、深链、情境入口；
4. **跨表聚合走注册表**，不要在报表定义里写 SQL；
5. **条件模板的 `M_IDX` 指向归属模块**，不是承载页；
6. 新增字段级/行级限制时，用**模块级**的字段权限与 `DATA_FILTER`，不要另造一套。

## 七、排障

| 现象 | 原因 |
|---|---|
| 用户看不到某张报表 | 看**归属模块**的 `REPORT_TAG`；系统里没有报表级 switch 可查 |
| 能看到报表但数据为空 | 行级 `DATA_FILTER` 把数据滤掉了；或条件模板限定过窄 |
| 报表出现在错误的地方 | 检查 `REPORT.M_IDX` 是否挂在正确的业务模块下 |
| 打印结果与列表不一致 | 版式与解释层的问题，见 [52-报表打印版式](./52-报表打印版式.md) |
| 想给某人单独放开某张报表 | 这是"造第二处真源"。改归属模块的权限，或用模块级字段/行级权限表达粒度 |
| 报表排序不生效 | 排序字段必须来自报表定义的可见列；`REPORT_SORT` 是定义来源 |

## 收口（依赖升级批次）

- 前端 `EOS.Web/src/features/reports` 只随表格库 `@tanstack/react-table` 8 → 9 换了 import 来源（v8 式 API
  由 [`lib/tanstackTable.ts`](../../EOS.Web/src/lib/tanstackTable.ts) 保留）——取数、归属与可见性口径未变。

## 收口（空主表模块）：定义解析不认 NULL

- **`MODULES.MASTER_TABLE` 是可空列**（库内有十来个模块为 NULL，多为目录节点）。定义解析读它时必须
  兜住 NULL：漏兜时 `reader.GetString` 抛 `SqlNullValueException`，表现为**该模块的报表页整页 500**，
  与数据权限无关。初值一律 `LTRIM(RTRIM(ISNULL(MASTER_TABLE,'')))`，与同一查询里的
  `DETAIL_TABLE` / `FILTER` 保持一致——同一行 SQL 里只有一列没兜，就是这种故障的来路。
- 兜底之后的行为才符合安全边界：**主表为空、又没有注册聚合数据源的报表就是"不存在"**（返回空 ⇒ 404），
  而不是 500。空主表的聚合报表仍按 `ReportAggregateRegistry` 放行，这条判据没有变。
- **6 张"不可达报表"的收尾（2026-10-08）**：`SYS_Modules_List`（菜单管理明细）与 `SYS_Talbles_List`（数据表信息明细）原先挂在没有主表的空壳模块（230901 / 230902）名下、长期 404，现按汇总报表登记（数据源就是 `MODULES` / `TABLES` 表本身）；`CAR_SUMMARY`（车辆汇总表）**不登记**——前端已有专属页面走 `EXEC dbo.RPT_CAR_SUMMARY`，它本来就能用，再登记一遍等于给同一张报表造第二真相；余下 `SFC_Process` / `SFC_Daily` / `CUS_ProIn` 三张**已按业务拍板直接退役**（2026-10-08，迁移 338）——它们的归属模块 28 / 1804 / 3003 都是没有承载页的目录模块，报表本身既无主表也无汇总数据源，属"留着也永远打不开"的条目；退役时按 `ReportAdminRepository.DeleteReportAsync` 的**同一套引用表清单**级联清理（`REPORT_SORT` / `REPORT_INBOX` / `REPORT_SUBSCRIPTION` / `REPORT_USER_STATE` / `SYS_USER_REPORT_PRINT`），不留孤儿行。

## 收口（页面外壳统一）

- 报表管理与报表查看页的卡内工具条改用 `.erp-card-toolbar`，页面承载容器随全站统一到 `ErpListCard`。
  取数、归属与可见性口径未变。

## 收口（列表统一到组合件）

- 报表中心、报表查看、收件箱、车辆汇总分析的列表改用列表组合件 `ErpListGrid`（原先是
  `ErpListCard` + `ErpTable` 手拼）；列宽持久化、选择态与分页脚由组合件承担。
- 报表身份（`reportId`）、归属（`REPORT.M_IDX`）、可见性（归属模块 `REPORT_TAG`）与条件模板的
  解释口径均未变——组合件只换外壳与表格装配方式。
