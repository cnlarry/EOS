# 01 代码地图与仓库结构

## 一、顶层结构

```
EOS.slnx                  解决方案（两个工程 + 测试）
EOS.API/                  后端：ASP.NET Core / .NET 10
EOS.Web/                  前端：React + TypeScript + Vite
EOS.API.Tests/            后端测试
db/                       建库与初始数据脚本
docs/guide/               本手册
screenshots/              README 用的界面截图
README.md                 项目概览
QUICKSTART.md             从空环境跑起来
ARCHITECTURE.md           架构说明（概览级）
CONTRIBUTING.md           贡献指南（提交前必读）
```

`ARCHITECTURE.md` 讲"是什么形状"，本手册讲"怎么用、怎么扩展"；两者不重复。

## 二、后端 `EOS.API/`

| 目录 | 放什么 |
|---|---|
| `Controllers/` | HTTP 契约与参数校验。一个业务域一个控制器，路由与权限门在这里 |
| `Data/` | 仓库与领域服务。**受控的元数据解释层**——把库里的元数据变成可执行的查询与写入 |
| `Data/Migrations/` | DbUp 版本化迁移脚本（`NNN_描述.sql`） |
| `Features/` | 领域规则与工作流，按域分子目录 |
| `Security/` | 认证、会话与授权 |
| `Errors/` | 错误码、异常类型与问题详情（ProblemDetails）出参 |
| `Middleware/` | 全局异常处理、请求日志 |
| `Validation/` | 校验结果模型 |
| `Health/` | 健康检查（数据库、迁移、附件存储、配置） |
| `Logging/` | 日志脱敏 |
| `Telemetry/` | 请求上下文、指标、DB 计时、JSON 文件日志 |
| `Models/` | 出入参模型 |
| `ReportFormats/` | 报表版式资产（`*.json`） |
| `Services/` | 后台调度等长驻服务 |
| `wwwroot/` | 附件等静态资源落盘位置 |

### `Data/` 的分层边界

`Data/` 子目录按能力划分：

| 子目录 | 内容 |
|---|---|
| `Workbench/` | 统一工作台的定义解析、查询组装、命令处理 |
| `Definitions/` | 定义的内容比较与发布判定 |
| `Forms/` | 统一表单的版式读取、推导、校验与提交 |
| `Query/` | 结构化条件的渲染 |
| `ValidationRules/` | 校验规则 |
| `Effects/` | 效果引擎：动作的配置化执行 |
| `DocumentActions/` | 单据动作目录与注册 |
| `Inventory/` | 库存域服务 |
| `Migrations/` | 迁移脚本 |

`Data/` **根目录**已平铺大量文件，新代码不应再往根目录加：领域能力放 `Features/<域>/`，
跨模块共享的原语放 `Data/<子目录>/`。这条由门禁脚本守住（根目录文件清单是"只减不增"的白名单）。

## 三、前端 `EOS.Web/`

```
src/
├─ app/                Provider、路由、懒加载、错误页
├─ components/
│  ├─ ui/              基础 UI 组件（隔离第三方视觉库）
│  ├─ layout/          应用外壳：AppShell、页头、工作区标签、导航
│  └─ common/          通用 ERP 组件（电子表格、选择器、列选择、查询构建…）
├─ features/           按业务域组织页面、类型、校验与 API
├─ services/api/       类型化 API client
└─ styles/ types/ …    主题变量、全局类型
```

### 分层约定

- **组件不直接 `fetch`**：数据流是 `页面组件 → TanStack Query → services/api → HTTP → EOS.API`。
- **`features/` 按域组织**，不建根级大 `pages/`、`utils/` 目录。
- **`components/ui/` 只做视觉隔离**，不含业务规则；`components/common/` 放有 ERP 共性的复用件。
- 通用组件从真实场景提炼，不提前封装尚未出现的需求。

| `print/` | 打印与版式 |
| `workflow/` | 流程定义与审批 |
| `search-center/` | 搜索中心 |
| `import/` | 导入 |

## 四、测试与建库

- `EOS.API.Tests/`：后端测试。`*Tests.cs` 是 xUnit 单测；
  `E2e*.ps1` / `Acceptance*.ps1` 是需要运行环境与真库的端到端/验收脚本。
- `db/bootstrap/`：从空环境建库的五个脚本，执行顺序见 [02-本地环境与运行](./02-本地环境与运行.md)。

## 五、我该去哪里改

| 我要做的事 | 先去哪个目录 |
|---|---|
| 加一个接口 | `EOS.API/Controllers/`，业务逻辑落到 `Data/` 或 `Features/<域>/` |
| 加一个库对象 | 新增迁移 `EOS.API/Data/Migrations/NNN_*.sql`…… |
| 改单据列表/表单的行为 | `EOS.API/Data/Workbench/` + `EOS.Web/src/features/document-workbench/` |
| 加一个选择器数据源 | `EOS.API/Data/ChooserRepository.cs` |
| 加一个单据动作 | `EOS.API/Data/DocumentActions/` 与 `Data/Effects/` |
| 调权限判断 | `EOS.API/Security/` |
| 加一个页面 | `EOS.Web/src/features/<域>/`，路由在 `src/app/` 登记 |
| 加一个通用组件 | `EOS.Web/src/components/common/` |
| 改错误出参 | `EOS.API/Errors/` |

对应的详细篇目见 [手册索引](./README.md)。
