# 46 统一选择器

**凡需从既有业务数据中挑选记录作为输入**（员工、用户、客户、供应商、物料、产品、仓库、部门、
模块、表、字段、报表……），一律使用统一选择器，不要在页面里自建弹窗或用手写表格凑。

理由不只是"省事"：列、默认列、权限、关键字与排序列都由服务端决定，
自建选择器必然绕开这些约定，最终表现为"某些账号在某个页面能选到不该看到的记录"。

前端组件：`EOS.Web/src/components/common/UnifiedChooser.tsx`，
数据源辅助：`EOS.Web/src/components/common/chooserSource.ts`。

## 一、两种数据源

| 方式 | 说明 | 适用 |
|---|---|---|
| `formField` | 复用 `CHOOSE_*` 表单字段元数据 | 单据表单上的字段选值（最常见） |
| `sourceKey` | 服务端注册的数据源 | 管理页面、跨模块选值 |

`loader` 只用于存量过渡，**新代码不得新增**。

## 二、端点

```
POST /api/v1/chooser/query
```

请求里前端只传 **`sourceKey` + 白名单参数**（关键字、排序、分页、`args` 等），
**不传表名、列名、SQL**。动态查询全部参数化。

服务端流程（`ChooserController.Query`）：

```
sourceKey 是否在注册表内？         否 → 400 UNKNOWN_SOURCE
  ↓
是否"表单设计态字段池"？           是 → 校验版式设计权（模块号来自 args）→ 失败即 404
  ↓
数据源是否定义了权限模块？          是 → 校验该模块的 CanBrowse → 失败即 404
  ↓
按注册表解析列/排序/关键字 → 参数化执行
  ↓
无返回 → 404 SOURCE_EMPTY
```

## 三、权限不足返回 404，不是 403

这是一条**刻意的约定**：

> 数据源权限不足时返回 `404 SOURCE_NOT_FOUND`，而不是 403。

原因：403 会告诉调用方"这个数据源存在，只是你没权限"——等于把数据源清单变成可探测面。
404 让"不存在"与"无权看"看起来一样，前端只依赖"拿不到数据"这一事实。

**新增数据源时沿用这个口径**，不要为了方便调试改成 403。

例外是"未注册的 sourceKey"返回 400 `UNKNOWN_SOURCE`——那是调用方传错了，不是权限问题。

## 四、服务端注册表

实现：`EOS.API/Data/ChooserRepository.cs`。一个数据源要登记**四处**（四张表都按 sourceKey
直接取下标，漏一处不会编译报错），缺一处就会缺能力：

| 登记 | 作用 | 缺了会怎样 |
|---|---|---|
| `RegisteredSources` | 可返回的列清单 | 该数据源不存在（400） |
| 排序键白名单（`StableSortColumns`） | 允许按哪些列排序 | 点表头排序报错或被忽略 |
| 关键字白名单（`KeywordExpressions`） | 关键字搜索命中哪些列（列 → `LIKE @Keyword` 表达式） | 搜索框无效 |
| 列表达式（`ColumnExpressions`） | 高级查询把条件下推到哪一列（列 → SQL 表达式） | 用该列下条件时 **500**（下推不到列表达式） |

另有两处接线：`PermissionModuleId(sourceKey)`（权限门；不挂门就是"登录即可读"）与
`QueryAsync` 里的 `switch` 分发（没有分支则查不出数据）。`NolockAllowlistTests` 之外没有别的门禁
会替你查这四处——登记完记得跑一节"新增一个数据源"里那条正反用例。

表名与列名**只来自注册表**，不信任前端提交。

### 已注册的数据源（部分）

| sourceKey | 说明 |
|---|---|
| `user-admin.employees` | 员工（参考实现） |
| `rights-admin.users` / `rights-admin.groups` | 用户 / 用户组 |
| `menu-admin.tables` / `.columns` / `.modules` / `.fields` / `.sprocs` / `.records` | 菜单与模块维护相关 |
| `field-admin.tables` / `.columns` / `.fields` | 字段维护相关 |
| `report-admin.fields` / `report-admin.modules` | 报表维护相关 |
| `depot-admin.locations` | 库位 |
| `inventory.batches` | 库存批次 |
| `form-designer.fields` | 表单设计态字段池（权限门是**版式设计权**，模块号取自 `args`） |
| `assistant-admin.modules` | 助手参数作用域要按模块配置时的候选集（权限门 3105）；候选集 = `MODULES` 全表，**与作用域键校验同源** |
| `module-groups.targets` | 模块分组（2315）要配分组的**目标模块**（权限门 2315）；候选集 = 统一工作台模块且有主表（判据 `dbo.V_MODULE_NODE`），**与服务端拒存规则同源**——选择器比校验松会出现"挑得动、保存被拒" |

注册表另提供一个**只读键清单**（`ChooserRepository.RegisteredSourceKeys`），供助手的能力目录
列出"有哪些来源可选"；它是同一份注册表的视图，**不是第二份来源清单**——
新增数据源只改 `RegisteredSources`，不要另建一份键列表。

**每条注册都要指得出消费方**：数据源只在"有界面真的用它"时才注册。基本资料导入（230902）在设计
过程中曾注册 `import.targets`，但它的界面最终定为"第 1 步在页面内直接列模块清单、点行选中"
（而非弹出选择器，见 [72-导入与导出](./72-导入与导出.md) 与决策清单 #150），注册便成了没有消费方的
死代码，已随该形态一并回滚——不要因为"以前有过"再加回来。

## 五、新增一个数据源

1. 在 `ChooserRepository` 的 `RegisteredSources` 登记 sourceKey 与列清单；
2. 登记排序键白名单（按需）；
3. 登记关键字白名单，每列写清 `LIKE @Keyword` 的列表达式（注意用 `LTRIM(RTRIM(...))`）；
4. 决定权限门：能挂到某个模块上的，登记 `PermissionModuleId`；
   设计态字段池这类动态模块号的，走专门分支；
5. 查询一律参数化；**表名/列名不得来自请求**；
6. 补测试：正例（能查到）+ 反例（无权限时 404、未注册时 400）。

## 六、前端

- 用 `UnifiedChooser`，**列与默认列必须来自服务端**（`FIELDS` + `SYSQL_DEFAULT` 元数据，
   或受控虚拟查找白名单），前端禁止硬编码列清单；
- 行键与回填字段按元数据键**大小写不敏感**取值；
- 选中后的值回填到表单字段，回填规则同样来自元数据。

## 七、唯一例外

**固定枚举/字典小集合**（状态、类型、是否）用下拉 `select`，不必套选择器。

除此之外没有例外：确无元数据支撑的聚合或跨系统数据，也应注册 `sourceKey` 承载，
**不得回退自建选择器**。

## 八、排障

| 现象 | 原因 |
|---|---|
| 400 `UNKNOWN_SOURCE` | sourceKey 拼错，或没在注册表登记 |
| 404 `SOURCE_NOT_FOUND` | 数据源不存在**或**当前用户无该数据源权限——两者按设计不可区分 |
| 404 `SOURCE_EMPTY` | 数据源执行后无返回 |
| 搜索框没反应 | 该数据源没登记关键字白名单 |
| 点表头排序无效 | 该列不在排序白名单里 |
| 设计态选字段报 404 | 缺版式设计权，或 `args` 里没带模块号/表名 |

## 收口（依赖升级批次）

- `UnifiedChooser` 只随表格库 `@tanstack/react-table` 8 → 9 换了 import 来源（v8 式 API 由
  [`lib/tanstackTable.ts`](../../EOS.Web/src/lib/tanstackTable.ts) 保留）——**列与默认列来自服务端**、
  行键与回填按元数据取值这些口径都没有变。
