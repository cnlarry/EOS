# 71 附件

附件是挂在**单据字段**上的文件。两个要点决定了它的实现方式：

1. **元数据在库、文件在磁盘**——库表 `dbo.ATTACHMENT` 记文件信息，实体文件存磁盘；
2. **权限按字段位强制**——附件权限是模块权限位的一部分，不是单独的"附件权限"。

实现：`EOS.API/Data/AttachmentRepository.cs`、`EOS.API/Controllers/AttachmentController.cs`、
`EOS.API/Health/AttachmentStorageHealthCheck.cs`。

## 一、端点

附件挂在单据下，路由带模块号：

```
api/v1/document-workbench/{moduleId:int}/attachments
```

| 操作 | 说明 |
|---|---|
| 列附件 | 按单据主键取该记录的附件清单 |
| 上传 | 新增附件（序号自增：`SERIAL_NO` 取当前最大值 +1） |
| 下载 / 查看 | 读文件 |
| 修改 | 更新附件信息 |
| 删除 | 删除记录与文件 |

## 二、四项权限

附件权限是模块权限的四个位（见 [21-授权模型](./21-授权模型.md)）：

| 权限位 | 含义 |
|---|---|
| `CanFileView` | 能否查看 |
| `CanFileUpda` | 能否上传（新增） |
| `CanFileEdit` | 能否修改 |
| `CanFileDele` | 能否删除 |

**逐项独立**：可以配成"能看能传，但不能删"。

服务端**每次都校验**——前端隐藏按钮只是体验。

## 三、数据模型

`dbo.ATTACHMENT` 的关键字段：

| 字段 | 含义 |
|---|---|
| `ID` | 附件主键 |
| `SERIAL_NO` | 同单据内的序号（新增时取 `MAX(SERIAL_NO)+1`） |
| `SelectList` 中的单据键 | 关联到具体单据记录 |
| 文件信息 | 原文件名、存储路径、大小等 |

**文件在磁盘**：删除附件时会同时处理记录与文件；磁盘不可写会导致上传失败
（由 `AttachmentStorageHealthCheck` 反映在 `/health/ready`）。

## 四、位置

| 位置 | 说明 |
|---|---|
| 落盘目录 | `EOS.API/wwwroot/` 下的上传目录（见 `appsettings` 配置） |
| 健康检查 | `attachment_storage` 是 `/health/ready` 的四项之一 |
| 前端 | 统一表单工具栏的「附件」动作 |

## 五、与统一表单的关系

- 附件入口在**统一表单工具栏**（浏览态），不在列表工具栏
  （见 [03-工程规范与硬约束](./03-工程规范与硬约束.md) 的工具栏约定）；
- 附件的可见性跟随字段级权限与模块权限；
- 只读模块（`ReadOnlyModuleIds`）**不发写路由**，附件上传/删除同样受限。

## 六、排障

| 现象 | 原因 |
|---|---|
| 上传按钮不见了 | 无 `CanFileUpda` |
| 上传报错、`/health/ready` 不健康 | 附件目录不可写（磁盘权限或空间） |
| 能看列表但打不开文件 | 文件已不在磁盘（记录残留）；比对记录与磁盘 |
| 删除报错 | 无 `CanFileDele`；或文件被占用 |
| 附件在别的单据下看不到 | 附件按单据主键关联，跨单据不可见属正常 |

## 七、注意事项

- **不要在磁盘上手工删文件**：记录与文件要一起处理，否则出现"记录在、文件没了"；
- **不要把大文件塞进数据库**：设计就是文件在磁盘；
- **附件目录不要纳入版本控制**（已在忽略项里）。
