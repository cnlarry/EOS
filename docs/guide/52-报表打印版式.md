# 52 报表打印版式

打印输出的样子**不由命令式代码决定**，而由**版式资产 + 解释层**决定。
这篇讲版式资产长什么样、怎么渲染、以及边界。

实现：`EOS.API/ReportFormats/`（版式资产）、`EOS.API/Data/ILayoutRenderer.cs`（渲染抽象）、
`QuestPdfLayoutRenderer.cs`（实现）、`PdfLayout.cs`、`ReportPdfService.cs`、
`ReportListPdfComposer.cs`、`EOS.API/Controllers/PrintController.cs`。

## 一、版式资产的组织

```
EOS.API/ReportFormats/
├─ layout.schema.v1.json     版式 schema（三重身份的单一契约）
├─ _generic/                 通用版式
├─ _card/                    卡片型版式
├─ 1405/                     按模块号组织
│  ├─ format.json            版式包定义（formatId / kind / title / moduleId / dataContract）
│  ├─ layout.json            版式本体（页面、区段、坐标、样式）
│  └─ sample.json            示例数据（供设计器预览渲染）
├─ 1406/ 1407/ 1503/ …
```

要点：

- **目录名就是模块号**（个别带后缀，如 `1406-pick/`、`1607-putaway/`），
  一个模块可以有多个版式；
- `_generic` / `_card` 是跨模块的通用版式；
- 版式资产是**文件**，不是库内配置——所以它走代码评审，不走元数据运维流程。

## 二、`layout.json` 的三重身份

schema 的说明写得最准：

> **存储格式 / 渲染契约 / 设计器文档模型。**

同一份 JSON 同时承担三件事，所以它**有 schema**：

| 约束 | 内容 |
|---|---|
| 必填 | `schemaVersion`、`kind`、`page`、`sections` |
| `schemaVersion` | 当前为 `1`；**变更需升版** |
| 坐标单位 | **mm** |
| 字号单位 | **pt** |
| 额外属性 | `additionalProperties: false`——多写字段会被判非法 |

`schemaVersion` 升版是有成本的：它是存储格式，也是渲染契约。改 schema 要同时考虑
存量版式文件的兼容。

## 三、两类版式

`kind` 只有两个取值：

| 取值 | 含义 |
|---|---|
| `document` | **单据型版式**：固定字段与明细（如客户订单、采购单） |
| `list` | **列表型版式**：列由报表数据决定，用于**报表清单打印** |

所以"打印一张单据"和"打印一份报表清单"走的是同一套资产机制，只是 `kind` 不同。

## 四、`format.json` 与 `sample.json`

| 文件 | 作用 |
|---|---|
| `format.json` | 版式**包**定义：`formatId`、`kind`、`title`、`moduleId`，以及 **`dataContract`**（可输出的字段清单：key / label / type） |
| `sample.json` | **示例数据**：模块号、标题、公司抬头、页脚、主表字段等，供渲染预览 |

`dataContract` 决定了版式里**能用哪些字段**——`layout.json` 引用的字段应落在它声明的范围内。
版式设计器用 `sample.json` 做无真实数据时的预览。

## 五、渲染

```
版式请求（模块号 / 报表）
   ↓
取版式资产（layout.json + format.json）
   ↓
解释层：ILayoutRenderer
   ↓
QuestPdfLayoutRenderer（基于 QuestPDF）生成 PDF
```

要点：

- **渲染是解释执行版式，不是执行版式里写的代码**——JSON 里只有坐标、区段与样式；
- **不新增命令式渲染旁路**：不要为某个单据单独写一个 "拼 PDF 的 C#"。
  需要不同的样子，就加/改版式资产；
- 报表清单打印由 `ReportListPdfComposer` 组装（`kind: list`），
  单据打印由 `ReportPdfService` 走单据版式（`kind: document`）。

## 六、端点

| 控制器 | 路由 | 作用 |
|---|---|---|
| `PrintController` | `POST api/v1/print/{moduleId}/pdf` | 按模块打印 PDF |
| 报表取数 | `api/v1/reports/{moduleId}` | 见 [50-统一报表](./50-统一报表.md) |
| 版式清单 | `api/v1/report-admin/formats` | 列出可绑定版式（见 [51-报表可视化设计器](./51-报表可视化设计器.md)） |

打印是**读路径**，审计用 best-effort 写入（资源类型 `PRINT` / `REPORT_PRINT`）。

## 七、改版式的做法

1. 找到对应模块目录（不存在就新建，目录名 = 模块号）；
2. 改 `layout.json`（或新增一个带后缀的版式目录）；
3. **符合 schema**：必填项齐全、单位正确、不写 schema 外的字段；
4. 字段引用要落在 `format.json` 的 `dataContract` 内；
5. 用 `sample.json` 预览渲染效果；
6. 若改了 schema 本身 → **升 `schemaVersion`**，并同步处理存量版式。

## 八、排障

| 现象 | 原因 |
|---|---|
| 打印报版式不存在 | 该模块没有版式目录，或目录名与模块号不匹配 |
| PDF 里字段空白 | 字段不在 `dataContract` 内；或该字段被字段级权限挡住 |
| 版式改了没生效 | 版式是编译进程序集的资源，需**重新构建并重启服务**（与改元数据不同） |
| 预览正常、实际打印不对 | `sample.json` 是示例数据，实际值可能触发布局换行；检查区段高度与行高 |
| 想给某单据单独写渲染代码 | 这是命令式旁路，不要做——改版式资产 |
| schema 校验失败 | 多写了 schema 外字段（`additionalProperties: false`），或漏了必填项 |

## 九、与"报表设计器"的关系

| 谁 | 负责 |
|---|---|
| 报表设计器（[51](./51-报表可视化设计器.md)） | 报表**取什么数**：字段、筛选、排序、归属模块 |
| 版式（本篇） | 报表/单据**长什么样**：页面、区段、位置、样式 |

两者通过 `REPORT.FORMAT_ID` 关联：报表定义引用版式，版式决定输出。
**改数据定义走报表设计器，改外观走版式资产**——混着改最容易出问题。

## 十、收口（QuestPDF 2026.9.1）：字体注册换成流式 API

- **`FontManager.RegisterFontWithCustomName` 已过时**（本仓把警告当错误 ⇒ 升级后直接编译失败）。改用
  `FontManager.RegisterFontFromStream`：**族名以字体文件自身声明的为准**，代码里不再另起名字；报表侧照旧按
  `PdfLayout.FontFamily` 引用该族名，两边必须一致。
- **启动期核对族名**：`Program.RegisterPdfFont` 注册后用 `FontManager.GetRegisteredFonts()` 复核一次，对不上
  往标准错误打一条 ERROR——中文字体失配在 PDF 里只表现为"字全变方框"，不核对就得等打印出来才发现。
- 测试侧同批换 API：`LayoutRendererSmokeTests`、`ReportListPdfSmokeTests`、`ReportListPdfPageParityTests`、
  `ReportListPdfLiveParityTests`、`ReportPdfServiceSmokeTests`。
