# 43 表单版式设计

**版式**决定表单长什么样：字段怎么排、跨几列、哪几个挤在一格、分几个页签。

版式是**模块级**的——同一张表在不同模块下可以有不同的排布。
与"报表可视化设计器"（[51-报表可视化设计器](./51-报表可视化设计器.md)）不是一回事，别混。

实现：`EOS.API/Data/Forms/`（推导、读取、校验、提交）、
`EOS.API/Controllers/FormLayoutController.cs`。

## 一、版式资产

| 表 | 内容 |
|---|---|
| `MODULE_FORM_LAYOUT` | 字段级版式行（主键 `M_IDX` + `T_ID` + `F_ID`） |
| `MODULE_FORM_TAB` | 页签（`M_IDX` + `TAB_NO` + `TAB_TITLE`） |

`MODULE_FORM_LAYOUT` 的列：`TAB_NO`、`ORDER_NO`、`SPAN`、`ROW_SPAN`、`NEW_LINE`、
`SECTION_ID`、`CELL_GROUP`、`CELL_ROLE`、`IS_HIDDEN`、`UPDATED_BY`、`UPDATED_AT`。

实测使用情况：263 个模块定制了版式，共 11583 行；复合格（`CELL_GROUP` 非空）1590 行。
`IS_HIDDEN=1` 与 `SECTION_ID` 非空的行数**都是 0**——这两个能力已定义但当前没有实际使用。

## 二、未定制 vs 已定制：语义完全不同

这是理解版式的关键，也是很多"改版式没用"的根源：

| 状态 | 语义 |
|---|---|
| **未定制**（该表没有版式行） | 字段按**元数据顺序原样渲染**；虚拟列被摘掉 |
| **已定制**（有版式行） | **以版式行为准**：只渲染版式里列出的字段（未列出的视为"未加入表单"，效果等同隐藏），顺序、跨度、复合格全部按版式 |

推论：

- 零配置模块的表单定义**逐字不变**——这是对拍判据，不要为了"统一"去给所有模块生成版式行；
- 一旦定制，**没列进去的字段就消失了**，包括你可能以为"默认会在"的字段；
- 但**不可移除类字段**不允许消失（见第五节）。

### 版式只做减法与排布

> **版式不能把权限挡掉的字段变出来。**

施加版式时，输入是**权限过滤后的字段集**；版式行引用不到的字段直接跳过。
所以"版式里排了、界面上没有"通常是权限问题，不是版式问题。

## 三、栅格

| 项 | 值 |
|---|---|
| 列数 | **页签声明**（`MODULE_FORM_TAB.LAYOUT_COLUMNS`，1 – 4，NOT NULL DEFAULT 4；模块级那层自迁移 319 起不存在） |
| `SPAN`（横向跨列） | 1 – **该行所属页签**的列数 |
| `ROW_SPAN`（纵向跨行） | 1 – **3**（三行约 78px；更高诉求改用多行文本控件） |
| `NEW_LINE` | 是否另起一行 |

列数是**页签级事实**——同一表单的页签 1 一行两列、页签 2 一行一列都合法（用户 2026-10-06 拍板）。
配置入口在**页签右键菜单的「布局列数」**：运行态表单、表单设计器画板、保存期校验三者同取这一处，
所以"设计态排 2 列、运行态按 4 列渲染"不可能发生。它随版式**同一笔保存、同一次重发布 ⇒ 保存即生效**，
不落在模块管理那条"存草稿 → 人工发布"的链上。超出范围的 `SPAN` / `ROW_SPAN` 在**推导时被钳制**，
在**校验时被拒绝**——两个方向都有保护。

**改列数时自动夹取**：把某页签从 4 列改成 2 列，该页签内 `SPAN > 2` 的行**当场夹到 2**（其它页签不动），
服务端写入侧同口径（`FormLayoutSubmission.Normalize` 按页签列数夹取）。所以调整布局即合规，
不会留下一堆"下次保存才被拒"的越界行。`check-form-layout.ps1` 的越界判据按**各页签自己声明的列数**逐行比。

**画板尺寸＝运行态容器尺寸**：打开方式选「弹窗」时，画板锁到模块声明的窗体宽
（高度取下限，内容超出时设计区继续滚动：拖拽的滚动补偿挂在设计区上，画板内再开一层滚动会让补偿算错），
行内折行位置因此与运行态一致；本页签 / 新页签方式下表单占满可用区域，画板同样铺满。

**行高是看得见的高度，不只是栅格占位**：栅格行高基准取 `--erp-form-row-height`（36px = 控件 26px +
上下内边距），`ROW_SPAN = 2/3` 的格因此在**设计画板与运行态都真的占 2/3 行高**
（72px / 108px 上下）。画板与运行态用同一 token、同一 `minmax(36px, auto)` 口径——
设计者调成"2 行"要立刻看到它变高，否则画板就违背了"所见即所得"。
（`minmax` 而非定值：内容更高的格——多行文本框、错误提示——仍能把行撑开。）

**行高还决定控件的形态**：长文本字段（`text`/`ntext`、`*REMARK`）
`ROW_SPAN = 1` 时渲染成**单行输入控件**，`≥ 2` 时才是多行文本框。
只有版式**没排过**这个字段（`rowSpan` 为空，即未定制的表）才回落到"整行独占 + 多行"的
启发式——否则设计者在画板上把备注调成 1 段宽 / 1 行高，运行态却被启发式顶回整行多行，
画板上的调整等于没生效。

## 四、复合格

复合格把几个字段挤进同一格、共用一个标签：

| 列 | 含义 |
|---|---|
| `CELL_GROUP` | 组名（同组字段共用一格） |
| `CELL_ROLE` | `1` = 主字段（带标签），`2` = 从字段（不带标签） |

规则与实现细节：

- **从字段必须有同组的主字段**，否则报错（`FORM_LAYOUT_COMPANION_WITHOUT_MAIN`）；
- **主字段不强制有启用中的选择器**——既有数据里存在"有组名但没配选择器"的格子，
  渲染上就是普通控件 + 同格从控件；强行卡住会让这类模块的版式保存不了；
- **一个格里多个从字段是常态**（如 BOM 的料号 + 品名 + 颜色），渲染侧按同格多控件排布；
- 同组多个主字段在既有数据里存在（组名复用），渲染侧把第二个主字段当成独立一格，不串格，
  故**不作为保存期拦截项**；
- 同格各字段**等宽均分**（设计态与运行态同一口径）：不按"主字段按内容、从字段占满"排，
  两组合/三组合/四组合一律均等；带选择器的字段与它的选择按钮算**一个**整体参与均分；
- 格内**三处距离相等**（字段↔按钮、按钮↔下一个字段、字段↔字段）：设计态与运行态同取
  `--erp-form-control-gap`。设计态每个字段尾部的角标容器**只在有角标时才占位**——
  空容器也会吃掉一份 flex 间距，让最后一段距离凭空多半格；
- 设计态给 `hasChooser` 的字段画一个与运行态同形的**选择器标记**（不可点，只是标注"这个字段是选入的"），
  故设计表单时一眼能看出哪些字段走选择器。
  设计态右键精修菜单的定位同样走 `useMenuPlacement`（贴近下缘时翻到落点上方）。

## 五、不可移除类字段

以下字段**既不能标隐藏，也不能整行不写**（"未列出"与隐藏同效）：

| 类别 | 说明 |
|---|---|
| 主键 | 单据的定位依据 |
| 单据生命周期系统列 | 状态位、经办人、日期等 |
| 用户可填的必填字段 | 用户能填且库里 NOT NULL 无默认值的列 |

**服务端可自行填充的字段不在此列**（`ServerFilled`）——它不算"用户可填"。

对应错误码：

| 错误码 | 含义 |
|---|---|
| `FORM_LAYOUT_REQUIRED_HIDDEN` | 必填/系统列被标记隐藏 |
| `FORM_LAYOUT_REQUIRED_MISSING` | 必填字段未加入表单（仅"已定制"的表检查） |

## 六、页签

- 页签号**不得重复**（`FORM_LAYOUT_TAB_DUPLICATE`）；
- 若提交了页签集合，**必须包含常驻的 1 号页签**（`FORM_LAYOUT_TAB_DEFAULT_MISSING`）——
  其余页签可删，1 号不可删；
- 版式行指向不存在的页签报 `FORM_LAYOUT_TAB_UNKNOWN`。

设计态页签的三个动作（都落在 `formDesignerDraft` 的纯函数上）：

| 动作 | 入口 | 语义 |
|---|---|---|
| 新增 | 页签条末尾的「+」 | `addTab`：取现有最大号 +1 |
| 改名 | 双击页签 / 页签右键「页签改名…」 | `renameTab`：改标题，页签号不变 |
| 删除 | 页签右键「删除页签」或页签上的 `×` | `deleteTab`：**其中的字段回到常驻 1 号页签**，不丢字段 |

删除前有确认；删的是当前活动页签时自动切回 1 号页签；1 号页签不可删（菜单项置灰）。

## 七、完整校验错误码表

保存时 fail-closed 校验（`FormLayoutValidator`）：

| 错误码 | 触发条件 |
|---|---|
| `FORM_LAYOUT_FIELD_UNKNOWN` | 版式行缺少字段代号 |
| `FORM_LAYOUT_FIELD_NOT_IN_MODULE` | 字段不属于该模块的表 |
| `FORM_LAYOUT_TAB_DUPLICATE` | 页签号重复 |
| `FORM_LAYOUT_TAB_DEFAULT_MISSING` | 缺常驻 1 号页签 |
| `FORM_LAYOUT_TAB_UNKNOWN` | 字段指向不存在的页签 |
| `FORM_LAYOUT_SPAN_OUT_OF_RANGE` | 列跨度超出 1..模块列数 |
| `FORM_LAYOUT_ROW_SPAN_OUT_OF_RANGE` | 行跨度超出 1..3 |
| `FORM_LAYOUT_REQUIRED_HIDDEN` | 必填/系统列被隐藏 |
| `FORM_LAYOUT_COMPANION_WITHOUT_MAIN` | 从字段没有同组主字段 |
| `FORM_LAYOUT_REQUIRED_MISSING` | 必填字段未加入表单 |

设计口径是 **fail-closed**：**引用不到的字段一律拒绝**，不给"配错了也能存"的余地。

## 八、明细版式

明细（子表）只有顺序与隐藏，没有跨度：

- 按版式行**重排**并剔除隐藏列；
- **调用方随后仍会补回必填与引擎必需的列**——明细列不像主表那样"未列出就消失"。

设计态明细面板标题栏右侧是**「字段管理」**（不再是"添加列"）：打开双栏弹窗
（左＝待选字段、右＝已选字段，可对已选字段上下排序），复用统一工作台的
`ErpColumnSelector`——对话框标题已写明对象（`字段管理（表名）`），故该组**组标题留空**，
不再顶一行多余的"明细列"（`ErpColumnSelector` 对空组名整行不渲染）。落点是纯函数 `applyDetailColumns`：

- 清单里有、明细行里没有的列 → 从字段池加入；
- 清单里没有的列 → 置为**移出表单**（不物理删行，保留排版属性，放回时原位回填）；
- **锁定列**（主键/系统列/用户可填必填）不允许移出，仍留在表单上；
- 顺序与 `ORDER_NO` 由同一函数重排——明细的拖拽排序仍是可用入口，但排序体验改由这里承担。

## 九、端点与权限

路由前缀 `api/v1/admin/form-layout`：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/{moduleId}` | 读版式状态 |
| `GET` | `/{moduleId}/templates` | 读模板 |
| `PUT` | `/{moduleId}` | 保存版式 |
| `POST` | `/{moduleId}/reset` | 重置 |

- **权限门是"版式设计权"**（`FormDesignPermissionResolver` 的 `CanDesign`），
  不是普通编辑权。无权限返回 403；
- 模块没有可设计的统一表单时返回 404 `FORM_LAYOUT_MODULE_NOT_FOUND`；
- 保存带**幂等键**（`IdempotencyKey`），重复提交不会产生两份版式。

> 注意：权限门用的是**版式设计权**。设计态选择器（`form-designer.fields` 数据源）
> 用的是同一把门，模块号从请求参数取。

## 十、排障

| 现象 | 原因 |
|---|---|
| 保存报"字段不属于该模块的表" | 版式行引用了别的表的字段——版式是模块级的，只能排本模块主/明细表的字段 |
| 保存报"必填字段未加入表单" | 已定制的表里漏了必填字段。要么加回去，要么改字段的必填设置 |
| 保存报"从字段没有对应主字段" | 复合格只配了从字段，缺同格主字段 |
| 保存报跨度越界 | `SPAN` 超出 1..**该行所属页签的列数**（页签未声明过则按 4），或 `ROW_SPAN` 超出 1..3；在设计器里改该页签的「布局列数」时越界行会被自动夹回来 |
| 重置后字段全回来了 | 重置 = 删除版式行，回到"未定制"，按元数据顺序渲染 |
| 版式改了但界面没变 | 模块定义快照未重发布（见 [41-定义快照与发布](./41-定义快照与发布.md)） |
| 想隐藏某字段但被拒绝 | 它是不可移除类字段（主键/生命周期列/用户可填必填）；改用字段级权限或改必填设置 |
