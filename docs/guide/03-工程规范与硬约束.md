# 03 工程规范与硬约束

**规则清单位于仓库根 [`AGENTS.md`](../../AGENTS.md) 第二、三节**，篇幅精炼、便于随时对照。
本篇讲这些规则**为什么存在**、**怎么落地**、**常见违规长什么样**。
两者冲突时以 `AGENTS.md` 为准，并回来修正本篇。

## 一、权限边界为什么只能在服务端

前端拿到的权限信息来自后端，用户可以改前端。因此：

> 前端权限判断只改善体验，**服务端必须对每个请求重新授权**。

落地要点：

- 控制器入口按模块 ID 做权限门（`CanBrowse` / `CanEdit` 一类），不要只在页面里判断；
- 权限键用 `资源.动作` 形式（如 `purchase-order.read`），前端用它决定按钮是否渲染，
  服务端用同一语义重新判定；
- **失败要 fail-closed**：未授权时拒绝，而不是"未配置就放行"。按钮级的自定义动作尤其如此——
  未获授权的用户不渲染按钮，服务端另行鉴权，无豁免。

常见违规：页面里隐藏了「批核」按钮，但 `/api/.../approve` 端点没有对应的权限门——
用 curl 就能绕过界面直接批核。

## 二、动态 SQL：白名单 + 参数化是两个独立的动作

界面上"查哪张表、按哪个字段排序、显示哪些列"都是运行时决定的，因此这些标识符天然来自外部输入。
防护分两层，缺一不可：

| 层 | 规则 | 不合格的例子 |
|---|---|---|
| 标识符 | 表名、列名、排序字段、查询字段**必须来自服务端白名单或定义** | 直接把前端传来的 `sortField` 拼进 `ORDER BY` |
| 值 | 一律参数化 | `WHERE CODE = '" + code + "'"` |

注意事项：

- **子表查询必须依赖有效的主表关联键**。缺少关联条件时禁止无条件读取子表——
  否则一次失误就会把整表数据带出来。
- **内部行键与显示列元数据分离**。行键（如 `__rowKey`）用于定位记录，
  不能因为"顺手"就把隐藏的关键字段重新塞进显示列返回。
- 结构化条件不要自己拼字符串。查询条件的正确形态是"字段 + 运算符 + 值"的结构，
  由服务端编译成参数化 SQL，见 [44-受控查询与条件模板](./44-受控查询与条件模板.md)。

## 三、受限表达式：保存即生效，没有发布流程

字段上可以存表达式（`VIRTUAL_EXP` 虚拟列表达式、`CONVERT_FUNCTION` 转换、`DATA_FILTER` 过滤）。
这些表达式最终会进入 SQL，因此不能未经解析直接使用。

- 保存字段时，表达式与字段一起提交（**空值 = 清空**），服务端在落库前用 `RestrictedExpressionService`
  做受控校验；**校验不通过则整单拒绝**，不做部分保存。
- `VIRTUAL_EXP` 只在 `IS_VIRTUAL=1` 的字段上生效，非虚拟字段一律拒绝。
- 运行时字段视图每次查询实时重建，所以保存完就生效，**不需要重新发布快照**。

> 历史上有过「校验 → 预览 → 发布」的三步流与对应端点，已废除。
> 看到有人要加"发布表达式"的功能，先确认不是把旧设计带回来。

## 四、命名：为什么必须全大写

数据库对象、以及 SQL 里的表别名一律大写：表名、列名、视图名、存储过程名、函数名、索引名、约束名。

原因不是审美，是**可检索性**：库里存在大小写混用的历史对象，而代码、元数据、白名单、
动态 SQL 分处不同语言与文件。统一全大写后，搜 `INV_PRO_DEPOT` 一定能找全所有引用点；
大小写混合时同一对象的引用会散落在多种写法里，改名与退役都会漏。

落地：

- 新建对象（含迁移里的表、列、索引、约束）全大写；
- 动态 SQL、元数据查询、白名单校验中的标识符必须与库内名称一致（全大写，或大小写不敏感匹配）；
- 禁止用驼峰或小写新建数据库对象。

## 五、元数据查询用 `sys.*`，不用 `INFORMATION_SCHEMA`

需要查"某表有没有某列""主键是哪几列"这类问题时：

```sql
-- 正确
SELECT c.name, TYPE_NAME(c.user_type_id) AS type_name, c.max_length, c.is_nullable
FROM sys.columns c
WHERE c.object_id = OBJECT_ID('dbo.FIELDS')
ORDER BY c.column_id;
```

- **禁止新增 `INFORMATION_SCHEMA.*` 查询**。它是多层视图 + 按名称字符串关联，
  实测主键列查询从 98ms 降到 2ms。
- 需同时覆盖表和视图时用 `sys.objects o ... o.type IN ('U','V')`。
- 类型名用 `TYPE_NAME(user_type_id)`。
- 字符列长度注意：`nvarchar` / `nchar` 的 `max_length` 是**字节数**（÷2 才是字符数），
  `max_length = -1` 表示 max 类型。
- 列顺序用 `column_id`，主键键序用 `key_ordinal`。

## 六、注释写什么

注释面向"为什么这么写 / 这段做什么"。**不记录任务上下文**：

| 不该出现 | 例子 |
|---|---|
| 任务/决策编号 | `// EOS-123`、`// ADR-018`、`// M7` |
| 开发日期与决策过程 | `// 2026-08-24 用户拍板` |
| 内部文档路径 | `// 见 docs/plans/xxx.md` |
| 新旧对照叙述 | `// 旧系统这样，新系统改成那样` |

表名、字段名、模块号、报表号等**业务标识符照常写**——它们是业务事实，不是任务上下文。
需要解释某处行为受历史约束时，写"为兼容既有数据/历史行为"这类中性措辞。

**为什么禁止引用内部文档路径**：代码随仓库分发，而 `docs/plans/`、`docs/status.md` 等内部工作文档
**不随仓库分发**——写进注释的路径，对任何在别处克隆仓库的读者都是一条死链。
要留下"为什么这么写"的线索，就把结论用中性措辞直接写在注释里，
**不要把读者引向一个他取不到的文件**；若结论的真值就在代码本身，写明"以本处为准"即可。

语言优先英文，同一文件内保持一致；`// TODO` 只描述遗留的技术事项。

## 七、前端：为什么强制统一组件

### 列表

所有列表一律用 `EOS.Web/src/components/common/ErpTable`，**禁止手写 `<table>` 做列表**。

理由：ERP 列表的信息密度高，用户对交互有一致预期——首列选择控件、表头排序、列宽拖拽、
Ctrl+C / 右键复制、键盘导航、吸顶表头，这些能力统一由 `ErpTable` 提供。手写表格会造成
"这个页面能拖列宽、那个不能"，且每处都要重写一遍复制粘贴与键盘逻辑。

数据行默认隔行浅底：`ErpTable` 按 `row.index`（**显示行号**）给第 2/4/6… 行加 `.erp-row-striped`，
不用 CSS `nth-child`——虚拟化的上下占位行也是 `<tr>`，会把整表奇偶翻掉。`ErpDataTable`
（以及任何带 `erp-data-table` 的手写表格）没有 `row.index`，由 `tbody tr:nth-child(even)` 兜底；
`ErpTable` 会带 `erp-table-js-striped` 关闭兜底，两套规则不会同时生效。裸 `<table class="table">`
不算标准表格，不会自动带——自定义页要隔行效果就用 `ErpDataTable`（列表则必须走 `ErpTable`）。
底色取 `--erp-table-stripe-bg`：浅色下比 hover 的 `--tblr-bg-surface-secondary` 更轻（悬停才是加深），
深色下比表头轻一档；选中行、当前行、区域选择与悬停都会覆盖底色，保证已有状态优先级不被打乱。

**列表页一律用组合件 `ErpListGrid`**（新页面不要再手拼 `ErpListCard` + `ErpTable`）。它收拢了每个列表
都一样的五件事：卡片外壳与命令栏、`loading/error/empty` 三态、`resizable` + 列宽持久化（`listId` 即
持久化键）、选择态（配了 `selection` 就默认"点行单选"）、分页脚。高级开关（虚拟化、区域选择/粘贴、
列宽写回服务端、列筛选、列重排）从 `tableProps` 透传——**组合件不复制这十几个 prop**。

| 场景 | 传什么 |
|---|---|
| 本地排序（数据已全在本页） | `sorting={{ mode: 'client' }}`（要受控可再给 `value`/`onChange`） |
| 分页取数（服务端排序） | `sorting={{ mode: 'server', value, onChange }}` |
| 选择态 | `selection={useListSelection(...).selection}`，同一份 hook 给出 `selectedIds` / `selectedRows` 给工具栏 |
| 分页 | `pagination={{ page, pageSize, total, onPageChange }}`（不传则是滚动加载或无分页） |
| 弹窗 / 面板里的表 | 只要"状态 + 表格"用 `plain`；要与列表页同款查询条/卡片时用默认形态，并用 `regionClassName` 指定滚动区 |
| 表格上方还要放提示条 | `before` |
| 页面自己的滚动区域（如工作台 `.erp-master-table-region`） | `regionClassName` |

`ErpTable` 仍是原语：需要"表格内可录入/可粘贴"(统一表单明细) 这类非列表用法时直接用 `ErpTable`。
存量 41 个文件 / 59 个调用点已全部迁到组合件（其中复杂页是"`ErpListCard` + `plain` 组合件"，卡内还有
筛选面板/子面板；纯表格页直接用组合件的卡片形态）；业务代码里只剩统一表单的明细录入格还在用 `ErpTable`。

**这些能力默认不全开，页面要逐项开**（2026-10-02 订正：原文读起来像"都是默认能力"，实际排序与
列宽都需要显式传参——不传不会有任何报错，只是那些菜单项与把手不出现，"能排序"这件事在界面上
不留痕迹，评审时也看不出来）：

| 能力 | 怎么开 | 不传的后果 |
|---|---|---|
| 复制（右键菜单 / `Ctrl+C`）、键盘导航、工作台容器内吸顶表头 | 默认开 | —— |
| 表头排序 | `clientSideSorting`（数据已全在本页）或 `onSortingChange`（服务端排序） | 表头菜单**根本不渲染** |
| 列宽拖拽 | `resizable`；再给 `storageKey` 让宽度按「用户 + 列表键」留在 localStorage | 列宽拖不动 |
| 行内单选 | `rowClickSingleSelect` | 点行没反应 |
| 操作列冻结 | 列 `meta: { frozenRight: true, … }` | 横向滚动时操作列被推到屏幕外 |
| 操作列初始宽度自适应 | 列 `meta: { autoWidth: true }` | 首屏宽度退化成"表头文字那么宽"，按钮被挤住 |
| 首列复选框 | 页面自己提供 `id: 'select'` 列（`meta: { className: 'erp-select-column', frozenLeft: true, resizable: false, truncate: false }`），再配 `rowSelection` + `onRowSelectionChange` + `getRowId` | 以为组件自动生成——不会。`rowSelection` 只是受控状态，没有列就没有控件 |
| 列宽写服务端个人层 | `persistResize={false}` + `onColumnResize` → `PUT /document-workbench/{id}/column-widths` | 默认只写 localStorage，换设备/换浏览器就丢 |
| 列头拖拽重排顺序 | `onColumnsReorder`（回调收到重排后的可见列键，含首列 `select`）；整个表头都能按下，鼠标移动 4px / 触屏 6px 才抓起；浮起预览只取列头高度、宽度封顶 200px，落点是一条 2px 插入线，拖到表格外松手即取消，左右边缘自动横向滚动（按住越久越快）；单击表头空白区打开表头菜单，拖动后不弹；父组件落手即乐观换序，成功后给带「撤销」的轻提示，失败原地换成失败态 +「重试」；表头菜单另提供「左移一列 / 右移一列」（首末列禁用，点完焦点回到表头） | 列头不可拖，顺序只能进「选择列」调 |
| 行键唯一 | `getRowId` 返回的键必须能标识一行：优先主键/服务端唯一键，快照类列表用下标 | **组件会兜底**：撞键的项按出现顺序补 `#2`/`#3` 并在开发期 `console.warn`，表格不会画成空白；但页面自己的 `rowSelection` / `activeRowId` 只认第一行，等于选择态错位。它拦的是"整表不可用"，不是替调用方定义身份 |

**电子表格手感（区域选择 / 粘贴 / 键盘）**：`ErpTable` 提供"像 Excel"的那几件事，页面按需开：

| 能力 | 怎么开 | 说明 |
|---|---|---|
| 单元格区域选择 | `cellSelection` | 在单元格上按住鼠标拖出一块矩形（或点一格后 Shift+点另一格）；有选区时 `Ctrl+C` 复制**纯块**（不带表头），`Esc` 取消，方向键在选区内移动、按住 Shift 扩选 |
| 区域粘贴 | `cellSelection` + `onPasteRange` | 回调给 `{ startRowIndex, columns, rows }`（列键从起点列到行尾），由页面决定写哪些字段；单值粘贴仍走输入框原生行为 |
| 区域清空 / 向下填充 | `onClearRange` / `onFillDown`（`Delete` / `Ctrl+D`） | 回调里带行下标与列键，页面按 `writableFields` 过滤——只读列既不落粘贴、也不被清空 |
| 行号/勾选/操作列不参与选区 | 列 `meta: { cellSelectable: false }`（`id: 'select'` 与 `__` 开头的列自动排除） | 否则选区会落在不可编辑的格子上 |
| 换批后回顶部 | `scrollResetKey`（把排序/筛选/关键词拼成一个值传进去） | 不传则停在旧偏移：排序完看到的是"另一批数据的中段"，看着像筛选没生效 |
| 全选行 | `Ctrl+A`（配了 `onRowSelectionChange` 就生效） | —— |
| 选区边界跳转 | `cellSelection` 下默认有：`Home`/`End` 到首个/末个可选列，`Ctrl+Home`/`Ctrl+End` 到首/末格，`Ctrl+方向键` 移到边界、`Ctrl+Shift+方向键` 扩选到边界 | 勾选/行号/操作列不在跳转范围，横向边界按可选列算 |

两条**不报错但会咬人**的规矩：

- **可录入表格的按键必须先让给控件**：`ErpTable` 自己的方向键 / Home / End / `Ctrl+C` 在
  `input` / `textarea` / `select` / `contenteditable` 内一律不接管——否则在格子里既挪不了光标，
  也复制不了选中的几个字。页面自建的录入格（如统一表单明细）要自己处理键盘，并在处理时
  `stopPropagation`：否则外壳那套"移动活动行"会同时触发，把视图滚走。
- **明细录入的键盘口径**：`Tab` / `Shift+Tab` 左右格（行尾折行），`Enter` / `Shift+Enter` 上下格，
  单行文本框里的上下键也走格子；`Enter` 越过末行才新增一行，方向键到边界就停，
  **`Tab` 走到末格交还浏览器**（拦住它等于把键盘用户困在明细里）。移动规则是纯函数
  `features/document-workbench/detailGridNav.ts`，改行为先改它的用例。

**性能约定（改完要保住"丝滑"）**：

- **行组件是 memo 的**：传给 `ErpTable` 的 `data` / `columns` 身份要稳（`useMemo` / `useCallback`）。
  页面每次渲染都新建一份列定义，等于让整表所有行重新实例化——打字时最明显。行内回调
  （`onRowClick` / `onRowDoubleClick`）可以照旧内联，组件内部经 ref 取用。组件内部把
  `table` 的 `state`、`getRowId` 与三个 onChange 也保持稳定身份，避免 TanStack 因内联对象重建行模型。
- **滚动窗口按帧合并并分块推进**：`virtualize` 下不读 `scrollHeight`（强制布局），总高按
  「表头高 + 行数 × 实测平均行高」估算；滚动事件用 `requestAnimationFrame` 合并，窗口按
  `VIRTUAL_CHUNK`（8 行）对齐，滚动 8 行才换一次窗口，窗口没变就不 setState。行高在激活/
  行数变化/容器 Resize 时重新量（取当前渲染行平均），隐藏标签恢复可见时由 `ResizeObserver`
  自恢复，不会停在旧窗口/旧行高。窗口碰到末行时提前触发 `onEndReached`，不等用户滚进底部占位。
- **列宽 effect 只随表格重建**：`onColumnResize` / `fitRef` 经 ref 取用，父组件传内联函数也不会
  重跑整个 effect；`autoWidth` 的 tbody 观察器只在真有自适应列时才挂。

**刷新不摘表**：列表的后台取数用 `placeholderData: keepPreviousData` 保留上一页，表格传
`loading={query.isFetching}`——保留旧行、降透明度、挡掉点击，右上角转小圈；`isPending` 只用于
"首次没有数据"时渲染整块 `LoadingState`。整块换成加载态会让表格消失再出现，是列表最刺眼的闪动。

**行高只有一个标准档位**：不传 `dense`（单元格 `padding: 5px`）。`dense` 输出 `erp-table-compact`
（`2px 6px`），那是**明细 / 子表**的档位——列表页传了就会与统一工作台"看起来不是一套东西"，
而这处差异不会报错、不会 lint、只能靠肉眼发现。明细要紧凑请用 `className="table-sm"`。

**满屏不滚动怎么来的**：页面根挂 `erp-full-list-page`。`.erp-list-card` 撑满页根、
`.erp-table-shell` 成为页内唯一滚动容器、表头吸顶——这三件事已在 `app.css` 的「全高裁溢出页」
段定义一次，**不要自己写 `calc(100dvh …)` 或内联高度**。页根也**不要挂** `gap-*` / `p-3`：
四周 10px 由工作区外壳的 `--erp-workspace-gap` 提供，Bootstrap 的间距工具类带 `!important`
会静默压掉它。

**操作列的标准写法**（各页一致，别自创）：`id: 'actions'`、`header: '操作'`、
`meta: { className: 'text-nowrap text-end', frozenRight: true, truncate: false, autoWidth: true }`；
按钮用 `Button size="sm" variant="ghost"` + 14px 图标 + `title`，外层容器 `d-inline-flex gap-1`。

**表格内按钮有两种写法，二选一，同一模块内保持一致**：

| 写法 | 观感 | 用在哪 |
|---|---|---|
| `Button size="sm" variant="ghost"` + 14px 图标 | 按钮大一号，行高约 30px | `/admin/groups`、字段维护、产品 BOM |
| 再叠 `erp-table-action` | 垂直 padding 压到 1px、字号 12px，行高回到 24px | 待办、流程监控 |

差别只有这一处，没有对错：

```css
.erp-data-table .btn-sm.erp-table-action { --tblr-btn-padding-x: 6px; --tblr-btn-padding-y: 1px;
  font-size: 12px; line-height: 1; min-height: 0; }
```

**新页面照抄目标页面所在的那一组**，不要自创第三种；混用会让同一次评审里的两张表
看起来不是一套东西。这一档差异不报错、lint 看不见，只能靠"与谁对齐"这个判断。

**组件参数只有一个调用方、且只传一个取值，它就应当消失。**

参数的存在意味"有两条路要维护"，而两条路里只走一条，另一条会在半年后变成**没人敢删的
死代码**——因为后来的读者不知道还有没有别的调用方。

判据不是"这个能力将来可能有用"，而是**"现在有没有第二个消费者"**。典型例子：1204 定制页
的维护组件曾同时支持"浏览态 / 编辑态"（照搬工作台的 `/view` + `/edit`）；后来浏览改由结构树
承担，`mode` 参数就只剩一个取值，那 9 处 `isEdit ? A : B` 全是死分支。

更危险的是**默认值**：`{ mode = 'view' }` 让"忘传参"的后果是整页只读——输入框点不动，
看起来像权限问题。删参数前至少先把默认值改成实际使用的那一支。

这条不报错、lint 也看不见，靠的是**每次改完路由或调用方后回查组件内部**：我改路由那次就
漏了这步，只改了调用点、没查组件里还剩多少分支。

**服务端排序**：分页取数的列表只能服务端排（客户端排序只会排当前这一页，看上去"排了"其实没排）。
页面把 `sorting` + `onSortingChange` 成对接到查询参数，**可排字段由服务端白名单决定**
（列 id → 库列的映射写在仓储里），前端提交的列 id 只用来查表——动态排序字段不得信任前端。
`ErpTable` 的 `onSortingChange` 只是回调，**`sorting` 必须一起传**：只传回调时表头箭头不会变。

列表里显示服务端给的**日期**时，按"日期标签"处理：按日聚合的值（`CAST(... AS date)`，
序列化成 `2026-10-01T00:00:00`）取前 10 位显示 `2026-10-01`，**不要** `new Date(…)` 再格式化——
后者会按本地时区重新解释这个值，西半球时区把日期挪到前一天，于是"10 月 1 日的用量"
排在 9 月 30 日那一行上。日期标签没有时区可挪，也就不该被时区挪。

相关约定：

- 列表**默认不设逐行操作列**，行内除首列选择外不放操作控件；行级动作优先通过工具栏或单据页触发。
  （已验收的定制页——2305/2306/2201/3102——实际保留了行内操作列，形态见下一条：
  放开它的前提是按钮形态统一，而不是各页自己发挥）；
- **操作列与普通列一样可拖列宽，初始宽度按按钮组自适应**（列 `meta: { frozenRight: true, autoWidth: true }`）：
  写死一个偏宽的固定像素值，在按钮少的页面上白占横向空间，按钮多了又不够；自适应用的与双击把手
  同一套算法（`useColumnResize` 的 `data-col-autofit`），拖过之后以拖拽值为准；
- 行内操作按钮统一 `variant="ghost"` + **14px 图标 + 文字**（对齐 2305/2306，见
  《定制页面清单》（内部资料，不随仓库分发）的 2201 验收记录）；可见文字已经是可访问名，
  **不必再挂同名 `aria-label`**——那会与对话框里同名的输入框撞车，把定位查询弄歧义；
- 工具栏（命令栏）按钮按位置分两种形态，二者都 28px 高、16px 图标：
  - **列表工具栏（统一工作台）一律纯图标**：`ErpCommandBar` 的 `iconOnly` 模式 +
    `className="erp-command-icon-btn"`（28×28 方形圆角），动作名只作 `title` 悬停提示与 `aria-label`。
    列表工具名长短不一（刷新 / 选择列 / 自适应列宽），带文字必然宽窄不齐；主操作「新增」同样是纯图标，
    只保留主色区分。要常显的数字（如已生效的查询条件数）用 `badge` 角标，不要塞回文字里；
  - **单据工具栏（统一表单）用图标 + 文字**：`className="erp-command-btn"`。批核 / 解批 / 结案
    这类低频动作必须能读出名字，自定义按钮的图标又是统一的（只靠 label 区分），不能纯图标化。
  工作台命令栏对"没挂这两个类"的按钮有一套 28×28 方块样式（文字会被裁掉），类名丢了不报错，
  只会让按钮变成一排看不懂的图标；
- 破坏性操作（删除）必须先在浏览态确认单据细节，**禁止列表页「选复选框 → 直接删除」**；
- 工具栏分两类：列表工具栏只放列表自身工具与「新增」入口；单据级动作全部放统一表单工具栏。
  详见 [40-统一工作台](./40-统一工作台.md) 与 [42-统一表单](./42-统一表单.md)。

### 页面骨架

所有工作区页面的页面根**必须**挂 `erp-base-page`——它是骨架的唯一入口（竖排、占满内容区、
区块间距 10px、`min-height:0`）。页面还得在下面两种形态里**显式选一个**：

- **满屏页**：再加 `erp-page-fill`。页级不出滚动条，滚动只能发生在内部区域（列表卡的表格区 /
  表单卡 / 设计器画布）。列表页、统一表单、工作台、报表、配置台、导入页都属于这一类；
- **流式页**：不加 `erp-page-fill`。内容可以高于视口，由标签面板（`.erp-tab-panel`）出页级滚动条
  （个人资料、首页这类）。

**四周 10px 不在页面根里出**：由外壳两层给——`.erp-tab-panel` 出上下、
`.erp-tab-panel > .container-fluid` 出左右。页面根**不得再写 padding/margin 间距工具类**
（Bootstrap 的 `p-*`/`m-*` 带 `!important`，要么叠成 20px、要么直接贴边）。

新增页面漏挂 `erp-base-page` 会被 `scripts/check-page-shell.ps1` 拦下（具名例外写在脚本里）。

**主表 + 子表的高度不用页面自己算**：页面根下是 `.erp-list-card` + `.erp-detail-card` 时，
自动按"主表占剩余高度、明细卡 30%（150~260px 区间）"分配，两张卡各自内部滚动。
**全屏表格页**（一个页面就一张大表）由 `.erp-page-fill > .erp-list-card > .erp-table-shell`
承担滚动——判据是"表格区是不是卡片的直接子项"，中间多套一层（如工作台的
`.erp-master-table-region`）则由那一层滚，避免双层滚动条。

**各页只声明与标准不同的地方**：固定高度、媒体查询下的退让、分区网格（如 dashboard 的分栏）。
骨架本身不要在页面里重抄。

同一个骨架原先被逐页抄了 12 遍，于是长出多种写法（间距有 `var(--erp-block-gap)` 与裸 `10px`，
最低高度有 `0` 与 `320px`）——改一次间距口径要改 12 处，漏一处看不出区别。满屏表格页的滚动契约
（卡片撑满 → 表格区内部滚动 → 表头吸顶）同理，原先在 8 处规则里逐字重复，新增页面必须照抄其中一份。

四类硬约束由 `scripts/check-page-shell.ps1` 拦——它**在 CI 里跑**（2026-10-12 接入，此前只登记在
"按需挑着跑"的表里，等于"谁记得谁跑"）：

- **页面根不写内联高度**：`style={{ height: 'calc(100dvh - 96px)' }}` 这类魔数在外壳高度变化
  （标签栏、页头调整）时必然算错，而且"改的人不知道要同步这个数字"；
- **不手写弹窗遮罩**（`rgba(0, 0, 0, 0.4)` + `zIndex: 1000`）、**不手拼卡内工具条**
  （`card-header py-` / `card-header d-flex`），两者各有统一件（`Modal` 与 `.erp-card-toolbar`）；
- **不手抄统一组件的骨架**：在页面里直接拼 `card erp-list-card` 或 `erp-data-table` 类名，等于抄了
  `ErpListCard` / `ErpTable` 的 DOM 却拿不到它们的能力（列宽持久化、选择列、键盘导航……），
  将来改骨架还得记得改 N 处。2026-10-12 之前有四处页面是这么写的，已收敛；判据落在门禁里，
  产类名的三个组件定义文件豁免。`-SelfTest` 用合成样本自检判别力（正例必抓、反例不误报）。

配套的 `scripts/check-css-classes.ps1` 同样在 CI：JSX 里的 `erp-*` 类名必须在 CSS 里有定义，
悬空类名存量已清零（新写一处即失败）。这两条挡不住的是"用对了组件但用法不对"，那靠评审。

### 页面级几何

页面根的几何——`display: flex; flex-direction: column; gap: var(--erp-block-gap);
flex: 1 1 auto; min-height: 0`——只在 `app.css` 的「页面骨架」段写一次，页面根类以**并列选择器**
加进那一组。需要覆写的差异项也各自只有一处：全高页的 `min-height: 320px; overflow: hidden`
集中在一个「全高裁溢出页」声明里，导入页的 grid 行高、模型管理页把 `min-height` 收回 `0`
留在各自区块。

**新页面只加一个页面根类名**，不要在自己的区块里重抄那几条声明——抄一遍，下次调整留白口径就会
漏掉它，页与页之间于是长出差量（2026-10-12 把此前被抄了 5 遍的一对声明收敛到一处）。
卡内头部行/工具条的**内部**元素间距是另一档（`5px` 按钮区 / `8px` 行内），不走
`--erp-block-gap`——那个 token 是「区块与区块之间」的口径。

工具条自身的几何同理：`.erp-list-command-bar` / `.erp-card-toolbar` / `.erp-menu-tree-toolbar` /
`.erp-menu-sort-bar` 的内边距、下边框、元素间距与是否折行，都在 `app.css` 一处定义，JSX 只挂语义类。
**不要**在工具条上再拼 `p-2 border-bottom d-flex gap-1 align-items-center`——同一个工具条各页
拼法不同，间距与折行就会各页不同（2026-10-12 菜单管理与权限矩阵的两行工具条已收敛到 CSS；
`gap-*` 还带 `!important`，会盖掉 CSS 里的间距）。

### 列表卡外壳

页面的白底圆角容器与命令栏只用 `EOS.Web/src/components/common/ErpListCard`：它渲染
`.card.erp-list-card`（命令栏 + 标题 + 主体 + 分页脚），命令栏由 `search` / `actions`
两个槽填充，按钮区统一是 `.erp-list-actions`。

- **禁止手写 `<div className="card erp-list-card">` 复刻骨架**，也禁止自造命令栏
  （`d-flex … border-bottom px-3 py-2` 那一类）：命令栏的高度、圆角、内边距、按钮间距与换行
  都由 CSS 一处定义，各页重抄一遍必然长成不同的样子——同一个系统看上去像两套。
- 页面根容器仍用各页的语义类（`erp-full-list-page` / `erp-report-page` / `erp-menu-admin` …），
  高度链与滚动归它们管。
- **定制形态的两栏页**（菜单管理 230101、配置面 230104）同样用 `ErpListCard`：
  它们是"左清单 + 右配置"，卡片与顶部命令栏照旧由外壳给，页面根另挂语义类
  （`erp-menu-admin` / `erp-config-workbench`），两栏走 `card-body`；
  配置面 230102 与 230103 已改成跨模块的扁平列表 + 弹窗，走的就是普通列表页这一套。
- **卡内那一行（标题 + 状态徽标 + 行内动作）用 `.card-header.erp-card-toolbar`**：命令栏下方
  或内嵌卡片头部的工具行，内边距、元素间距、是否折行只此一处定义。原先 14 处手拼
  `card-header py-2 d-flex align-items-center gap-2`（纵向留白有 `py-1` / `py-2` / `px-3`，
  间距有 `gap-1` / `gap-2`），改一处不会同步到别处。
- **列表上方的统计/说明行（"共 N 个…"）用 `.erp-list-header`**：它曾经是**悬空类名**——
  4 处挂在没有定义的类上，看起来写了样式其实只有 Bootstrap 工具类生效（样式类门禁的基线里
  一直挂着它们）。现已定义，基线相应下调。
- **弹窗一律用 `components/ui/Modal`**，不要手写遮罩层（`position-fixed` + `rgba(0,0,0,.4)` +
  `zIndex:1000` + `card shadow`）。手写版只有一个好处——点遮罩关闭——换来的是遮罩浓淡、
  宽度档位、`maxHeight` 各写一遍；统一件没有这个能力，故**关掉的方式是右上角 × 或页脚按钮**
  （全站一致，不要再给单个弹窗加回去）。
- **`ErpTable` 的例外**：弹窗内的**紧凑明细对照表**（十几行的差异/变更明细，不需要列宽拖拽、
  选择列、分页与吸顶表头）允许直接手写 `<table class="table table-sm">`——套 `ErpTable` 会给
  三行数据引入整套交互。**判据是"这张表要不要那些列表能力"**，不是它在不在弹窗里：
  要列表能力的（可选列、要排序、要复制、行数多、要分页）一律用 `ErpTable`。
- **色值走变量**：语义色用 `var(--tblr-*)`；本页专用的档位（如业务流程图的域色与中性灰阶）
  在该页自己的 `.css` 顶部集中声明一次，不要散在十几条规则里各写一遍裸色值。
- **字号与圆角走刻度变量**：`--erp-font-2xs/xs/sm/md/lg`（10/11/12/13/15px）与
  `--erp-radius-xs/sm/md/lg/pill`（4/6/8/12/999px）在 `app.css` 的 `:root` 只声明一次，
  新规则不写字面量。圆角三档对应「小控件 → 按钮/导航 → 卡片/弹窗」，字号四档对应
  「徽标 → 辅助说明 → 正文与表格 → 标题」。**例外**：登录页营销排版、助手 markdown 内容
  （13–16px 是富文本自身的层级）、打印字号、品牌标记与登录 mark 的 logo 比例圆角
  （10/11/20px 随图标尺寸走，不属于控件档位）。
- **例外**是形态上本就没有列表语义的页面（整屏打印视图 `PrintViewPage`、全屏助手面板
  `AssistantPage`）：不套列表卡，白底圆角由各自的容器负责。
- 已收敛的手写骨架：`FieldEditorPage`、`LayoutDesignerPage`、`RightsMatrix`、
  `ButtonRightsMatrix`（2026-10-12 改为复用 `ErpListCard`）。

### 表格与域内档位

- **数据列表一律用 `ErpTable` / `ErpDataTable`**；**弹窗内的紧凑明细**是明确的例外——十几行的
  「项目 / 旧值 / 新值」对照（字段变更历史、表达式审计、行为预演、助手改动对比、表单草稿）
  用手写 `<table class="table table-sm">` 即可：为三五行数据套数据表，会连带引入拖列宽、选择列、
  分页一整套交互，那是为形式牺牲结构（2026-10-12 逐条判定后登记为例外，不再当作待收敛项）。
- **域内档位不走全站 token**：feature 目录 .css 里的自造色板与字号/圆角档位，是本域有意的取色与
  密度（业务流程图与参考图形一致的图形用色、版式设计器那张密集工具栏的 10 / 11 / 12px 字号）。
  口径是：语义色引用 `var(--tblr-*)`（主题变更随之生效）；域内特有档位在文件头**集中声明一次**
  （如 `business-flow.css` 的 `--erp-flow-*`），不散落在各条规则里。**不要**为了"看起来用了 token"
  把域内档位映射到语义位——值对不上，映射等于改视觉；也不要写具体色值回退
  （`var(--tblr-primary, #206bc4)` 那种，旧版主色回退值永不生效，留着只会被误读为设计色）。
- **电子表格的行高与单元格留白只由一对 token 决定**：`--erp-table-cell-pad-y` / `-x`（`app.css`
  的 `:root`，当前上下 6.5px、左右 5px ⇒ 数据行约 30px）作用于全部 `erp-data-table`，所以工作台、
  列表页、报表矩阵、选择器弹窗一起变。要放宽或收紧密度**只改这一处**，不要在页面或 feature 的
  .css 里重写 `td` 的 padding。**主表列表与明细表共用同一档**，不给明细另起密度：明细编辑行因为
  格内是 30px 的输入控件而自然更高（约 43px），占位行 `.erp-detail-filler` 按同一算式
  `calc(30px + pad-y × 2)` 跟齐——两者分开写数字，调档时必然走散。与 Excel 同步的复制、
  区域选择等行为只取文本，不受留白影响。
- **吸顶表头必须自带不透明底色**：Tabler 的 `.table thead th` 把底色清成了 `transparent`，
  `position: sticky` 之后滚动内容会从表头里透出来（表现为列头与下面的 td 叠在一起）。
  故表头底色统一走 `--erp-table-header-bg`（`app.css` 的 `:root`，body-color 混 5% 到卡面），
  冻结列的表头也走同一 token（`.erp-frozen-*` 那条给的是卡面白，贴在表头里会亮出一块）。
  **不要**换用 `--tblr-bg-surface-tertiary`——它是 `color-mix(…, transparent)`，同样会透；
  也不要直接用 `--tblr-bg-surface-secondary`，它在浅色下几乎等于白，读不出层次。

### 选中态

左栏、树、清单里"当前选中的那一项"统一用一组 token（`app.css` 文件头）：`--erp-active-bg`（底色）、
`--erp-active-fg`（文字）、`--erp-active-bar`（左缘 2px 色条）。底色是"品牌色混当前主题卡面"的
`color-mix`，深色主题另给一组更强的混比——**不要**在页面里写 `var(--tblr-primary-lt)` 加固定色条：
浅色下能看，深色下要么发白要么几乎看不见，同一个"选中"在两种模式里长成两样。

- 标准形状：**圆角底色 + 左缘色条**（`box-shadow: inset 2px 0 0 var(--erp-active-bar)`），
  不需要额外边框——底色与色条已经足够，再加描边会变成第二层框；
- 表格行的选中（`.erp-row-active`）只用同一组底色，不加色条（行没有圆角，色条会显得突兀）；
- **左栏清单一律用 `components/common/ErpSelectionList`**（230104 配置面与字段设置页已接）：
  主行 / 次行 / 右侧附加信息、空态、加载态与滚动都由它承担，页面只给宽度与分隔线
  （如 `.erp-config-rail` / `.erp-field-nav`），不要复制条目样式；
- 树形选择仍用 `ErpTree`，选中态走同一组 token；菜单树、权限树、字段选择器已按这套统一，
  新增页面不再另起一套。

### 弹窗

字段多或列表长的弹窗，一律给 `Modal` 传 **`scrollable`**：滚动收进 `.modal-body`
（`overflow-y: auto`），标题与页脚（保存 / 取消）**固定不动**。

- **不要让整窗高过视口**：那样只能滚外层，而滚外层会把页脚一起推出屏幕——实测 620px 视口下
  模型参数弹窗 765px 高，「保存 / 取消」都在屏幕外（窗口高 800 时它又"刚好能看"，所以这种缺陷
  只在矮窗口露出来）；
- **不要再给内层列表另设 `maxHeight` + `overflow`**：那会变成"窗口里再套一个小滚动区"，
  一层滚动比两层清楚；
- 弹窗尺寸仍随内容自适应（`scrollable` 只加上限，不把短内容拉满）。

**层次（遮罩浓度、背景模糊、描边与投影）只在 `app.css` 的「弹窗层次」段定义一次。**
Tabler 把遮罩放在 `.modal-backdrop` 上，而本项目不渲染该元素，实际只有 4px 模糊、透明边框与
`box-shadow-sm`，白卡会直接浮在白底上；故由 `.modal.modal-blur` 与 `.modal-content` 统一补
底色、模糊、描边与双层投影。页面与组件不要再加 `backdrop-filter`、`box-shadow` 或自绘遮罩——
叠加的结果是有的弹窗浓、有的淡，又回到"每个弹窗各写一遍"。

### 选择器

凡"从既有业务数据中挑记录"的输入（员工、客户、供应商、物料、产品、仓库、部门、模块、表、字段、
报表……），一律用 `UnifiedChooser`，禁止页面内自建弹窗或用表格手搓。

数据源只允许两种：

| 方式 | 说明 |
|---|---|
| `formField` | 复用 `CHOOSE_*` 表单字段元数据 |
| `sourceKey` | 服务端注册的数据源（`POST /api/chooser/query`） |

`loader` 只用于存量过渡，**新代码不得新增**。列与默认列必须来自服务端元数据，前端不得硬编码列清单。
新增数据源在 `EOS.API/Data/ChooserRepository.cs` 注册（可排序列/关键字/列表达式白名单 + 权限门 + 参数化查询）。

例外只有一个：固定枚举/字典小集合（状态、类型、是否）用下拉 `select`。
确无元数据支撑的聚合或跨系统数据，也应注册 `sourceKey` 承载，不得回退自建选择器。
**行内受控下拉不算选择器**：选项由父组件按上下文算出来的那种（如表达式构建器里"这个字段该选哪些列"）
保持下拉——它既不独立取数，也不需要弹窗、多选与分页，套进 `UnifiedChooser` 只会把行内紧凑布局撑开。

字段维护（2302）的三个元数据候选清单（未登记物理表 / 未管理字段 / 幽灵字段）就是这么收进来的：
它们的源是 `sys.objects` / `sys.columns`——**库里的物理对象，不是已登记的元数据行**——所以列表达式
只能在 `ChooserRepository` 里写死（同 `menu-admin.columns` 对 `sys.columns` 的做法），
而"还没登记"正是这些数据源的全部意义。

### 反馈

按"要不要用户决策"选形态，三档：

| 场景 | 形态 |
|---|---|
| 瞬时、不需决策（动作被拒绝、保存/复制成功） | 全局轻提示 `useToast().notify`（右上角、自动消失、可手关） |
| 与页面内容相关（表单校验、加载失败、发布结果） | 页内 `alert-*` / `AsyncState`，不盖浮层 |
| 需要用户决策（脏页离开、破坏性操作、档位确认） | `Modal` 确认 |

唯一实现是 `EOS.Web/src/components/ui/Toast.tsx`，**禁止各页面自建浮层提示**。
同一件事的连续状态（如"列顺序已调整 → 未保存 → 已撤销"）用 `key` 复用一条提示、原地改文案/语义/动作；
状态失效（如「选择列」改写了整份列集，旧撤销目标不再有效）用 `dismissKey(key)` 立即清掉。

### 工作区标签与跨模块跳转

标签按「模块窗口」建模：**一个模块一个标签**，列表、单据浏览/编辑/新增/复制都在同一个标签里；
跨模块只切/开标签，绝不顶掉来源。规则全文与理由见
[ADR-040](../decisions/ADR-040-工作区标签的导航模型.md)，这里只列落到代码上的四件事：

| 你要做的事 | 唯一写法 | 不要写 |
|---|---|---|
| 去另一个模块 / 页面（待办→单据、报表中心→报表、字段设置、流程图→模块） | `useOpenTab()(url, { locate: true })` | `navigate('/workbench/…')`——那会把当前标签顶成目标模块 |
| 菜单类入口（侧栏、菜单搜索、首页快捷） | `openTab(url)`（只聚焦，不挪动它停在哪一页） | 自己判断"是否已开"——身份由外壳算，页面看不到 |
| 表单的"返回" | `navigate(workbenchList(moduleId))` | `navigate(-1)`、`?back=` 参数、硬编码 `'/bom/product'` |
| 同模块两单并排（对照窗口） | `openForm(url, { openMode: 'NEWTAB' })` | 页面自己拼第二个标签或开浏览器窗口 |

三条不变式，改导航相关代码时先对照：

1. **标签身份 ≠ 地址**：身份是「模块 / 页面路径 / 单据（模块+主键）」，`?keyword=`、`?from=` 都不参与
   （`workspaceTabs.ts` 的 `tabIdentityOf` 是唯一计算点，不要在页面里自己拼去重键）。
2. **页面不猜"从哪来"**：来源由标签栏承载，目标页不需要记住它；`from` 只用于标题旁的「← 来源」提示。
3. **`navigate()` 只用于同一个标签内部的移动**（列表↔单据、页面族内的父子页）。
   跨身份用它等于把当前现场顶掉——这正是 ADR-040 要消除的那类问题。

门禁 `scripts/check-tab-navigation.ps1` 拦三类退化写法（`navigate(-1)`、`back=` 参数机制、
`window.open('/(workbench|report|admin)…')`）。

## 八、提交

提交信息采用 Conventional Commits：`<type>(<scope 可选>): <描述>`，描述用简体中文。

```
feat(purchase): 采购订单支持部分入库
fix: 限额原子扣减与用量估算回退
docs: 补充统一选择器数据源注册说明
```

type 取值、唯一真源与**「写什么 / 不写什么」的清单在 [`AGENTS.md`](../../AGENTS.md) 第四节「提交信息」**——
本节只讲为什么，**不复述那份清单**（抄一份必然两处漂移；`CONTRIBUTING.md` 的「提交信息」也指向同一处）。

读者是后来翻 `git log` / `git blame` / 发布说明的人，他**只读仓库、不读对话**。所以判据是一句话
**离开本次会话还能不能被理解与验证**：会话身份（`按用户要求` / `用户拍板` / "第 N 步"）、验证流水
（`门禁通过` / `测试全绿` / `用例 N 条`）、过程叙述（`顺带` / `经过排查`）都过不了这一关；
而 ADR 编号、`LESSONS.md` 的 `L<n>`、迁移编号、模块号这些**仓库内可长期定位的锚点**，正是为
"跳出会话仍可定位"而存在的。

自查：`pwsh scripts/check-commit-msg.ps1 -Message '拟用的提交信息'`（只拦硬信号与格式违规，不做文风评判）。

提交前确认 `EOS.Web` 与 `EOS.API` 的验证命令全部通过（见 [06-测试与质量门禁](./06-测试与质量门禁.md)）。
